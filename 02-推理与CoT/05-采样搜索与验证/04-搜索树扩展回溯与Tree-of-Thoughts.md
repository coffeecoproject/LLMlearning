# 搜索树扩展、回溯与 Tree of Thoughts

> [!summary]
> Tree of Thoughts 不要求一次生成完整答案，而是把局部想法作为节点，反复执行“扩展、评价、保留和回溯”。

## 为什么不一次生成到底

完整采样只能在回答结束后比较结果。如果错误出现在第一步，后面大量 Token 可能都浪费在错误方向上。

树状搜索先观察局部路径：

```text
问题
├── 想法 A
├── 想法 B
└── 想法 C
```

评价后只扩展有希望的分支：

```text
问题
├── A
│   ├── A1
│   └── A2
└── B
    ├── B1
    └── B2
```

## 一轮怎样运行

1. 控制器把当前节点交给模型；
2. 模型生成几个下一步候选；
3. 评价器为候选打分或分类；
4. 控制器保留部分节点；
5. 从保留节点继续向前生成；
6. 达到答案、预算或停止条件后结束。

## 回溯的真实含义

如果 `A2` 被判定为死路，系统不会逆向删除模型已经生成的 Token，而是丢弃 `A2` 分支，取出之前保存的 `A` 节点，再扩展另一条后缀。

```text
A → A2 失败
→ 恢复保存的 A
→ A → A3
```

## 中间状态必须系统可见

如果控制器要决定 A 与 B 哪个更值得扩展，就需要得到某种可评价的中间表示。它可以是自然语言步骤、结构化计划、代码状态或数学表达式。

这些状态不一定展示给最终用户，但必须对搜索控制器或评价器可用。

## Tree of Thoughts 不等于模型内部天然有一棵树

论文框架用模型生成和评价“Thought”，再由外部算法维护树。不能据此推断 Transformer 内部 Hidden State 就按照同样的树结构运行。

## 什么时候值得使用

- 早期选择会明显影响最终结果；
- 可以评价局部进展；
- 问题允许尝试不同策略；
- 额外模型调用的延迟和成本可以接受。

如果最终结果容易直接验证，生成几条完整答案可能比维护复杂搜索树更简单。
