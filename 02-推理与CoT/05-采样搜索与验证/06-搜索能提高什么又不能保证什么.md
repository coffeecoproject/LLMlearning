# 搜索能提高什么又不能保证什么

> [!summary]
> 搜索增加找到好路径的机会，验证增加筛掉错误候选的证据，但两者的效果仍受候选质量、评价标准和计算预算限制。

## 搜索可能改善什么

- 降低一次随机生成走错路径的影响；
- 尝试不同分解方法和假设；
- 在早期淘汰明显错误的分支；
- 为可验证任务提供更多候选；
- 用更多 Test-time Compute 换取更高成功机会。

## 为什么仍不能保证正确

### 所有候选可能共享同一错误

如果模型误解了题目，A、B、C 可能只是同一误解的不同写法。

### 评价器可能选错

模型评分器也会受到措辞、长度和自信语气影响。错误候选可能看起来更完整。

### 验证标准可能不完整

```text
测试通过
```

只代表通过了已有测试，不代表覆盖所有真实场景。

### 计算预算有限

系统不可能无限扩展分支，必须设置候选数、深度、时间或费用上限。正确路径可能尚未被采样就已经停止。

## 成本怎样增长

粗略理解：

```text
总计算投入
≈ 路径数量 × 每条路径平均推理投入
  + 评价与验证成本
```

这不是精确计费公式，但能说明为什么“更多路径 + 每条 high effort”可能很昂贵。

## 什么时候应优先改进上下文

如果所有候选都缺少关键事实，再多搜索也只是在错误或不完整的上下文中反复生成。此时更应该先：

- 获取真实文件或数据；
- 消除冲突指令；
- 明确任务约束；
- 建立可执行的验证条件。

## 最终判断框架

```text
候选不稳定
→ 增加独立采样

早期决策容易走错
→ 使用分步搜索和回溯

最终结果可程序检查
→ 使用结果验证

中间步骤本身很关键
→ 使用过程评价或过程验证

缺少真实信息
→ 先补上下文或调用工具，不要只增加搜索
```

## 理解检查

1. 为什么十条候选仍可能全部错误？
2. 测试通过为什么不一定证明任务完整完成？
3. “路径数量 × 单条推理投入”说明了什么系统取舍？
