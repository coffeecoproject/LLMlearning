# CoT 中间推理文本概览

> [!summary]
> Chain of Thought（CoT，思维链）是模型在最终答案之前生成的一串中间推理文本；这些 Token 会进入后续上下文，给模型提供更多可继续计算的步骤，但它们不等于模型内部计算的完整记录，也不能保证答案正确。

## CoT 在完整流程中的位置

```text
用户问题
→ 模型读取当前上下文
→ 生成中间步骤 Token（CoT）
→ 已生成步骤成为后续上下文
→ 模型继续生成
→ 最终答案
```

CoT 没有替换 Transformer，也没有绕过下一 Token 预测。它只是让模型在给出最终答案前，先生成一些能被后续步骤继续读取的内容。

## 输入、作用和输出

| 问题 | 框架理解 |
|---|---|
| 输入是什么 | 当前问题、系统指令和已有上下文 |
| CoT 做什么 | 把一次较大的推理跳跃展开为若干中间步骤 |
| 为什么可能有帮助 | 后面的 Token 可以读取前面已经写出的条件、局部结果和计划 |
| 输出是什么 | 一串中间 Token，之后通常还有最终答案 |
| 它不是什么 | 不是 Transformer 内部全部 Hidden State 变化的录像，也不是正确性证明 |

## 一个最小例子

问题：

```text
每箱有 4 个杯子，3 箱一共有多少个？
```

直接回答可能是：

```text
12 个。
```

使用 CoT 时，模型可能先生成：

```text
每箱 4 个，共 3 箱，所以计算 4 × 3 = 12。
```

这里的 `4 × 3` 和 `12` 会成为后续 Token 可以关注的历史内容。这个例子只是说明中间文本怎样参与后续生成，不代表所有题目都需要展示详细步骤。

## 为什么中间 Token 可能提高成功率

如果模型直接从问题跳到答案，需要在一次较短的生成路径中完成所有关系组合。CoT 把它展开成：

```text
识别条件
→ 写出局部关系
→ 得到中间结果
→ 根据中间结果继续生成
```

这相当于给运行阶段增加了可见的文本工作区和更多生成步骤。

但如果前面的中间步骤写错，后面的 Token 也可能沿着错误继续生成。因此：

```text
更多中间步骤
→ 可能增加解决复杂问题的机会
≠ 自动增加真实事实
≠ 自动保证推理正确
```

## CoT 是否一定展示给用户

不一定。产品可能：

- 展示模型生成的中间步骤；
- 只展示一段推理摘要；
- 使用不向用户展示的 Reasoning Token；
- 只返回最终答案。

因此，界面上看到解释，不代表看到了模型内部计算的完整过程；界面上只看到答案，也不能反推出模型完全没有投入额外推理计算。

## CoT 与搜索、验证的关系

```text
一条 CoT
= 一条向前生成的中间文本路径

搜索
= 建立并比较多条候选路径

验证
= 用规则、工具、模型或人类检查步骤或结果
```

CoT 可以单独存在，不一定有搜索；搜索可以生成多条 CoT；验证可以检查一条或多条路径。

## 最重要的边界

> [!warning]
> CoT 写得详细，只说明模型生成了一段详细解释，不足以证明这段解释忠实反映了答案形成原因，也不足以证明最终答案正确。

模型可能出现：

- 中间步骤本身错误；
- 先得到答案，再生成看似合理的解释；
- 在过长过程中重复、偏离或自相矛盾；
- 在缺少事实时编造中间依据。

所以 CoT 是一种运行阶段的推理路径，不是独立验证证据。
