# 推理与 CoT 框架速览概览

> [!summary]
> 大模型推理不是突然脱离下一 Token 预测，而是利用内部计算和连续生成的中间 Token，把复杂问题展开成更多可继续计算的上下文；搜索与验证还能在这条生成主线之外进一步筛选路径。

## 先看最小主线

### 直接回答

```text
问题
→ 模型内部计算
→ 直接生成答案 Token
```

### 使用 CoT

```text
问题
→ 生成中间步骤 Token
→ 中间步骤进入后续上下文
→ 继续计算和生成
→ 最终答案
```

### 加入外部搜索与验证

```text
问题
→ 生成多条候选推理路径
→ 比较、搜索或验证
→ 选择或修正
→ 最终答案
```

三者都仍然依赖 LLM 的逐 Token 生成，但使用的计算量和外部控制不同。

## 一个最小例子

题目：

```text
17 × 24 等于多少？
```

直接回答可能马上生成 `408`。

CoT 路线可以生成：

```text
17 × 20 = 340
17 × 4 = 68
340 + 68 = 408
```

这些步骤不是一次 Forward 同时出现，而是逐 Token 生成；先生成的步骤会成为后面 Token 的上下文。

如果再加入验证，可以让程序重新计算 `17 × 24`，检查最终答案是否为 `408`。

## 四个名称的最小区别

| 名称 | 最小理解 |
|---|---|
| 推理（Reasoning） | 从已知条件经过一个或多个关系得到结论的能力或行为 |
| CoT | 模型生成的中间推理文本序列 |
| 搜索（Search） | 尝试和比较多条可能路径，而不是只沿一条生成到底 |
| 验证（Verification） | 用规则、模型、工具或人类检查步骤或结果 |

CoT 可以存在但没有搜索；搜索可以生成多个 CoT；验证可以检查最终答案，也可以参与搜索过程。

## 最重要的三个边界

### CoT 不等于完整内部计算

模型每次 Forward 都有大量 Hidden State 变化。输出的文字步骤只是生成结果的一部分，不能假定它完整披露了所有内部因果过程。

### 推理 Token 不会改变自回归结构

它们仍由 Output Layer、Logits 和 Runtime 逐个生成。区别在于模型在最终答案前使用了更多中间 Token。

### 更长不等于更正确

更多步骤提供额外计算空间，也可能带来错误传播、重复和事后合理化。正确性仍需评估或验证。

## 来源

> [!source]
> - [Chain-of-Thought Prompting](https://arxiv.org/abs/2201.11903)把 CoT 定义为一系列中间推理步骤，并报告其在部分复杂任务上的表现提升。
> - [Self-Consistency](https://arxiv.org/abs/2203.11171)说明从单条 CoT 扩展到多条推理路径并选择一致答案的路线。
> - [Tree of Thoughts](https://arxiv.org/abs/2305.10601)把单路径生成扩展为可探索、评价和回溯的外部搜索框架。
