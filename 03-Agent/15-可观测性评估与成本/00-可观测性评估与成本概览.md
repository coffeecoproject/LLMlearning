# 可观测性、评估与成本概览

> [!summary]
> Agent 评估不仅看最终回答，还要观察目标是否完成、工具是否正确使用、状态是否可恢复、权限是否受控，以及完成任务消耗了多少时间和资源。

> [!info] 层级定位
> **基础 Agent 结构**至少记录模型调用、工具结果和失败；完整 Trace、离线评估集、成本归因、恢复指标和审计报表属于持续与高可靠生产结构。

## 可观测链路

```text
Goal
→ Run
→ Phase / Attempt / Step
→ Observation / State Change
→ Evidence / Acceptance

同时关联产品交互链：
Thread → Turn → Item

以及实际调用链：
Model Call → Tool Call → Tool Result
```

这三条链不是同一棵父子树，但都需要稳定身份和时间关系。把它们关联起来，才能判断某个用户 Turn 中的哪次 Model Call，推动了哪个 Run Step，又产生了什么 Observation。

## 本专题要解决的问题

- Log、Trace、Metric 和 Audit 有什么区别；
- 如何重放和解释一次 Agent Run；
- 模型质量、工具质量和控制系统质量怎样分开测量；
- 任务成功率、虚假完成（False Completion）和恢复成功率（Recovery Rate）等指标说明什么；
- 离线评测、模拟环境和真实线上反馈怎样组合；
- Token、模型调用、工具、等待和人工时间怎样计入成本；
- 怎样避免只优化容易测量的指标。

## 关键边界

模型 Benchmark 高不等于 Agent 任务成功率高；一次任务最终成功，也可能经历了越权、重复副作用或不可接受成本。
