# 中断、恢复与幂等入口

> [!summary]
> 生命周期层需要为中断和恢复预留明确入口：恢复时先读取权威状态并核对外部现实，再决定是否创建新的 Attempt，而不是重新播放最后一句话。

## 中断可能发生在哪里

```text
模型请求发送前
模型生成过程中
Tool Call 已提交但结果未收到
工具已经成功但状态尚未保存
状态已保存但客户端未收到响应
验证过程中
等待用户时
```

最危险的是系统不知道副作用是否已经发生。

## Resume 不是继续聊天

```text
Resume
→ 加载 Run、当前版本和未完成 Attempt
→ 检查最后一个已提交事件
→ 核对外部工具或 Candidate 的真实状态
→ 判断旧动作可否重试
→ 记录恢复决定
→ 创建新的受控 Attempt 或进入阻塞
```

是否继续使用原 Thread 是次要策略。关键状态必须存在于 Thread 之外。

## 幂等入口

**幂等**指重复提交同一逻辑命令不会重复产生业务效果。

例如：

```text
create_refund(orderId, commandId)
```

如果网络超时后重试相同 `commandId`，系统应返回原结果或拒绝重复创建退款，而不是再次退款。

## 本专题只建立入口

这里需要知道生命周期必须支持：

- Interrupt；
- Cancel；
- Resume；
- Reconcile；
- 新 Attempt；
- 重复命令识别。

外部现实核对、重试分类和修复预算会在 [[00-Observation反馈重试与恢复概览|Observation、反馈、重试与恢复]] 中详细展开。
