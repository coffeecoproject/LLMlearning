# 预算、超时与无限循环防护

> [!summary]
> Agent 的停止不能只依赖模型自觉；Runtime 需要对 Turn、Token、时间、工具调用、重试和费用设置硬边界。

## 为什么 Agent 容易循环

常见循环模式包括：

- 反复读取相同文件；
- 工具失败后无变化地重试；
- 模型不断修改自己的计划；
- 在两个方案之间来回切换；
- 验证失败后重复提交同一 Candidate；
- 缺少事实却不断增加推理 Token。

## 多维预算

```text
maxTurns
maxToolCalls
maxRetriesPerAction
maxElapsedTime
maxModelTokens 或模型费用
maxConcurrentActions
maxCandidateGenerations
```

实际系统不一定全部需要，但不能只有一个模糊的“尽量别太久”。

## 预算用尽不是成功

预算耗尽后可能进入：

```text
BLOCKED
→ 需要用户扩大预算或补充信息

FAILED
→ 本次 Run 无法完成

WAITING_FOR_INPUT
→ 需要人工决定下一步
```

不能因为已经花了很多 Token 就降低验收标准。

## 检测无进展

除了计数，还可以观察：

- 连续多轮没有新 Observation；
- 相同工具和参数重复出现；
- Candidate digest 没有变化；
- 相同错误重复发生；
- Plan 在同几个状态间循环。

这些信号可以触发重新规划、人工接管或停止。

## 超时的两层含义

```text
单个操作超时
→ 某次模型或工具调用等待过久

整个 Run 超时
→ 总任务超过允许的时间窗口
```

操作超时后必须判断外部动作是否可能已经成功，不能默认重新执行。
