# 运行对象与状态机概览

> [!summary]
> Agent Runtime 用稳定的运行对象记录“谁在完成哪个目标、当前处于什么阶段、哪次调用产生了什么结果”，再由状态机约束哪些转换合法。

## 两条互相配合的结构

```text
身份结构
Goal → Run → Phase → Attempt → Turn / Step

控制结构
READY → RUNNING → WAITING / VERIFYING → 终态
```

身份结构回答“这条记录属于谁”；状态机回答“现在可以做什么”。

## 为什么只保存消息列表不够

对话顺序可以告诉我们先后说了什么，但很难可靠回答：

- 哪个 Goal revision 产生了这次动作；
- 工具是否已经真实执行；
- 失败的是哪次 Attempt；
- 当前是否允许重试；
- 模型说完成后是否已经验收；
- 进程重启后应该恢复到哪里。

因此需要结构化身份和显式状态。
