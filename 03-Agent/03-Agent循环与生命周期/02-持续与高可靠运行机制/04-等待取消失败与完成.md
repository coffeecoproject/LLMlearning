# 等待、取消、失败与完成

> [!summary]
> Agent Run 不应只有“运行中”和“完成”两种状态；等待、阻塞、失败和取消表达不同现实，也决定系统能否以及怎样继续。

## WAITING_FOR_INPUT：等待输入

表示系统缺少用户或外部主体才能提供的信息，例如：

```text
已支付订单是否允许自动退款？
```

等待不是失败。获得合法输入后可以继续，但必须检查 Goal 和上下文是否需要修订。

## BLOCKED：当前无法安全继续

例如：

- 缺少生产环境权限；
- 必要外部服务不可用；
- Goal 中存在互相冲突的成功条件；
- 必要验证工具不存在。

Blocked 应说明阻塞原因和解除条件。

## FAILED：本次运行失败

例如：

- 重试预算耗尽；
- 协议持续不兼容；
- 工作空间损坏且无法恢复；
- 发生不可恢复执行错误。

失败不等于 Goal 永远无法完成；可以根据策略创建新的 Run 或修复系统问题。

## CANCELLED：主动终止

取消可能来自用户、管理员或安全策略。系统需要：

- 阻止新动作启动；
- 尝试中断可取消操作；
- 核对已经产生的副作用；
- 保存当前状态和未完成事项。

取消不能被显示为成功完成。

## COMPLETED：目标已被接受

可靠定义不是：

```text
模型说 done
```

而是：

```text
Completion Request
→ Verification
→ Evidence
→ Acceptance
→ Run 进入 COMPLETED
```

## 终态和可恢复状态

系统需要明确哪些状态可以 Resume，哪些需要创建新 Run，哪些已经终止。这个选择属于产品策略，不能只根据最后一条助手消息判断。
