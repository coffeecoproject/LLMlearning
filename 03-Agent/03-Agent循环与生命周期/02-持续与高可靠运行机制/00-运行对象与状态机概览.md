# 运行对象与状态机概览

> [!summary]
> Agent Runtime 用稳定的运行对象记录“谁在完成哪个目标、当前处于什么阶段、哪次调用产生了什么结果”，再由状态机约束哪些转换合法。

> [!note] 整篇层级：持续与高可靠结构（选读）
> 基础 Agent 可以只使用一个循环变量和消息列表；稳定 Run、Phase、Attempt 与状态机用于持久任务、恢复、并发和审计。

## 三类互相配合的结构

```text
任务控制结构
Goal → Run → 可选 Phase / Attempt → Step

产品交互结构
Thread → Turn → Item

循环执行结构
Model Call → Action → Observation → 下一次 Model Call

状态转换结构
READY → RUNNING → WAITING / VERIFYING → 终态
```

任务对象回答“这项工作属于哪次执行”；产品协议回答“用户和 Agent 的交互怎样记录”；循环结构回答“模型和工具怎样反复往返”；状态机回答“现在允许做什么”。

## 为什么只保存消息列表不够

对话顺序可以告诉我们先后说了什么，但很难可靠回答：

- 哪个 Goal revision 产生了这次动作；
- 工具是否已经真实执行；
- 失败的是哪次 Attempt；
- 当前是否允许重试；
- 模型说完成后是否已经验收；
- 进程重启后应该恢复到哪里。

因此需要结构化身份和显式状态。
