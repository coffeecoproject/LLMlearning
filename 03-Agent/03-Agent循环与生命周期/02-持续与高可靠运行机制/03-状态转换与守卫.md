# 状态转换与守卫

> [!summary]
> 状态机明确当前 Run 可以进入哪些下一状态；转换守卫则检查所需条件是否已经满足，避免模型或程序随意跳过阶段。

## 为什么需要状态机

自由循环常见写法是：

```text
只要模型还想继续
→ 就再次调用模型
```

它很难表达：

- 未确认 Goal 不允许执行写操作；
- 没有 Candidate 不能运行产物验证；
- 缺少用户决定时必须暂停；
- 测试失败后不能直接宣布完成；
- 已取消 Run 不能继续执行工具。

## 转换和守卫

```text
READY → RUNNING
守卫：Goal 当前有效、配置和权限已经绑定

RUNNING → VERIFYING
守卫：存在明确 Completion Request 和可验证 Candidate

VERIFYING → COMPLETED
守卫：全部 required criteria 获得合格 Evidence
```

守卫是 Runtime 检查的条件，不是 Prompt 中的一句提醒。

## 谁可以提出和提交转换

```text
LLM
→ 可以提出完成、提问或动作

Runtime Command
→ 请求合法状态转换

Transition Policy
→ 判断当前状态和条件是否允许

State Store
→ 原子保存新状态与审计事件
```

模型不能直接写 `status = COMPLETED`。

## 为什么转换需要版本

如果两个请求同时读取 `RUNNING`：

- 一个准备进入 `WAITING_FOR_USER`；
- 另一个准备执行新工具。

没有版本检查，它们可能互相覆盖。转换应携带预期当前版本，只有仍然匹配时才能提交。

## 状态机不要假装解决所有问题

状态机保证“转换合法”，不保证：

- Goal 本身正确；
- 模型计划合理；
- 工具没有内部缺陷；
- 验证条件覆盖完整。

它是控制边界，不是智能来源。
