# 状态与持久化概览

> [!summary]
> 状态是 Agent 当前真实进行到哪里的结构化记录；关键状态应保存在模型对话之外，使进程重启、新线程和上下文压缩都不会抹掉任务事实。

## 三类信息

```text
权威状态
→ Goal、阶段、决定、Candidate、Evidence、Acceptance

运行记录
→ Turn、Tool Call、错误、重试和审计事件

临时工作信息
→ 模型摘要、假设、搜索提示和短期草稿
```

三者的可信程度和生命周期不同，不能都当成聊天历史处理。

## 持久化也有不同深度

```text
对话持久化
→ 保存消息，使线程可以恢复

线程目标持久化
→ 额外保存 Objective、状态和预算，例如 Codex Thread Goal

任务契约持久化
→ 进一步保存 Criteria、Scope、revision、Candidate、Evidence 和 Acceptance
```

前一层不自动具备后一层的控制能力。Codex 已经具有线程目标持久化；CodeClosure 一类架构则继续追求项目级任务契约和证据状态。

## 本专题要解决的问题

- 什么必须持久化，什么可以丢弃；
- 当前状态与事件历史有什么区别；
- 谁可以提出状态变化，谁拥有写入权；
- 并发或重复请求怎样避免覆盖；
- 版本、revision、digest 和 provenance 分别解决什么问题；
- 为什么新模型线程仍能继续同一个任务。

## 关键边界

模型输出通常是 Proposed State Change。真正的状态变更应由 Agent Runtime 校验并原子提交。聊天记录、模型“记忆”和摘要不应成为唯一权威来源。
