# 模型调用与决策协议概览

> [!summary]
> Agent 不是读取一段随意的模型文字来猜下一步，而应尽量通过明确的输入合同和结构化输出协议区分回答、工具请求、提问、计划与完成申请。

> [!info] 层级定位
> 基础 Agent 可以只区分普通回复与 Tool Call；严格 Response Schema、协议版本、模型路由、回退和结构化完成申请属于高可靠增强。

## 一次模型交互

```text
Context Package
→ 模型请求
→ 模型生成 Token
→ 结构化结果
   ├── MESSAGE
   ├── TOOL_CALL
   ├── QUESTION
   ├── PLAN_PROPOSAL
   └── COMPLETION_REQUEST
→ Agent Runtime 校验
```

上面的结果类型是说明性分类，具体系统可以采用不同协议。

## 本专题要解决的问题

- System Instruction、用户内容和工具描述怎样共同进入请求；
- Function Calling、Structured Output 和普通文本有什么区别；
- 模型为什么只能提出动作，不能直接获得控制权；
- Schema 校验、大小限制和未知字段怎样处理；
- 流式 Token、完整 Item 和 Turn Completed 分别说明什么；
- Reasoning Effort、模型选择和回退策略应由谁控制；
- 协议版本变化怎样避免悄悄破坏 Agent。

## 关键边界

模型生成了合法 JSON，只代表格式可解析；它不代表动作有权限、事实可信或任务已经完成。
