# 执行产物与工作空间概览

> [!summary]
> Agent 的任务结果通常不只是聊天文字，而是代码、文档、数据库变化或外部操作；系统需要明确产物身份、工作空间、允许变更范围和可验证版本。

> [!info] 层级定位
> 基础 Agent 只需能读取或产生真实结果；Artifact 身份、版本、Provenance、隔离工作区和发布边界属于持续与高可靠实现。

## 产物主线

```text
基础版本
→ 创建隔离工作空间或 Candidate
→ Agent 执行动作
→ 记录实际变更
→ 冻结待验证版本
→ 对这个确切版本建立 Evidence
→ 接受、修复或丢弃
```

## 本专题要解决的问题

- Artifact、Candidate、Workspace 和 Environment 分别是什么；
- 为什么控制状态不能放在模型可随意修改的工作目录；
- 实际变更怎样和 Goal Scope、Plan 对比；
- 为什么验证前需要稳定的版本身份或内容摘要标识（digest）；
- 修复失败产物时为什么应保留代际关系；
- 文件系统、数据库和外部 API 的产物边界有什么不同；
- 临时文件、缓存和最终交付物怎样区分。

## 关键边界

Worker 可以修改候选产物，但不应同时修改控制数据库、验收决定或自身权限。验证证据必须绑定到被检查的确切产物版本。

## 阅读路线

- 只看框架：可在工具之后选读；
- 理解机制：能够解释“验证的是哪个确切版本”；
- 为搭建做准备：把可写产物和 Agent 控制状态放在不同权限边界。
