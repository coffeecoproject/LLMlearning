# 验证、证据与验收概览

> [!summary]
> Agent 至少需要在停止前检查结果；任务风险越高，越需要把模型自查、真实工具验证、可追溯 Evidence 和独立 Acceptance 逐层分开。

> [!info] 两层边界
> **基础 Agent 结构**可以在停止前读取真实工具结果并做最小检查；Candidate 身份、Evidence 绑定和独立 Acceptance 属于持续与高可靠理想结构。

## 验收也有不同控制深度

```text
模型自我检查
→ 模型根据当前上下文判断是否完成

工具证据检查
→ 模型读取真实文件、测试和运行结果后再判断

独立 Acceptance
→ 外部系统把成功条件、确切 Candidate 和当前 Evidence 对应后决定能否结束
```

当前 Codex Thread Goal 已要求模型在标记完成前进行逐项完成审计并检查真实状态，但最终仍由同一个 Agent 调用 `update_goal(complete)`。下面的完整链路属于更高可靠等级。

## 高可靠完成链路

```text
Worker 提交 Completion Request
→ 冻结或识别确切 Candidate
→ 运行 Verification Obligations
→ 形成与 Candidate 绑定的 Evidence
→ Acceptance 对照 Success Criteria
→ ACCEPT / REPAIR / BLOCK
```

## 本专题要解决的问题

- Check、Verification、Evidence、Evaluation 和 Acceptance 有什么区别；
- 谁定义验收条件，谁执行检查，谁批准完成；
- 测试退出码、日志、截图和人工确认怎样成为证据；
- 为什么证据必须绑定 Goal revision、环境和 Candidate；
- 旧证据何时失效；
- Verifier Model、自我检查和独立工具各有什么可信边界；
- 验证范围遗漏为什么比单项测试失败更隐蔽。

## 关键边界

执行者可以提出完成和证据线索，但不应仅凭自己的叙述批准自己。Acceptance 也不能凭空创造事实，只能消费当前合格证据。
