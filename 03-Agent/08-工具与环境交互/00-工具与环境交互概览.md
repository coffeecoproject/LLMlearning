# 工具与环境交互概览

> [!summary]
> 工具让 Agent 从“生成文字”扩展到“读取或改变真实环境”；模型负责提出调用，Agent Runtime 负责授权和调度，工具执行器负责产生真实结果。

> [!info] 层级定位
> **基础 Agent 结构**需要 Tool Call、程序执行和 Tool Result；最小权限、Approval、事务、幂等和完整审计属于持续与高可靠结构，按工具风险逐步增加。

## 持续与高可靠调用链（选读）

```text
LLM 生成 Tool Call
→ 校验工具名称和参数 Schema
→ 检查当前阶段、权限和审批要求
→ Tool Executor 执行
→ 捕获输出、错误和副作用
→ 写入 Observation 与审计记录
→ 下一轮模型调用
```

## 本专题要解决的问题

- 工具、Function Calling、应用程序接口（API）、命令行界面（CLI）和模型上下文协议（Model Context Protocol，MCP）分别是什么；
- Tool Schema 为什么同时影响模型理解和运行安全；
- 读取工具与写入工具为什么需要不同权限；
- 工具执行成功、业务成功和任务成功有什么区别；
- 超时、部分成功和不可逆副作用怎样表达；
- 重复调用怎样通过幂等键或事务避免重复操作；
- Tool Result 应怎样进入状态和下一轮上下文。

## 关键边界

MCP 等协议解决的是工具和资源怎样被发现、描述和调用，不会自动解决业务权限、验收、幂等或错误恢复。

## 后续展开

1. 工具注册、发现与 Schema；
2. Tool Call 的生成、校验和执行；
3. 只读、可逆和不可逆动作；
4. MCP、API、CLI 与本地函数；
5. Tool Result、Observation 与错误模型；
6. 幂等、事务、超时和取消。

## 阅读路线

- 只看框架：本页；
- 理解机制：模拟一次从 Tool Call 到 Observation 的完整过程；
- 为搭建做准备：从一个无副作用的只读工具开始，再增加写操作。

工具产生真实结果后，继续学习 [[00-Observation反馈重试与恢复概览|Observation、反馈、重试与恢复]]。如果任务会改变代码、文档或外部系统，还需要结合 [[00-执行产物与工作空间概览|执行产物与工作空间]]。
