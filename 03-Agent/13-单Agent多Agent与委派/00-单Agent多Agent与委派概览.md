# 单 Agent、多 Agent 与委派概览

> [!summary]
> 多 Agent 是把任务、上下文和权限分给多个执行单元，再汇总结果；它可以增加并行和隔离，也会增加协调、冲突、成本和验证难度。

## 委派主线

```text
主 Agent 或控制器
→ 定义子任务合同
→ 创建独立或继承式上下文
→ 分配工具和权限
→ 子 Agent 执行
→ 返回结构化结果与证据
→ 汇总、冲突处理和最终验收
```

## 本专题要解决的问题

- Subagent、Worker、角色和模型调用有什么区别；
- 上下文继承、复制、摘要和完全隔离怎样选择；
- 并行任务需要满足哪些独立性条件；
- 主 Agent 怎样防止子 Agent 越出 Scope；
- 多个结果冲突时由谁裁决；
- 委派失败、超时和部分完成怎样传播；
- 多 Agent 何时只是增加复杂度而没有提高可靠性。

## 关键边界

多 Agent 不等于模型内部多路径搜索，也不等于多个 Agent 自动互相验证。每个子任务仍需要明确输入、产物、权限和验收条件。
