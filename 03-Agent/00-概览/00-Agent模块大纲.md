# Agent 模块大纲

## 模块定位

> [!summary]
> Agent 不是单独一种模型，而是把 LLM 放进一个受控执行系统：系统维护目标和状态，为每次模型调用构建上下文，执行经过许可的工具，接收环境反馈，并用验证与停止规则决定下一步。

它承接前两个模块：

```text
LLM
→ 提供语言、知识和逐 Token 生成能力

推理与 CoT
→ 提供单条推理路径、候选搜索和验证思路

Agent
→ 把模型接入目标、状态、工具、环境和持续执行循环
```

## 核心问题

> 怎样把一个可能出错、每次只根据当前上下文生成结果的概率模型，组织成能够跨步骤完成真实任务、保存进度、限制权限、处理失败并提供验收证据的系统？

## 本模块讲的是能力地图，不是唯一标准

Agent 领域没有一套所有产品都必须照搬的统一结构。不同系统会把相同职责合并在一个 Agent Loop 中，或者拆成多个受控组件。

本模块按三层逐步学习：

```text
最小 Agent
→ 模型 + 工具 + Observation + 多轮循环 + 停止条件

持续 Agent
→ 再增加持久目标、状态、恢复、预算和较完整的自我检查

高可靠控制型 Agent
→ 再按风险增加正式任务契约、可选 Goal Intake、阶段权限、Candidate、Evidence 和独立 Acceptance
```

前一层能够成立，不代表已经具备后一层的可靠性；后一层是工程增强，也不是“Agent”一词成立的前提。

详细判断方法见 [[01-Agent基础结构与高可靠理想结构怎样区分|Agent 基础结构与高可靠理想结构怎样区分]]。

## 第一层：Agent 基础结构主线

~~~text
用户提出当前请求或目标
→ 外部程序组织本次模型输入
→ 调用 LLM
→ LLM 返回回答或候选 Tool Call
→ 程序校验并执行允许的工具
→ 工具结果成为下一次模型调用的 Observation
→ 模型根据新结果继续或停止
~~~

这是理解 Agent 的必读主线。它不要求正式 Goal Contract、持久 Run、独立 Context Builder 服务、Context Manifest、Candidate、Evidence 或独立 Acceptance。

## 第二层：高可靠理想主线（可选）

```text
用户原始需求
→ 形成目标、范围和成功条件
→ Agent Runtime 创建或恢复 Run 与运行状态
→ Context Builder 选择本次 Model Call 需要的信息
→ 调用 LLM
→ LLM 返回提问、计划、工具调用或完成申请
→ 如果需要规划：校验并保存可执行的 Plan 或 Task
→ 如果需要行动：校验权限和参数后执行工具
→ 工具结果成为 Observation，并更新运行状态
→ 继续、重试、重新规划、等待用户或申请完成
→ Verifier 根据真实产物形成 Evidence
→ Acceptance 根据成功条件决定是否满足 Goal
→ 输出结果、证据和审计记录
```

这是一条高可靠参考主线，不是所有 Agent 的最小定义。其中只有一部分由 LLM 完成。目标持久化、工具执行和权限控制依赖模型外部程序；Goal Intake、Context Manifest、独立 Evidence Store 和 Acceptance Engine 则属于按风险逐步增加的控制能力。

## 必须反复区分的六个层面

| 层面 | 主要职责 |
|---|---|
| 用户界面或业务应用 | 接收需求、展示状态、获得确认 |
| Agent Runtime / Harness | 维护循环、状态、权限、工具和恢复 |
| 模型服务接口 | 接收模型请求并返回生成结果 |
| 模型 Runtime | 执行模型的 Prefill、Decode 和资源调度 |
| LLM | 根据当前 Token 上下文生成下一 Token |
| 工具与真实环境 | 读取或改变代码、数据库、网页和外部系统 |

Verifier、策略引擎和持久化存储可以作为 Agent Runtime 的组成部分，也可以独立部署。物理部署可以合并，但逻辑职责不能混为一谈。

## 学习路线

### Agent 基础结构路线

```text
01 Agent 框架速览
→ 02 目标与任务契约
→ 03 Agent 循环与生命周期
→ 04 运行状态与持久化
→ 05 上下文构建与工作记忆
→ 06 模型调用与决策协议
→ 08 工具与环境交互
→ 10 Observation、反馈、重试与恢复
→ 11 验证、证据与验收
→ 12 权限、安全与人类控制
→ 17 边界与复习
```

这条路线用于理解完整因果链。每个专题先只读其中标为“基础 Agent 结构”的部分；如果总览没有单独展开两层，则只读概览的最小主线和框架停止点。`07 规划、分解与任务图` 是复杂任务的可选分支，可以先跳过。

### 持续与高可靠 Agent 选读

以下内容不是基础 Agent 的完成条件。只有准备长任务、生产实现、高风险工具或独立审计时，才继续深入。

按 `01 → 17` 顺序学习，并按任务风险选择下列能力：

- Goal、Run、Phase、Step、Attempt 等任务对象；
- 状态存储与 Context Package；
- 跨 Turn 恢复、复杂权限和副作用控制；
- 状态机、重试、幂等与恢复；
- Candidate、Evidence、Acceptance；
- 权限、Sandbox、Approval 和审计；
- Agent Runtime、服务边界、评估与成本。

### 可以后置

- 多 Agent 编排；
- 大规模分布式调度；
- 框架之间的 API 差异；
- 向量数据库参数；
- 自动学习或修改模型 Weight；
- 复杂自治组织和开放式长期运行。

可靠的单 Agent 应先于多 Agent。

## 后续实际搭建的递进目标

```text
阶段 A：最小工具循环
当前请求 + 模型调用 + 一个只读工具 + Tool Result 回传 + 最大步数

阶段 B：受控循环 Agent
多次 Model Call + Observation + 工具参数校验 + 错误处理 + 基础日志

阶段 C：持久 Agent
外部状态 + 任务恢复 + 幂等工具 + 审计日志

阶段 D：可验证 Agent
成功条件 + Candidate + Evidence + 独立 Acceptance

阶段 E：工程化 Agent
服务接口 + 权限 + 并发 + 评估 + 成本控制

阶段 F：按需要增加多 Agent
委派 + 上下文隔离 + 结果汇总 + 失败传播
```

## 与后续模块的边界

本模块会学习 Agent 所需的运行状态、上下文选择和外部工作记忆，但不会把它们直接等同于持续学习。

```text
Agent 状态与外部记忆
→ 保存任务运行所需的信息

持续学习
→ 研究系统怎样跨任务积累、选择、更新和遗忘经验

模型参数更新
→ 通过训练改变模型本身
```

## 分层完成标准

### 基础结构完成

- 能画出从用户目标到工具执行、反馈、验证和停止的完整链路；
- 能明确指出 LLM、模型 Runtime 和 Agent Runtime 分别负责什么；
- 能把当前目标、运行状态、模型 Context、工具结果和 Observation 分开；
- 能解释模型为什么只应提出工具调用，而不应直接拥有无限权限；

达到这里就可以认为 Agent 的基础结构学习完成。

### 持续与高可靠结构完成（可选）

- 能把 Goal Contract、Plan、State、Working Memory、Candidate、Evidence 和 Acceptance 分开；
- 能设计任务的重试、恢复、幂等和人工确认边界；
- 能先实现可靠单 Agent，再判断是否真的需要多 Agent；
- 能搭建一个具有持久状态、真实工具、独立验证和审计能力的高可靠控制型 Agent；
- 能判断某个问题不需要 Agent，而适合普通模型调用或确定性 Workflow。
