# 架构模式与搭建路线概览

> [!summary]
> Agent 架构不应从“选择最流行框架”开始，而应从任务需要的目标、状态、工具、失败恢复和验收边界开始，再选择最小可用模式。

> [!info] 层级定位
> 本专题同时展示最小 Agent 与高可靠搭建路线；阅读时先实现基础循环，再按任务长度和风险增加持久化、恢复、独立验证和服务架构。

## 常见模式地图

```text
单次 Tool Use
→ 一次模型调用选择或填写工具

Agent Loop / ReAct（Reasoning and Acting，推理与行动）
→ 根据 Observation 反复决定下一步

Planner–Executor
→ 计划与执行分开，并允许重新规划

Workflow + Agent
→ 确定性阶段包围局部动态决策

Graph / State Machine
→ 显式表示阶段、依赖和转换

Durable Agent Runtime
→ 持久状态、恢复、证据、权限和审计
```

这些模式可以组合，不必互相排斥。

## Workflow、Agent Loop 与 Loop Engineering

```text
Workflow / State Machine
→ 预先规定阶段、转换和允许动作

Agent Loop
→ 运行时反复进行 Model Call、Action、Observation 和继续判断

Agent Runtime / Harness
→ 承载上下文、模型、工具、状态、权限和循环的控制程序

Loop Engineering
→ 设计和优化目标、上下文、工具、反馈、验证、预算与停止条件的工程实践
```

它们不是替代关系。常见高可靠结构是：

```text
外层 Workflow 管理长期阶段和硬边界
    ↓
某个阶段启动一次 Agent Run
    ↓
Agent Runtime 在 Run 内维持 Agent Loop
    ↓
外层 Verification / Acceptance 判断是否推进状态
```

`Loop Engineering` 是正在形成中的工程术语，适合帮助理解“工程重点已经从单次 Prompt 扩展到整个反馈循环”，但不应拿它替换较稳定的 Workflow、Agent Loop 和 Runtime 概念。详细选读见 [[01-Workflow-Agent-Loop与Loop-Engineering|Workflow、Agent Loop 与 Loop Engineering]]。

## 从基础 Agent 到控制型 Agent

```text
基础 Agent
→ 当前目标 + Agent Loop + Tool Result + 停止条件

持续 Agent
→ 持久 Goal / Run + 状态恢复 + 预算 + 工作记忆

高可靠控制型 Agent
→ Goal Contract + 阶段权威 + Candidate/Evidence + 独立 Acceptance
```

这不是“普通 Agent 与特殊 Agent”的区别，而是控制深度不同。搭建时应从任务风险出发，只增加真正需要的层级。

## 本专题要解决的问题

- 如何根据任务的不确定性和风险选择模式；
- 为什么 Workflow + Agent 往往比完全自由循环更容易控制；
- 何时需要 Planner、Graph、事件驱动或持久执行；
- 框架库、模型供应商和领域控制层怎样解耦；
- 如何从一个工具扩展到可靠闭环；
- Code Agent、Research Agent 和业务 Agent 的控制重点有什么不同；

## 建议搭建顺序

```text
1. 定义一个可验证 Goal
2. 接入一个只读工具
3. 建立显式 Agent Loop 和最大步数
4. 持久化 Run 与 Observation
5. 增加一个受控写工具
6. 建立独立 Verification 与 Acceptance
7. 增加恢复、权限和审计
8. 建立评估集和成本指标
9. 最后判断是否需要多 Agent
```
