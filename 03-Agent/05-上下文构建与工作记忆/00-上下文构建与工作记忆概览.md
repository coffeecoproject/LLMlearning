# 上下文构建与工作记忆概览

> [!summary]
> Agent 的外部状态并不会自动进入 LLM；Context Builder 必须在每次调用前选择当前阶段真正需要的信息，并把它组织成模型能够读取的上下文。

## 基础 Agent 中的主线位置

```text
系统指令 + 当前用户请求 + 必要历史 + 工具说明 + 最新 Tool Result
→ 程序按模型接口组装消息
→ 发起本次 Model Call
→ LLM 生成回答或 Tool Call
```

若任务需要跨 Turn 恢复、检索大量资料或审计输入来源，才在这条链路前增加持久状态、工作记忆、Retrieval、Context Package 与 Manifest。

## 本专题的两层边界

### Agent 基础结构

最小 Agent 只需要由程序在每次 Model Call 前组织当前请求、必要历史、工具描述和最新 Tool Result。它可以只是一个消息数组拼装函数，不要求独立的 Context Builder 服务，也不要求 Context Package、Manifest 或正式工作记忆库。

~~~text
当前请求 + 必要历史 + Tool Result
→ 程序组织本次输入
→ 模型调用
~~~

### 持续与高可靠理想结构（选读）

长任务、跨 Turn 恢复、多用户系统或高风险工具才需要进一步考虑：

- 持久 Run State 与工作记忆；
- 来源、版本、信任级别和失效传播；
- Retrieval、摘要与 Compaction；
- Context Package 与 Manifest；
- 跨 Run 隔离、Prompt Injection 和审计。

这些能力提高可靠性，不是 Context 能够被构造的定义条件。

## 本专题要解决的问题

- State、Context、Session、Thread、Memory 有什么区别；
- 为什么一个 Turn 内可以构建多份 Context；
- 为什么不能默认重放全部历史；
- Context Builder 与 Context Compiler 分别强调什么；
- Summary、Retrieval 和 Compaction 各解决什么问题；
- 怎样标注事实来源、版本和可信级别；
- 新线程、续接线程和隔离上下文怎样选择；
- 上下文窗口未满为什么仍可能出现注意力干扰。

## 高可靠实现中常见的五个逻辑对象

| 对象 | 最小理解 |
|---|---|
| 外部状态 | Runtime 当前认为任务进行到哪里，并可与真实环境核对 |
| 工作记忆 | 当前任务中以后可能再次取用的信息 |
| Context Package | 为某一次 Model Call 选择和组织的结构化输入 |
| Model Request | 按具体模型接口编译后的请求 |
| Context Manifest | 记录这次选择、版本、裁剪与来源 |

关系是：

~~~text
Thread、Goal、Run State、Turn、Observation、工作记忆和资料
→ 每次 Model Call 前重新选择
→ Context Package
→ Model Request
→ 本次实际输入 Token
~~~

## 工作记忆的准确边界

本专题中的工作记忆主要指“当前任务可再次取用的信息”。它不等于模型 Weight，也不自动构成跨任务持续学习。

工作记忆可以保存已确认事实、用户决定、待办、假设和 Artifact 引用，但模型只能看到本次被 Context Builder 取回的部分。审批、文件当前内容和 Run 状态仍应由各自权威系统回答，不能由工作记忆取代。

## 阅读路线

### 只看框架

只读本页。能够解释“程序在每次 Model Call 前组织当前输入，Thread 中保存的内容不等于模型全部可见”，即可继续下一个主要组件。

### 理解机制

阅读 01 与 02，重点掌握：

- 指令权限、事实权威和本次相关性的区别；
- 一个 Turn 为什么可以有多次不同 Context；
- 为什么 Tool Result 和外部资料不自动成为高权限指令。

### 继续深入（选读）

阅读 03 → 07，理解：

- Retrieval、摘要、Compaction 和 Truncation 的区别；
- 工作记忆的写入、失效和取回；
- Package、Manifest、版本与 Provenance；
- 不可信资料、过期记录和跨 Run 信息怎样隔离。

### 为搭建做准备

基础 Agent 先实现一个消息组装函数：

~~~text
系统指令 + 当前请求 + 工具定义 + 必要历史 + 最新工具结果
→ 按模型接口生成本次请求
~~~

需要持久恢复、来源追踪或审计时，再设计 Context Package 和 Manifest：

~~~text
调用目的
→ 按 Scope 收集
→ 来源与版本校验
→ 排序和 Token 预算
→ 编译请求
→ 记录 Manifest
~~~

向量数据库参数、特定供应商的 Prompt Cache、分布式检索服务和跨任务长期记忆可以后置。它们不影响本章框架完整性。

如果你能说明“Thread 中保存的记录不会自动进入 LLM；程序会在每次 Model Call 前重新组装这一次实际发送的输入”，本专题的框架与基础机制已经完成。来源、版本、Manifest、检索与工作记忆生命周期属于持续与高可靠选读。
