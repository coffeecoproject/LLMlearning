# 规划、分解与任务图概览

> [!summary]
> 规划把 Goal 转成可执行、可验证且具有依赖关系的任务；它可以由模型提议，但任务图、约束和完成状态需要由外部系统保存和校验。

> [!note] 整篇层级：复杂任务可选能力
> 基础 Agent 可以不生成完整 Plan，而是每轮根据 Observation 决定下一步。持久 Task、依赖图、里程碑和计划版本属于复杂或高可靠任务。

## 从目标到执行

```text
Goal 与当前状态
→ Context Builder 形成模型输入
→ 模型提出计划或下一步动作
→ Runtime 校验并保存可执行部分
→ 选择当前可以执行的 Task
→ 工具执行并返回 Observation
→ 必要时重新规划
```

规划位于模型决策和实际行动之间。模型可以提出计划，但真正可执行的任务、依赖和状态需要由 Agent Runtime 保存和校验。

> [!note]
> 规划是按任务复杂度增加的能力，不是最小 Agent 的必经步骤。简单任务可以在每轮直接选择下一个工具；复杂任务才需要显式 Plan 或任务图。

## 本专题要解决的问题

- Goal、Plan、Task、Step 和 Workflow 有什么区别；
- 计划应该一次生成完，还是随着观察逐步形成；
- 顺序列表、状态机、有向无环图（Directed Acyclic Graph，DAG）和一般任务图分别适合什么任务；
- 如何表示依赖、阻塞、并行和共享资源；
- 计划变化怎样避免越出 Goal Scope；
- 为什么“模型写了一份计划”不等于系统已经拥有可执行计划；
- Graph Engineering 与普通 Prompt 编排的边界。

## 关键边界

计划是执行假设，不是事实。新 Observation 可以使计划失效，但重新规划不能绕过用户约束、权限和成功条件。
