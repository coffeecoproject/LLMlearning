# 请求、响应与流式事件分别是什么

> [!summary]
> 请求表达“希望服务做什么”，响应表达“服务最终怎样结束”，流式事件则是在请求尚未结束时持续报告新增内容、状态或错误。

> [!phase] 运行阶段：API传输

## 普通请求和一次性响应

概念化请求可能包含：

```text
模型名称
messages或input
最大输出长度
生成选项
是否启用stream
```

不启用 Streaming 时，客户端通常等待请求完成，再收到一个完整响应：

```text
请求发送
→ 服务生成完整结果
→ 返回最终响应
```

## 流式事件

启用 Streaming 后，一次请求可能对应多个事件：

```text
请求开始
→ 内容增量事件
→ 更多内容增量事件
→ 状态或工具参数事件
→ 完成事件
```

这些事件共同属于同一次请求，不是每个事件都重新调用了一次模型。

## 事件不等于模型Token

模型按 Token 推进生成，但服务可以合并、拆分或延后发送可显示内容。因此：

```text
一次模型Decode步骤
≠ 必然对应一个网络事件
≠ 必然对应屏幕上的一个字
```

网络层负责怎样传，模型层负责怎样算。两者有时间上的连接，但对象并不相同。

## 常见误解

1. **“收到十个事件就是模型生成了十个Token。”** 事件和 Token 不存在固定一一对应。
2. **“完成事件又执行了一次模型。”** 它通常只是表示请求进入完成状态。
3. **“不开Streaming就不是逐Token生成。”** 模型仍可能逐步生成，只是服务等结束后一次返回。

## 理解检查

1. 一次请求为什么可以产生多个流式事件？
2. 关闭 Streaming 后，模型生成机制必然改变吗？
3. 为什么不能从界面刷新次数推断 Token 数量？
