# 离线推理、本地模型服务与托管 API 有什么区别

> [!summary]
> 三种方式都能使用模型，但责任边界不同：离线推理只服务当前程序，本地模型服务把模型包装成长期 API，而托管 API 又把 Runtime、硬件和部分运维交给外部平台。

> [!phase] 运行阶段：部署与调用方式
> 本篇不讨论模型训练，也不讨论 Agent 怎样规划任务。

## 先看三条路径

### 1. 离线推理

```text
本地程序
→ 在同一程序中加载Tokenizer和模型
→ 直接执行generate
→ 得到结果
```

它适合学习、实验和批量处理。程序结束后，已加载模型通常也随进程结束。

### 2. 自己运行模型服务

```text
客户端或Agent
→ 你管理的API Server
→ 你运行的vLLM等Runtime
→ 你准备的GPU和开放模型
```

模型长期驻留，多个客户端可以通过网络调用。你得到更多控制，也承担硬件、部署、扩缩容、监控和故障恢复。

### 3. 调用托管模型API

```text
客户端或Agent
→ 托管平台提供的API地址
→ 平台管理的模型服务器和Runtime
→ 平台管理的计算设备
```

调用方不必在本地加载模型、执行 Tokenizer 或管理 KV Cache，但仍要组织请求、保护凭证并处理返回结果。

## 同一句输入发生了什么

假设输入是“法国的首都是哪里？”：

| 方式 | 谁加载模型 | 谁执行Tokenizer | 谁管理KV Cache | 调用方看到什么 |
|---|---|---|---|---|
| 离线推理 | 当前本地程序 | 当前本地程序 | 当前本地Runtime | 函数调用结果 |
| 自建模型服务 | 自己的服务端 | 自己的服务端Runtime | 自己的Runtime | 自己的API响应 |
| 托管API | 平台服务端 | 平台服务端 | 平台Runtime | 平台API响应 |

这里变化的是软件放在哪里、由谁负责；模型生成仍然要经过 Tokenize、Prefill、Decode 和文本恢复。

## “本地只调用API”是什么意思

它不是说模型省略了 Runtime，而是说 Runtime 移到了远端：

```text
本地没有执行
≠ 整条链路没有执行

本地只看到API
→ 远端仍需Runtime、Tokenizer、模型和硬件
```

## 常见误解

1. **“托管API不需要Runtime。”** Runtime 仍然存在，只是由服务提供方运行。
2. **“使用开放模型就必须部署到自己电脑。”** 开放模型也可以部署在自己的云服务器或托管平台。
3. **“调用API就不需要写任何程序。”** 至少仍需发送请求、保存凭证、处理结果和错误。
4. **“自建API会改变模型能力。”** 部署方式主要改变控制、成本、延迟和运维责任，不自动提高模型能力。
