# 网络分块为什么不等于模型 Token

> [!summary]
> 模型 Token 是模型内部处理文本的单位；流式事件和网络数据块是服务向客户端传输信息的单位，两者没有必须一一对应的关系。

## 一条真实链路中有三种单位

```text
模型生成的Token
→ Runtime或服务器整理成事件
→ 网络把事件拆分或合并后传输
→ 客户端把收到的文字显示出来
```

例如模型先后得到三个 Token。服务器可以积累两个再发出，也可以用多个事件描述一个复杂输出；网络层还可能把一个事件拆成几段字节。用户最终看到的“文字跳动次数”因此不能用来准确数 Token。

## 一个简化例子

假设模型 Token 对应的解码片段是：

```text
“大”  “模型”  “。”
```

客户端可能收到：

```text
事件1："大模型"
事件2："。"
```

也可能因为网络读取方式，先拿到事件的一部分字节，等待后续字节后才能解析。这里模型仍生成了三个 Token，网络表现却不必是三次。

## 为什么要区分

- 看到一次更新，不能断言模型只生成了一个 Token；
- 网络卡顿，不一定表示模型停止计算；
- Token 计费或上下文长度，应以服务端 Tokenizer/计量结果为准，不能按屏幕刷新次数估算。

## 边界

模型的自回归顺序发生在 Runtime 和模型执行层；流式传输只负责尽早交付已经可用的结果，不让尚未确定的未来 Token 提前存在。
