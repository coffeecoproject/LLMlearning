# 一个模型从启动到完成首个请求

> [!summary]
> 用 Qwen3-8B 和 vLLM 作为公开案例，可以把完整路径串成两段：先启动服务并加载模型资产，再把用户 Messages 转成引擎请求，经过调度、Prefill、Decode 和输出处理返回结果。

> [!phase] 运行阶段：公开实现案例
> 以下只采用官方公开资料能够支持的职责和接口；具体耗时、显存布局和服务器内部瞬时状态没有实测时不作断言。

## 场景设定

假设开发者希望在自己的机器或服务器上提供 Qwen3-8B 聊天服务，并使用 vLLM 的 OpenAI 兼容服务器。

这里的 vLLM 是推理 Runtime 和模型服务的一种开源实现。本案例选择它，是为了观察模型资产怎样被装配成可调用服务；并不表示运行开放模型只能使用 vLLM。

这里不要求记命令，只跟踪对象：

```text
开放模型仓库：Qwen/Qwen3-8B
推理Runtime：vLLM
服务接口：OpenAI兼容Chat API
用户输入：法国的首都是哪里？
```

## 阶段一：启动模型服务

### 1. 指定模型

启动配置告诉 vLLM 使用 `Qwen/Qwen3-8B`。这一步只是选定目标，还没有产生用户回答。

### 2. 读取配套资产

Runtime 需要解析或获得：

```text
模型配置
权重文件
Tokenizer规则与特殊Token
Chat Template
生成默认配置
```

Qwen 模型卡同时给出了 Transformers 直接加载和 vLLM 服务两种使用入口，说明同一模型资产可以被不同 Runtime 装配。

### 3. 建立模型并加载权重

模型配置告诉执行软件应该建立怎样的 Causal LM 结构，权重被还原并放入可用设备。vLLM 的 GPU Worker 负责加载模型权重和执行前向计算，Engine Core 负责调度、KV Cache 管理和协调执行。

### 4. 准备服务资源

Runtime 建立调度器、请求处理路径和缓存资源；API Server 开始监听请求。只有健康检查通过并进入 Ready 状态，客户端才应该把它视为可用服务。

此时仍然没有某个用户的输入 Token 或 KV Cache 内容。

## 阶段二：第一个请求到达

用户发送概念化请求：

```text
model: Qwen/Qwen3-8B
messages:
  - role: user
    content: 法国的首都是哪里？
```

### 1. API Server接收并校验

服务确认请求格式、模型名称和参数是否可接受。如果不合法，可以在模型计算前返回错误。

### 2. 输入处理

```text
Messages
→ Qwen配套Chat Template
→ Tokenizer
→ Token IDs
→ Runtime内部请求状态
```

请求获得自己的 ID、生成设置和后续 KV Cache 归属。

### 3. 加入调度

请求进入 Runtime。即使这是第一条业务请求，Engine 仍决定何时执行它；多请求时还会与其他请求一起调度。

### 4. 执行Prefill

已知输入经过模型，建立该请求输入部分的 KV Cache，并产生首个输出 Token 的 Logits。

### 5. 执行多轮Decode

生成控制过程逐步选择 Token，Runtime 调度相应的模型前向步骤，并让该请求的 KV Cache 随已处理位置增长。

### 6. 输出处理

Token IDs 被恢复为文字。服务可以完整返回，也可以把增量内容组织为 Streaming 事件。

### 7. 请求结束

遇到 EOS、Stop 或长度限制后：

```text
请求状态变为完成
→ 返回最终结果和相关元数据
→ 释放或回收该请求资源
→ 模型继续留在服务中
```

## 哪些是公开事实，哪些是教学抽象

| 内容 | 证据性质 |
|---|---|
| Qwen3-8B仓库有模型、Tokenizer和生成配置 | 可检查公开文件 |
| Qwen模型卡给出vLLM服务入口 | 官方模型卡公开说明 |
| vLLM Engine负责输入、调度、执行和输出处理 | vLLM官方架构文档 |
| 每一步具体用时和显存地址 | 本篇没有实测，未知 |
| 某个托管Qwen服务一定采用相同部署 | 不能由本地案例推出 |

## 把完整路径压缩成一句话

> 模型仓库提供可还原的模型资产，Runtime 把它们装配为长期运行的执行服务；请求到达后，服务再建立独立请求状态，调用同一模型完成 Prefill 和 Decode，返回结果后回收请求资源。

## 常见误解

1. **“API Server就是模型。”** 它是接收请求的服务层，背后还有 Runtime 和模型。
2. **“第一条请求到达时才训练Qwen3-8B。”** 运行时加载并读取训练好的参数。
3. **“请求结束后Qwen模型也被删除。”** 通常只回收请求状态，模型继续服务。
4. **“OpenAI兼容API说明服务器内部和OpenAI相同。”** 只说明接口形状兼容。
