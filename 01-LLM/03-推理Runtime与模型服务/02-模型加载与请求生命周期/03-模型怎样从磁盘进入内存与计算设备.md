# 模型怎样从磁盘进入内存与计算设备

> [!summary]
> 磁盘上的权重只是持久化数据；Runtime 要读取配置、建立模型结构、把权重还原成张量并放到可执行设备，模型才真正具备接受前向计算的条件。

## 三个位置先分清

```text
磁盘或远程仓库
→ 适合长期保存文件

CPU内存
→ 程序运行时读取、整理和暂存数据

GPU显存或其他设备内存
→ 加速器执行模型计算时直接使用的数据空间
```

“模型已经下载”通常只说明文件存在，并不等于模型已经加载到可执行设备。

## 一条概念化加载路径

```text
1. 确定模型目录、版本和文件
2. 读取模型配置
3. 选择支持该架构的模型实现
4. 创建模型结构
5. 逐步读取权重文件或权重分片
6. 把权重还原成运行时张量
7. 按策略放到CPU、GPU或多个设备
8. 准备Runtime工作区和缓存资源
9. 必要时进行编译或预热
10. 标记服务就绪
```

不同框架可能合并、延迟或重排其中一些步骤。这是一条因果图，不是所有 Runtime 必须逐行照做的程序。

## 为什么需要“建立结构”再装入权重

权重值需要有明确归属：

```text
某个矩阵
→ 属于第几层
→ 是Attention投影还是FFN
→ 应该有什么形状
```

模型配置和实现先确定骨架，加载器再把权重映射到相应位置。只有数值而不知道结构，无法正确执行前向计算。

## 设备放置直白来说是什么

设备放置回答：

> 模型的每部分参数和计算实际由哪个设备承载？

可能情况包括：

- 全部放在一张 GPU；
- 一部分在 GPU，一部分在 CPU；
- 不同层或张量分布到多张 GPU；
- 某些暂不使用的数据保留在更慢的存储层。

把模型拆到多个设备不等于免费获得速度。设备之间还要传递中间结果，后续会在“执行优化、并行与部署”中学习。

## 数据精度为什么在加载时出现

同一组参数可以用不同数值格式存储或运行。较低精度通常可以减少容量和数据搬运，但可能引入兼容性、精度或实现限制。

本篇只记住：

```text
参数数量决定“有多少数”
数值格式影响“每个数怎样存和算”
```

具体量化方法和容量计算不属于本篇必修内容。

## 加载成功为什么仍可能无法接收请求

权重读完后，Runtime 可能还需要：

- 建立 KV Cache 可用空间；
- 选择兼容算子；
- 初始化请求队列和调度器；
- 准备 Tokenizer；
- 执行一次预热来发现形状或编译问题；
- 启动模型服务器并通过健康检查。

所以“文件读取完成”和“服务 Ready”仍不是完全相同的状态。

## 开放实现观察：Transformers

Hugging Face 官方文档说明，`from_pretrained()`会从本地目录或 Hub 读取配置和预训练权重；AutoModel 会依据配置选择相应模型类。官方加载指南还把大模型加载描述为创建模型、加载权重并把权重放到模型与设备上的过程，并提供 `device_map` 来控制设备放置。

这些事实帮助理解加载阶段，但 Transformers 只是一个实现入口，不代表 vLLM、SGLang 或托管服务必须采用完全相同的内部步骤。

来源：[Transformers：Loading models](https://huggingface.co/docs/transformers/en/models)、[Transformers：Auto Classes](https://huggingface.co/docs/transformers/model_doc/auto)，核对日期：2026-07-27。

## 常见误解

1. **“模型文件在SSD上，GPU可以直接把它当模型运行。”** 文件通常要被还原并放入执行环境。
2. **“加载模型就是重新训练模型。”** 加载读取已有参数，不计算 Loss 或更新权重。
3. **“文件分片就是GPU并行方案。”** 存储分片与运行时设备分工是两个层次。
4. **“权重放得下，服务就一定能运行。”** KV Cache、工作区和其他运行资源也需要空间。
5. **“设备越多一定越快。”** 跨设备通信和任务形状可能带来额外代价。
