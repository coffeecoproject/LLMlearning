# Runtime 性能与模型回答质量怎样区分

> [!summary]
> Runtime 性能衡量回答以多快、多稳、多省的方式产生；模型质量衡量回答是否正确、有用并符合要求。两者必须分别测试，再检查优化是否让其中一方退化。

## 两组不同问题

| Runtime性能 | 模型或系统质量 |
|---|---|
| 首Token多久出现？ | 事实是否正确？ |
| 后续输出是否平稳？ | 推理过程是否可靠？ |
| 每秒处理多少请求？ | 是否遵循格式和约束？ |
| 显存和成本怎样？ | 工具选择和最终结果是否正确？ |

一个模型可以生成得很快却答错，也可以答得较好却因队列拥堵让用户等很久。

## 为什么优化后要两边都测

- 只改调度或网络，通常主要影响性能，但仍要检查错误和截断；
- 量化会改变数值表示，既要测容量和速度，也要测目标任务质量；
- 更换更小模型可能大幅提速，却可能降低复杂任务能力；
- 增加并发可能提高吞吐，却增加尾部延迟和失败率。

## 一个报告怎样阅读

1. 先确认模型与服务版本没有被偷换；
2. 阅读 [[04-为什么Benchmark必须写明测试条件|测试条件]]；
3. 分别找 TTFT、ITL/TPOT、端到端时间和总吞吐；
4. 查看中位数和慢尾分位数，而非只看平均；
5. 查看错误率、完成原因和资源占用；
6. 另找目标任务的质量评估，不能用 tokens/s 代替。

## 最终因果链

```text
模型能力决定“可能生成什么”
Runtime决定“怎样执行和服务”
Agent与验证系统决定“怎样围绕目标使用并检查结果”
```

三者相互影响，却不能互相替代。

## 理解检查

1. 为什么量化优化需要同时做性能测试和质量测试？
2. 一个报告只有平均 tokens/s，至少还缺哪些信息？
3. Runtime 更快为什么不等于 Agent 任务完成得更可靠？
