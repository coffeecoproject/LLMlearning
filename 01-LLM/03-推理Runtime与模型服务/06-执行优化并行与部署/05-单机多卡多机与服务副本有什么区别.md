# 单机、多卡、多机与服务副本有什么区别

> [!summary]
> 多个设备既可以共同承载一份放不下的模型，也可以各自运行完整模型来服务更多请求；“设备更多”并不能说明采用了哪一种组织方式。

## 四种直白形态

| 形态 | 直白理解 | 常见目的 |
|---|---|---|
| 单机单设备 | 一份模型主要在一个设备运行 | 简单、成本可控 |
| 单机多卡 | 同一机器内多块 GPU 协作或各跑副本 | 放下更大模型或提高容量 |
| 多机协作 | 一次模型执行跨机器通信 | 单机仍放不下或需要大规模并行 |
| 多服务副本 | 多份完整模型各自接收请求 | 增加整体并发、隔离故障 |

## “拆模型”和“复制模型”是两条路线

```text
拆模型：一次请求需要多个设备共同完成
复制模型：每个副本能独立完成请求，路由器把不同请求分过去
```

拆模型解决“一个设备放不下或算不过来”；复制模型主要解决“请求太多”。现实系统也可以同时采用两者，例如每个副本内部用四张卡，外部再部署多个副本。

## 为什么跨机器更复杂

模型层或张量被拆开后，设备之间必须交换中间结果。跨机器通信通常比单机内部更慢、故障点也更多，所以设备数量翻倍并不意味着单请求速度翻倍。

## 一个部署例子

```text
入口负载均衡器
├─ 副本A：4张GPU共同承载模型
└─ 副本B：4张GPU共同承载模型
```

请求甲和乙可分别进入 A、B；但进入 A 的单个请求仍可能需要 A 内四张 GPU 协作。
