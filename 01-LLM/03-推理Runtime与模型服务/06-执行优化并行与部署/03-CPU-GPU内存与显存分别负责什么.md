# CPU、GPU、内存与显存分别负责什么

> [!summary]
> CPU 更适合组织控制流程，GPU 更擅长执行大规模并行数值计算；内存和显存分别是它们可直接高效使用的主要工作空间，但具体分工由 Runtime 决定。

## 用一条请求看分工

```text
接收请求、解析参数、排队        → 常由CPU侧程序组织
Tokenizer与数据准备             → 常在CPU侧完成
Transformer的大量矩阵计算       → 通常交给GPU等加速器
模型权重、激活、KV Cache        → 尽量放在计算设备可快速访问的显存
```

这是常见路径，不是不可改变的硬规则。模型也能只用 CPU 运行，只是大模型通常更慢；某些状态还可以在内存和显存之间转移。

## 内存与显存为什么不能只看总和

模型文件在磁盘上有 20 GB，不表示拥有 20 GB 显存就一定能服务。运行时还可能需要：

- 已加载权重；
- 中间计算结果（激活和工作区）；
- 每个请求增长的 KV Cache；
- Runtime 自身的管理空间。

而且数据若频繁在内存和显存之间搬运，虽然“放得下”，速度也可能受到传输限制。

## 常见误解

**GPU 负责整个服务器的一切。** 请求接收、排队和许多控制逻辑通常仍由 CPU 侧程序负责。

**显存够放权重就一定能运行任意并发。** KV Cache 和中间工作空间也需要容量。
