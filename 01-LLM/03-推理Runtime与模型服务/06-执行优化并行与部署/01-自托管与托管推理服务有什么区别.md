# 自托管与托管推理服务有什么区别

> [!summary]
> 自托管和托管服务可以运行相同的开放模型；主要差别不是 Transformer 怎样计算，而是谁负责模型 Runtime、计算设备、网络服务和日常运维。

> [!phase] 运行阶段：部署方式
> 本篇讨论训练完成后的模型怎样被长期运行，不讨论预训练和微调。

## 先看共同部分

无论部署在哪里，一项可调用的模型服务都不能缺少：

```text
模型配置、权重与Tokenizer资产
+ 推理Runtime
+ CPU、GPU或其他计算设备
+ 接收请求的服务接口
```

托管服务不会让这些环节消失，只是改变谁拥有和管理它们。

## 路径一：自己托管

```text
你的应用或Agent
→ 你维护的API和模型服务器
→ 你运行的vLLM等Runtime
→ 你租用或购买的计算设备
→ 你选择的开放模型
```

你通常需要处理：

- 选择并验证模型版本；
- 配置 Runtime 和硬件；
- 处理启动、升级、监控和故障；
- 决定扩缩容、访问控制和日志策略；
- 测量实际延迟、吞吐量和成本。

优势是控制更直接，代价是工程和运维责任更大。

## 路径二：托管推理服务

```text
你的应用或Agent
→ 平台提供的Endpoint/API
→ 平台管理的模型服务器与Runtime
→ 平台管理的计算设备
```

平台可能负责准备容器、下载模型资产、启动 Runtime、健康检查和扩缩容。调用方仍需选择模型、配置服务、支付资源费用并正确使用 API。

## 一个责任对比

| 工作 | 自托管 | 托管推理服务 |
|---|---|---|
| 选择模型 | 你 | 你 |
| 组织业务上下文 | 你 | 你 |
| 部署Runtime | 你 | 平台通常负责 |
| 管理GPU实例 | 你 | 平台通常负责 |
| KV Cache工程管理 | 由你部署的Runtime完成 | 由平台部署的Runtime完成 |
| Agent工具与权限 | 你 | 仍然是你 |
| 结果验证 | 你 | 仍然是你 |

“平台负责”也不等于你可以忽略配置和测量。模型大小、硬件规格、扩缩容策略和流量特点仍会影响费用与体验。

## 怎样选择

选择不是简单比较某一次 API 单价，还要考虑：

- 请求量是否稳定且足以持续利用硬件；
- 是否需要精确控制模型版本和 Runtime 配置；
- 数据、网络和合规要求；
- 团队是否具备推理运维能力；
- 故障恢复、扩容和监控的成本；
- 目标模型是否真的满足业务质量要求。

## 常见误解

1. **“开放模型就等于本地部署。”** 开放模型也可以由云平台托管运行。
2. **“托管服务没有Runtime。”** Runtime 位于平台服务端。
3. **“托管后不需要做安全设计。”** 业务权限、数据最小化和凭证保护仍是调用方责任。
4. **“自托管一定更便宜。”** 只有结合利用率、硬件、运维和质量要求才能判断。
