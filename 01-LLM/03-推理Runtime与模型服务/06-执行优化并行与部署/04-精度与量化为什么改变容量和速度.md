# 精度与量化为什么改变容量和速度

> [!summary]
> 同一组参数可以用不同精细程度的数字表示；表示更紧凑通常能减少存储和传输压力，但是否更快、质量损失多大，要由硬件、算法和模型共同决定。

## 一个生活化但有限的类比

把 `3.1415926` 记成 `3.14`，记录更短，却丢失了一些细节。量化也会用更紧凑的数值格式表示模型权重，有时也处理激活或 KV Cache。

类比到此为止：真实量化不是简单把每个参数随意四舍五入，而会使用缩放、分组和校准等方法控制误差。

## 为什么可能节省资源

同样数量的参数，如果每个参数占用更少空间：

```text
模型权重占用下降
→ 更可能放入有限显存
→ 读取权重的数据量可能下降
→ 某些硬件上可能运行得更快
```

但“更小”不自动等于“更快”。如果硬件不擅长相应格式，或 Runtime 需要频繁转换，速度提升可能很小，甚至下降。

## 哪些东西不要混在一起

- **参数规模**：模型有多少参数；
- **数值精度**：每个参数怎样表示；
- **量化模型资产**：已经按某种方案转换并保存的权重；
- **Runtime支持**：执行引擎和硬件能否正确、高效运行该格式。

一个 70B 模型量化后仍然是约 700 亿参数的模型，并不会变成 7B；只是参数表示更紧凑。

## 质量边界

量化可能使某些任务几乎无明显变化，也可能让敏感任务退化。不能只看文件大小判断质量，应在目标任务上评估。模型结构、量化方案和位宽名称本身都不是质量保证。
