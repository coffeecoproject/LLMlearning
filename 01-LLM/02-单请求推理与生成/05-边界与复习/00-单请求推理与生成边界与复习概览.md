# 单请求推理与生成边界与复习概览

> [!summary]
> 本专题把单请求推理重新放回完整系统：参数固定不等于没有临时状态；模型生成不等于 Runtime 服务；一次 API 调用也不等于完整 Agent。

## 为什么还需要这一组笔记

前面的专题已经解释一次回答怎样生成。本专题不再重复计算主线，而是解决学习过程中最容易发生的跨层混淆：

```text
模型能根据上下文回答
≠ 模型参数已经学习

模型产生了工具调用文字
≠ 工具已经真实执行

Runtime执行模型
≠ Runtime负责判断事实正确

一次输出包含很多推理Token
≠ 已经形成Agent闭环
```

## 当前最重要的四条边界

```text
上下文适应 ≠ 参数更新
KV Cache ≠ 长期记忆
逐 Token 生成 ≠ Agent 多步执行
服务端批处理 ≠ 一个回答的未来 Token 同时生成
```

## 完成本专题后应能回答

1. 模型在当前对话接受新定义，为什么不代表参数已经更新？
2. 模型、生成控制器、Runtime、API 和客户端分别负责什么？
3. 为什么模型生成“调用工具”不等于工具已经执行？
4. 一次 LLM 请求、一次 CoT 推理和一个 Agent 任务怎样区分？
5. 哪些状态随请求变化，哪些属于训练后通常固定的参数？
