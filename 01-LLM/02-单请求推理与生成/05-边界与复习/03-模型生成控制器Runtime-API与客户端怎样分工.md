# 模型、生成控制器、Runtime、API 与客户端怎样分工

> [!summary]
> 模型负责把当前输入状态转换为 Logits；生成控制器负责选 Token 和判断停止；Runtime 负责执行与资源；API 负责通信协议；客户端负责组织用户交互。真实产品可以把它们装在同一个程序里，但逻辑职责仍然不同。

> [!phase] 运行阶段：系统分层
> 本篇讨论一次请求经过哪些软件职责，不推断任何闭源服务内部具体怎样部署。

## 为什么容易混在一起

用户看到的通常只有：

```text
输入一句话
→ 收到一段回答
```

但一段回答至少可能经过：

```text
客户端
→ API
→ 模型服务器与Runtime
→ 生成控制器
→ 模型前向计算
→ 逐步返回
```

某个开源库可能同时实现其中几层，托管服务也可能隐藏多层。是否部署在同一进程，不改变这些职责的区别。

## 1. 模型：产生Logits

固定参数模型的核心职责是：

```text
输入Token及当前状态
→ Embedding、Transformer、Output Layer
→ 下一Token对应的Logits
```

模型本身通常不负责：

- 保存用户账号的完整聊天记录；
- 发起网络请求；
- 在操作系统中执行命令；
- 决定页面如何逐字显示；
- 判断一个工程任务是否真正验收完成。

## 2. 生成控制器：把Logits变成生成循环

生成控制器连接多次模型前向计算：

```text
读取Logits
→ 应用Temperature、Top-p等规则
→ 选择Token
→ 检查EOS、Stop或长度限制
→ 若未停止，将Token送入下一轮
```

因此，“模型输出概率”和“系统最终选择哪个 Token”不是完全相同的职责。

## 3. Runtime：让模型真正跑起来

Runtime 负责把逻辑计算落实到设备和资源上，例如：

- 加载模型权重与配置；
- 把张量送到 CPU、GPU 或其他设备；
- 执行 Prefill 和 Decode；
- 管理 KV Cache；
- 组织多个请求的 Batch 与调度；
- 处理内存、并行和算子执行。

单请求主线解释“为什么要 Prefill 和 Decode”；Runtime 继续解释“怎样高效执行这些步骤”。

## 4. API：建立调用边界

API 定义调用双方怎样交换信息，例如：

```text
请求：模型名称、Messages、生成配置
响应：文本、结构化输出、用量信息、错误
流式事件：增量内容、状态变化、结束信号
```

认证、请求格式、错误码和网络传输属于接口层。API 暴露了什么，不等于服务器内部结构就是什么。

模型服务器是承载 API、Runtime 和相关服务逻辑的软件容器或服务进程；它不是模型参数本身，也不代表所有产品都采用相同内部拆分。

例如接口返回 `output_text`，不能据此推断模型内部一次性生成了整段文本。

## 5. 客户端或应用：组织用户体验

客户端可能负责：

- 接收用户输入；
- 保存 Thread 或 Session；
- 选择哪些历史消息进入新请求；
- 展示 Streaming 内容；
- 把工具结果重新加入 Messages；
- 处理中断、重试和界面状态。

客户端保存了历史，不代表模型自动看到了全部历史；最终仍要看本次实际发送了什么。

## 用一个请求串起来

用户输入：

```text
请用一句话解释KV Cache。
```

可能经历：

```text
客户端：加入系统指令和相关历史
→ API：把结构化请求发送给服务端
→ Runtime：准备模型执行和请求状态
→ 模型：Prefill并产生Logits
→ 生成控制器：选择Token并组织后续循环
→ Runtime：反复执行增量Decode
→ API：发送增量事件
→ 客户端：恢复并显示可读文字
```

这是一张逻辑职责图。具体产品可能合并步骤，也可能在不同机器上拆得更细。

## 谁对“正确”负责

模型可以生成正确答案，但它的 Logits 不带“已经通过外部事实验证”的保证。其他层也不会自动创造正确性：

```text
模型提出内容
→ 应用或Agent调用可靠工具
→ 验证结果
→ 根据证据决定接受、修正或升级人工处理
```

因此，Runtime 解决“怎样执行”，验证系统解决“结果是否满足要求”，两者不要混淆。

## 常见误解

1. **“API就是模型。”** API 是调用边界，背后还可能有服务端、Runtime 和模型。
2. **“Temperature是模型训练参数。”** 在普通生成中，它通常属于 Logits 处理配置。
3. **“Streaming说明模型一次只返回一个字符。”** 网络事件、Token 和字符是不同对象。
4. **“客户端有完整Session，所以模型也看见了全部Session。”** 只有本次被组织并发送的内容才进入模型上下文。
5. **“Runtime提高了速度，也就提高了答案事实正确率。”** 执行效率和内容正确性是不同维度。

1. 谁产生 Logits，谁选择 Token，谁把计算放到 GPU 上？
