# 参数固定、上下文适应与持续学习有什么区别

> [!summary]
> 普通推理可以让模型根据当前上下文改变回答，但通常不会更新模型参数；外部记忆会保存信息，却仍要重新放入上下文；只有明确执行训练更新，才属于模型参数层面的学习。

> [!phase] 三种阶段必须分开
> 本篇同时对比普通运行、外部系统记忆和训练更新。它们都可能让后续表现发生变化，但变化发生的位置不同。

## 先看一个容易误判的例子

用户在当前对话中说：

```text
以后在这段对话里，“青鸟”表示我们的发布计划。
```

随后问：

```text
青鸟什么时候执行？
```

模型能够按照新定义回答，并不直接证明它已经修改参数。更常见的过程是：

```text
“青鸟”的定义仍在当前输入中
→ 模型通过Attention读取这段上下文
→ 形成与当前语境相关的Hidden State
→ 生成符合定义的回答
```

换一个完全不携带这段历史的新请求，模型可能就不知道“青鸟”是什么意思。

## 第一种变化：上下文适应

上下文适应常被称为 **In-context Learning**。这里的“Learning”容易造成误解：它表示模型能根据当前示例、定义或要求调整本次行为，不等于训练算法更新了权重。

```text
发生变化：本次输入Token、Hidden States、Logits、KV Cache
通常不变：Embedding、Attention、FFN等模型参数
```

上下文一旦被截断、压缩遗漏或不再发送，这种适应依据也可能消失。

## 第二种变化：外部记忆与检索

应用或 Agent 可以把“青鸟是发布计划”保存到数据库、文件或记忆系统。新会话开始后，再检索并放入模型输入：

```text
信息写入外部存储
→ 新请求到来
→ 检索相关信息
→ 重新放入Messages
→ 模型在当前上下文中使用
```

这能跨请求保留信息，但学习发生在**系统状态**层，不是模型参数层。

模型没有直接读取整座数据库。只有被应用选中并放进本次上下文的内容，才可能影响这次生成。

## 第三种变化：参数更新

如果希望模型本身在没有原始提示的情况下也改变行为，通常需要进入明确的训练过程：

```text
准备训练样本
→ 前向计算
→ 计算Loss
→ 反向传播
→ 优化器更新参数
→ 保存新模型版本或适配器
```

这可能是预训练、微调、偏好优化、在线学习或其他参数更新方法。共同点不是名称，而是存在“根据训练信号修改参数”的步骤。

普通聊天中多生成一段推理文字，不等于执行了这条链路。

## 三者放在一起比较

| 方式 | 信息主要存在哪里 | 是否改模型参数 | 离开当前请求后是否保留 |
|---|---|---:|---|
| 上下文适应 | 当前输入与临时运行状态 | 否 | 不一定 |
| 外部记忆/检索 | 数据库、文件、记忆服务 | 否 | 可以，但需要再次检索 |
| 参数学习 | 模型权重或适配器 | 是 | 随新模型版本保留 |

## “持续学习”为什么不能只理解为长对话

持续学习关注系统怎样在运行过程中不断吸收新经验，并在未来稳定使用。它可能组合：

```text
经验采集
+ 外部记忆
+ 数据筛选
+ 评估
+ 必要时参数更新
```

因此，长上下文、Agent 记忆和持续训练都可能参与持续学习系统，但三者不能互相替代。

## 什么会出问题

- 把上下文适应当成参数学习，会高估模型跨会话记忆能力；
- 把数据库里保存的信息当成模型已经知道，会忽略检索与注入步骤；
- 把未经验证的对话直接用于在线训练，可能把错误、隐私数据或攻击内容写进模型；
- 只更新参数而不做评估，无法判断新能力是否破坏旧能力。

## 常见误解

1. **“模型记住了我的名字，所以权重已经更新。”** 更可能是历史仍在上下文，或应用重新注入了记忆。
2. **“RAG让模型学会了新知识。”** RAG 主要把检索结果放入当前输入，通常不修改基础模型参数。
3. **“推理模型会在思考时训练自己。”** 生成推理 Token 仍可只是固定参数下的前向计算。
4. **“只要会保存Session，就是持续学习。”** Session 保存解决的是状态持久化，不等于经验筛选、知识整合和参数更新。

## 理解检查

1. 模型在当前对话接受一个新定义，哪些状态改变了，哪些参数通常没变？
2. 外部记忆为什么必须经过检索并重新进入上下文？
3. 判断是否发生模型学习时，最关键的技术证据是什么？
