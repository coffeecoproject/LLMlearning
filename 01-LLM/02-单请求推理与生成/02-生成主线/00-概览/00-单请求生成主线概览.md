# 单请求生成主线

> [!summary]
> 本专题跟踪一个请求从消息输入到 Token 序列结束的完整因果链，不讨论其他请求怎样共享服务器资源。

## 真实执行顺序

```text
输入准备
→ Prefill：建立 Prompt 的 KV Cache，并产生首次 Logits
→ 选择 Token 1
→ 检查停止条件
→ 若继续，将 Token 1 送入增量 Decode
→ 产生下一轮 Logits
→ 选择 Token 2
→ 检查停止条件
→ 继续循环或结束
→ Tokenizer Decode 恢复文本
```

因此，Token 选择和增量 Decode 不是各自只发生一次的前后两段，而是交替形成循环：

```text
Logits → 选择一个 Token → 检查停止 → 增量 Decode → 新 Logits → ……
```

## 专题阅读顺序

下面的顺序是为了先理解生成循环依赖的机制，再学习候选选择方法；它不等同于各环节在运行时只按一次线性顺序发生。

1. [[00-输入准备概览|输入准备]]：消息怎样成为模型输入；
2. [[00-Prefill与首次预测概览|Prefill 与首次预测]]：模型怎样读取当前上下文；
3. [[00-KV-Cache与增量Decode概览|KV Cache 与增量 Decode]]：怎样复用历史 Attention 状态；
4. [[00-Token选择策略概览|Token 选择策略]]：怎样从候选中选出一个 Token；
5. [[00-停止与文本恢复概览|停止与文本恢复]]：怎样结束循环并还原文本。
6. [[00-完整生成循环串联复习概览|完整生成循环串联复习]]：用同一个例子走完所有环节。

## 各层职责

```text
模型外输入准备：Messages → Chat Template → Tokenizer
模型前向计算：Embedding → Transformer → Output Layer → Logits
模型外生成控制：处理 Logits → 选 Token → 判断停止
```

“模型外”不等于“不重要”，而是说明职责所在。网络 Streaming 和多用户服务不参与决定这条单请求因果链，因此已经移至 Runtime 部分。
