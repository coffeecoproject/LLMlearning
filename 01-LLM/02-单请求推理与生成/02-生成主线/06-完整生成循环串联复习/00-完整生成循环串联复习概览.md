# 完整生成循环串联复习概览

> [!summary]
> 本专题不增加新的模型组件，而是把输入准备、Prefill、首次 Token 选择、增量 Decode、停止检查和文本恢复重新接成一条完整因果链。

## 为什么需要单独串联

前面的专题按照概念分别解释各个环节，但真实生成不是简单执行一次“Decode”，再执行一次“Token 选择”。它包含一次启动阶段和一个重复循环：

```text
一次启动：输入准备 → Prefill → 首次 Logits

重复循环：处理 Logits → 选择 Token → 检查停止
                         ↓ 若继续
                    增量 Decode → 新 Logits

结束阶段：生成 Token IDs → Tokenizer Decode → 文本
```

## 阅读内容

1. [[01-一次回答怎样完整生成|一次回答怎样完整生成]]：使用一个教学化例子走完全部环节。

## 完成标准

读完后应当能够解释：

1. 第一个回答 Token 和后续 Token 的 Logits 分别来自哪里；
2. 刚选出的 Token 在什么时候进入 KV Cache；
3. Output Layer、生成控制器和 Tokenizer Decode 各自负责什么；
4. 为什么“每个逻辑生成步骤选择一个 Token”不等于每个 Runtime 调度轮次或网络事件只能包含一个 Token。
