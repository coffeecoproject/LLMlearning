# 单请求推理与生成大纲

> [!summary]
> 本部分只跟踪一个已经训练完成、参数保持固定的 LLM 请求，解释它怎样从输入消息走到逐 Token 输出；多请求调度、服务并发和部署工程移入独立的 [[00-推理Runtime与模型服务大纲|推理 Runtime 与模型服务]]。

## 研究对象

```text
一组当前请求消息
→ 输入协议与 Tokenizer
→ Prefill：处理可见上下文
→ 得到下一 Token 的 Logits
→ 选择一个 Token
→ 利用 KV Cache 增量 Decode
→ 满足停止条件
→ Tokenizer Decode 恢复文本
```

这里研究的是“一条回答自身怎样形成”，不是“服务器怎样同时承载很多回答”。

## 必须经过的四个层次

| 层次 | 本部分讲什么 | 是否属于模型权重内部 |
|---|---|---|
| 输入准备层 | Messages、Chat Template、Tokenizer、输入张量 | 否，但决定模型实际看到什么 |
| 模型计算层 | Prefill、Causal Attention、Output Layer、Decode | 是模型前向计算 |
| 单请求运行状态 | Hidden States、历史 Token、KV Cache | 不是长期参数 |
| 生成控制层 | Logits 处理、Token 选择、停止条件 | 通常由生成循环执行 |

输入准备和生成控制虽然位于模型外部，但它们是理解一次真实请求不可缺少的直接接口。它们与多请求调度、网络服务和部署工程不是同一层。

## 五部分结构

1. [[00-单请求推理与生成框架速览概览|框架速览]]：一页建立完整请求心智模型；
2. [[00-单请求生成主线概览|生成主线]]：输入准备、Prefill、KV Cache、Decode、选择与停止；
3. [[00-上下文与多轮交互概览|上下文与多轮交互]]：上下文窗口、截断和历史重组；
4. [[00-单请求效率与资源概览|单请求效率与资源]]：输入长度、输出长度、延迟和请求内缓存；
5. [[00-单请求推理与生成边界与复习概览|边界与复习]]：区分训练、模型计算、生成控制与 Runtime。

## 明确移出本部分的内容

以下内容统一进入 [[00-推理Runtime与模型服务大纲|推理 Runtime 与模型服务]]：

- 模型权重加载与设备放置；
- Batch 与 Continuous Batching；

## KV Cache 为什么在两部分都会出现

```text
本部分：为什么历史 K、V 可以复用，Decode 怎样读取它们
Runtime：缓存怎样占用、分页、复用、迁移和回收内存
```

同一个对象可以跨越模型接口和系统工程，但每篇笔记只负责一个层次。

## 阶段边界

> [!info] 运行阶段
> 模型权重通常保持不变；当前输入、Hidden States、Logits、已生成 Token 和 KV Cache 会随请求改变。

本部分不展开 Loss、反向传播、优化器、CoT 策略或 Agent 工具循环。
