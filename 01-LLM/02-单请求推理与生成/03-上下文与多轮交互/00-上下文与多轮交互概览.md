# 上下文与多轮交互概览

> [!summary]
> 模型每次只能依据本次请求中实际可见的 Token 生成；多轮对话通常由外部系统保存并重新组织历史，而不是模型在参数里自动永久记住聊天内容。

## 本专题回答什么

```text
一次请求究竟能看见多少内容？
→ 上下文窗口

内容进入窗口后一定会被正确使用吗？
→ 不一定，还要经过相关性识别、检索、整合和生成

内容过长时谁决定删什么？
→ Truncation 与上下文管理

下一轮为什么看起来记得上一轮？
→ 外部系统重新发送相关历史

KV Cache、Prompt Cache 和长期记忆相同吗？
→ 不同层级的复用机制
```

## 先看完整关系

```text
对话历史、系统指令、当前问题、工具结果等候选内容
→ 应用选择并组织本次请求
→ Chat Template 与 Tokenizer
→ 本次实际输入的 Token 序列
→ 受上下文窗口限制
→ Prefill 与后续生成
```

模型只能使用最后真正进入本次输入序列的内容。信息保存在聊天数据库里，不等于本次模型一定能够看见。
