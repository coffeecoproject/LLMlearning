# 上下文、缓存与长期记忆有什么区别

> [!summary]
> 上下文是模型本次能够使用的内容，KV Cache 和 Prompt Cache 是复用已有计算的状态，长期记忆则通常是模型之外保存并在需要时重新取回的信息；它们可能连接，但不是同一个对象。

> [!phase] 运行阶段与系统边界
> 本篇先建立对象区别。缓存的分页、跨请求共享和回收属于 Runtime；Agent 如何写入、检索和验证长期记忆属于后续模块。

## 六个容易混淆的对象

| 对象                    | 保存或表示什么                        | 主要目的            | 是否自动成为本次可见内容          |
| --------------------- | ------------------------------ | --------------- | --------------------- |
| 当前上下文                 | 本次请求实际使用的 Token 序列             | 给模型提供当前条件       | 是                     |
| 对话历史存储                | 过去的原始消息和元数据                    | 保存会话记录          | 否，需要被选择并重新加入          |
| KV Cache              | 已处理 Token 在各 Attention 层的可复用状态 | 避免重复计算历史 K、V    | 它表示已经属于当前序列的前缀，不增加新内容 |
| Prompt / Prefix Cache | 相同输入前缀的可复用计算结果                 | 减少重复 Prefill 成本 | 否，只复用相同前缀的计算          |
| Agent 长期记忆            | 外部保存的事实、事件、摘要或经验               | 跨任务、跨会话取回信息     | 否，需要检索并注入上下文          |
| 模型参数                  | 训练形成的大量权重                      | 承载模型的一般能力和行为倾向  | 它持续影响计算，但不是可逐条读取的聊天记录 |

## 当前上下文：模型此刻真正能用什么

当前上下文是逻辑内容层：无论客户端提交完整文字，还是服务端根据会话状态恢复，模型这一轮能够依赖的内容必须属于最终有效序列。

```text
数据库里有 100 条历史
→ 应用本轮只选择 12 条
→ 模型当前上下文只包含被选择并成功放入窗口的内容
```

## KV Cache：把已经做过的 Attention 计算留下来

KV Cache 不负责决定“哪段历史重要”。它通常表示模型已经处理过的序列前缀：

```text
前缀 Token 已进入模型
→ 每层形成 K、V
→ 保存 K、V
→ 后续 Token 直接读取
```

释放 KV Cache 只意味着以后可能需要重新计算，不必然删除应用保存的原始消息。

它在单请求中的计算原理见 [[01-KV-Cache保存什么|KV Cache 保存什么]]；分页、分配与回收属于 [[00-KV-Cache工程管理概览|Runtime 的 KV Cache 工程管理]]。

## Prompt Cache：复用相同前缀，不是多出一块知识

当多个请求具有相同的长前缀时，Runtime 或服务可以缓存这部分前缀的计算结果：

```text
相同 System Prompt + 相同文档前缀
→ 复用对应计算
→ 减少重复 Prefill
```

如果新请求换了前缀内容，旧缓存不能凭空把被省略的新事实补进上下文。Prompt Cache 优化“算得更快或更省”，不决定模型应该记住什么。

## 长期记忆：先保存，再检索，再放回上下文

Agent 的长期记忆通常是外部系统能力：

```text
从对话或任务中提取信息
→ 写入数据库、文件或向量存储
→ 后续任务按需要检索
→ 把选中的内容加入新请求上下文
→ 模型才能在这一轮使用
```

这条链可能在跨会话后仍然工作，但可靠性取决于写入内容是否正确、检索是否命中、信息是否过期以及注入位置是否合适。

## 模型参数为什么也不能简单叫“记忆库”

训练确实会让信息以分布式方式影响参数，但模型参数不是一个可以按用户逐条查看、精确删除和可靠读取的聊天数据库。当前用户说一句“我叫小林”，通常只改变当前请求状态，不会自动触发训练把这句话写入参数。

## 同一条信息可能经过多个层级

“用户叫小林”可以同时出现于：

```text
对话历史数据库：保存原始消息
→ 本次上下文：应用把消息重新加入请求
→ KV Cache：模型处理这段上下文后形成计算状态
```

如果系统还把它提取为用户档案，则它也可能进入 Agent 长期记忆。但这些是同一事实的不同表示和生命周期，不能因为内容相同就把系统对象混为一谈。

## 常见误解

1. **“KV Cache 保存了对话，所以它就是长期记忆。”** 它主要用于当前序列的计算复用，生命周期和数据结构都不同。
2. **“Prompt Cache 命中后，模型能看到没有提交的新内容。”** Cache 只能复用对应前缀，不能创造输入中不存在的信息。
3. **“数据库保存了用户资料，模型自然会知道。”** 必须由应用检索并加入当前上下文。
4. **“把信息加入上下文就等于微调了模型。”** 上下文适应不改变长期参数。
