# 上下文窗口限制什么

> [!summary]
> 上下文窗口限制的是一次生成过程中模型能够共同处理的 Token 位置数量；模型只能依据本次请求中实际进入窗口的内容生成，无法直接读取窗口之外的信息。

> [!phase] 运行阶段
> 本篇讨论训练完成后的模型请求。训练时使用多长序列是另一个问题，不在这里展开。

## “上下文”到底是什么

对模型而言，上下文不是聊天界面，也不是完整数据库，而是经过输入准备后真正交给模型的 Token 序列。它可能包含：

- System、Developer、User 等不同角色的指令；
- 当前用户问题；
- 被重新发送的历史消息；
- 工具返回结果或检索内容；
- Chat Template 加入的角色边界和其他特殊 Token；
- 已经生成、并参与后续 Decode 的回答 Token。

因此，用户界面中只看到一句短问题，不代表模型输入也只有这句话。

## 为什么窗口是有限的

模型的位置机制、训练配置和运行实现都面向有限长度的序列；序列变长还会增加 Attention 计算、临时状态和 KV Cache 的资源需求。因此模型或服务必须声明并执行一个可支持的长度范围。

这里要区分硬性容量和实际使用效果：

```text
硬性可用上限
← 模型配置、位置实现、Runtime 与 API 限制

长上下文中的实际表现
← 还会受到训练长度分布、内容位置和干扰信息影响
```

具体模型的公开窗口数字属于版本化配置，不能把某个模型的数值推广到所有 LLM。

## 窗口为什么以 Token 而不是字符计算

模型沿 Token 位置进行 Embedding、Position 和 Transformer 计算。同样一段可见文字，经过不同 Tokenizer 后可能占用不同数量的 Token：

```text
文字长度相同
≠ Token 数量一定相同
≠ 占用的上下文位置一定相同
```

中文、英文、代码、空格和 Emoji 的切分规律不同，所以不能用固定的“一个汉字等于一个 Token”估算窗口。

## 一个教学化例子

假设某个模型的一次生成最多容纳 20 个 Token。经过 Chat Template 和 Tokenizer 后：

```text
System 指令       4 Token
历史消息          7 Token
当前问题          5 Token
协议特殊标记      2 Token
-------------------------
当前输入合计     18 Token
```

这时窗口只剩下 2 个位置供后续序列继续增长。示例中的数字是虚构的，只用于说明预算关系。

## “模型记得”与“模型看见”

如果上一轮内容被重新放进本次输入，模型可以在当前上下文中使用它；如果那段内容没有被重新发送，也没有通过其他机制加入输入，模型计算时就看不见它。

```text
保存在应用数据库中
≠ 已进入本次上下文

已进入本次上下文
≠ 已永久写入模型参数
```

这也是为什么相同模型在不同应用中可能表现出不同的“记忆能力”：上层系统组织的输入不同。

## 在窗口里不等于可以违反因果顺序

对 Decoder-only 模型，Prefill 时完整 Prompt 虽然已经存在于输入张量中，各位置仍受 Causal Mask 限制：

```text
靠前的 Prompt 位置：只能读取自己及左侧内容
最后一个 Prompt 位置：可以读取此前全部 Prompt
生成中的当前位置：可以读取 Prompt 和已确认的生成 Token
```

因此，“内容位于上下文窗口中”描述的是它有没有进入这条序列；“当前位置能看哪些 Token”还要由因果可见性决定。后续生成仍不能读取尚未产生的未来 Token。

## 窗口更长不等于任何位置都使用得一样好

“支持最多 N 个 Token”首先表示容量边界，不自动保证模型对窗口内每个细节都同样敏感。信息所在位置、内容密度、干扰项和模型训练方式都可能影响实际使用效果。

因此要区分：

- **能放进去**：没有超过允许的 Token 数量；
- **能被注意到**：模型在这次生成中实际利用了相关内容；
- **能可靠回答**：模型正确理解并使用了内容。

它们不是同一承诺。

## 常见误解

1. **“上下文窗口是聊天记录能保存多久。”** 不是。聊天记录可长期存储，但每次只能选取有限内容进入模型。
2. **“窗口之外的内容模型会自动去数据库查找。”** 不会，除非应用或 Agent 主动检索并加入本次输入。
3. **“20 万 Token 就表示每个细节都能可靠记住。”** 容量和可靠利用能力不同。
4. **“字符数小于窗口数字就一定放得下。”** 窗口按具体 Tokenizer 产生的 Token 计数。

## 理解检查

1. 为什么聊天界面中的可见文字不等于模型的完整输入？
2. 一段历史保存在数据库中，模型为什么仍可能看不见？
3. 完整 Prompt 已经进入 Prefill，为什么靠前位置仍不能看右侧 Token？
4. “能够放入窗口”和“能够可靠使用”有什么区别？
