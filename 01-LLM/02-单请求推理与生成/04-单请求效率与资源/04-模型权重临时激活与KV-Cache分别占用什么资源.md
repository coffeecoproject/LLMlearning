# 模型权重、临时激活与 KV Cache 分别占用什么资源

> [!summary]
> 权重是模型运行所需的固定参数主体；临时激活和工作区支持当前前向计算；KV Cache 保存本次序列各层可复用的 Attention 状态。三者都可能占用显存，但来源、寿命和增长方式不同。

> [!phase] 运行阶段
> 本篇只说明一个请求能够观察到的资源角色。模型加载、设备放置、多个请求共享权重以及缓存块分配属于 Runtime；训练阶段还要保存梯度和优化器状态，不在本篇范围内。

## 先看三只不同的“箱子”

```text
模型权重
模型长期带着的参数

临时激活与工作区
当前计算过程中的中间结果和临时操作空间

KV Cache
本次生成期间为历史位置保留的Attention状态
```

它们不能都笼统叫“模型内存”。如果不区分，就无法解释为什么：

- 同一个模型长上下文更占资源；
- 生成结束后部分内存可以释放；
- 多请求可以共享权重，却各自需要请求状态；
- 推理内存与训练内存构成不同。

## 1. 模型权重：固定基础占用

权重包括 Embedding、Attention、FFN、Normalization 和 Output Layer 等处训练得到的参数。运行时通常先把它们加载到可计算的设备上。

在一次普通请求期间：

```text
用户输入改变
→ 权重通常不改变

生成更多Token
→ 权重数量通常也不增加
```

一个粗略估算是：

```text
权重存储量 ≈ 参数数量 × 每个参数的存储字节数
```

例如，一个虚构的 70 亿参数模型若每个参数用 2 字节表示：

```text
7,000,000,000 × 2字节
≈ 14 GB
```

这是理想化参数主体估算，未包含元数据、临时缓冲、对齐开销和其他运行状态。低精度或量化可以减少权重存储，但真实占用不能只用位数机械相乘得出。

## 2. 临时激活与工作区：为当前计算服务

Token 的表示在模型中逐层变化：

```text
初始表示
→ Block 1输出
→ Block 2输出
→ ……
→ 最终Hidden State
```

这些中间表示及算子所需的临时空间，可以统称为临时激活与工作区。普通推理只进行前向计算，通常不必像训练那样为反向传播长期保留全部中间结果。

但这不代表推理没有激活内存：

- Prefill 同时处理多个输入位置，需要适配相应张量形状；
- Decode 虽然主要处理当前新增位置，仍要经过全部层；
- 不同算子可能需要额外临时缓冲；
- 实现可以复用或及时释放一部分空间。

因此，激活占用会随序列形状、模型结构和实现变化，不适合用一个固定数字概括。

## 3. KV Cache：随可见序列增长的请求状态

在每层 Attention 中，已处理 Token 会形成 K、V。为了避免每轮重新计算历史 K、V，运行时将它们保留下来：

```text
Prefill处理输入
→ 建立输入位置的KV Cache

每生成一个新Token
→ 增加这个位置在各层的新K、V
```

所以对同一模型、同一表示精度来说，KV Cache 通常大致随可见 Token 数增长。

### 一个虚构小模型例子

假设教学模型有：

```text
2层
每层2个KV Head
每个Head维度2
当前序列4 Token
K和V两份状态
每个数2字节
```

用于理解形状的简化计算：

```text
2层 × 2个KV Head × 2维 × 4 Token × 2(K和V) × 2字节
= 128字节
```

如果序列从 4 Token 增长到 8 Token，其他条件不变，这部分示意占用也会约翻倍。

> [!warning] 示例边界
> 这里的模型和数字完全是教学虚构。真实 KV Cache 还取决于层数、KV Head 数、Head Dimension、数据类型、布局和结构变体；GQA、MQA、MLA 等会改变 K、V 的组织和存储方式。

## 三者的寿命对比

| 对象 | 何时出现 | 通常保留多久 | 是否随当前序列增长 |
|---|---|---|---|
| 模型权重 | 模型加载时 | 模型提供服务期间 | 否 |
| 临时激活/工作区 | 某一步前向计算时 | 当前计算需要期间 | 取决于阶段和实现 |
| KV Cache | Prefill开始建立 | 当前生成或会话复用期间 | 是 |

生成结束后，KV Cache 是否立刻释放、保留多久、能否跨轮复用，是 Runtime 和产品策略，不是 Transformer 权重自己决定的。

## 容量和带宽不要混淆

- **内存容量**：能不能放得下权重、KV Cache 和临时空间；
- **内存带宽**：单位时间能搬运多少数据；
- **计算能力**：单位时间能完成多少矩阵运算。

一个模型“能放进显存”不代表一定生成得快。尤其在 Decode 中，每一轮都要使用大量权重并读取历史状态，数据搬运速度可能成为重要瓶颈。

## 常见误解

1. **“模型占14GB，所以每个请求都新增14GB。”** 多请求通常共享同一份已加载权重；每个请求主要增加自己的运行状态。
2. **“KV Cache是模型参数的一部分。”** 它是由当前输入和已生成 Token 产生的临时状态。
3. **“推理没有激活，因为不训练。”** 推理仍有前向中间结果，只是不需要按训练方式保存全部反向传播材料。
4. **“量化到4-bit，真实显存一定正好等于参数量乘0.5字节。”** 还存在布局、元数据、缓存、工作区和实现开销。

2. 为什么生成结束后可以释放 KV Cache，但通常不会卸载模型权重？
3. “模型放得下”和“模型跑得快”为什么不是同一个问题？
