# 输入长度为什么主要影响 Prefill

> [!summary]
> 回答开始前，Prefill 必须处理本次实际输入的全部 Token；输入越长，模型需要处理的位置越多，所以首 Token 通常等待更久，并建立更大的初始 KV Cache。

> [!phase] 运行阶段
> 本篇讨论输入已经完成 Chat Template 和 Tokenizer 处理、准备进入模型之后的单请求计算，不讨论历史消息如何被选择，也不讨论其他请求是否正在排队。

## 从上一专题接过什么

[[02-输入输出与总长度怎样计算|输入、输出与总长度怎样计算]]已经说明，真正进入模型的输入不只是当前一句话，还可能包括：

```text
系统指令
+ 历史消息
+ 当前问题
+ 工具结果
+ Chat Template产生的标记
= 本次输入Token序列
```

本篇继续追问：当这条序列变长时，模型运行会发生什么？

## 先用阅读材料来理解

假设有两个请求：

```text
请求A：阅读 20 Token 后回答
请求B：阅读 2,000 Token 后回答
```

两者都只要求回答一句话，但请求 B 在回答之前必须先处理更多输入位置。因此，即使两者最终输出一样长，请求 B 的首 Token 通常也会更晚出现。

这类似于先阅读材料再回答问题：答案同样只有一句，不代表准备答案前阅读的材料同样多。

> [!warning] 类比边界
> 模型不是像人一样逐字默读。Prefill 可以利用矩阵计算并行处理输入位置；这个类比只表达“已有材料必须先被处理”，不表示程序一定逐 Token 串行读取 Prompt。

## Prefill实际增加了哪些工作

对每个输入位置，模型都要经过大致相同的主干：

```text
Token ID
→ Embedding与位置信息
→ 多层Transformer Block
→ 产生各层表示
```

在每层 Attention 中，还会形成这个位置的 K、V，以供后续 Token 使用。因此，输入变长至少会带来两类增加：

1. 更多位置需要经过多层模型计算；
2. 更多位置的 K、V 需要写入初始 KV Cache。

## 为什么不能只说“长度翻倍，时间一定翻倍”

真实关系不是固定倍数，原因包括：

- Attention 要处理位置之间的关系，长度变化会改变计算形状；
- GPU 等硬件对大矩阵的利用率可能与小矩阵不同；
- 模型可能使用 MHA、GQA、MQA 或 MLA 等不同结构；
- 精度、算子实现和硬件都会改变速度；
- Runtime 可能采用分块 Prefill、并行计算或其他优化。

因此可以确定的是“输入变长通常增加 Prefill 工作”，不能只凭长度直接推出精确等待时间。

## 输入长度也会影响后续 Decode

“主要影响 Prefill”不等于“只影响 Prefill”。

假设回答刚开始：

```text
短输入：已有 20 个历史位置
长输入：已有 2,000 个历史位置
```

第一个新增 Token 进入 Decode 时，它的 Query 需要从可见历史 K、V 中读取相关信息。长输入一开始就拥有更长的历史，因此通常还会：

- 占用更多 KV Cache；
- 让后续 Attention 读取更多历史状态；
- 缩小上下文窗口中可留给输出的空间。

## 一个简单数字例子

下面只是说明结构，不代表真实模型耗时：

```text
请求A
输入：100 Token
输出：20 Token

请求B
输入：1,000 Token
输出：20 Token
```

两者 Decode 轮数都大约由 20 个输出 Token 决定，但 B 的差异是：

```text
Prefill处理的位置更多
+ 初始KV Cache更大
+ 每轮Decode面对的历史更长
```

因此，不能因为输出长度相同，就认为两个请求耗时和资源相同。

## 常见误解

1. **“Causal Attention不能看未来，所以 Prefill 必须逐 Token 串行运行。”** 信息可见性是因果的，但整段已知 Prompt 的很多矩阵计算可以并行。
2. **“输入只影响第一个 Token。”** 输入对 TTFT 的影响最明显，但也决定初始 KV Cache 和后续历史长度。
3. **“文字字符数就是输入长度。”** 模型处理的是 Token；中文、英文、代码、数字和 Emoji 的切分可能不同。
4. **“同样长度在所有模型上耗时相同。”** 模型结构、参数规模、精度、硬件和实现都会影响结果。

## 理解检查

1. 两个请求输出同样长，为什么长输入请求仍可能更慢？
2. Prompt 内部遵守因果遮罩，为什么 Prefill 仍能并行计算很多位置？
3. 为什么长输入也会影响后续 Decode，而不只是 TTFT？
