# LLM 模块大纲

## 模块定位

LLM 是整套学习的基础模块。本模块先研究模型本身，再进入后续的推理与 CoT、Agent、持续学习和更高级智能系统。

本模块需要建立一条完整因果链：

```text
模型由什么构成
→ 一个固定参数模型怎样生成回答
→ Runtime 怎样承载和服务模型
→ 训练如何改变模型
→ 能力为什么形成
→ 能力为什么存在边界
→ 怎样评估、优化并理解模型演进
```

## 核心问题

> 一个通过大量数据和预测目标训练出来的模型，怎样形成语言与知识能力，并在运行时根据上下文生成有用但不一定可靠的结果？

## 六部分结构

```text
第一部分  基础结构与计算机制
          ↓
第二部分  单请求推理与生成
          ↓
第三部分  推理 Runtime 与模型服务
          ↓
第四部分  LLM 训练与对齐
          ↓
第五部分  能力形成与边界
          ↓
第六部分  评估、优化与模型演进
```

六部分把模型机制、单请求生成、服务系统和参数训练分开：

- 第二部分研究一个请求自身怎样逐 Token 生成；
- 第三部分研究 Runtime 怎样加载模型、管理多个请求和提供服务；
- 第四部分研究模型参数和行为倾向怎样形成；
- 第五部分重新连接结构、运行和训练，解释能力与失败；
- 第六部分研究怎样测量、优化和比较模型与系统。

## 第四部分：LLM 训练与对齐

> [!map]
> 详细结构见 [[01-LLM/04-LLM训练与对齐/00-概览/00-LLM训练与对齐大纲|LLM 训练与对齐大纲]]。

### 定位

回答“模型参数、基础能力和行为倾向怎样形成”。训练决定模型能够学到什么，后训练和对齐进一步塑造模型倾向于怎样回应。

### 一级大纲

1. 训练到底在改变什么
2. 数据工程、样本构造与 Causal LM 训练目标
3. 前向计算、Loss、反向传播与参数更新
4. 预训练、Checkpoint 与基础能力形成
5. 数据规模、模型规模、计算规模与分布式训练
6. 后训练的目的和主要阶段
7. 指令学习与任务适应
8. 偏好学习与行为对齐
9. 强化学习、可验证反馈与其他路线
10. Fine-tuning、蒸馏与模型适配
11. 训练数据质量、偏差与污染
12. 训练稳定性、遗忘与能力权衡

### 本部分结束时应能回答

> 为什么基础模型、指令模型和经过不同对齐方法处理的模型，会在相同输入下表现出不同的回答倾向？

## 六部分的边界

| 部分 | 主要研究对象 | 暂时不深入的内容 |
|---|---|---|
| 基础结构与计算机制 | 五类核心结构与一次前向数据流 | 完整运行、参数更新与 Runtime 服务 |
| 单请求推理与生成 | 一条请求的固定参数生成过程 | 多请求调度、参数训练和 CoT |
| 推理 Runtime 与模型服务 | 加载、调度、缓存工程、接口与部署 | 模型能力形成和 Agent 任务循环 |
| 训练、后训练与对齐 | 参数与行为倾向的形成 | Agent 的长期学习循环 |
| 能力形成、表现与边界 | 能力来源和失败机制 | Agent 系统可靠性设计 |
| 评估、优化与模型演进 | 测量、改进、比较与发展路线 | 对 AGI 的综合判断 |

## 模型观察与证据边界

每一部分在适合时选择具体模型进行观察，但不把某个模型的配置当成所有 LLM 的统一规律。模型是否来自 OpenAI，不改变证据要求：能观察到什么，就只用它说明什么。

| 模型类型 | 适合观察什么 | 不能据此断言什么 |
|---|---|---|
| OpenAI `gpt-oss` 精确版本 | 公开权重、配置、MoE 等可检查结构以及本地运行和微调方式 | 其他闭源 GPT 模型一定采用相同内部架构 |
| OpenAI 闭源 GPT 精确版本 | 官方公开的输入输出、上下文、推理参数、工具调用和产品行为 | 未公开的参数量、Attention、FFN、MoE 或训练配方 |
| Qwen、DeepSeek、Llama 等开放权重精确版本 | 官方配置、权重结构、技术报告和实现差异 | 所有 LLM 都采用该模型的具体设计 |

OpenAI 官方资料明确把 `openai/gpt-oss-20b` 作为可加载的 Causal LM，并说明它采用 Mixture-of-Experts（MoE）架构，因此它可以进入架构与训练实现观察。闭源 GPT 的内部结构若无官方公开资料，统一记录为“未知”，不能根据回答表现反推。

OpenAI 来源：[Fine-tuning with gpt-oss and Hugging Face Transformers](https://developers.openai.com/cookbook/articles/gpt-oss/fine-tune-transfomers#prepare-the-model)，核对日期：2026-07-27。

观察材料优先来自：

1. 官方 Model Card；
2. 官方代码仓库；
3. 对应版本的配置文件；
4. 官方技术报告。

所有版本敏感信息需要标明模型全名、来源与核对日期，并区分公开事实、合理推断和未知信息。

## LLM 模块完成标准

完成六部分后，应当能够：

1. 描述从文本输入到 Token 输出的完整模型链路；
2. 区分模型机制、单请求 Inference、Runtime 服务、训练、后训练和对齐；
3. 解释主要能力如何形成以及为什么不稳定；
4. 判断一个问题来自模型、上下文、训练、解码还是评估方式；
5. 阅读开放权重模型的基础配置和 Model Card；
6. 对模型能力、成本和风险做有证据的比较；
7. 带着准确的 LLM 心智模型进入 [[02-推理与CoT/00-推理与 CoT 模块大纲|推理与 CoT]] 模块。
