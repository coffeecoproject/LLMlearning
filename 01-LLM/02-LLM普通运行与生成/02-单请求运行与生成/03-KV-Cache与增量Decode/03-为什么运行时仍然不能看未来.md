# 为什么运行时仍然不能看未来

> [!summary]
> 运行时要预测的未来 Token 还没有被决定；Causal Attention 继续保证当前位置只依赖已经存在的 Token，使运行方式与模型学到的“根据过去预测下一个 Token”目标一致。

## 最直接的原因：未来还不存在

当上下文是：

```text
我今天想吃
```

模型正在决定下一个 Token。它不能读取尚未生成的“火锅”或“面条”，因为两者还只是候选，尚未成为上下文事实。

## Prompt 已知，为什么内部位置仍不能互看未来

Prefill 时整段 Prompt 已经由用户提供，但 Decoder-only 模型仍对 Prompt 内各位置应用因果可见性：

```text
位置 1：看 1
位置 2：看 1~2
位置 3：看 1~3
```

这样每个位置的表示都符合“只根据前缀预测后续”的模型定义，也使历史 K、V 在后来加入 Token 时可以保持有效。

## 这是 Decoder-only 架构的典型特征吗

是。现代文本生成 LLM 常采用 Decoder-only Causal Transformer。这里的“Decoder-only”不是“不做 Tokenizer Encode”，也不是没有任何解码过程；它表示模型主体没有单独的 Encoder 堆叠，而使用带因果约束的 Decoder 型 Block 直接处理前缀并续写。

Encoder-decoder 模型则会先让 Encoder 双向读取完整输入，Decoder 再通过 Cross-Attention 读取 Encoder 输出，同时对自己的生成序列保持因果约束。两种结构不同，但自回归输出端仍不能读取尚未生成的未来输出。

## 如果允许看未来会怎样

训练时，当前位置可能直接偷看正确答案；运行时，这些答案又不存在。训练和运行条件将不一致，模型也无法作为正常的前缀续写器使用。

## 与 KV Cache 的关系

正因为历史位置不会被未来信息反向改写，历史 K、V 才能缓存。若每加入一个新 Token 都要改变所有旧位置状态，缓存复用就会失去这个简单基础。
