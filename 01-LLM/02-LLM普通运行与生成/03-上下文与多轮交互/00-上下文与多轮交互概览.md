# 上下文与多轮交互概览

> [!summary]
> 模型每次只能依据本次请求中实际可见的 Token 生成；多轮对话通常由外部系统保存并重新组织历史，而不是模型在参数里自动永久记住聊天内容。

## 本专题回答什么

```text
一次请求究竟能看见多少内容？
→ 上下文窗口

内容过长时谁决定删什么？
→ Truncation 与上下文管理

下一轮为什么看起来记得上一轮？
→ 外部系统重新发送相关历史

KV Cache、Prompt Cache 和长期记忆相同吗？
→ 不同层级的复用机制
```

## 计划阅读顺序

1. 上下文窗口限制的对象；
2. 输入 Token、输出 Token 与总长度；
3. Truncation 何时触发、谁执行以及可能丢失什么；
4. 多轮对话怎样重新组织历史；
5. 当前上下文、KV Cache、Prompt Cache 与长期记忆的区别。
