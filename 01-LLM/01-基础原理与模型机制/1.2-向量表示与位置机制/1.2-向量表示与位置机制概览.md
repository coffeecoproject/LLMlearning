# 1.2 向量表示与位置机制

> [!goal]
> 理解 Token ID 怎样变成 Transformer 可以计算的初始向量，以及模型为什么还需要以不同方式获得 Token 的位置信息。

## 与上一专题的连接

[[1.1-Tokenizer文本离散化系统概览|Tokenizer]] 的输出是整数编号：

```text
文本
→ Tokenizer
→ Token ID 序列
```

但 ID 只是词表中的索引。例如 ID `10001` 不表示它比 ID `10000` “语义更大”，也不能直接用编号之间的距离表达词义。因此模型还需要：

```text
Token ID
→ Embedding Lookup
→ 初始向量
→ 获得或注入位置信息
→ 进入 Transformer Block
```

> [!note]
> `10001` 只是示意 ID，不来自具体模型。

## 本专题边界

### 本专题负责

- 向量的最低必要直觉；
- Token ID 到初始向量的映射；
- Embedding 参数在训练和运行阶段的不同状态；
- 初始 Embedding 与上下文化 Hidden State 的概念边界；
- 三类位置机制的目的和作用位置。

### 本专题暂不展开

- Q、K、V 怎样计算；
- Attention Score 和 Attention Weight；
- RoPE 的旋转矩阵推导；
- ALiBi 怎样具体修改 Attention Score；
- Transformer Block 内部怎样更新 Hidden State；
- LM Head、Logits 和下一个 Token 概率；
- Embedding 检索、向量数据库和 RAG。

这些内容分别属于后续的 Attention、Transformer Block、输出机制和 Agent/RAG 工程。

## 必须保持的概念边界

```text
Token ID：词表索引
Token Embedding：查表得到的初始参数向量
Position Mechanism：让计算获得顺序或相对距离信息
Hidden State：经过模型层处理后不断变化的表示
```

- Embedding 不是 Tokenizer 的输出；Tokenizer 输出 Token ID。
- Embedding Matrix 属于 LLM 参数，不属于 Tokenizer 词表文件。
- 初始 Embedding 不等于完整、固定的“词义向量”。
- Hidden State 不等于模型永久记忆，也不等于最终答案。
- 不能把所有位置机制都讲成“位置向量加到 Token 向量上”：Absolute Position 常这样做，RoPE 作用于 Attention 的 Q/K，ALiBi 作用于 Attention Score。

## 阶段标记

- **【模型训练阶段】**：Embedding Matrix 作为模型参数被更新。
- **【模型运行阶段】**：根据 Token ID 查表，并执行前向计算，通常不更新 Embedding 参数。
- **【两阶段共同】**：模型结构、词表规模、Hidden Size 和位置机制必须与模型权重匹配。

## 完成标准

完成本专题后，应当能够：

1. 解释 Token ID 已经是数字，为什么仍不能当作语义数值使用；
2. 推演 Token ID 如何通过 Embedding Matrix 变成向量；
3. 解释 `vocab_size × hidden_size` 与 Embedding 参数量的关系；
4. 区分 Embedding 的训练更新和运行查表；
5. 区分初始 Token Embedding 与上下文化 Hidden State；
6. 说明模型没有位置信息时会缺失什么；
7. 指出 Absolute Position、RoPE、ALiBi 分别作用在哪里；
8. 带着正确输入表示进入下一专题 Causal Self-Attention。
