# 1.1.7.6 Tokenizer 专题总结

> [!summary]
> Tokenizer 用一套固定、可复现的规则，把开放文本转换为有限词表中的 Token ID 序列；这条链路在 Token ID 处结束，随后才进入 Embedding 和 Transformer。

## 完整主线

```text
原始文本
→ Normalization
→ Pre-tokenization（如果该方案需要）
→ Tokenization Model
→ Token
→ Vocabulary 查找
→ Token ID
→ 加入必要的 Special Token 与输入整理
→ 交给 Embedding
```

不同实现中，部分步骤的顺序、名称或组合方式可能不同，但核心任务相同：建立文本与有限整数集合之间的稳定映射。

## 必须分清的对象

| 名称 | 一句话理解 |
|---|---|
| Tokenizer | 完整文本离散化系统 |
| Token | Tokenizer 产生或识别的离散单位 |
| Vocabulary | Token 与 ID 的有限映射集合 |
| Token ID | 某个 Token 在特定词表中的整数编号 |
| BPE / WordPiece / Unigram | 构建词表和决定切分的方法 |
| SentencePiece / tiktoken / HF Tokenizers | 实现训练或执行流程的工具 |
| Embedding | Tokenizer 之后，把 ID 映射为向量的模型层 |

## 训练与运行再区分一次

```text
【Tokenizer 训练】
训练语料 → 学习词表与切分规则 → 保存 Tokenizer

【LLM 训练】
固定 Tokenizer → 语料变成 ID → 更新神经网络参数

【LLM 运行】
用户文本 → 同一 Tokenizer → ID → Embedding → Transformer
```

聊天时调用 Tokenizer，通常是在使用已经确定的规则，不是在重新训练 Tokenizer。

## Tokenizer 的三个核心权衡

### 1. 有限词表与开放文本

现实文本无限，词表有限，因此需要子词、字符或字节组合来处理新字符串。

### 2. 词表规模与序列长度

较大的词表能保存更多常见片段，但需要更多词表相关参数；较小单位更容易组合覆盖文本，却可能产生更长序列。

### 3. 紧凑表示与可组合性

完整长片段表示紧凑；较小片段能在新词之间复用。实际 Tokenizer 要在二者之间折中。

## Tokenizer 怎样影响后续模型

```text
切分规则
→ 决定模型接收到哪些离散位置
→ 影响序列长度和基本学习单位
→ 影响表示效率与部分学习难度
```

但 Tokenizer 不独立决定模型能力。训练数据、架构、参数、优化与后训练同样关键。

## 最重要的五条边界

1. Token 不等于单词，也不固定等于字符。
2. Token ID 不是通用编码，只在对应词表中有意义。
3. 能编码一种文本，不代表模型理解这种文本。
4. Tokenizer decode 不等于 Transformer Decoder，也不等于生成策略。
5. Tokenizer 到 Token ID 为止；ID 变向量属于 Embedding。
