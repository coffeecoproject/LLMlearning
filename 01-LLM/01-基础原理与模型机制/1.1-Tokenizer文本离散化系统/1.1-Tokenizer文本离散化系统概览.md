# Tokenizer：文本离散化系统

> [!goal]
> 理解开放世界中的文本怎样被转换成有限词表中的离散编号，以及这种转换为什么会影响模型的输入长度、计算效率和文本处理能力。

## 本专题边界

本专题研究：

```text
原始文本
→ Tokenizer
→ Token
→ Token ID
```

下一专题再研究：

```text
Token ID
→ Token Embedding
→ Transformer 可计算的向量表示
```

因此，本专题不会提前深入 Embedding、Attention、采样或参数训练。

## 学习顺序

1. [[1.1.1-Token概览|1.1.1 Token]]：先理解为什么需要 Token，以及 Token 到底是什么。
2. [[1.1.2-Vocabulary与Token ID概览|1.1.2 Vocabulary 与 Token ID]]：理解词表、Token 与整数编号之间的关系。
3. [[1.1.3-文本表示路线概览|1.1.3 文本表示路线]]：比较单词、字符、子词与字节四条路线。
4. [[1.1.4-词表构建与切分方法概览|1.1.4 词表构建与切分方法]]：理解 BPE、WordPiece 与 Unigram 的定位。
5. [[1.1.5-Tokenizer处理流程概览|1.1.5 Tokenizer 处理流程]]：串起编码与解码的完整过程。
6. [[1.1.6-工具与实现概览|1.1.6 工具与实现（可选工程观察）]]：观察 tiktoken、SentencePiece 等具体实现；不属于文本进入模型后的新增步骤。
7. [[1.1.7-影响与边界概览|1.1.7 影响与边界]]：理解 Tokenizer 对模型效率和能力边界的影响。

## 专题核心问题

```text
Tokenizer 为什么存在？
→ 它处理的 Token 是什么？
→ Vocabulary 和 Token ID 分别起什么作用？
→ 文本可以按什么基本单位表示？
→ BPE、WordPiece、Unigram 怎样构建和使用词表？
→ 一次完整的编码与解码经历哪些步骤？
→ 这些选择怎样影响实际模型？
```

## 概念层级

```text
Tokenizer（完整系统）
├── 1.1.1 处理的对象：Token
├── 1.1.2 使用的资源与输出：Vocabulary 与 Token ID
├── 1.1.3 采用的表示路线：单词 / 字符 / 子词 / 字节
├── 1.1.4 可能采用的方法：BPE / WordPiece / Unigram
├── 1.1.5 完整处理流程
├── 1.1.6 具体工具或实现
└── 1.1.7 影响与边界
```

这里最重要的纠正是：BPE、WordPiece 和 Unigram 不是 Token 的三种类型，而是构建词表和决定切分结果的不同方法。

## 本专题的讲解方式

每个知识点优先通过例子理解，再进入真实机制。例如：

```text
输入文本：“我喜欢苹果🍎”
→ 看它可能被切成哪些 Token
→ 看每个 Token 怎样映射为 Token ID
→ 换一个 Tokenizer，比较结果为什么不同
→ 再解释背后的词表、表示路线和切分方法
```

主线不依赖复杂公式。必要的数学或实现细节会放在“可选深入”部分，不影响连续阅读。

## 完成标准

完成本专题后，应当能够：

1. 解释为什么神经网络不能直接把文字字符串当作数值张量计算；
2. 说明 Token 为什么不等于单词或字符；
3. 区分 Token、Token ID、Vocabulary 与 Tokenizer；
4. 推演文本变成 Token ID 的基本流程；
5. 解释有限词表如何覆盖开放文本；
6. 比较字符级、单词级、子词级和字节级路线；
7. 区分表示路线、切分算法与具体工具；
8. 说明 Token 数量为什么影响上下文、计算量和成本；
9. 解释为什么模型与 Tokenizer 必须配套。
