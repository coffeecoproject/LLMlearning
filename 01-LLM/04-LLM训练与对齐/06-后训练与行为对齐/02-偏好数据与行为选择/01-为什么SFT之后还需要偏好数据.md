# 为什么 SFT 之后还需要偏好数据

> [!summary] 一句话理解
> SFT 主要示范“一个好回答可以长什么样”，偏好数据进一步表达“面对多个都能生成的回答时，哪个更符合目标”。

## 所属阶段

这是 **后训练阶段**。本篇比较 SFT 数据与偏好数据提供的学习信号，不讨论运行时采样参数。

## 一个问题可能有很多合理回答

用户问：

```text
请给完全不懂技术的人解释 KV Cache。
```

候选回答可能是：

```text
A：技术上基本正确，但一开始就列出大量张量与显存公式。

B：KV Cache 会保存之前 Token 已经计算出的 K、V，
   后续生成时可以复用，从而减少重复计算。

C：KV Cache 就是模型的长期记忆，所以它能永远记住用户。
```

三者不是简单的“标准答案与空白答案”：

- A 可能正确，但不符合非专业用户的学习目标；
- B 在准确性、长度和受众之间更平衡；
- C 很直白，但概念错误。

如果训练数据只提供 B，模型能模仿 B；但它没有直接看到：

```text
B 为什么优于 A
B 又为什么优于 C
```

偏好比较给出了这层相对信息。

## SFT 提供的是示范信号

SFT 常见结构：

```text
Prompt
→ Reference Response
```

`Reference Response` 就是这条 SFT 样本提供的参考回答，也就是模型在该样本中被要求模仿的目标回答。

训练会提高参考回答 Token 在对应上下文中的概率。

但一个参考回答往往同时混合了很多属性：

- 是否正确；
- 是否完整；
- 是否遵循格式；
- 是否适合受众；
- 是否简洁；
- 是否安全；
- 是否承认不确定性。

仅看这一条示范，很难明确知道其中哪些差异最重要。

## 偏好数据提供的是比较信号

偏好数据常见结构：

```text
Prompt
├── Chosen：回答 B
└── Rejected：回答 A 或 C
```

它告诉训练系统：

```text
在相同 Prompt 下
→ 更希望 B，而不是另一个候选
```

这是一种相对判断，不要求先给每个回答定义绝对满分答案。

这一整组“同一个 Prompt、Chosen 和 Rejected”也叫一个 **偏好对（Preference Pair）**。

## 为什么比较有时比重新写标准答案容易

面对两个回答，人常常能较快判断：

```text
哪个更准确？
哪个遗漏更少？
哪个更符合用户要求？
```

但让标注者从空白开始写出一个覆盖所有细节的完美答案，通常更慢，也更依赖写作能力。

比较并不天然正确，但它降低了部分数据制作难度，并能利用模型自己生成的候选暴露真实错误模式。

## 偏好数据不是为了替代 SFT

常见顺序是：

```text
Base Model
→ SFT 建立基本助手行为
→ 用当前或相关模型生成候选回答
→ 收集偏好比较
→ 继续进行偏好优化
```

没有基础 SFT 时，候选可能大量偏离助手格式，比较数据会浪费在非常初级的差异上。

所以两者更像分工：

```text
SFT：先把模型带到“基本会回答”的区域
偏好优化：再改善这些可生成回答之间的选择倾向
```

## 偏好不只是在选文风

偏好标准可以包括：

- 事实正确性；
- 指令遵循；
- 推理与答案一致；
- 信息是否完整；
- 安全与合规；
- 是否避免无根据断言；
- 是否正确使用工具结果；
- 长度和表达方式。

但只有比较者能够可靠判断并且标准明确时，这些维度才会形成高质量信号。

## 常见误解

### SFT 已经给了正确答案，所以偏好数据只是重复

不是。SFT 提供一个目标序列，偏好数据突出多个候选之间的相对优先关系。

### Rejected 一定是完全错误的回答

不一定。它可能正确但冗长，也可能只遗漏一个关键条件。

### Chosen 是永远正确的标准答案

不是。它只是在当时的候选、标准和标注者判断中更受偏好。

### 有了偏好数据就不再需要高质量 SFT

不对。偏好优化通常建立在已经具有基本指令行为的模型之上。

1. SFT 与偏好数据分别提供什么不同信号？
2. 为什么“正确但不适合受众”的回答可能成为 Rejected？
3. 为什么 Chosen 不等于客观完美答案？
