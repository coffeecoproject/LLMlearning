# 偏好数据与行为选择概览

> [!summary]
> 偏好数据不只给模型看一个参考答案，而是比较同一问题下的多个候选回答，用“哪个更好”的相对信号继续塑造模型的回答倾向。

## 所属阶段

本专题属于 **后训练阶段**，重点是偏好数据本身怎样表达行为选择。

偏好数据怎样被训练方法转换成参数更新，将在后续专题分别学习；本专题不提前展开强化学习公式。

## 核心名词先认识

这一小节反复使用的名称不多，先建立最小认识即可：

| 名称 | 直白理解 |
|---|---|
| 偏好（Preference） | 面对多个候选时，按给定标准更希望哪一个出现 |
| 偏好数据（Preference Data） | 记录“哪个候选相对更好”的训练数据 |
| Prompt | 候选回答共同面对的输入条件，可以是一条问题，也可以包含多轮对话 |
| 候选回答（Candidate Response） | 模型针对同一个 Prompt 生成、等待比较的回答 |
| Chosen | 本次比较中相对更受偏好的候选 |
| Rejected | 本次比较中相对较差的候选，不一定完全错误 |
| 偏好对（Preference Pair） | 同一个 Prompt 加上一组 Chosen 与 Rejected |
| 偏好标签（Preference Label） | 记录哪个候选胜出、是否平局或无法判断 |
| 元数据（Metadata） | 来源、模型版本、比较标准、置信度等附加说明 |
| 偏好优化（Preference Optimization） | 利用偏好数据继续训练模型，使目标行为更容易出现 |

> [!note]
> `Chosen` 与 `Rejected` 是数据中的角色标签，不是两种 Token，也不是模型运行时的固定按钮。

后面还会看到四个训练名称。本专题先认清它们的位置，不要求掌握算法：

- **SFT**：Supervised Fine-Tuning，监督微调；让模型模仿参考回答；
- **Reward Model**：奖励模型；学习预测哪种回答更符合偏好；
- **RLHF**：Reinforcement Learning from Human Feedback，基于人类反馈的强化学习；
- **DPO**：Direct Preference Optimization，直接偏好优化；直接利用偏好对训练语言模型的一类方法。

## 一条主线

```text
同一个 Prompt
→ 生成多个候选回答
→ 按明确标准比较
→ 得到 Chosen / Rejected 或排序
→ 训练方法把比较结果变成参数更新信号
→ 模型更倾向生成被偏好的行为
```

这里要把三层分开：

```text
偏好数据：记录哪个候选更受偏好
训练算法：决定怎样利用这个比较结果更新参数
运行生成：模型仍然逐 Token 计算 Logits 并生成回答
```

## 从 SFT 接过来的问题

SFT 样本通常表示：

```text
Prompt → 一个理想回答
```

偏好样本则表示：

```text
同一个 Prompt
├── 回答 A：较好
└── 回答 B：较差
```

它补充的不是“更多 Token”这么简单，而是候选之间的相对选择信息。

## 本专题边界

- 偏好不等于客观事实；
- `Chosen` 只表示在给定标准与候选集合中更受偏好，不表示完美；
- `Rejected` 不一定完全错误，也可能只是稍差；
- 偏好数据需要经过训练方法才能影响 Weight；
- 普通用户点赞通常不会让当前模型立即在线更新参数；
- 运行时仍需要工具、规则与验证系统保证现实任务结果。

## 学完后的理解标准

应当能够回答：

1. 为什么一个高质量参考答案仍不能完整表达回答偏好？
2. `Chosen` 和 `Rejected` 是 Token、分数，还是候选回答？
3. 谁可以提供偏好标签，各自可能错在哪里？
4. 为什么偏好训练完成后，运行时仍然是逐 Token 生成？
5. 为什么“更受偏好”不等于“事实一定正确”？
