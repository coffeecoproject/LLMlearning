# 人类、模型与验证器分别能提供什么偏好

> [!summary] 一句话理解
> 人类擅长判断需求、表达与价值取舍，模型评审擅长扩大规模，验证器擅长检查有明确答案的结果；三者都不是万能裁判，可靠偏好数据需要按任务组合并保留来源。

## 所属阶段

这是 **后训练数据构造阶段**。本篇讨论谁产生反馈，不把反馈来源与具体训练算法绑定。

## 人类反馈

**Human Feedback（人类反馈）**是由人类阅读候选后给出的比较、评分或修改意见。

人类比较者可以判断：

- 回答是否真正回应了需求；
- 解释是否适合目标受众；
- 哪些遗漏在业务上重要；
- 语气是否合适；
- 两个都正确的答案哪个更有帮助；
- 某些价值、安全和社会影响问题。

但人类也可能：

- 缺少专业知识；
- 被流畅表达误导；
- 更偏好长回答或自信回答；
- 对同一标准理解不同；
- 疲劳后降低一致性；
- 代表特定群体，而不是所有人的价值。

所以“Human Feedback”并不等于没有偏差的普遍人类意志。

## 模型反馈

**模型评审（Model Judge）**是让另一个模型暂时充当比较者，按给定标准判断哪个候选更好。它属于数据构造工具，不等于模型已经自动学会了这些判断。

可以让另一个模型按照 Rubric 比较候选：

```text
请比较 A 和 B：
1. 是否遵循指令；
2. 是否存在事实错误；
3. 是否遗漏关键风险；
4. 给出选择与理由。
```

优势：

- 成本较低且速度快；
- 可以覆盖大量候选；
- 格式较统一；
- 容易重新运行不同标准；
- 可用于预筛选后再交给人工。

局限：

- 评审模型也会幻觉；
- 可能偏好与自己相似的表达；
- 可能过度奖励长度、格式和表面推理；
- 对高难专业问题未必有判断能力；
- 如果生成模型和评审模型共享缺陷，错误可能被共同忽略。

模型评审扩大的是判断规模，不自动提高判断真实性。

## 程序验证器反馈

**Verifier（验证器）**是按照明确规则检查结果的程序，例如运行测试、核对标准答案或验证 JSON 格式。

有些任务存在明确可检查结果：

```text
数学答案是否等于标准答案
代码是否通过测试
JSON 是否符合 Schema
SQL 是否产生预期结果
工具调用参数是否合法
证明是否通过形式化检查器
```

验证器的优势：

- 对明确规则可重复；
- 不受语言流畅度迷惑；
- 相同输入通常得到相同结果；
- 可以自动产生大量结果反馈。

局限：

- 只能检查被写进规则的部分；
- 测试通过不等于没有隐藏缺陷；
- 不能轻易判断解释是否对用户有帮助；
- 错误测试或错误标准答案会产生错误信号；
- 现实业务价值往往无法压缩成一个自动分数。

## 用户在线反馈

产品中的点赞、点踩、重新生成和编辑行为也可能成为数据来源，但需要谨慎解释：

```text
用户点踩
```

可能表示：

- 答案错误；
- 太长；
- 风格不喜欢；
- 用户问题本身表达错了；
- 工具结果不符合预期；
- 用户只是误触。

因此在线行为通常需要清洗、聚合、隐私处理和原因分类。

而且：

```text
用户点了一次赞
≠ 当前模型立刻更新 Weight
```

它通常先进入数据管线，经过筛选、训练与评估后，才可能影响未来模型版本。

## 为什么需要混合反馈

以代码任务为例：

```text
验证器：测试是否通过、格式是否有效
模型评审：代码是否可能遗漏影响面
人工专家：方案是否符合业务与架构意图
```

更可靠的流程不是让一种裁判包办所有维度，而是按能力分工。

## 来源与权重为什么必须保留

一条偏好至少应区分：

```text
来源：人工 / 模型 / 程序验证器 / 用户行为
标准：正确性 / 帮助性 / 安全性 / 格式
版本：哪个模型、哪个验证器、哪套规则
置信：一致、分歧或无法判断
```

否则训练后出现过度拒绝、偏长或事实退化时，很难追溯是哪个信号造成的。

## 公开研究观察

InstructGPT 使用人工标注者对模型输出排序。Anthropic 的 Helpful and Harmless 研究同样使用偏好建模与 RLHF，并讨论了帮助性、安全性以及训练目标之间的关系。

## 常见误解

### 人工偏好就是客观事实

不是。人工判断需要 Rubric、培训、复核和领域能力。

### 模型评审规模大，所以一定更可靠

不成立。它可能大规模复制同一种偏差。

### 程序验证器通过就代表回答整体最好

不一定。它只能证明规定的可验证部分。

### 用户点赞会让模型实时自我学习

通常不会。数据收集、训练与线上推理是不同阶段。

## 理解检查

1. 为什么人类适合判断“是否对用户有帮助”，却不一定能判断高难代码是否正确？
2. 模型评审最大的规模优势与共同缺陷风险分别是什么？
3. 为什么测试通过只能提供局部偏好信号？
4. 为什么必须记录反馈来源和规则版本？
