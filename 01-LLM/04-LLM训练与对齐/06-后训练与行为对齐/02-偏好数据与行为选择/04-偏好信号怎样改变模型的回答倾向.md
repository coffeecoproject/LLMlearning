# 偏好信号怎样改变模型的回答倾向

> [!summary] 一句话理解
> Chosen 与 Rejected 本身只是比较记录；训练方法需要把它转换成 Loss 或 Reward 信号，经过 Backward 与 Optimizer 更新参数后，模型才会在相似上下文中更倾向于生成被偏好的回答。

## 所属阶段

本篇连接 **偏好数据构造阶段** 与 **偏好训练阶段**，只建立机制地图。下面出现的 Reward Model、RLHF、PPO 和 DPO 只需先知道各自位于哪一步，不要求理解公式与工程实现。

## 偏好标签不会自动进入 Weight

一条数据：

```text
Prompt：一句话解释 Embedding。
Chosen：Embedding 是把离散 Token 映射成连续向量表示的参数化过程。
Rejected：Embedding 就是给每个词随便分配几个数字。
```

保存这条记录并不会立即改变模型。

仍然需要：

```text
读取许多偏好样本
→ 训练目标计算偏差
→ Backward 产生 Gradient
→ Optimizer 更新 Weight
```

它与前面学习的参数更新主线相同，区别在于 Loss 不再只是模仿一个参考回答的下一 Token。

## 两条主要利用路线

### 路线一：先训练 Reward Model，再做 RLHF

**Reward Model（奖励模型）**学习预测一个回答有多符合偏好；**RLHF（基于人类反馈的强化学习）**再利用这种奖励信号继续训练语言模型。

这里的 **Reward（奖励）**不是金钱，而是训练系统用来表示“这个结果有多符合目标”的数值信号。

```text
偏好对
→ Reward Model 学习给回答评分
→ 语言模型生成回答
→ Reward Model 提供奖励信号
→ 强化学习更新语言模型
```

Reward Model 相当于先学习一个“偏好评分器”。具体怎样训练和使用，留到后续专题。

### 路线二：直接使用偏好对

**DPO（Direct Preference Optimization，直接偏好优化）**不先训练一个独立评分器，而是直接利用 Chosen 与 Rejected 的相对关系更新语言模型。

```text
Prompt + Chosen + Rejected
→ DPO 等训练目标直接比较两条回答
→ 更新语言模型参数
```

DPO 不要求先训练一个独立 Reward Model，但仍然需要一个明确的训练目标、Forward、Loss、Backward 与参数更新。

在标准 RLHF 路线中经常出现的 **PPO**，只需要暂时理解为“一种利用奖励更新模型的方法”；它的具体计算不属于本小节。

两条路线共同的目标是：

```text
提高相对更受偏好回答的生成倾向
降低相对较差回答的生成倾向
```

它们怎样限制模型偏移、怎样计算 Loss，并不相同。

## 一个不使用公式的数字示例

以下数字只是说明趋势，不是真实模型的完整计算。这里的“相对倾向”不是数据库中的固定评分，而是模型在相同上下文下生成这些回答的相对可能性。

训练前，在某类 Prompt 下：

```text
回答 A：正确、简洁                    相对倾向 0.30
回答 B：正确但冗长                    相对倾向 0.35
回答 C：流畅但存在关键事实错误          相对倾向 0.35
```

偏好数据反复表示：

```text
A > B
A > C
```

经过许多参数更新后，可能变成：

```text
回答 A 的生成倾向提高
回答 B、C 的相对生成倾向降低
```

模型并不是把三个完整答案存入一张选择表，而是参数变化影响了回答中许多 Token 条件概率，最后改变整条序列出现的相对可能性。

## 为什么是相对倾向，而不是硬规则

偏好训练不会安装：

```text
if Prompt == X:
    return Chosen
```

模型仍会受到以下因素影响：

- 当前 Prompt 的措辞；
- System Instruction；
- 对话上下文；
- 生成温度与采样；
- 模型没有见过的新组合；
- 多个偏好目标之间的冲突。

因此训练后通常是“更可能”出现目标行为，不是绝对执行。

## 运行阶段发生了什么

训练完成后，偏好影响主要已经进入新模型版本的 Weight。

普通运行时仍然是：

```text
Prompt Token IDs
→ Transformer Forward
→ Logits
→ 生成下一个 Token
→ 循环
```

Runtime 通常不会在每生成一个 Token 时重新拿训练集中的 Chosen 与 Rejected 做比较。

所以：

```text
偏好训练改变 Weight
≠ 运行时增加一个固定答案数据库
≠ Runtime 每轮自动调用 Reward Model
```

产品可以额外部署在线评分器或验证器，但那是另一种系统设计，不是偏好训练的必然组成。

## 为什么不能只把 Rejected 从训练数据删除

如果只保留 Chosen 做 SFT，模型会看到“应该模仿什么”；保留比较关系还能表达：

```text
模型当前容易生成的另一个回答
为什么相对不希望它出现
```

两者提供的训练约束不同。但偏好优化不一定总胜过额外 SFT，仍需要通过评估确认。

## 常见误解

### Chosen 会作为完整答案直接写进一个参数位置

不是。它通过许多 Token、Loss、Gradient 和共享参数产生分散影响。

### 偏好训练后，Runtime 每一步都必须调用 Reward Model

不一定。完成训练的模型可以独立运行；是否增加在线评分器取决于产品架构。

### DPO 不需要训练

错误。它不需要标准 RLHF 的独立 Reward Model 和在线强化学习流程，不等于不执行参数训练。

### 偏好优化会让模型永远选择 Chosen

不会。它改变的是分布与行为倾向。
