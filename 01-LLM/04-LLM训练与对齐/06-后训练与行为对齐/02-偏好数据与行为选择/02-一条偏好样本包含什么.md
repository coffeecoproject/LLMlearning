# 一条偏好样本包含什么

> [!summary] 一句话理解
> 一条最常见的偏好样本包含同一个 Prompt、一个相对更受偏好的 Chosen 回答和一个相对较差的 Rejected 回答，必要时还带有比较标准、来源与置信信息。

## 所属阶段

这是 **后训练的数据构造阶段**。此时首先组织文本或 Messages；真正训练前，配套 Tokenizer 才会把它们编码成 Token IDs。

## 最小结构

教学化表示：

```json
{
  "prompt": "用一句话解释 Token。",
  "chosen": "Token 是模型处理文本等信息时使用的基本离散单位。",
  "rejected": "Token 就是一个汉字。"
}
```

三个核心字段是：

| 字段 | 表示什么 |
|---|---|
| `prompt` | 两个候选共同面对的输入条件 |
| `chosen` | 按当前比较标准相对更好的候选 |
| `rejected` | 在这次比较中相对较差的候选 |

这里的字段名只是常见教学表达。真实数据集可能使用 `input`、`response_0`、`response_1`、`winner` 或其他结构。

## Prompt 不一定只有一句 User 消息

真实 Prompt 可能包含：

```text
System Instruction
+ 多轮历史
+ 当前 User 请求
+ 工具定义
+ 已返回的 Tool Result
```

因此更一般的偏好样本可能是：

```text
共同上下文 Messages
├── Candidate Response A
└── Candidate Response B
```

比较必须建立在相同上下文上，否则无法确定差异来自回答质量还是输入不同。

这里的 `Candidate Response` 就是“候选回答”：它还没有被认定为好或坏，只是等待比较的一个模型输出。

## Chosen 和 Rejected 是候选回答，不是 Token 类型

`Chosen` 不是一种 Special Token，`Rejected` 也不是一个 Token ID。

它们通常是两段完整候选回答。训练准备阶段会分别经过：

```text
Chat Template
→ Tokenizer
→ Chosen Sequence Token IDs

Chat Template
→ Tokenizer
→ Rejected Sequence Token IDs
```

之后训练算法才比较两条序列在同一 Prompt 下的相对倾向。

## 为什么需要完全相同的 Prompt

假设：

```text
回答 A 面对：“只用一句话解释。”
回答 B 面对：“请详细解释。”
```

这时 A 更短、B 更长，并不能说明哪一个更好，因为两者遵循的是不同要求。

标准偏好对通常固定 Prompt，只改变候选回答。

## 除了三个字段，还可能记录什么

高质量数据通常还需要元数据（Metadata）。元数据不是回答正文，而是帮助理解、筛选和追溯这条样本的附加信息，例如：

```text
比较标准：正确性、帮助性、简洁性、安全性
候选来源：哪个模型或模型版本
生成设置：温度、最大长度等
标注来源：人工、模型评审或验证器
标注者一致性：是否多人同意
置信度：高、中、低
是否平局：两个回答是否难以区分
拒绝原因：事实错误、遗漏、过长、违规等
数据版本：这条记录属于哪批构造流程
```

这些内容不一定全部直接进入训练，但对过滤、审计和分析错误非常重要。

## 两两比较、排序和打分有什么区别

### 两两比较

```text
A > B
```

只回答两个候选谁更好。

### 多候选排序

```text
C > A > B > D
```

一次对多个候选排序，之后可以按训练配方转换成若干对。

### 独立打分

```text
A：4分
B：2分
```

每个候选单独评分。不同标注者对“4 分”的尺度可能不同，因此相对比较有时更稳定，但也并非总是如此。

## 一个更细的示例

Prompt：

```text
用户：上下文不超过窗口，模型就一定能利用所有信息吗？
```

Chosen：

```text
不一定。窗口表示信息可以进入计算，Attention 提供关联机制，
但模型仍可能因为干扰、位置和任务难度没有正确利用关键信息。
```

Rejected：

```text
一定可以，只要没有超过窗口，模型就能完整记住并准确使用。
```

偏好理由：

```text
Chosen 区分了“进入窗口”和“正确利用”；
Rejected 把容量误解成能力保证。
```

## 一个 Prompt 可以拥有多条偏好对

假设候选排序为：

```text
C > A > B
```

可以形成：

```text
C > A
C > B
A > B
```

但这些派生偏好对高度相关，不能简单把它们误认为三条完全独立的新知识。数据划分时也要避免同一 Prompt 的近重复进入训练集和评估集两边。

## 常见误解

### Chosen 和 Rejected 会一起放进模型的运行时上下文

普通运行时不会。它们是训练样本的两个分支，不是每次用户对话都携带的示例。

### Rejected 越差越好

不一定。明显胡言乱语很容易比较，却未必能教会模型区分两个高质量回答之间的细微差别。

### 给出一个数值评分就一定比两两比较精确

不一定。评分尺度可能因标注者而异，也可能制造虚假的精度感。
