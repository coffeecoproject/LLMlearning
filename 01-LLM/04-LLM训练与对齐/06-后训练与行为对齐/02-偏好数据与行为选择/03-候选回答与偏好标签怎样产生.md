# 候选回答与偏好标签怎样产生

> [!summary] 一句话理解
> 偏好数据通常先让模型对同一个 Prompt 生成多个有差异的候选，再让人工、模型评审或验证器按照明确标准比较，并对分歧与低质量样本进行复核和过滤。

## 所属阶段

这是 **离线的后训练数据构造阶段**。“离线”表示先集中构造数据和训练新模型版本；“在线”表示模型已经部署，正在响应真实用户。这里虽然会运行模型生成候选，但不是普通用户请求的在线生成，也还没有进入偏好参数更新。

## 完整数据构造流程

```text
收集 Prompt
→ 固定共同上下文
→ 生成多个候选回答
→ 按标准进行比较
→ 处理平局和分歧
→ 质量过滤
→ 保存偏好样本及来源
```

## 第一步：选择 Prompt

Prompt 可能来自：

- 人工编写的任务；
- 经过隐私与安全处理的真实请求分布；
- 专门设计的边界案例；
- 旧模型经常失败的任务；
- 数学、代码等可以验证的题目；
- 多轮、工具调用或安全场景。

如果 Prompt 分布过窄，模型可能只在那一类问题上表现出偏好改善。

## 第二步：生成有差异的候选

可以让同一个模型多次采样，也可以使用不同模型或不同模型版本产生候选。

```text
同一个 Prompt
├── 候选 A：模型采样 1
├── 候选 B：模型采样 2
├── 候选 C：另一模型生成
└── 候选 D：人工回答
```

为什么不只使用最高概率回答？

因为数据构造需要看到模型可能走向的不同路径，包括：

- 正确但冗长；
- 简洁但遗漏；
- 格式正确但事实错误；
- 推理过程完整但最终计算错误；
- 内容正确但违反用户明确要求。

候选过于相同，比较信号很弱；候选差异过于明显，又只能教会非常初级的选择。

## 第三步：按统一标准比较

标注者是负责比较候选并给出偏好标签的人或系统。它不能只凭“我喜欢哪个”随意选择，而需要使用 Rubric（比较准则），例如依次检查：

```text
1. 是否遵循用户明确要求？
2. 是否存在事实或逻辑错误？
3. 是否遗漏关键条件？
4. 是否包含无根据的断言？
5. 表达是否适合目标受众？
6. 是否存在安全问题？
```

不同维度可能冲突：

```text
A 更完整，但很冗长
B 更简洁，但遗漏一个边界
```

因此准则还需要说明哪个维度优先，或者允许标记“无法判断”。

## 第四步：处理平局与分歧

真实比较并不总有清晰赢家：

```text
标注者 1：A 更好
标注者 2：B 更好
标注者 3：两者接近
```

可采用的处理方式包括：

- 多人复核；
- 保留平局标签；
- 计算一致性；
- 丢弃低置信样本；
- 按具体维度分别标注；
- 交给领域专家判断。

强行把所有比较压成明确胜负，会把不确定性伪装成确定标签。

## 第五步：质量过滤与数据划分

需要检查：

- Prompt 与候选是否对应；
- 两个候选是否意外完全相同；
- Chosen 是否包含隐蔽事实错误；
- 比较理由是否与标签一致；
- 是否含个人敏感信息；
- 是否与评估集重复；
- 同一 Prompt 的派生 Pair 是否跨越训练和评估划分。

偏好标签本身也是训练数据，不是天然可信的真理。

## 一个完整例子

Prompt：

```text
只用两点说明 BPE 为什么存在。
```

候选 A：

```text
1. 在固定词表下组合出未完整收录的词。
2. 在字符粒度和整词粒度之间折中序列长度与覆盖能力。
```

候选 B：

```text
BPE 是一种压缩算法。它非常复杂，最早用于数据压缩……
```

比较结果：

```text
Chosen：A
Rejected：B
理由：A 遵循“两点”要求并解释了 Tokenizer 场景；B 偏离问题且过长。
```

这里的偏好同时包含指令遵循和内容相关性，而不只是语言风格。

## InstructGPT 的公开流程

InstructGPT 先使用人工示范进行 SFT，再针对 Prompt 采样多个模型输出，让标注者对这些输出进行排序；排序数据随后用于训练 Reward Model，并继续进行 RLHF。

这说明偏好数据构造本身就包含一次模型运行：

```text
模型生成候选
≠ 模型已经接受偏好训练
```

生成候选只是收集训练材料的一步。

> [!source]
> 来源：[Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)，Ouyang 等，2022。核对日期：2026-07-29。

## 常见误解

### 人工比较就一定没有偏差

不对。标注者可能受文化、领域知识、回答长度和措辞影响。

### 使用模型生成候选属于模型自我学习

不准确。候选只有经过比较、构造成数据并实际执行参数更新后，才可能影响新模型版本。

### 所有偏好对都应该有巨大质量差距

不对。接近的高质量候选能提供细微选择信号，但也更容易产生标注分歧。

## 理解检查

1. 为什么候选既不能完全相同，也不应全部是“好答案对胡言乱语”？
2. Rubric 为什么会影响最终训练出来的行为？
3. 为什么平局和分歧不能被简单忽略？
4. 候选生成为什么仍属于数据构造，而不是偏好训练本身？
