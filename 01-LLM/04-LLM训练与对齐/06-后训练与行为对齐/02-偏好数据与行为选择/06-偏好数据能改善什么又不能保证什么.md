# 偏好数据能改善什么，又不能保证什么

> [!summary] 一句话理解
> 偏好数据能让模型更常选择符合比较标准的回答，但效果受候选、标注者、规则和任务分布限制，不能把相对偏好自动变成事实真理、普遍价值或现实完成证明。

## 所属阶段

这是 **偏好数据小节的边界与串联复习**。后续还会学习 Reward Model、RLHF、DPO，以及使用可验证结果作为奖励的 RLVR。这里先知道它们都是利用反馈继续训练模型的不同路线，不要求记忆英文全称或算法过程。

## 偏好数据可以改善什么

### 候选之间的细微选择

例如让模型更倾向：

- 回答完整但不过度展开；
- 遵循用户指定格式；
- 说明必要边界；
- 避免重复和无关铺垫；
- 在信息不足时承认不确定；
- 正确使用 Tool Result；
- 避免明显危险或有害行为。

### 模型真实错误分布

候选由当前模型生成时，偏好数据可以直接覆盖模型常犯的错误：

```text
模型经常生成什么
→ 哪些生成虽然流畅但不受希望
→ 应当把倾向推向哪里
```

这比只让人工凭空写理想答案更贴近模型实际输出分布。

### 难以写成单一标准答案的任务

摘要、解释、对话帮助性等任务可能没有唯一字符串答案。偏好比较允许在多个合理候选中选择相对更好的一个。

## 为什么偏好不等于事实

标注者可能更喜欢一个表达自信、结构漂亮的回答，即使其中隐藏了事实错误。

```text
更容易被喜欢
≠ 更接近真实世界
```

事实问题仍需要：

- 权威资料；
- 检索或数据库；
- 计算与工具；
- 领域专家；
- 独立验证。

## 为什么偏好不等于普遍人类价值

偏好标签来自特定：

```text
标注人群
+ 训练说明
+ 产品目标
+ 文化背景
+ 时间与环境
```

它表达的是这些条件下的选择，不应被描述成所有人的统一价值。

InstructGPT 论文也明确将其行为对齐限定为特定标注者和研究者所表达的偏好，而不是一个抽象、完整的“人类价值”定义。

## 常见的数据偏差

### 长度偏差

标注者可能更容易认为长回答更认真，导致模型越来越冗长。

### 表面风格偏差

标题、列表和自信语气可能掩盖内容错误。

### 位置偏差

如果候选展示顺序没有随机化，比较者可能偏向先看到或后看到的回答。

### 难度偏差

简单问题容易积累大量高一致性标签，高难专业问题却数量少、分歧大。

### 候选覆盖偏差

如果所有候选都遗漏同一个关键事实，选出其中较好的一个也无法补回这个事实。

## 为什么可能出现过度对齐

如果训练信号反复奖励谨慎和拒绝，模型可能对正常请求也过度拒绝。

如果反复奖励简洁，模型可能在复杂问题上过早结束。

如果反复奖励完整，模型可能对简单问题输出过长答案。

因此对齐目标之间需要平衡：

```text
帮助性
真实性
安全性
简洁性
完整性
能力保持
```

## 偏好优化仍然不能保证 Agent 任务完成

一个代码模型可能更倾向输出：

```text
我已经运行测试并确认修改正确。
```

偏好训练可以减少无根据的完成声明，却不能证明测试真的执行了。

现实闭环仍需要：

```text
Agent调用工具
→ 获取真实结果
→ 程序检查退出状态与产物
→ 验收系统绑定代码版本和证据
```

模型行为训练与外部系统保证仍是两层。

## 怎样评估偏好数据是否有效

不能只看训练 Loss，还应比较：

1. 人工或独立评审对新回答的胜率；
2. 事实正确性是否保持或提高；
3. 指令与格式遵循；
4. 是否出现过度拒绝；
5. 回答长度是否异常变化；
6. 数学、代码、多语言等基础能力是否退化；
7. 未见 Prompt 和真实用户分布上的表现；
8. 不同人群与不同评审器是否得到相似结论。

如果只用训练数据的同一种评审器做评估，可能只是测到模型更会迎合该评审器。

## 常见误解

### 偏好胜率提高等于事实正确率提高

不一定。两者需要分别评估。

### Chosen 数据全部来自人类，所以代表全体人类价值

不成立。偏好受标注群体、规则和场景影响。

### 使用自动验证器就能消除所有偏差

不能。验证器只覆盖可形式化检查的部分。

### 偏好训练可以替代 Agent 验收系统

不能。模型倾向与现实执行证据是不同层。
