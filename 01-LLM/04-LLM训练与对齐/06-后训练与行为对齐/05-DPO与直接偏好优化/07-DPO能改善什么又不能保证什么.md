# DPO 能改善什么，又不能保证什么

> [!summary] 一句话理解
> DPO 能让模型更倾向生成偏好数据中被选中的行为模式，但它继承候选、标签和数据覆盖的全部局限，不能把相对偏好自动变成事实正确或现实完成证明。

## DPO 可能改善什么

当偏好数据可靠且覆盖充分时，DPO 可能改善：

- 指令遵循；
- 简洁与完整的平衡；
- 回答相关性；
- 拒绝与安全行为；
- 格式遵循；
- 对不确定性的表达；
- 特定产品所需的语气和风格。

它能直接利用模型常见的错误候选，告诉训练系统：

```text
不是只模仿什么
还要区分什么相对不希望出现
```

## Chosen 仍然只是相对更好

如果两个候选都错：

```text
Chosen：遗漏一个重要条件
Rejected：核心结论完全错误
```

DPO 可以学习偏向 Chosen，但不能自动补回被两者共同遗漏的正确内容。

```text
Chosen > Rejected
≠ Chosen = 正确答案
```

## 固定数据限制了模型能看到什么

原始离线 DPO 训练时读取预先收集的偏好对。Policy 更新后可能产生新的：

- 表达方式；
- 错误模式；
- Reward 取巧行为；
- 长度和格式偏差；
- 专业领域问题。

如果这些没有出现在固定数据里，DPO 不会自动获得新的比较标签。这是它相对 On-policy Rollout 路线的重要边界。

可以定期用新 Policy 生成候选、重新标注并开始下一轮数据训练，但那已经是更完整的数据迭代系统，不是单次离线 DPO 自动完成的。

## 数据偏差会进入 Policy

如果标注者总偏好长回答，DPO 可能让模型更冗长；如果总偏好自信语气，模型可能减少合理的不确定说明。

常见风险包括：

- 长度偏差；
- 表面格式偏差；
- 特定语言或人群偏差；
- 过度拒绝；
- 迎合用户；
- 多样性下降；
- 对 Reference 原有能力的损伤。

DPO 省略 Reward Model，并没有省略偏好本身的偏差。

## 为什么还可能过度优化

大量重复或单一标准的偏好对，可能让 Policy 过度放大某种行为：

```text
反复奖励简洁
→ 复杂问题中过早结束

反复奖励完整
→ 简单问题也过度展开

反复奖励谨慎
→ 正常请求也拒绝
```

Reference 和 Beta 能限制偏移，但不能替代数据平衡与独立评估。

## DPO 不会使模型变成确定性系统

训练后的模型仍根据 Logits 和生成参数逐 Token 输出。DPO 只改变概率分布：

```text
目标行为更可能出现
不等于每次必然出现
```

Temperature、上下文措辞、System Instruction 和未见任务仍会影响结果。

## 对 Agent 设计意味着什么

DPO 可以训练模型更倾向：

- 选择正确的工具调用格式；
- 遵循执行约束；
- 根据工具结果而不是凭空回答；
- 在失败后提出合理修正；
- 避免无依据宣布完成。

但偏好数据只能塑造行为倾向。可靠 Agent 仍需要：

```text
工具真实执行
→ 保存状态
→ 测试与验证
→ 对照验收条件
→ 失败则继续处理
```

如果 Chosen 只写着“测试通过”，却没有真实测试证据，DPO 仍可能学会复述这个错误模式。

## 应怎样评估 DPO

不能只看训练 Loss，应分开检查：

1. 未见偏好对上的人类胜率；
2. 与独立 Judge 的一致性；
3. 事实、数学和代码正确率；
4. 指令与格式遵循；
5. 回答长度和多样性；
6. 过度拒绝、迎合和套话；
7. 不同语言、领域和人群表现；
8. 相对 SFT 起点是否出现能力退化；
9. 新 Policy 输出分布上的表现。

## 从 DPO 进入下一步

DPO 使用“哪个候选更好”的比较信号。某些任务则可以获得更硬的结果证据：

```text
数学答案是否正确
代码测试是否通过
格式是否可解析
环境目标是否达成
```

## 常见误解

### 没有 Reward Model 就没有 Reward Hacking 或偏差

错误。Policy 仍可能利用偏好数据中的表面规律，偏差只是从评分器转移到了数据与目标。

### DPO 可以把相对较好的答案自动修正为正确答案

不能。它只利用提供的比较关系更新倾向。

### DPO 后 Agent 不需要测试

错误。偏好训练不能证明外部操作真实成功。
