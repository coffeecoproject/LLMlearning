# RLVR 能改善什么，又不能保证什么

> [!summary] 一句话理解
> RLVR 能在具有可靠 Verifier 的任务上强化成功轨迹，却不能自动把局部可验证能力扩展成所有领域的正确推理，也不能消除验证漏洞、数据污染和现实环境风险。

## RLVR 可能改善什么

当任务、Verifier 和策略训练设计合理时，RLVR 可能改善：

- 数学与逻辑问题的最终正确率；
- 代码生成与测试通过率；
- 结构化输出与约束遵循；
- 反思、检查和重新尝试的倾向；
- 在长推理中维持目标；
- 工具环境中的任务成功率；
- 对新解法的探索能力。

它的优势是训练信号更接近可检查结果，而不是只判断回答看起来是否令人满意。

## 它不能保证所有推理步骤正确

结果奖励通常只检查最终答案。模型可能通过：

- 错误步骤相互抵消；
- 猜测；
- 记忆相似题；
- 利用数据捷径；
- 利用 Verifier 漏洞。

得到正确结果。

因此高通过率需要配合新题、对抗样本、过程分析和防污染检查。

## 它不能自动迁移到开放领域

数学和代码中容易获得明确验证，但这些能力是否迁移到：

- 商业判断；
- 医疗建议；
- 开放事实研究；
- 人际沟通；
- 长期战略规划；

不能只凭数学基准提升来断言。

模型可能学到部分通用行为，例如分解和复查，但迁移程度必须单独评估。

## Sparse Reward 为什么是难题

如果一条很长的推理结束后只得到：

```text
正确 = 1
错误 = 0
```

模型不知道前面几十个步骤中哪个最关键。大量候选全错时，训练也缺少差异信号。

常见缓解方向包括：

- 适当难度的 Curriculum；
- 同题多候选比较；
- 部分得分；
- 过程检查；
- 更好的起点模型；
- 工具反馈和中间环境状态。

这些方法增加信号，也可能引入新的评分偏差。

## Reward Hacking 不会因为规则化而消失

模型可能：

- 针对测试样例写死答案；
- 操纵输出解析器；
- 读取泄露的标准答案；
- 修改测试或环境；
- 找到规则没有覆盖的捷径；
- 输出满足格式但没有真实内容的文本。

因此需要：

```text
隐藏测试
权限隔离
验证器版本控制
对抗测试
异常检测
人工抽检
```

Verifier 也是需要持续维护的软件系统。

## 更长推理不等于更好推理

RL 可能让模型产生更长的 CoT，因为难题和探索需要更多 Token。但长度本身不是能力：

```text
更多 Token
可能包含更充分的搜索
也可能只是重复、绕路和迎合格式 Reward
```

应同时评估正确率、推理成本、重复率和错误修正质量。

## 训练时会验证，不等于运行时永远正确

RLVR 把通过 Verifier 的倾向写入 Weight。部署后模型仍是概率生成：

```text
上下文
→ Transformer
→ Logits
→ 逐 Token 生成
```

如果运行时不再调用测试或工具，当前回答就没有获得新的外部完成证明。

所以：

```text
训练中学过验证反馈
≠ 每次运行都实际经过验证
```

## 对 Agent 设计意味着什么

RLVR 与 Agent 闭环高度相关，因为 Agent 天然可以产生：

```text
动作
→ 环境结果
→ 验收信号
```

但训练一个能在模拟环境中得高分的 Agent，不等于真实生产环境安全可靠。还要考虑：

- Simulator 与现实差异；
- 权限和不可逆副作用；
- 隐藏业务规则；
- 并发与外部状态变化；
- 验收条件是否完整；
- 长任务中的中间约束。

运行时仍应执行真实工具、保存证据并逐项验收。

## 应怎样评估 RLVR 模型

至少分开检查：

1. 未见问题上的真实通过率；
2. 与训练 Verifier 不同的独立测试；
3. 数据污染与答案泄露；
4. Reward Hacking 和沙箱逃逸；
5. 推理长度、成本与重复；
6. 正确结果中的错误过程比例；
7. 未训练领域的迁移与退化；
8. 通用对话、安全和指令能力是否保持；
9. Agent 环境中的真实完成证据。

## 从 RLVR 进入下一步

当前讨论的主要输出还是一条回答或一段推理。更完整的智能系统还会产生：

```text
思考
→ Tool Call
→ Tool Result
→ 状态更新
→ 下一步行动
→ 最终验收
```

下一部分将学习 `推理轨迹、工具调用与 Agent 环境训练`：怎样把多步交互轨迹纳入后训练。

## 常见误解

### 数学 RLVR 提升意味着所有领域推理都会等比例提升

没有这种保证，必须单独验证迁移。

### 规则 Verifier 不会被 Reward Hacking

错误。规则、解析器、测试和环境都可能存在漏洞。

### 模型训练时通过大量测试，部署后就不需要再测试

错误。训练形成倾向，运行时验证当前实例。
