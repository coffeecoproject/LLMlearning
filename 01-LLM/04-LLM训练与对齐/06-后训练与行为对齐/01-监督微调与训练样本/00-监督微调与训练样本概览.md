# 监督微调与训练样本概览

> [!summary]
> SFT 使用带角色、指令和理想回答的样本，继续训练 Base Model，使它更倾向于按目标格式回应用户。

## 六个学习问题

1. [[01-预训练样本与SFT样本有什么区别|预训练样本与 SFT 样本有什么区别]]：先区分基础能力数据与行为示范；
2. [[02-Base-Model为什么不能直接当助手|Base Model 为什么不能直接当助手]]：理解为什么会续写不等于会稳定回应；
3. [[03-一条对话怎样变成SFT训练序列|一条对话怎样变成 SFT 训练序列]]：连接 Messages、Chat Template、Tokenizer 与训练序列；
4. [[04-Labels与Loss-Mask怎样作用|Labels 与 Loss Mask 怎样作用]]：区分 Prompt 条件、Assistant 目标和三类 Mask；
5. [[05-SFT怎样通过许多示范改变模型行为|SFT 怎样通过许多示范改变模型行为]]：理解许多局部更新怎样形成可泛化行为；
6. [[06-SFT能改善什么又不能保证什么|SFT 能改善什么，又不能保证什么]]：明确事实、推理、工具、记忆和安全边界。

## 一条主线

```text
Base Model
→ 角色化 Prompt 与理想 Assistant 回答
→ Chat Template
→ Token IDs
→ Assistant 位置 Labels 与 Loss Mask
→ Forward、Loss、Backward、Optimizer Step
→ 许多不同示范持续更新参数
→ SFT Model 更倾向按指令回应
```

底层仍然是下一 Token 训练；变化主要来自样本表达的目标行为与 Loss 计算位置。

## 阅读顺序

按编号阅读即可。只想建立框架时，先读第 1、2、5、6 篇；第 3、4 篇解释训练数据怎样真正进入计算。

## 边界

- SFT 属于参数训练，不是普通运行时 Prompt；
- Chat Template 负责组织角色，SFT 负责让模型学习这些角色结构；
- Loss Mask 与 Causal Mask、Padding Mask 不是同一个对象；
- SFT 可以训练工具调用表示，但真实工具执行仍属于 Agent；
- SFT 提供理想示范，候选回答之间的偏好比较进入下一小节；
- 本节不展开 Learning Rate、全参数微调、LoRA 和分布式训练工程。

## 理解检查

1. 为什么 Base Model 有知识却仍可能不稳定回答用户？
2. User Token 不计算 Loss 时为什么仍然影响回答训练？
3. SFT 为什么改变的是行为倾向而不是硬编码规则？
4. SFT 为什么不能单独保证事实正确和工具执行成功？
