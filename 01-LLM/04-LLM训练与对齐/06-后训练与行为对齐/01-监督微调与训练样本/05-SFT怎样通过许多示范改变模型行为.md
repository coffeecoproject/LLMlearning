# SFT 怎样通过许多示范改变模型行为

> [!summary] 一句话理解
> 每条 SFT 示例只产生一次局部误差信号；大量不同指令反复把参数推向相似行为后，模型才会从“记住示范形式”逐渐变成“面对新指令也更倾向作出类似回应”。

## 所属阶段

**后训练阶段。** 本篇解释多条 SFT 数据怎样累积成行为倾向，不展开多卡训练、Learning Rate 调度或 LoRA 等训练工程。

## 一条样本只改变很小一部分倾向

样本：

```text
User：只用一句话解释 Token。
Assistant：Token 是模型处理信息时使用的基本离散单位。
```

模型如果输出过长或开头错误，Assistant 位置会产生 Loss。Backward 再让相关参数发生小幅变化。

这一次更新可能让相似上下文下的目标 Token 概率略微提高，但不会立即写入一条永久规则：

```text
只要出现“只用一句话”
→ 必须执行某个硬编码函数
```

模型仍然是在参数化概率分布中生成。

## 多条不同示范为什么能形成共同规律

训练数据可能包含：

```text
请简要解释……
只回答一个数字……
请输出 JSON……
把下面内容总结为三点……
使用中文回答……
如果信息不足请明确说明……
```

如果理想回答都遵循相应约束，许多 Gradient 会反复强化：

```text
识别指令中的约束
→ 在回答中保持约束
```

模型并非只记住一句固定 Prompt，而是可能在共享参数中形成对相似表达的泛化。

## 一个教学化累积过程

假设只看“简洁回答”这一种倾向：

```text
样本 1：一句话解释概念
样本 2：不超过 30 字总结
样本 3：只列三个要点
样本 4：删除背景铺垫
……
```

模型逐渐发现这些不同 Prompt 都要求限制输出范围。

新问题：

```text
请用最短的话说明 Embedding。
```

即使训练集中没有这句完全相同的话，模型也可能根据相近模式给出简短回答。

这就是 SFT 希望获得的泛化，而不是只在训练 Prompt 上复读标准答案。

## SFT 主要在调整哪些行为

### 指令识别

把 User 内容当成需要回应的任务，而不是继续正文。

### 回答形式

学习列表、表格、JSON、代码块、简短或详细说明等形式。

### 多轮一致性

利用前面消息中的定义、要求和已给信息继续当前对话。

### System Instruction

根据 System 角色中的身份、语气和边界改变回答。

### 工具协议

在适当上下文中输出 Tool Call，并根据 Tool Result 继续。

### 不确定与拒绝模式

在数据覆盖的情形中，学习承认不知道、请求补充信息或拒绝特定请求。

这些都是概率倾向，不是绝对不可违反的程序规则。

## 数据覆盖决定模型有机会学什么

如果 SFT 数据只有普通问答，模型未必稳定学会：

- 复杂 JSON Schema；
- 多轮工具调用；
- 长代码仓库任务；
- 精确坐标输出；
- 很长的推理轨迹；
- 特定企业流程。

所以模型是否支持某种行为，不能只看“SFT 过”三个字，还要看数据类型、质量与评估。

## 数据比例会改变行为方向

假设教学数据中：

```text
90% 都是长篇解释
10% 是简洁回答
```

模型可能形成偏长的默认风格。

反过来，如果绝大多数回答都极短，模型可能在真正需要推理和说明时过早结束。

SFT 数据混合需要平衡：

- 简洁与完整；
- 通用与专业；
- 单轮与多轮；
- 纯文本与工具轨迹；
- 帮助性与安全行为；
- 不同语言与领域。

## 为什么数据质量比简单堆数量更重要

错误示范会向错误方向更新参数：

```text
Prompt：2 + 3 等于多少？
错误 Assistant：6
```

格式正确不能弥补答案错误。

其他常见问题：

- 回答看似流畅但没有遵循指令；
- 推理过程与最终答案矛盾；
- Tool Call 参数与工具定义不匹配；
- 拒绝了正常问题；
- 合成数据反复使用单一文风；
- 多轮上下文中人物或事实不一致。

因此现代 SFT 管线常结合规则、执行测试、模型评审和人工抽检。

## 为什么可能出现过拟合

如果数据量小、重复次数过多，模型可能过度贴合训练样本：

- 看到相似 Prompt 就复用固定句式；
- 在训练任务上好，在改写问题上差；
- 过度输出数据中的口头禅；
- 对某种模板依赖过强。

这也是为什么需要独立验证集、改写测试和真实用户分布评估。

## 为什么还可能损伤基础能力

SFT 继续修改 Base Model Weight。如果数据过窄或更新过强，可能导致：

- 通用语言能力下降；
- 某些知识和代码能力退化；
- 回答风格过度单一；
- 只会按照训练格式作答；
- 对长尾任务的表现下降。

这类现象常被放在能力遗忘或 Alignment Tax 的讨论中。是否真的发生，需要比较 SFT 前后的多类评估，不能只看聊天体验。

## 为什么 SFT 后仍然常有偏好优化

对于一个 Prompt，可能存在许多“都说得通”的回答：

```text
回答 A：正确但过长
回答 B：简洁但漏掉条件
回答 C：完整、清楚且符合用户要求
```

SFT 通常给出一个参考答案，让模型模仿它；但它不直接表达多个候选回答之间的细微优先关系。

后续偏好数据会进一步告诉模型：

```text
在这些候选中
→ 哪个更好
```

所以 SFT 是行为起点，偏好优化继续改善回答选择。

## 开放模型观察：Qwen2.5

Qwen2.5 报告描述其 SFT 数据包含超过 100 万个示例，覆盖长文本、数学、代码、指令遵循、结构化数据、逻辑推理、跨语言和稳健 System Instruction，并进行了两轮 SFT 训练。

这说明真实 SFT 不是单一问答集合，而是由多类目标共同组成的数据配方。

但公开“超过 100 万条”和“训练两轮”，仍不能让外部知道每条样本、精确比例和全部过滤阈值。

> [!source]
> 来源：[Qwen2.5 Technical Report](https://arxiv.org/abs/2412.15115)，Qwen Team，2024。核对日期：2026-07-29。

## 怎样知道行为真的改善了

至少需要测试：

1. **训练分布内**：常见指令是否更稳定；
2. **改写问题**：换一种表达后是否仍能遵循；
3. **组合约束**：同时要求格式、长度和语言时是否满足；
4. **边界条件**：信息不足或指令冲突时怎样处理；
5. **能力保持**：知识、代码和多语言是否退化；
6. **真实任务**：用户实际是否更偏好输出。

只看训练 Loss 下降，不能证明这些方面全部改善。

## 常见误解

### 一条高质量示范就能稳定教会一种行为

通常不够。模型需要多样表达和边界情况才能更好泛化。

### SFT 数据越多，模型一定越好

不一定。错误、重复和比例失衡的数据也会放大问题。

### SFT 只改变语气，不改变能力

过于绝对。它主要塑造行为，但任务示范也可能改善或损伤具体能力。

### SFT 完成后就不需要评估

不对。必须同时检查目标行为、泛化、边界和基础能力保持。
