# Base Model 为什么不能直接当助手

> [!summary] 一句话理解
> Base Model 学到的是“各种文本接下来通常怎样延续”，而助手需要稳定识别角色、服从指令、选择回答形式并遵守行为边界；SFT 用大量理想交互示范，把这些行为变成更高概率的生成路径。

## 所属阶段

**后训练阶段。** 本篇从已经训练完成的 Base Model 出发，解释为什么还需要 SFT。普通用户聊天只运行训练后的模型，不会在每次提问时自动执行 SFT。

## 先看 Base Model 的真实目标

预训练中，模型见过大量不同文本：

```text
百科文章
小说
新闻
论坛讨论
问答
代码
对话记录
```

它学习的是：

```text
给定前文
→ 哪个 Token 更可能继续出现
```

因此，Base Model 已经可能具备知识、语言、代码和一定推理能力，但它没有只学习一种“助手应该怎样回应”的规则。

## 同一句输入可能有多种合理续写

用户输入：

```text
请解释什么是光合作用。
```

从互联网文本分布看，后面可能出现：

```text
答案正文
更多类似问题
一段教学对话
网页导航文字
论坛用户的不同观点
```

这些都可能是训练资料中出现过的文本结构。

用户真正希望的是：

```text
把前文识别为指令
→ 直接给出准确、清楚、适合用户的解释
```

这比“语言上可以继续”多了一层行为选择。

## 一个教学对比

### Base Model 可能续写

```text
User：请列出三种水果。
Assistant：
User：再列出三种蔬菜。
Assistant：
```

它可能把输入当成待续写的对话模板，继续编写下一条 User，而不是回答当前问题。

### SFT 后模型更倾向回答

```text
User：请列出三种水果。
Assistant：苹果、香蕉、橙子。
```

区别不是底层 Transformer 换了，而是参数经过行为示范继续更新后，助手式路径的概率变高。

## 助手行为包含哪些额外要求

一个可用助手通常需要学习：

- 区分 System、User、Assistant 等角色；
- 把 User 内容识别为请求，而不是普通正文；
- 遵循长度、格式、语言和语气要求；
- 根据上下文继续多轮对话；
- 不伪造自己已经执行的现实动作；
- 在适当条件下拒绝或表达不确定；
- 按协议生成 Tool Call 或结构化输出。

预训练可能让模型见过其中部分模式，但不能保证它们稳定成为默认行为。

## 角色标记为什么需要训练

运行时可以把消息组织为：

```text
System：你是一个简洁的助手。
User：解释 Token。
Assistant：
```

但 `System`、`User` 和 `Assistant` 的边界对模型而言最终仍要变成 Token 或其他输入表示。

如果训练时从未学习这些标记怎样对应角色，单独在运行时加入它们，不一定能稳定触发期望行为。

```text
Chat Template 提供结构
+ SFT 让模型学习结构的含义
→ 角色格式才成为可靠行为条件
```

## 为什么只写一个更强 System Prompt 还不够

Prompt 可以在不修改参数的情况下引导模型已有能力，但它有边界：

- 指令可能与模型原有文本倾向竞争；
- 不同措辞可能触发不同表现；
- 复杂格式不一定稳定遵循；
- 边界情况可能偏离角色；
- Prompt 不能把模型没有学会的行为凭空写入参数。

SFT 的作用是让大量不同 Prompt 都把参数推向类似的目标行为，从而提高泛化与稳定性。

## SFT 实际改变什么

SFT 通常从 Base Model Weight 继续训练：

```text
Base Model Weight
+ 指令与理想回答样本
→ Forward
→ Loss
→ Backward
→ Optimizer 更新 Weight
→ SFT Model
```

它会改变 Embedding、Attention、FFN 和输出层等被开放训练的参数，而不是在模型外增加一张固定问答表。

## 一个简单概率直觉

同样输入：

```text
User：只用一句话解释 Embedding。
Assistant：
```

教学示意：

```text
SFT 前：
直接简短回答       0.30
继续模拟新问题     0.25
写成长篇文章       0.20
其他               0.25

经过许多相似示范后：
直接简短回答       0.75
继续模拟新问题     0.05
写成长篇文章       0.10
其他               0.10
```

数字完全是虚构的，只用于说明 SFT 提高目标行为的概率，而不是写入绝对 `if-else` 规则。

## SFT 是否会增加新能力

可能，但要谨慎表达。

如果 SFT 数据包含模型尚不熟悉的领域、工具格式或推理示范，参数更新可能改善相关能力。但 SFT 数据量通常远小于预训练，主要作用往往是：

```text
把已有基础能力组织成用户可调用的行为
```

所以一个能力较弱的 Base Model，不会因为少量漂亮答案就自动变成远强于自身基础能力的模型。

## OpenAI 的公开案例：InstructGPT

InstructGPT 工作从预训练 GPT-3 出发，收集标注人员写出的理想回答示范，并先使用监督学习进行 SFT；之后再收集回答排序，进入 Reward Model 与 RLHF 阶段。

这条公开路线说明：

```text
预训练 GPT-3
→ 人类示范 SFT
→ 偏好比较与 RLHF
→ InstructGPT
```

论文还报告，在其人类评估分布上，1.3B InstructGPT 的输出偏好高于 175B GPT-3。这不能简化为“小模型普遍强于大模型”，而是说明行为对齐会显著影响用户实际感受。

> [!source]
> 来源：[Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)，Ouyang 等，2022。核对日期：2026-07-29。

## Base、SFT 与最终 Chat Model 的关系

```text
Base Model
→ 具有基础生成能力

Base Model + SFT
→ 更倾向遵循指令和回答

SFT Model + 偏好优化 / RL
→ 进一步改善帮助性、安全性和回答选择

模型 + Runtime + System Prompt + Tools
→ 用户实际使用的产品系统
```

因此 SFT 是从 Base Model 到助手的重要桥梁，但通常不是全部后训练。

## 常见误解

### Base Model 完全不会回答问题

不一定。预训练中也有问答和对话文本，它可能回答，但行为不够稳定。

### Chat Model 只是 Base Model 加了一段 System Prompt

通常不是。两者的 Weight 往往已经因后训练而不同。

### SFT 给每个问题写入一个固定答案

不是。它通过许多示范更新共享参数，目标是形成可泛化的行为倾向。

### 模型越大，就自然越会遵循人的意图

规模提升基础能力，但意图遵循仍需要专门数据、训练和评估。
