# SFT 能改善什么，又不能保证什么

> [!summary] 一句话理解
> SFT 能让模型更稳定地表现成目标助手，但它仍然是从有限示范中学习生成倾向，不能自动保证事实正确、价值偏好一致、推理无误或现实任务已经执行。

## 所属阶段

这是 **监督微调小节的边界与串联复习**。后续偏好优化和强化学习会继续改变行为，但同样不能替代事实来源、工具执行和外部验证。

## SFT 最直接改善什么

### 把输入识别为需要回应的指令

Base Model 可能继续文本；SFT Model 更倾向进入 Assistant 回答角色。

### 遵循明确格式

例如：

```text
只回答一个数字
输出三个要点
返回指定 JSON 字段
使用中文解释
```

只要训练数据覆盖相似要求，SFT 可以显著提高格式遵循概率。

### 保持多轮角色

模型更容易区分谁是用户、谁是助手，并利用前面消息继续当前对话。

### 学习工具调用协议

它可以学会生成函数名、参数和角色边界，也可以学习在 Tool Result 返回后继续回答。

### 形成目标语气和风格

例如简洁、专业、礼貌或教学式表达。

### 改善部分任务能力

如果示范包含经过验证的代码、数学、结构化数据或长文本任务，模型可能提高相应任务表现。

## 为什么 SFT 不等于完全理解人的意图

用户意图可能包含：

- 明说的要求；
- 没有说出的背景；
- 相互冲突的约束；
- 错误前提；
- 需要追问才能确定的选择；
- 组织或社会环境中的隐含规则。

SFT 能让模型学会常见意图模式，却不能读取用户没有提供的信息。

```text
更像会回应
≠ 能访问用户全部真实目的
```

## 为什么 SFT 不能保证事实正确

SFT Loss 检查的是模型是否接近参考回答。参考回答自身也可能：

- 已经过时；
- 来自错误教师模型；
- 缺少来源；
- 在复杂问题上只是看起来合理；
- 与现实数据库不一致。

如果示范把错误答案当成 Label，训练反而会强化错误。

因此事实性仍需要高质量数据、搜索、RAG、工具或权威数据库。

## 为什么 SFT 不能稳定表达所有偏好

对同一个 Prompt，可能有多个合理回答：

```text
A：很详细，但太长
B：很简洁，但漏了一个风险
C：长度合适、完整且语气友好
```

SFT 通常只展示某个理想答案，没有直接告诉模型：

```text
C 优于 A
A 又优于 B
```

这种“候选之间哪个更好”的信号，是后续偏好数据、Reward Model、DPO 或 RLHF 要解决的问题。

## 为什么 SFT 不能保证推理过程正确

模型可以模仿高质量推理示范，但仍可能：

- 在中间步骤计算错误；
- 从错误前提继续生成；
- 模仿推理格式却没有正确关系；
- 最终答案正确但过程错误；
- 在训练分布外失效。

SFT 提高的是相应推理轨迹的生成概率，不是给模型安装一个永不出错的数学证明器。

可验证任务还可以通过 RLVR、代码执行和答案检查继续训练，这属于后续内容。

## 为什么 SFT 不能执行现实动作

工具调用示范可以让模型输出：

```json
{"tool": "write_file", "path": "app.py"}
```

但这仍然只是一段 Token。真正执行需要：

```text
Agent 解析 Tool Call
→ 检查权限
→ 调用工具
→ 获取真实结果
→ 把结果重新交给模型
→ 验证任务是否完成
```

训练模型输出协议与运行系统执行协议是两层不同工作。

## 为什么 SFT 不会带来用户长期记忆

SFT 更新的是一个模型版本的通用 Weight，并不为每个用户自动创建可查询档案。

用户当前姓名、项目决定和最新任务状态仍需要：

- 当前 Context；
- Session；
- 外部 Memory；
- 数据库或文件；
- 检索与重新注入。

SFT 可以教模型“怎样使用用户档案”，但档案本身仍在模型外管理。

## 为什么安全示范也不是绝对防线

SFT 可以提供拒绝和安全回答示范，但现实输入组合远多于训练样本。

模型可能：

- 对危险请求漏拒绝；
- 对正常请求过度拒绝；
- 在改写、编码或多轮情境中偏离；
- 遇到相互冲突指令时选错优先级。

所以安全通常还需要偏好训练、专门评估、输入输出检测和产品策略。

## 一个完整例子

目标：让模型成为代码助手。

### SFT 可以训练

```text
读取错误描述
→ 给出搜索建议
→ 按 Tool Call 格式请求读取文件
→ 根据工具结果解释代码
→ 生成补丁格式
```

### SFT 不能单独保证

```text
读取了仓库全部相关文件
测试真的执行成功
修改没有破坏其他模块
依赖版本是最新的
用户全部验收条件已经满足
```

后半部分必须由 Agent、工具、测试和验收证据补齐。

## SFT、System Prompt 与规则引擎的区别

| 方式 | 改变位置 | 作用特点 |
|---|---|---|
| SFT | 模型 Weight | 让目标行为在许多相似输入上更自然出现 |
| System Prompt | 当前 Context | 在本次运行中引导模型已有行为 |
| 规则引擎 | 模型外程序 | 对明确条件执行确定逻辑或拦截 |

三者可以组合：

```text
SFT 提供默认助手行为
+ System Prompt 提供当前任务规则
+ 外部程序执行硬性检查
```

不能指望其中一个完全替代另外两个。

## InstructGPT 的公开边界

InstructGPT 论文报告了指令遵循、偏好和安全等方面的改善，同时明确指出模型仍会犯简单错误。

这很好地说明：

```text
后训练显著改善用户体验
≠ 消除概率模型的全部错误
```

> [!source]
> 来源：[Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)，Ouyang 等，2022。核对日期：2026-07-29。

## 为什么下一步要学习偏好数据

SFT 已经回答：

```text
“理想回答可以长什么样？”
```

下一步要回答：

```text
“同一个问题的多个回答中，人或验证系统更希望哪个？”
```

这是从单一示范进入候选比较，也是理解 RLHF 与 DPO 的前提。

## 常见误解

### SFT 后模型就不会幻觉

不会。SFT 可以改善承认不确定的行为，但不能自动核验所有事实。

### SFT 数据里有工具调用，模型就能自己执行工具

不对。模型学习调用表示，Agent 负责现实执行。

### SFT 只负责礼貌和语气

过于狭窄。它也可以训练格式、工具协议、任务方法和部分领域能力。

### 后续 RLHF 会解决 SFT 的全部边界

也不会。偏好优化继续塑造选择，但实时事实、权限、记忆和验收仍在模型外。

## 理解检查

1. SFT 最直接把 Base Model 的哪类行为变得更稳定？
2. 为什么参考答案本身错误时，SFT 可能强化错误？
3. 工具调用格式与真实工具执行分别属于哪一层？
4. 为什么 SFT 后还需要偏好数据？

## 本小节结论

```text
Base Model
+ 角色化指令和理想回答
+ Labels 与 Loss Mask
+ 大量参数更新
→ SFT Model

SFT Model
→ 更像可用助手
→ 但仍需偏好优化、事实工具和系统验收
```
