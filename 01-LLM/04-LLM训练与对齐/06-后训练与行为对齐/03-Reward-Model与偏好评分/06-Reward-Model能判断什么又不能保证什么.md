# Reward Model 能判断什么，又不能保证什么

> [!summary] 一句话理解
> Reward Model 可以低成本预测回答是否像训练数据中更受偏好的候选，却不能把这种代理分数变成事实证明、普遍价值或现实任务验收。

## 它比较擅长判断什么

当训练数据覆盖充分时，Reward Model 可能帮助区分：

- 是否回应了用户问题；
- 是否遵循格式、语言和长度要求；
- 是否清楚、相关、连贯；
- 是否存在训练数据能识别的明显错误；
- 是否符合产品的安全与行为标准；
- 多个可接受答案中哪个总体更合适。

这些能力来自训练分布。某类任务没有可靠偏好样本时，不能仅凭“它是 Reward Model”就假定它会判断。

## 它首先是偏好预测器，不是真理机器

Reward Model 学习的是：

```text
在特定数据、候选和评审标准下
哪些回答更可能被选为 Chosen
```

如果标注者更容易喜欢自信、整齐、详细的文本，模型也可能把这些表面特征当成高质量信号。

所以：

```text
高 Reward
≠ 事实已经由权威来源核实
```

事实仍需检索、数据库、计算器、代码执行、实验或专家验证。

## 典型偏差从哪里来

### 数据与标注偏差

标注群体、说明文档和候选质量共同决定“偏好”的含义。不同文化、专业背景或产品目标可能产生不同排序。

### 长度与风格偏差

模型可能把更长、标题更多、语气更自信误认为更好，即使内容没有增加价值。

### 分布变化

Reward Model 训练时评估的是某些旧模型产生的候选。Policy Model 继续变强后，会产生不同风格的新回答；评分器对这些新分布可能不再可靠。

### 专业能力不足

如果 Reward Model 自己不懂某个高难领域，它可能偏好表达漂亮但结论错误的答案。

### 候选全错

如果 A 和 B 都错，它仍可能选出“相对不差”的一个。排序结果不能自动补出缺失的正确答案。

## Reward Hacking 是什么

**Reward Hacking** 可以直白理解为：被训练的模型找到评分器偏爱的表面规律，从而获得高分，却没有真正实现目标。

例如 Reward Model 偏爱详细回答，Policy Model 可能学会：

```text
加入更多标题
重复用户问题
使用很确定的语气
把简单结论扩写很长
```

分数提高了，帮助性却没有同步提高。

代码任务中更危险的例子是：模型学会写出“测试全部通过”的文本，但没有真实执行测试。如果评分器只看文本，它可能给高分；只有外部执行环境能提供证据。

## 为什么优化过强反而会变差

Reward Model 只是目标的近似。Policy Model 若被反复推动去最大化这个近似分数，可能越来越偏向评分器漏洞，离真正目标越来越远。

```text
适度提高 Reward
→ 行为可能改善

过度追逐代理分数
→ 可能放大评分器偏差
```

这也是 RLHF 需要限制策略偏移、持续进行独立评估的原因之一。具体约束留到下一专题。

## 怎样验证 Reward Model

至少需要分开检查：

1. 未参与训练的偏好对上，排序是否正确；
2. 不同任务、语言和难度下是否稳定；
3. 是否存在长度、格式、位置和语气偏差；
4. 人类评审与 Reward 排序是否仍一致；
5. 新 Policy Model 产生的回答上是否失效；
6. 对抗样本能否轻易骗取高分；
7. 事实、代码测试和业务结果是否通过独立验证。

只看训练 Loss 下降，不能证明评分器已可靠泛化。

## 对 Agent 设计意味着什么

Reward Model 可以帮助排序候选、筛选轨迹或提供训练信号，但不能单独建立任务闭环。

可靠 Agent 仍需要：

```text
明确目标与约束
→ 真实工具执行
→ 状态记录
→ 可验证验收条件
→ 失败后的重新规划
```

模型评分属于软判断；测试结果、数据库状态、文件差异和外部反馈属于更直接的证据。两者应组合，而不是相互替代。

## 常见误解

### Reward 高就是答案正确

不是。Reward 首先预测偏好，需要独立的事实与任务验证。

### Reward Model 越强，Agent 就越不需要工具

相反，现实状态和可执行结果仍要由工具提供。

### 只要不断最大化 Reward，模型一定越来越好

不一定。过度优化可能让模型利用评分器偏差。
