# 为什么需要 Reward Model

> [!summary] 一句话理解
> 人工偏好比较很有价值，却无法在后续训练中持续评审模型生成的海量新回答；Reward Model 的作用是从有限比较数据中学出一个可重复使用的偏好评分器。

## 从上一节的问题开始

我们已经有许多偏好对：

```text
Prompt：一句话解释 Token。

Chosen：Token 是模型处理信息时使用的基本离散单位。
Rejected：Token 就是一个英文单词。
```

这些记录告诉我们：在这组候选和评审标准下，第一条回答更好。

但如果语言模型接下来生成一条从未出现过的新回答：

```text
Token 是 Tokenizer 划分并映射为 ID 的文本或符号单元。
```

训练系统还需要判断这条回答有多符合目标。原来的偏好对并没有直接记录这个新回答的分数。

## 为什么不能每次都继续找人评分

理论上可以让人不断评审，但实际训练可能产生大量新回答。全靠人工会遇到：

- 成本高、速度慢；
- 不同标注者可能不一致；
- 模型更新后还会产生新的回答分布；
- 强化学习需要反复获得反馈，很难每一步都等待人工；
- 某些专业任务需要稀缺专家。

因此需要一个中间层：

```text
有限的人类比较
→ 训练 Reward Model
→ Reward Model 自动评估大量新回答
```

它把人工判断扩展成可计算、可批量使用的近似信号。

## Reward Model 学的不是一张答案表

Reward Model 并不是保存：

```text
问题 1 → 答案 A 得 9 分
问题 2 → 答案 B 得 7 分
```

它通过参数训练，学习输入内容、回答方式和偏好标签之间的共同规律。例如，它可能逐渐对这些特征更敏感：

- 是否真正回应了问题；
- 是否遵循格式和长度要求；
- 是否出现明显事实或逻辑问题；
- 是否包含危险内容；
- 是否清楚、相关、不过度绕弯。

这些不是人工硬编码进去的固定规则，而是模型从训练样本中形成的统计性判断。它也可能把表面风格误当成质量。

## 为什么需要结合 Prompt 一起判断

同一句回答不能脱离问题单独评分。

回答：

```text
3
```

面对 `1 + 2 等于多少？` 可能很好；面对 `请解释 Attention` 则完全不够。

所以 Reward Model 通常需要读取：

```text
Prompt / 对话上下文
+ 候选回答
```

再判断这条回答是否适合当前任务。

## 为什么不是直接使用规则程序

规则程序擅长检查可明确写出的条件，例如：

```text
JSON 是否可解析
代码测试是否通过
回答是否超过 100 字
是否包含禁止词
```

但“是否解释清楚”“是否真正有帮助”“是否兼顾完整与简洁”很难全部写成固定规则。Reward Model 可以学习这类模糊、组合性的偏好。

相反，能够程序验证的结果通常应继续使用真实验证器，而不是全部交给 Reward Model 猜测。

## 它解决的是可扩展性，不是绝对正确性

Reward Model 的价值是：

```text
让有限反馈可以影响大量后续训练样本
```

它没有解决：

```text
谁定义“更好”
标注是否正确
事实是否真实
评分是否会被模型钻空子
```

这些问题会继续成为它的能力边界。

## 常见误解

### Reward Model 是把人类价值完整复制进模型

不是。它学习的是特定数据、评审说明与标注群体所表达的偏好近似。

### 有了 Reward Model 就不需要人工

不是。人类仍参与数据设计、抽检、评估和目标修订；Reward Model 主要扩大反馈规模。

### 所有目标都应该让 Reward Model 判断

不是。可执行测试、数据库事实和现实状态更适合交给对应工具验证。
