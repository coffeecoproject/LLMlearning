# 为什么不能从数据比例直接推导能力

> [!summary] 一句话理解
> 数据比例决定训练机会，却不会按相同比例变成能力；最终表现还由数据质量、模型容量、Tokenizer、训练目标、优化过程、跨领域迁移和评估方式共同决定。

## 最常见的错误推导

```text
训练数据中 20% 是代码
→ 模型拥有 20% 代码能力
```

这个推导没有成立的单位：“20% 能力”本身就没有统一定义。代码补全、修复、解释、运行和大型项目修改是不同任务，无法压缩成一个与数据比例一一对应的百分比。

## 原因一：同类 Token 的价值不同

```text
10 亿 Token 的重复模板代码
≠ 10 亿 Token 的多语言项目、测试和高质量文档
```

数据类别只说明粗略来源，不能表示每个 Token 提供了多少新规律。

## 原因二：能力之间会共享参数

代码、数学和自然语言会共同使用 Attention、FFN、Embedding 等参数。

某项训练可能：

- 帮助其他能力，产生正迁移；
- 与其他能力竞争，产生干扰；
- 只在相似任务上有效；
- 在模型容量扩大后才更充分吸收。

所以数据类别与能力模块不是一对一映射。

## 原因三：模型规模和训练计算不同

相同数据交给不同参数规模、不同训练 Token 预算的模型，结果可能不同。

```text
数据足够但模型容量不足
→ 难以同时吸收大量复杂模式

模型很大但训练或数据不足
→ 参数没有获得充分学习信号
```

这会在下一节“规模、架构与能力形成”继续说明。

## 原因四：Tokenizer 与样本结构不同

Tokenizer 会影响中文、代码、数字和特殊符号被切成多少 Token；序列长度、文档边界和上下文组织会影响模型实际看到哪些关系。

因此“原始文件占比”还不等于“有效训练 Token 占比”，更不等于“有效 Loss 权重占比”。

## 原因五：训练目标和阶段不同

同一份代码可以用于：

- 基础下一 Token 预训练；
- 代码填空；
- 指令问答 SFT；
- 带测试反馈的强化学习。

数据表面相似，目标不同，参数获得的训练信号也不同。

## 原因六：能力必须通过评估定义

若要判断代码能力，需要明确：

- 测的是补全、生成、修复还是项目级修改；
- 是否实际执行测试；
- 是否包含训练数据污染；
- 测试语言和难度是什么；
- 是否允许工具和多轮反馈。

没有评估定义，就不能把“能力更强”变成可验证结论。

## 正确的因果表述

更准确的说法是：

```text
提高某类高质量数据的有效训练权重
→ 增加相关模式反复影响参数的机会
→ 在模型容量与训练配方允许时
→ 相关任务表现可能提升
→ 最终必须由独立评估确认
```

“可能”不是回避结论，而是保留真实训练系统中的多因素关系。

## 怎样阅读模型技术报告

看到“使用更多数学数据”“扩展到多少万亿 Token”时，应继续问：

1. 这是原始数据量、去重后数据量，还是实际训练 Token？
2. 数据是否分阶段使用或被重复采样？
3. Base 与 Instruct 的训练阶段是否分开？
4. 能力提升由哪些评估支持？
5. 是否同时改变了模型规模、训练计算或其他配方？

如果多个因素一起改变，就不能把全部提升只归因于一个数据数字。

## 闭源模型边界

OpenAI 等闭源模型通常不会公开完整数据清单与精确混合比例。因此可以根据官方报告讨论已公开事实，但不能从模型表现倒推出其完整训练数据，也不能把开放模型配方当作其内部设定。

## 常见误解

### 某能力强，就证明训练集中一定有大量对应答案

不能证明。可能有相关数据、跨领域迁移、合成数据或后训练等多种来源。

### 两个模型参数量相同，能力差异就只来自数据

不一定。Tokenizer、架构细节、训练目标、优化过程和后训练也可能不同。

### 技术报告公布了 Token 总量，就已经完整公开训练数据

不是。总量不等于来源、比例、质量和阶段配方。

## 理解检查

1. 为什么“20% 代码数据”不能换算成“20% 代码能力”？
2. 原始文件占比、训练 Token 占比与 Loss 权重为什么可能不同？
3. 阅读数据规模声明时，还需要检查哪些因素？
