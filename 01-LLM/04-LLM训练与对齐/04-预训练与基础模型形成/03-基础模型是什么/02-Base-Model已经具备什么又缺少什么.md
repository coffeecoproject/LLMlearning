# Base Model 已经具备什么，又缺少什么

> [!summary] 一句话理解
> Base Model 已经具有广泛的语言、知识与模式能力，但这些能力主要服务于文本续写，不自动等于稳定的指令遵循、对话角色和安全行为。

## 先看它已经具备什么

预训练完成后，Base Model 通常可能具备以下能力，具体强弱取决于模型、数据和训练规模。

### 语言结构

它能形成语法、词义、篇章结构和多语言模式，生成连贯文本。

### 知识与关系

训练文本中的人物、地点、概念和领域关系会形成参数化倾向，使模型可以续写或回答许多知识问题。

### 代码与格式

如果训练中有足够代码，它可能补全函数、延续语法和生成常见实现。

### 上下文学习

Prompt 中给出示例或格式后，Base Model 可能根据当前上下文延续相同模式，即使参数没有在当前请求中更新。

这些能力不是每次都能稳定调用，也不保证事实正确。

## 为什么它更像条件续写器

Base Model 的主要行为可以直白地表示为：

```text
给定当前前缀
→ 生成在训练分布中较合理的后续
```

例如输入：

```text
问题：法国的首都是哪里？
答案：
```

训练数据中常见这种问答格式，因此 Base Model 可能续写“巴黎”。

但输入：

```text
请只回答城市名称：法国的首都是哪里？
```

它不一定稳定遵守“只回答城市名称”，因为“用户提出要求，助手必须遵守”并不是普通预训练目标明确保证的行为。

## 它通常缺少什么

### 稳定的指令遵循

它可能回答要求，也可能继续改写要求、补充另一段对话或生成不符合指定格式的文本。

### 清晰的对话角色

它未必稳定区分 System、User 和 Assistant 的行为边界，除非训练和格式已经专门塑造这些关系。

### 偏好与安全边界

预训练数据包含多种互相冲突的内容。Base Model 不会仅凭下一 Token 目标自动形成统一的帮助性、安全性和拒绝策略。

### 工具使用协议

它可能见过代码或 API 文本，但不等于能稳定按照 Agent Runtime 规定的结构调用工具。

## “缺少”不等于完全没有

Base Model 可能在训练语料中见过问答、对话、礼貌表达和安全文本，所以它有时也能表现得像助手。

更准确的说法是：

> 这些行为没有通过专门后训练成为足够稳定、可控和一致的默认倾向。

Base 与 Chat 的区别是行为分布和稳定程度，不是简单的“一个会、一个完全不会”。

## 为什么 Base Model 仍然有价值

- 它保留较通用的预训练能力，可作为研究基础；
- 可以继续进行领域预训练；
- 可以使用不同指令数据塑造不同助手；
- 可以用于文本概率评估、补全或不需要聊天行为的任务；
- 便于比较后训练究竟改变了哪些行为。

## 能力与行为要分开

可以把两者先这样区分：

```text
能力：模型有没有形成完成某类任务所需的内部模式
行为：在当前提示和规则下，它是否稳定选择并表现出这种能力
```

模型可能“具有相关能力但没有按要求调用”，也可能“输出形式正确但内容能力不足”。后训练主要改善行为调用和分布，但也可能继续增强某些能力。

## 常见误解

### Base Model 不能回答问题

不一定。问答也可以被视为文本续写，它可能回答；问题在于稳定性和行为控制。

### Base Model 没做安全对齐，所以一定每次都输出危险内容

不能这样绝对化。它的输出仍取决于训练数据、Prompt 和概率分布，只是没有专门行为对齐提供的稳定边界。

### Instruct Model 只是在 Base Model 外面加了一句 System Prompt

不是。主差异通常包括后训练造成的参数变化；Prompt 只是运行时输入。
