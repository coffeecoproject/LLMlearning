# 基础模型是什么概览

> [!summary]
> Base Model 是完成基础预训练后选定的一组模型权重；它已经形成广泛的文本预测能力，但尚未必形成稳定的指令遵循、对话格式和行为边界。

## 它位于哪里

```text
初始化参数
→ 大规模预训练
→ Base Model
→ 后训练
→ Chat / Instruct Model
```

Base Model 不是训练起点，也不是“什么都不会”的模型。它是基础预训练的主要结果，同时又是后训练和许多模型适配路线的起点。

## 先处理一个中文歧义

中文“基础模型”有时也被用来翻译更宽泛的 **Foundation Model**。

- **Base Model**：通常指主要完成预训练、尚未经过特定指令对齐的模型版本；
- **Foundation Model**：更宽泛，强调一个大规模训练、可适配多种下游任务的基础模型家族或系统。

本小节讨论的是更具体的 **Base Model**。不同机构的命名不完全统一，判断时应优先看模型卡中的训练阶段，而不是只看名称。

## 一张最小对比表

| 阶段 | 主要训练来源 | 典型行为倾向 |
|---|---|---|
| 刚初始化 | 尚未从文本学习 | 能计算，但输出通常无意义 |
| Base Model | 大规模预训练文本 | 擅长条件续写，已形成广泛基础能力 |
| Chat / Instruct Model | Base Model 再经过指令、偏好等后训练 | 更倾向回答用户、遵守格式与行为要求 |

表格描述的是阶段差异，不保证所有模型都有完全相同的训练配方或行为表现。

## 最重要的边界

- Base Model 已经训练完成，不等于随机模型；
- Base Model 能回答一些问题，不等于已经稳定接受“用户指令”这一交互关系；
- Chat Template 能组织对话 Token，但模板本身不能替代后训练；
- Chat / Instruct Model 运行时仍然生成下一个 Token，并没有换成另一套基本 Transformer 原理；
- API 中的商业模型是模型产品，不能仅根据产品名推断内部是否公开存在某个 Base Checkpoint。

## 学完后的判断标准

你应该能够解释：

1. 为什么 Base Model 既是训练结果，又可以成为下一阶段的起点；
2. 为什么它具备知识和代码能力，却可能不按用户要求回答；
3. 为什么 Base 与 Instruct 的差异主要来自训练阶段和参数，而不只是 Prompt 格式；
4. 为什么“模型权重”和用户最终调用的“模型产品”不是同一个层级。
