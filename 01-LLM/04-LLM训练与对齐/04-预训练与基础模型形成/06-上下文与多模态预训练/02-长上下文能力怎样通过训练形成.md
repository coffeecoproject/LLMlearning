# 长上下文能力怎样通过训练形成

> [!summary] 一句话理解
> 长上下文能力通常通过位置机制适配、真实长序列数据和继续参数更新共同形成；训练常从短序列逐步扩展到长序列，以降低成本和训练不稳定性。

## 所属阶段

**训练阶段。** 本篇解释模型开发者怎样让 Base Model 学会处理更长序列，不讨论 Runtime 怎样为长请求分配 KV Cache 或多张 GPU。

## 为什么不从最长序列开始训练全部数据

长序列 Attention 需要处理更多 Token 之间的关系，训练成本和显存需求会明显增加。

如果大量早期样本本来就很短，把所有训练都强行放进最长窗口，可能造成：

- 大量无意义 Padding；
- 单个 Batch 能容纳的样本减少；
- 训练吞吐下降；
- 更高显存与通信压力；
- 在模型尚未学好基础语言时过早支付高昂长序列成本。

因此常见思路是：先形成基础能力，再进行专门的长上下文阶段。

## 一条简化训练路线

```text
短到中等长度的大规模预训练
→ 模型先学习语言、知识和代码规律
→ 调整或扩展位置机制
→ 加入更长且有真实远距离关系的数据
→ 继续训练参数
→ 用多种长上下文任务评估
```

不同模型不一定严格采用相同阶段，但这条路线能说明每一步的必要性。

## 第一步：结构必须能够表示更远位置

模型首先要能区分更长序列中的位置。

例如，原来训练到 8K，现在希望扩到 128K，开发者可能需要调整：

- RoPE 的频率相关设置或缩放方案；
- 最大位置范围相关配置；
- Attention 或长序列实现；
- 训练与推理使用的位置编号规则。

这里不是简单“加入更多位置数字”。位置表示必须在更长范围内仍然让 Attention 得到可用的相对关系。

具体结构已在 [[05-RoPE的作用位置与直觉|RoPE 的作用位置与直觉]] 介绍，本篇不展开公式。

## 第二步：模型必须真的看到长序列

假设模型只训练以下样本：

```text
第 1～100 个 Token 内就能找到答案
```

即使把样本填充到 100K，模型仍然没有充分理由学习跨越很远的位置。

有效的长上下文数据应包含真实的远距离依赖，例如：

- 长篇文章后面的问题依赖前面的定义；
- 多份文档需要交叉比较；
- 长代码仓库片段需要追踪定义与调用；
- 长视频后面的问题依赖早先事件；
- 长 Agent 轨迹需要保持早先目标和约束。

关键不是“样本看起来很长”，而是正确预测需要使用远处信息。

## 第三步：继续执行相同的参数更新机制

长上下文训练并没有发明另一种神秘学习方式。它仍然可以使用已经学过的主线：

```text
长序列样本
→ Forward
→ Logits
→ Loss
→ Backward
→ 更新模型参数
```

区别在于输入更长、位置范围更大、数据依赖更远，因此参数收到新的训练信号。

训练后模型才可能在远距离位置上形成更合适的 Attention 和内部表示。

## 为什么常常逐步增加长度

可以用教学路线理解：

```text
8K → 16K → 32K → 64K → 128K
```

逐步扩展有两个直观目的：

1. 不让位置分布和训练难度一次变化过大；
2. 逐阶段观察长上下文能力是否提升，同时检查短上下文能力是否退化。

这类似课程从短文章逐渐升级到长材料，但真实训练改变的是参数与位置关系，并不是模型像人一样在课堂中阅读。

## 一个真实开放模型案例：Llama 3.1

Meta 的 Llama 3 报告公开了一条具体路线：

```text
初始预训练
→ 长上下文预训练
→ Annealing 收尾阶段
```

报告描述其长上下文阶段将长度从 8K 分六个阶段逐步扩展至 128K，并使用约 800B 训练 Token。最终 Llama 3.1 模型支持最高 128K 上下文。

这个案例说明：

```text
128K 并非只靠修改配置得到
→ 还进行了专门、渐进的长上下文训练
```

> [!source]
> 来源：[The Llama 3 Herd of Models](https://arxiv.org/abs/2407.21783)，Meta，2024；[Introducing Llama 3.1](https://ai.meta.com/blog/meta-llama-3-1/)，Meta，2024。核对日期：2026-07-29。

## 多模态模型为什么也需要长上下文训练

图片可能变成大量视觉表示，视频还会包含多帧。它们与文字放在一起后，整条输入序列可能很快变长。

Qwen2.5-VL 技术报告公开的预训练路线包括：

| 阶段 | 主要数据 | 训练序列长度 |
|---|---|---:|
| Visual Pre-Training | 图片描述、视觉知识、OCR | 8,192 |
| Multimodal Pre-Training | 加入文本、图文交错、VQA、视频等 | 8,192 |
| Long-Context Pre-Training | 加入长视频、长 Agent 轨迹、长文档 | 32,768 |

这再次展示了“数据内容”与“训练长度”需要一起变化。

> [!source]
> 来源：[Qwen2.5-VL Technical Report](https://arxiv.org/abs/2502.13923)，Qwen Team，2025。报告中的阶段和数字属于 Qwen2.5-VL，不应视为所有模型的统一配方。核对日期：2026-07-29。

## 为什么还要保留短文本数据

如果长上下文阶段只关注超长样本，模型原有的短文本质量可能受到影响。

训练数据常需要混合：

```text
短文本能力
+ 中等长度理解
+ 长距离检索与整合
→ 尽量兼顾不同使用场景
```

所以目标不是让所有样本都变长，而是让长度分布与能力目标相匹配。

## 训练完成后怎样确认真的学会了

至少需要分层评估：

1. **基础可运行性**：目标长度能否稳定计算；
2. **远距离检索**：能否找到远处明确事实；
3. **跨段整合**：能否组合多处信息；
4. **位置稳定性**：信息位于开头、中间和结尾时是否都能利用；
5. **短上下文保持**：扩展长度后原有能力是否退化；
6. **真实任务**：长代码、长文档或长视频是否真正受益。

标称窗口长度只能回答第一层的一部分。

## 与运行时优化的边界

训练解决“参数是否学会利用长距离信息”。运行阶段还要解决：

- Prefill 需要多长时间；
- KV Cache 占多少显存；
- 一次能并发多少请求；
- 是否需要 Context Parallel；
- 服务是否对 API 输入设置更小上限。

因此一个模型训练支持 128K，不代表每个部署服务都会允许用户用满 128K。

## 常见误解

### 长上下文训练就是把短文档拼得很长

不够。拼接只能增加长度；如果答案不需要远距离信息，训练信号仍可能很弱。

### 长度必须一次从 8K 改到 128K

不是。真实模型可以分阶段扩展，具体路线取决于位置机制、数据和预算。

### 训练长度越长，模型所有能力都会提高

不一定。资源分配、数据质量和短文本能力保持都需要独立检查。

### 运行时多放几次长文档，模型就会永久适应

不会。普通推理不更新参数。

## 理解检查

1. 为什么长序列训练数据必须包含真实远距离依赖？
2. 分阶段增加训练长度主要解决什么问题？
3. 为什么训练支持 128K，不等于服务一定向用户开放 128K？
