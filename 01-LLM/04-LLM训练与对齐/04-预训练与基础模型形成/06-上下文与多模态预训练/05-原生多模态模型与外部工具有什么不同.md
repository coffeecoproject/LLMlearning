# 原生多模态模型与外部工具有什么不同

> [!summary] 一句话理解
> 原生或联合多模态让视觉、音频等表示进入模型内部的训练和计算；外部工具路线先由独立程序提取结果，再把结果作为文本或结构化数据交给 LLM，两者可以组合，但信息路径和可验证性不同。

## 所属阶段

本篇主要比较 **系统结构**，同时标注训练和运行边界：

- 多模态模型的内部连接在训练阶段形成；
- Agent 是否调用 OCR、语音识别或图像分析工具，是运行阶段的编排决定；
- 用户只看到“上传图片”接口时，不一定能从外部判断服务内部采用哪种路线。

## 先区分四种常见形态

### 形态一：外部转换管线

```text
语音
→ 独立语音识别模型
→ 文字
→ 文本 LLM
→ 回答文字
→ 独立语音合成模型
→ 声音
```

中间的文本 LLM 实际只看到了转写文字。原始语气、背景声或多人重叠说话可能在转写过程中丢失。

### 形态二：视觉编码器与 LLM 组成一个多模态模型

```text
图片 → Vision Encoder → Projector ─┐
                                     ├→ LLM → 文字回答
文字 → Text Tokenizer → Embedding ──┘
```

视觉表示直接参与模型计算，相关组件通过多模态数据进行训练。LLaVA、Qwen2.5-VL 等公开模型可以帮助理解这类结构。

它们内部仍然可以包含不同组件，所以“一个多模态模型”不等于“内部没有编码器”。

### 形态三：更统一的端到端多模态模型

```text
文字 / 图片 / 音频 / 视频表示
→ 同一个联合训练的神经网络系统
→ 文字 / 音频 / 图像等输出
```

这种路线希望减少先转写、再推理、再合成造成的信息损失与延迟。不同模态仍可能有各自的前后处理或表示方式，“端到端”也不必理解成所有原始字节都经过完全相同的层。

### 形态四：Agent 调用外部工具

```text
用户上传发票图片
→ Agent 决定调用 OCR 工具
→ OCR 返回文字与坐标
→ LLM 根据工具结果分析
→ Agent 校验并输出
```

LLM 可以是纯文本模型，也可以同时是多模态模型。工具调用是模型外的执行循环，不是多模态预训练本身。

## 一个真实例子：同一张收据的两条路径

用户问：

```text
“这张收据总金额是多少？”
```

### 原生视觉路线

```text
收据图片
→ 视觉表示直接进入多模态模型
→ 模型生成“总金额是 128 元”
```

优势是模型可以结合文字、版面和其他视觉信息整体判断。

风险是：如果模型看错数字，它可能仍然自然地给出答案，外部系统不一定知道错在哪里。

### OCR 工具路线

```text
收据图片
→ OCR 工具
→ {"total": "128.00", "currency": "CNY", "box": [...]}
→ LLM 解释结果
```

优势是中间结果可以保存、检查、交叉验证，也可以换用专门票据解析器。

风险是：OCR 自己也会识别错误，而且可能丢失未被其输出结构保留的视觉信息。

### 组合路线

```text
多模态模型直接查看图片
+ OCR 返回结构化结果
+ 规则检查金额字段
→ 对比后生成答案
```

在高准确性任务中，原生感知与外部工具往往不是二选一，而是相互提供证据。

## “原生多模态”不是一个足够精确的架构说明

这个词可能被用于不同含义：

- 从预训练开始就混合多种模态；
- 已有 LLM 后接视觉组件，再进行联合训练；
- 同一模型可以直接接收多类输入；
- 同一网络还能直接生成音频或图像；
- 产品 API 对用户隐藏了内部多个模型。

因此看到“原生多模态”时，应继续问：

```text
哪些模态进入了同一个模型？
表示由什么组件产生？
哪些组件一起训练？
输入和输出分别支持什么？
公开资料能证明到哪一步？
```

## OpenAI 的公开案例怎样理解

OpenAI 在 GPT-4o 发布资料中说明，早期 ChatGPT Voice Mode 使用三段管线：

```text
语音转文字
→ GPT-3.5 / GPT-4 处理文字
→ 文字转语音
```

OpenAI 同时说明 GPT-4o 是跨文本、视觉和音频端到端训练的单一新模型，输入与输出由同一神经网络处理。

这个公开案例恰好说明两种路线的差异：早期管线会让主 LLM 丢失部分音调、多人说话和背景声音信息；联合模型有机会直接利用这些信号。

但公开资料没有披露 GPT-4o 的完整层级、编码器配置和训练数据细节，因此不能进一步声称它具体采用了哪种未公开内部结构。

> [!source]
> 来源：[Hello GPT-4o](https://openai.com/index/hello-gpt-4o/)，OpenAI，2024。核对日期：2026-07-29。

## API 接受图片能证明什么

它能证明服务接口支持图片输入。

它不能单独证明：

- 图片由哪个模型处理；
- 是否先经过 OCR 或安全过滤；
- 内部是不是一个端到端网络；
- 图片产生多少视觉 Token；
- 视觉组件和语言组件是否从头联合预训练。

如果提供方没有发布模型卡或技术报告，这些内部细节应标记为未知。

## Agent 为什么仍然需要工具

即使底层模型原生看图，外部工具仍有独立价值：

- 读取实时摄像头或本地文件需要权限；
- 专业 OCR、医学影像或工业检测工具可能更专门；
- 工具可以返回坐标、置信度和可复核记录；
- Agent 可以比较多个结果并设置验收规则；
- 工具可以执行动作，而模型输出本身只是表示。

所以：

```text
多模态模型
→ 扩大模型能够理解的输入类型

Agent + 工具
→ 扩大系统能够访问、验证和执行的范围
```

## 多模态模型会让上下文变得更长

图片、音频和视频转成模型表示后，也会占用模型计算位置或其他内部容量。

```text
文字 Token
+ 图片视觉位置
+ 视频帧表示
+ 输出 Token
→ 共同受到模型和服务容量限制
```

不同 API 对“图片折算多少 Token”的计费和实现规则可能不同；这属于具体服务规则，不能从通用模型原理推导。

## 三条路线怎样选择

| 需求 | 更可能采用的路线 |
|---|---|
| 理解整张自然图片与文字关系 | 多模态模型 |
| 精确提取可复核字段 | 专用工具，必要时配合多模态模型 |
| 保留语调和背景声音 | 直接音频多模态模型更有机会 |
| 调用摄像头、打开文件、点击界面 | Agent 与工具权限 |
| 高风险任务要求证据链 | 工具结果、规则和外部验证 |

这张表是工程选择方向，不代表任何路线天然可靠。

## 常见误解

### 一个 API 能收图片，就一定是端到端原生多模态

不能这样判断。服务内部可能隐藏多个组件。

### 原生多模态模型不再需要 OCR

不一定。专用 OCR 仍可能提供更精确、结构化、可复核的结果。

### Agent 调用视觉工具后，文本 LLM 就变成了多模态模型

没有。系统获得了多模态处理能力，但文本 LLM 本身接收的仍可能只是工具返回的文字或 JSON。

### 单一神经网络意味着所有模态使用完全相同的 Tokenizer

不是。不同模态仍可能需要各自的编码、采样和输出表示。

## 理解检查

1. 文本 LLM 使用 OCR 结果与视觉表示直接进入模型，有什么不同？
2. 为什么“API 支持上传图片”不能证明内部一定是单一端到端模型？
3. 原生多模态模型已经能看图时，Agent 为什么仍可能调用外部工具？

## 本小节结论

```text
长度配置
≠ 长上下文能力

多模态输入接口
≠ 多模态理解能力

多模态模型能力
≠ 工具访问与执行能力
```

三组边界分清后，就能准确判断一项能力究竟来自模型训练、Runtime 支持，还是 Agent 的外部编排。
