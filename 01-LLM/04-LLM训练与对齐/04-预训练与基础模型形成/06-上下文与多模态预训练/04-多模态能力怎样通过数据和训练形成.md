# 多模态能力怎样通过数据和训练形成

> [!summary] 一句话理解
> 编码器和连接层只让不同模态能够进入计算；模型还要通过图片—文字、音频—文字、视频—文字等关联数据反复更新参数，才会逐渐把不同表示与语言含义和任务行为对应起来。

## 所属阶段

本篇需要明确分成三个层次：

1. **组件预训练**：先让视觉或音频编码器学会提取本模态特征；
2. **多模态预训练与表示对齐**：让不同模态与语言模型建立联系；
3. **多模态后训练**：让模型学会按指令回答、拒绝和调用工具。

本专题重点是前两层。第三层只用于说明边界，详细行为对齐将在后续模块学习。

## 为什么有 Encoder 仍然不够

假设图片经过 Vision Encoder 后产生：

```text
[视觉向量1] [视觉向量2] [视觉向量3] ……
```

这些向量可能包含颜色、形状和布局，但语言模型一开始不一定知道：

```text
哪种模式对应“苹果”
哪种模式对应“在桌子左边”
哪种模式对应图片里的文字
```

连接层可以让向量宽度匹配，却不会自动赋予这些跨模态含义。关联必须从数据和 Loss 中学习。

## 第一类数据：图片与描述

最直观的样本是：

```text
[一张红苹果放在木桌上的图片]
文字：一只红苹果放在木桌上。
```

训练过程中，模型根据视觉表示和前文预测描述中的 Token。预测错误产生 Loss，再通过 Backward 更新相关参数。

经过许多不同图片和描述，模型才可能逐渐建立：

```text
视觉模式 ↔ 物体词语
空间关系 ↔ 方位表达
场景组合 ↔ 整体描述
```

一张图片不会让模型学会完整的“苹果概念”；能力来自大量、多样且相互约束的样本。

## 第二类数据：图文交错材料

真实文章可能是：

```text
第一段文字
图片 A
对图片 A 的解释
第二段文字
图片 B
结合两图的结论
```

这种 Interleaved Image-Text Data 不只是给图片配一句标题，还让模型学习图片与前后文章怎样共同表达内容。

它有助于多图理解和多模态 In-Context Learning，但数据可能很嘈杂：网页图片可能只是装饰，与正文没有真正关系。

因此数据清理不仅要看图片是否清晰，还要看图文是否相关、互补和信息密度是否平衡。

## 第三类数据：针对具体视觉能力的样本

不同数据类型会提供不同训练机会：

| 数据 | 示例 | 主要训练机会 |
|---|---|---|
| OCR | 图片中的招牌文字及转写 | 识别图中文字 |
| VQA | 图片 + 问题 + 答案 | 根据视觉内容回答问题 |
| Grounding | 描述 + 边界框或点 | 把语言对象对应到具体位置 |
| 文档解析 | 表格、图表、版面 + 结构结果 | 理解布局与结构 |
| 视频描述 | 视频片段 + 事件描述 | 联系画面变化与时间 |
| GUI 轨迹 | 截图 + 操作步骤 | 识别界面状态与动作关系 |

如果训练数据中几乎没有精确坐标、复杂表格或长视频，仅凭普通图片描述不一定自然产生这些能力。

## 音频训练数据提供什么信号

音频能力也可以由不同配对关系形成：

```text
语音 ↔ 文字转写
语音 ↔ 说话人或情绪标签
环境声音 ↔ 事件描述
语音问题 ↔ 语音或文字回答
音乐片段 ↔ 风格与结构描述
```

如果系统先把语音转成文字再交给 LLM，主模型主要学习文字内容；如果模型直接接收音频表示，它才有机会利用语调、停顿、背景声音等非文字信息。

是否真的获得这些能力，仍取决于训练数据是否保留并标注了相应信号。

## 一个简化的下一 Token 训练例子

输入：

```text
[图片表示]
问题：桌上有什么？
答案：一个红色苹果。
```

模型生成答案时仍可以执行：

```text
预测“一个”
→ 追加后预测“红色”
→ 再预测“苹果”
```

它与文本 LLM 的自回归生成主线相同；变化在于上下文中多了经过训练连接的视觉表示。

训练实现可能只对答案部分计算语言 Loss，也可能加入视觉编码器自己的目标或其他跨模态目标。不同模型配方不同，不能假定所有多模态模型只有一种 Loss。

## 为什么常常分阶段训练

如果视觉编码器、Projector 和 LLM 一开始全部一起大幅更新，训练可能不稳定，也可能破坏 LLM 已有的语言能力。

一种常见路线是：

```text
已有 Vision Encoder + 已有 LLM
→ 先训练连接层或视觉侧，使表示初步对齐
→ 再开放更多参数做联合多模态训练
→ 最后进行视觉指令微调
```

阶段设计可以帮助不同组件逐渐建立连接，也能控制训练成本。

但它不是唯一方案。有些模型会从更早阶段联合训练多个模态，有些会冻结部分组件，有些会使用离散的统一 Token。阅读技术报告时必须看具体配方。

## 预训练与指令微调不要混在一起

### 多模态预训练主要解决

```text
视觉 / 音频表示与语言有什么关系？
怎样预测与这些表示相关的内容？
```

### 多模态指令微调主要解决

```text
用户问“请比较两张图”时应该怎样回答？
要求输出 JSON 坐标时怎样遵循格式？
遇到不确定或危险请求时怎样处理？
```

基础感知和任务行为相互依赖，但不是同一阶段。

## 真实模型观察：LLaVA

LLaVA 从预训练视觉编码器和已有 LLM 出发，通过连接层建立视觉—语言联系，再使用视觉指令数据训练对话行为。

它说明：

```text
连接视觉表示
≠ 自动成为视觉助手

还需要视觉—语言对齐数据
+ 指令形式的数据
```

> [!source]
> 来源：[Visual Instruction Tuning](https://arxiv.org/abs/2304.08485)，Liu 等，2023。核对日期：2026-07-29。

## 真实模型观察：Qwen2.5-VL

Qwen2.5-VL 报告公开了多阶段路线：

1. 训练视觉侧，使用图片描述、视觉知识和 OCR 等数据；
2. 开放全部参数，加入图文交错、VQA、数学、视频、Agent 和纯文本数据；
3. 增加长视频、长文档和长 Agent 数据，并把训练序列扩展到 32,768；
4. 预训练后再进行 SFT 和 DPO。

报告称其多模态预训练语料从 Qwen2-VL 的约 1.2T Token 扩展到约 4.1T Token。这里的 Token 统计包含其多模态训练口径，不能与纯文本模型数字简单横向比较。

> [!source]
> 来源：[Qwen2.5-VL Technical Report](https://arxiv.org/abs/2502.13923)，Qwen Team，2025。核对日期：2026-07-29。

## 为什么还要混入纯文本数据

多模态联合训练可能改变语言模型参数。保留纯文本数据有助于：

- 维持已有语言和代码能力；
- 让模型在没有图片时仍能正常工作；
- 避免全部训练信号被某一模态主导；
- 学习图文交错而不是只学习固定问答格式。

这与长上下文训练保留短文本数据的原因相似：增加新能力时还要防止旧能力明显退化。

## 多模态数据更多也不保证理解正确

可能的问题包括：

- 图片和描述不匹配；
- OCR 标签错误；
- 视频采样错过关键时刻；
- 合成数据重复模型原有错误；
- 数据只有物体名称，没有空间或因果关系；
- 训练场景与真实输入差异过大。

所以仍需要按图片理解、OCR、空间定位、视频时间关系和跨模态推理分别评估。

## 常见误解

### 给 LLM 接上 Vision Encoder，就已经会看图

不够。还要训练连接和跨模态关系。

### 图片描述数据能自动训练出所有视觉能力

不能。坐标定位、文档解析和长视频理解通常需要更有针对性的数据。

### 多模态训练会自动保留原有文字能力

不一定。参数联合更新可能带来能力干扰，需要数据混合与评估。

### 多模态预训练和视觉指令微调是一回事

不是。前者重点建立表示与基础能力，后者重点塑造用户交互行为。
