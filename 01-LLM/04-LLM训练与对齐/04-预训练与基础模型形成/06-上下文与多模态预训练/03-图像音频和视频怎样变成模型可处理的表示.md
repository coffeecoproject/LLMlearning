# 图像、音频和视频怎样变成模型可处理的表示

> [!summary] 一句话理解
> 文本先由 Tokenizer 变成 Token ID，再由 Embedding 变成向量；图片、音频和视频通常先由各自的编码器或离散化方法变成一串表示，再映射到语言模型能够共同处理的表示空间。

## 所属阶段

**训练阶段与运行阶段共同使用同一条表示路线。**

- 训练阶段让视觉、声音与语言表示建立关联；
- 运行阶段使用已经训练好的编码器和连接结构处理用户输入，不临时发明新的映射。

本篇先解释数据怎样进入模型，不讨论这些能力怎样被训练；训练过程在下一篇。

## 为什么图片不能直接进入文本 Tokenizer

文本 Tokenizer 接收的是字符串，例如：

```text
苹果在桌上
→ Token ID
→ Token Embedding
```

图片原始内容通常是一组像素，音频是一段随时间变化的采样，视频则同时包含画面和时间变化。

```text
图片：宽 × 高 × 颜色通道
音频：时间上的声音采样
视频：许多按时间排列的画面，可能还有声音
```

它们不是普通文字，因此不能假设文本 Tokenizer 会把一张照片拆成 BPE Subword。

## 常见的图像输入路线

可以先建立一条最常见的概念路线：

```text
图片
→ 切成 Patch 或其他视觉单元
→ Vision Encoder 提取视觉特征
→ Projector / Connector 调整表示
→ 一串视觉表示进入语言模型
→ 与文字共同参与后续计算
```

### Patch 是什么

Patch 是图片中的一小块区域。教学上可以把一张图片想象成四块：

```text
┌────┬────┐
│ P1 │ P2 │
├────┼────┤
│ P3 │ P4 │
└────┴────┘
```

每块经过视觉模型后变成一个向量。真实模型可能有更多 Patch、不同分辨率策略或进一步压缩，不能把四块当成固定设计。

### Vision Encoder 是什么

Vision Encoder 是负责从图片中提取视觉表示的神经网络。例如它可能让不同位置的向量逐渐包含：

- 颜色和纹理；
- 形状和物体部分；
- 文字、布局与场景；
- 与其他区域的关系。

“提取特征”不是把图片完整复制到某个向量，而是形成适合后续任务使用的数学表示。

### Projector 或 Connector 是什么

视觉编码器的输出宽度和分布不一定与语言模型的 Hidden State 匹配，所以中间常有连接层。

教学示意：

```text
Vision Encoder 输出：[0.2, 0.7, -0.1]
                        3 个数

LLM Hidden Size：      4 个数

Projector 映射后：     [0.4, -0.2, 0.8, 0.1]
```

这里的数字是虚构示例。Projector 的真实意义不只是补一个数字，而是通过训练把视觉表示转换到语言模型可用的宽度和分布。

## 视觉表示进入语言模型后是什么形状

假设一张图片最终产生 4 个视觉位置，每个表示宽度等于 `hidden_size = 4`：

```text
视觉表示形状：[4, 4]
             ↑  ↑
        4 个位置  每个位置 4 维
```

文字也会形成一串宽度为 4 的向量。模型可以把它们按既定格式组合：

```text
[图片开始] [视觉1] [视觉2] [视觉3] [视觉4] [图片结束]
问题：桌上有什么？
```

这些“视觉1～4”是教学标签。真实系统可能使用特殊占位 Token、独立位置编码、交叉注意力或其他连接方式。

## “视觉 Token”是不是文本 Token

它们都可以占据序列位置，所以工程资料常把视觉表示称为 Visual Token。

但需要区分：

```text
文本 Token
→ 通常来自文本 Tokenizer 和 Vocabulary Lookup

视觉 Token
→ 可能是视觉编码器产生的连续向量
→ 不一定拥有文本词表中的 Token ID
```

因此“图片用了 1,000 个视觉 Token”通常表示它贡献了约 1,000 个模型处理位置，不一定表示词表新增了 1,000 个图片单词。

## 分辨率为什么会影响视觉 Token 数

如果图片分辨率更高或被切成更多区域，视觉表示数量可能增加：

```text
小图片 → 较少视觉位置
大图片 → 较多视觉位置
```

更多位置可以保留更细节的信息，但也会：

- 占用更多上下文位置；
- 增加 Attention 计算；
- 增加 Prefill 和显存成本。

不同模型会采用固定分辨率、动态分辨率、区域裁剪或视觉 Token 压缩等方案。

## 音频怎样形成表示

音频常见路线可以简化成两类。

### 连续特征路线

```text
声音波形
→ 分成短时间片段
→ Audio Encoder
→ 一串音频向量
→ 映射后与语言模型连接
```

### 离散音频 Token 路线

```text
声音波形
→ Audio Codec / Tokenizer
→ 一串离散音频单位
→ 模型处理或生成这些单位
```

前者强调连续特征，后者把声音压缩成可预测的离散编号。具体模型可能组合使用，两者不能一概而论。

音频中除了文字内容，还可能包含语调、节奏、说话人和环境声音。先转写成文字会丢失其中一部分信息。

## 视频怎样形成表示

视频不是“一张更大的图片”。它包含空间和时间两个维度。

简化路线：

```text
视频
→ 选择或采样多个 Frame
→ 每个 Frame 提取视觉表示
→ 加入时间顺序或时间位置
→ 与文字问题共同进入模型
```

如果把每一帧的所有细节都保留，序列会迅速变得非常长。因此视频模型通常还要处理：

- 采样多少帧；
- 不同帧率怎样对应真实时间；
- 哪些区域或时刻需要更高精度；
- 怎样压缩重复画面。

## 开放模型观察

### LLaVA：视觉编码器加连接层

LLaVA 论文公开了一种容易理解的路线：把预训练视觉编码器与语言模型连接，并通过视觉指令数据训练它们的联系。

这个案例适合理解：多模态模型可以从已有视觉模型和已有 LLM 出发，中间增加跨模态连接，而不一定从零训练所有组件。

### Qwen2.5-VL：动态视觉位置

Qwen2.5-VL 技术报告描述了 Vision Transformer、Cross-modal Projector 和 LLM 的常见结构，并让不同尺寸图片动态产生不同数量的视觉 Token。视频还加入与绝对时间对齐的位置表示。

这个案例说明：多模态表示不仅要解决“看到了什么”，还要保留图片中的空间位置和视频中的时间关系。

> [!source]
> 来源：[Visual Instruction Tuning](https://arxiv.org/abs/2304.08485)，Liu 等，2023；[Qwen2.5-VL Technical Report](https://arxiv.org/abs/2502.13923)，Qwen Team，2025。核对日期：2026-07-29。

## 表示能够进入，不等于已经理解

连接好形状只解决：

```text
视觉或音频表示
→ 能够进入语言模型计算
```

要让模型知道“这个视觉表示对应红苹果”“这段声音是讽刺语气”，还需要配对数据、训练目标和参数更新。

这与 Token Embedding 的学习类似：向量形式本身不是语义，语义关系来自训练。

## 常见误解

### 图片先被 OCR 成文字，所以模型才能看图

有些系统确实先调用 OCR，但原生视觉语言模型通常还能接收视觉表示。OCR 只是其中一种信息来源或工具。

### Visual Token 一定存在于文本 Vocabulary 中

不一定。它可能是直接进入模型的一段连续向量表示。

### Projector 只是改变数组长度，没有学习作用

不是。它通常包含可训练参数，用来建立跨模态表示连接。

### 视频只是把每一帧原样全部放进模型

通常不是。真实系统需要采样、压缩和时间位置设计，否则 Token 数与计算成本会非常高。
