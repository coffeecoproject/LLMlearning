# 预训练能形成什么，又不能保证什么

> [!summary] 一句话理解
> 预训练能让模型获得强大的语言预测、知识关联和模式组合能力，但下一 Token 目标不会自动赋予事实核验、稳定服从、长期记忆、现实行动和完成验收能力。

## 所属阶段

这是 **预训练部分的最终边界检查**。

理解这些边界不是否定模型能力，而是为了把后训练、Runtime、RAG、Agent 和评估放在正确位置。

## 预训练真正优化了什么

核心目标仍然是：

```text
给定前面的 Token
→ 提高正确下一个 Token 的概率
```

为了在海量不同文本上持续降低 Loss，模型参数不得不学习许多可复用规律。

所以“只是预测下一个 Token”与“只能做简单补字”不是一回事。任务形式简单，但要在复杂数据上做好它，需要形成复杂内部表示。

## 能形成的第一类能力：语言结构

模型会逐渐学习：

- 词语搭配；
- 句法与语序；
- 段落结构；
- 文体与格式；
- 指代和上下文关系；
- 多语言之间的部分联系。

因此 Base Model 能进行连贯续写，而不是只输出高频词。

## 能形成的第二类能力：知识与概念关联

训练资料中反复出现：

```text
北京 ↔ 中国 ↔ 首都
牛顿 ↔ 物理 ↔ 经典力学
HTTP ↔ 请求 ↔ 响应
```

参数会形成支持这些预测的分布式关系。

这让模型能够回答大量知识问题，但知识不是一张可逐行查询、自动更新和保证正确的数据库表。

## 能形成的第三类能力：代码与结构模式

如果训练中包含高质量代码，模型可能学习：

- 语法；
- 常见 API 用法；
- 函数和模块结构；
- Bug 修复模式；
- 测试与错误信息之间的联系。

但它仍可能引用不存在的 API，漏掉仓库约束，或生成局部正确但系统错误的修改。

## 能形成的第四类能力：上下文适应

模型可以根据当前输入临时适应：

```text
用户给出三个示例
→ 模型从示例中识别格式
→ 按相似形式回答第四个问题
```

这叫 In-Context Learning。它改变本次计算中的 Hidden State 和 KV Cache，不自动改变模型 Weight。

所以它表现得像“现场学会了”，但下次新请求如果没有这些示例，能力不一定保留。

## 能形成的第五类能力：一些组合与推理行为

大规模训练可能让模型学到：

- 分解问题的文本模式；
- 根据条件逐步变换表示；
- 模仿证明、计算和规划过程；
- 组合多个已学规律解决新问题。

但推理过程仍通过一连串 Token 生成实现，每一步都可能偏离。它不是自动附带形式证明器或真实世界模拟器。

## 为什么预训练不能保证事实正确

训练目标检查的是：

```text
真实训练文本的下一个 Token 是什么？
```

它通常不在每次输出时检查：

```text
这句话今天是否仍然真实？
来源是否可靠？
是否与数据库记录一致？
```

训练资料还可能过时、冲突、错误或缺失。因此模型可以生成语言上很像正确答案的错误内容。

## 为什么预训练不能保证遵循用户意图

互联网文本包含小说、网页、问答、代码和争论。Base Model 学到的是多种文本如何延续，而不是唯一的“助手角色”。

用户输入：

```text
请把下面内容总结成三点：……
```

Base Model 可能总结，也可能继续编写更多类似指令或模拟后续对话。

SFT 和偏好对齐才会进一步强化：

```text
把输入识别为用户请求
→ 采用助手角色
→ 按期望格式回应
```

## 为什么预训练不能保证计算和推理正确

模型可以学会常见计算模式，但生成过程中的局部高概率选择不等于全局证明。

```text
前几步看起来合理
→ 某一步选错 Token
→ 后续继续围绕错误前提生成
→ 最终答案自然但错误
```

更强模型和推理训练可以降低错误率，但工程系统仍需要测试、计算器、代码执行或形式验证。

## 为什么预训练不会自动获得最新知识

训练 Weight 反映训练截止前的统计关系。训练结束后，现实世界继续变化：

- 法律和价格变化；
- 软件版本更新；
- 公司人员变化；
- 新论文和新闻出现。

普通运行不会自动更新参数，因此实时信息需要搜索、数据库、RAG 或新的训练过程。

## 为什么预训练不提供长期记忆

需要分开三类状态：

```text
Weight
→ 训练形成的长期参数

Context / KV Cache
→ 当前请求中的临时工作状态

Agent Memory / Database
→ 模型外可检索、可更新的持久信息
```

Base Model 不会因为与某个用户聊天，就自动在 Weight 中建立该用户的永久档案。

## 为什么预训练不会执行现实动作

模型原生输出的是 Token 或其他模态表示。

```text
“我已经修改文件”
```

只是一段文字，除非外部系统真的：

- 授予文件权限；
- 调用写入工具；
- 检查修改结果；
- 运行测试；
- 记录操作证据。

这些属于 Agent 与工具层。

## 为什么更强模型仍然需要 Agent 闭环

模型增强通常会提高：

- 意图理解概率；
- 代码与计划质量；
- 首次尝试成功率；
- 长任务中的连贯性。

但复杂任务的完成状态存在模型外部：

```text
文件是否真的修改？
测试是否通过？
数据库迁移是否成功？
部署环境是否健康？
用户约束是否全部满足？
```

Agent 的工具调用、状态管理、验证和失败恢复，用来把概率提案连接到可观察结果。

## 一张层级边界表

| 层级 | 主要增加什么 | 不能替代什么 |
|---|---|---|
| 预训练 | 基础语言、知识、代码和组合能力 | 指令对齐、实时事实、外部执行 |
| 后训练 | 助手行为、偏好、安全和推理风格 | 权威事实来源、工具结果 |
| Runtime | 高效执行模型和生成 | 目标规划、长期记忆 |
| RAG / Search | 外部资料与更新信息 | 模型判断和任务执行 |
| Agent | 规划、工具、状态和反馈循环 | 底层模型能力、真实验收证据 |
| Evaluation | 发现成功率与失败模式 | 直接提升能力，除非结果进入改进循环 |

这些层不是互相排斥，而是共同组成可靠系统。

## 开放模型与闭源模型都受这条边界影响吗

只要核心仍是通过概率建模和参数训练形成能力，这些基本边界就仍然存在。

闭源模型可能拥有更强后训练、工具系统、检索和产品编排，让边界在用户界面中不明显，但不能据此认定底层模型原生拥有数据库、文件权限或永久记忆。

判断时要继续追问：

```text
能力来自 Weight？
来自本次 Context？
来自 Runtime？
来自外部工具？
还是来自 Agent 工作流？
```

## 什么时候需要进一步训练

如果问题主要是：

```text
模型长期缺少某个领域的表达与规律
```

可以考虑 Continued Pretraining、SFT、LoRA 或蒸馏。

如果问题主要是：

```text
需要查询每天变化的数据
需要访问企业私有记录
需要执行和验收任务
```

通常更需要 RAG、工具和 Agent，而不是把所有信息反复写入 Weight。

## 常见误解

### 训练数据足够大，模型就不会幻觉

不会自动成立。数据规模不能改变“生成概率分布而非实时核验”的基本路径。

### 后训练能把 Base Model 的所有事实都纠正

不能。后训练数据有限，主要塑造行为，也不能保证覆盖全部知识错误。

### 模型参数更大后，Agent 就没有必要了

模型更强会改变 Agent 的分工和循环次数，但外部权限、实时状态和验收仍属于系统层。

### 使用工具后，模型输出就一定正确

也不一定。模型可能选错工具、误读结果或遗漏约束，因此仍需结构化状态和验证。

## 理解检查

1. 为什么简单的下一 Token 目标仍可能形成复杂能力？
2. 预训练知识与数据库记录有什么根本区别？
3. In-Context Learning 为什么不等于参数更新？
4. 模型能力增强后，Agent 的哪些职责仍然不能消失？

## 本专题结论

```text
预训练
→ 形成强大的概率模型和 Base Model

后训练
→ 塑造更可用的助手行为

Runtime
→ 高效执行模型

工具、记忆、验证与 Agent
→ 把模型能力连接到真实任务闭环
```

理解这条边界后，就可以进入训练工程：如此庞大的参数、数据和 Step，现实中怎样由多张 GPU 稳定完成。
