# 模型卡、技术报告、配置文件和权重分别能证明什么

> [!summary] 一句话理解
> 模型卡主要说明模型身份、用途和评估，技术报告说明公开的方法与实验，配置文件说明加载所需的结构字段，权重保存训练结果；它们互相补充，但任何单一文件都不能完整还原训练过程。

## 所属阶段

这是 **阅读与证据判断方法**，适用于训练、运行和模型选型。

目标不是学会部署 Hugging Face，而是以后看到模型资料时能够判断：

```text
这是发布事实？
这是根据文件得到的推断？
还是厂商根本没有公开？
```

## 先看四种资料各自负责什么

| 资料 | 主要回答 | 通常不能单独回答 |
|---|---|---|
| Model Card | 模型是谁、用途、版本、评估、限制 | 完整参数更新过程 |
| Technical Report | 架构思路、数据口径、训练阶段、实验 | 所有原始数据与每个超参数 |
| `config.json` | 程序怎样构造模型结构 | 参数学到了什么、数据来自哪里 |
| Weight 文件 | 训练完成后的参数数值 | 参数为什么变成这些值 |

还可能看到 Tokenizer 文件、`generation_config.json`、推理代码和许可证，它们属于不同证据。

## Model Card 能证明什么

模型卡可能公开：

- 精确模型名称和版本；
- Base、Instruct 或其他变体；
- 参数规模；
- 输入与输出模态；
- 上下文长度；
- 训练数据的高层说明；
- 评测结果；
- 适用范围、风险与许可证。

例如一个官方模型卡明确写：

```text
Model：Example-7B-Base
Type：Pretrained Causal Language Model
Context Length：128K
```

可以据此说“官方将这个版本发布为 Base Model，并标称支持 128K”。

但不能据此声称：

```text
它在任何 128K 任务上都可靠
它的训练数据已经完整公开
它使用了某个没有披露的内部算法
```

## Technical Report 能证明什么

技术报告通常比模型卡更深入，可能说明：

- 为什么选择某种架构；
- 数据总 Token 数和高层组成；
- 预训练分成哪些阶段；
- 使用什么训练目标；
- 长上下文或多模态怎样扩展；
- 与哪些基线比较；
- 哪些实验支持作者结论。

但技术报告仍可能省略：

- 完整数据清单和每条样本；
- 所有过滤阈值；
- 每个阶段精确混合比例；
- 全部训练代码、随机种子和故障处理；
- 内部失败实验；
- 产品服务额外使用的系统层。

所以“有论文”不等于“任何人都能完全复现”。

## `config.json` 能证明什么

配置文件主要告诉加载程序怎样创建兼容结构。

以 Qwen 官方 `Qwen2.5-7B` 配置为例，其中公开：

```json
{
  "hidden_size": 3584,
  "intermediate_size": 18944,
  "num_hidden_layers": 28,
  "num_attention_heads": 28,
  "num_key_value_heads": 4,
  "max_position_embeddings": 131072,
  "vocab_size": 152064,
  "tie_word_embeddings": false
}
```

这些字段可以支持以下结论：

- Residual 主干宽度是 3,584；
- 有 28 个 Transformer Layer；
- Query Head 与 KV Head 数不同，使用 GQA 类结构；
- 词表和位置范围按相应数字配置；
- 输入 Embedding 与输出权重不绑定。

但这些字段不能告诉我们：

- 某条知识储存在哪个参数；
- 具体训练文本是什么；
- 每个数据类别占比；
- 训练 Loss 曲线；
- 模型在真实任务上是否可靠；
- 运行服务是否开放完整配置长度。

> [!source]
> 来源：[Qwen2.5-7B 官方 `config.json`](https://huggingface.co/Qwen/Qwen2.5-7B/blob/main/config.json)。以上数字只适用于该明确版本。核对日期：2026-07-29。

## Weight 文件能证明什么

Weight 文件保存训练后参数，例如：

```text
Embedding Weight
Attention Weight
FFN Weight
Normalization 参数
Output Weight
```

结合配置与加载代码，可以检查：

- 参数张量是否存在；
- 张量形状是否匹配架构；
- 总参数量大致是多少；
- 模型能否执行 Forward；
- 运行输出与评测表现。

但只看训练后的数字，通常无法唯一反推出：

```text
它见过哪一条训练样本
某个参数由哪次更新造成
数据经过哪些完整过滤
训练按什么顺序进行
```

许多不同训练路径可能得到相近表现，最终权重不是完整训练日志。

## Tokenizer 文件是另一类证据

Tokenizer 相关文件可能证明：

- Vocabulary 内容和大小；
- 文本怎样切分；
- Token 与 ID 映射；
- Special Token；
- Normalization 与 Pre-tokenization 规则；
- BPE Merge 或 Unigram 模型数据。

它们不能证明 LLM 参数是否训练充分，也不能说明某种切分一定带来更强能力。

## `generation_config.json` 又是什么

它通常保存默认生成行为，例如：

```text
eos_token_id
temperature
top_p
do_sample
```

这些字段影响运行时怎样从 Logits 选 Token，不描述模型内部 Transformer 参数怎样训练。

修改生成配置可能改变回答风格和随机性，但不会重新训练 Weight。

## 推理代码能不能暴露训练架构

推理实现可以帮助确认：

- Weight 怎样加载；
- Forward 路径怎样计算；
- KV Cache 怎样组织；
- Tool Call 或 Chat Template 怎样解析；
- Runtime 支持哪些优化。

它通常不能完整揭示训练数据、训练集群和未发布的训练流程。

这也是为什么不能从 Codex CLI 源码反推出闭源 GPT 模型内部用了哪一种 Attention：CLI 位于 Agent 客户端层，不包含服务器模型的 Weight 和 Forward 实现。

## 三种结论标签

阅读模型资料时，建议主动使用三种标签。

### 已公开事实

```text
官方 config 写明 num_hidden_layers = 28
```

可以作为该版本的公开事实。

### 合理推断

```text
num_attention_heads = 28
num_key_value_heads = 4
→ 可以推断不是标准 MHA，而是分组共享 KV 的结构
```

推断应写明依据，且允许被更完整资料修正。

### 未知

```text
训练数据中中文代码具体占多少比例？
```

如果官方没有披露，就应标记未知，而不是根据回答风格猜测。

## 开放权重与完整开源不是一回事

可以拆成几层：

| 开放内容 | 用户得到了什么 |
|---|---|
| Model Card | 说明与评估 |
| Config / Tokenizer | 结构和编码规则 |
| Open Weights | 可加载的训练后参数 |
| Training Code | 训练实现 |
| Training Data | 数据或可复建清单 |
| License | 允许怎样使用和修改 |

一个项目可以开放其中部分，而不是全部。

例如 OpenAI 将 `gpt-oss` 作为开放权重模型发布，并公开架构和高层训练说明；这不表示 OpenAI 的闭源 GPT 产品模型也采用完全相同结构或公开程度。

> [!source]
> 来源：[Introducing gpt-oss](https://openai.com/index/introducing-gpt-oss/)，OpenAI。核对日期：2026-07-29。

## 一个推荐的核对顺序

以后遇到一个新模型，可以依次看：

1. 精确模型名、版本和发布机构；
2. 官方 Model Card；
3. 官方 Technical Report；
4. 官方 Config 与 Tokenizer；
5. Weight 与官方加载代码；
6. 评测协议和原始结果；
7. 哪些关键问题仍未公开。

这样能够避免从模型名、参数量或宣传语直接跳到内部结论。

## 常见误解

### 有 Weight，就拥有完整模型训练技术

不是。Weight 是训练结果，不是完整数据、代码和过程记录。

### `config.json` 写 128K，就证明模型能可靠使用 128K

不能。还需要训练和评测证据。

### 技术报告没写的细节可以从输出表现反推

通常不能唯一反推。多种数据与架构组合可能产生相似输出。

### 同一家公司的开放模型可以代表其所有闭源模型

不能。除非官方明确说明关系，否则应分别判断。

## 理解检查

1. Model Card、Technical Report、Config 和 Weight 各自最主要的证据是什么？
2. 为什么 Weight 不能直接还原每条训练数据？
3. “公开事实”“合理推断”和“未知”应该怎样区分？
4. 为什么 `gpt-oss` 的架构不能直接外推给闭源 GPT 模型？
