# Scaling Law 应该怎样理解

> [!summary] 一句话理解
> Scaling Law 是从一组训练实验中观察到的经验规律：在其他条件相对可比时，增加模型规模、有效数据和训练计算，模型的平均预测 Loss 往往以较平滑但收益递减的方式改善。

## 所属阶段

**预训练阶段。** Scaling Law 主要帮助研究者在正式训练前估计资源分配和总体趋势，不是 Runtime 的扩缩容规则，也不是“模型越大就一定出现 AGI”的公式。

## 为什么需要 Scaling Law

训练大模型成本很高，不能等完整训练结束后才发现资源比例不合适。

开发者需要提前回答：

```text
固定计算预算下
→ 应该做更大的模型？
→ 还是让较小模型读取更多 Token？
→ 继续增加资源可能获得多大平均收益？
```

Scaling Law 的作用就是用许多较小规模实验拟合趋势，为更大训练提供决策依据。

## “Law”不是自然界不可违背的定律

这里的 Law 更接近“在特定实验范围内反复观察到的稳定经验关系”。

它依赖于：

- 模型家族；
- 数据分布与质量；
- Tokenizer；
- 训练目标；
- 优化配方；
- 计算预算的定义；
- 用什么指标测量。

如果这些条件明显变化，原来的拟合关系也可能需要重新估计。

## 最直白的趋势

可以用一组教学数字理解。假设同一模型家族在可比数据上训练：

| 训练资源 | 测试 Loss（教学示意） |
|---|---:|
| 1 份 | 3.0 |
| 2 份 | 2.6 |
| 4 份 | 2.3 |
| 8 份 | 2.1 |

这里的数字不是任何真实模型结果，只说明两个特点：

1. 资源增加时，平均 Loss 可能比较平滑地下降；
2. 每次资源翻倍，收益通常不会也跟着翻倍。

这就是“收益递减”的直觉：继续扩大仍可能有收益，但获得下一段提升往往需要投入更多资源。

## Loss 下降与能力提升是什么关系

预训练 Loss 衡量模型平均预测下一个 Token 的偏差。Loss 下降通常说明模型更好地拟合了测试文本分布。

但不能直接推出：

```text
Loss 降低 10%
→ 数学能力提高 10%
→ 事实可靠性提高 10%
```

不同任务对基础预测能力的要求不同，评测方式也不同。平均 Loss 是重要基础指标，却不是所有下游能力的统一刻度。

## Scaling Law 怎样被得到

研究者通常不会只训练两个模型，而会训练一系列不同组合：

```text
较小模型 + 较少 Token
较小模型 + 较多 Token
较大模型 + 较少 Token
较大模型 + 较多 Token
……
```

然后记录每组实验的：

- 参数或有效模型规模；
- 训练 Token 数；
- 训练计算；
- 验证或测试 Loss。

最后寻找能够描述总体趋势的曲线。

这是一种由实验数据归纳规律的过程，不是先用公式证明所有模型都必须如此。

## “计算最优”是什么意思

假设只有固定预算：

```text
预算 = 100 个计算单位
```

可能有不同分配方案：

```text
方案 A：模型很大，只能训练较少 Token
方案 B：模型较小，可以训练更多 Token
方案 C：模型与 Token 数相对平衡
```

所谓 compute-optimal，指在规定条件和预算下，哪种组合预计能得到更低 Loss，而不是寻找世界上永远最好的模型尺寸。

Chinchilla 工作进一步强调：模型参数和训练 Token 数要共同增长，不能长期只扩大参数。

## 早期 Scaling Law 与 Chinchilla 为什么看起来不同

早期研究同样发现模型、数据和计算扩大时 Loss 呈现可预测趋势，但对固定计算预算怎样分配模型与数据，得到的具体建议与后续研究并不完全相同。

这并不表示 Scaling Law 完全失效，而说明：

```text
实验范围、模型家族和拟合方法变化
→ 对最优资源比例的估计也可能变化
```

因此应该学习“怎样用实验寻找趋势”，而不是死记某一个固定参数与 Token 比例。

> 主要来源：[Scaling Laws for Neural Language Models](https://arxiv.org/abs/2001.08361)，Kaplan 等，2020；[Training Compute-Optimal Large Language Models](https://arxiv.org/abs/2203.15556)，Hoffmann 等，2022。核对日期：2026-07-29。

## Scaling Law 能帮助判断什么

- 在同一训练体系内，继续扩大资源是否仍可能改善平均 Loss；
- 固定预算下，模型和数据怎样分配更合理；
- 正式大规模训练前，小实验是否表现出预期趋势；
- 一个训练计划是否明显存在“大模型但训练不足”等问题。

## Scaling Law 不能保证什么

### 不能保证某项能力在某个参数量出现

它可以描述平均趋势，却很难精确预测“到 30B 参数一定会学会某项任务”。

### 不能保证事实可靠和行为安全

Loss 目标没有内置事实核验、价值判断或 Agent 验收系统。

### 不能跨不同模型直接比较一个数字

不同模型可能改变数据、架构、Token 数、后训练和评测。仅凭参数量不能做公平比较。

### 不能证明规模是唯一原因

如果新模型同时改变数据质量、MoE、训练目标和后训练，就不能把全部提升只归因于“变大”。

## 与“能力涌现”的关系

Scaling Law 常表现为平滑的平均 Loss 曲线，但某个具体评测可能看起来突然从失败变为成功。

这两件事可以同时发生：

```text
底层预测能力逐渐改善
        ↓
任务跨过评分阈值
        ↓
评测结果看起来突然跳升
```

是否存在真正无法由平滑变化解释的能力涌现，需要更细致实验，不能只看一张阶梯状准确率图。

## 常见误解

### 计算增加两倍，能力就增加两倍

不是。收益通常递减，而且能力没有统一的倍数单位。

### Scaling Law 可以算出某个模型的全部能力

不能。它主要描述选定指标在特定训练体系中的总体趋势。

### Loss 平滑下降，所以所有任务都必须平滑提升

不一定。任务指标可能有阈值、离散评分或样本数量限制。

### 找到计算最优比例后，数据质量就不重要了

不是。无效、冲突或污染数据不会因为比例正确就自动变成高质量训练信号。

## 理解检查

1. 为什么 Scaling Law 是经验规律，而不是绝对自然定律？
2. 为什么训练资源翻倍不意味着能力翻倍？
3. compute-optimal 描述的是哪一种“最优”？
