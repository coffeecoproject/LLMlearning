# 能力涌现是真的突然出现吗

> [!summary] 一句话理解
> 有些能力会在更大模型上明显出现，但“突然出现”可能来自内部能力跨过可用门槛，也可能来自评测指标把连续改善显示成跳变；仅凭一张曲线不能断定模型内部发生了神秘突变。

## 所属阶段

主要观察 **预训练规模与模型能力形成**，但判断是否“涌现”属于评估问题。这里不讨论 Agent 通过工具循环获得的系统能力。

## “能力涌现”最初在说什么

一种常见定义是：

```text
较小模型在某任务上几乎不会
→ 扩大到某个规模后明显会了
```

例如，随着模型扩大，一项任务的准确率可能表现为：

```text
小模型：接近随机
中模型：接近随机
大模型：明显高于随机
```

如果只看这些离散点，就很容易得到“能力突然出现”的印象。

## 第一种可能：能力逐渐改善，但跨过了可用门槛

假设模型完成一个任务需要连续做对三个环节：

```text
理解问题
→ 保持中间条件
→ 生成正确答案
```

较小模型可能每个环节都只有一定成功概率。随着基础能力逐渐提高，完整链条一次做对的概率才开始明显上升。

于是用户体验可能是：

```text
原来几乎不能用
→ 某个规模后偶尔可用
→ 再扩大后比较稳定
```

底层变化可以是渐进的，但“能否完成整个任务”具有门槛。

## 第二种可能：评分方式制造了阶梯

看一个教学例子。假设模型答案质量是连续提高的：

| 模型 | 接近正确程度 | Exact Match 得分 |
|---|---:|---:|
| A | 0.60 | 0 |
| B | 0.75 | 0 |
| C | 0.90 | 0 |
| D | 1.00 | 1 |

`Exact Match` 只有完全一致才得 1 分，所以前三个模型全部显示为失败，D 突然显示成功。

从离散得分看：

```text
0 → 0 → 0 → 1
```

从底层接近程度看：

```text
0.60 → 0.75 → 0.90 → 1.00
```

所谓跳变可能主要来自测量尺，而不是内部能力在某一刻凭空出现。

> [!example] 教学示意
> “接近正确程度”是为了说明连续指标与离散指标的差异，并非真实评测中的统一变量。

## 第三种可能：评测采样点太少

假设真实变化发生在：

```text
7B → 9B → 11B → 13B
```

但研究只测了：

```text
7B 和 13B
```

中间过程没有被观察到，也会让结果看起来像突然跳升。

因此研究“涌现”时要检查：

- 模型规模采样是否足够密；
- 指标是否连续；
- 测试题数量是否足够；
- Prompt 和评分是否一致；
- 是否存在数据污染或后训练差异。

## 是否意味着所有涌现都是假的

不能这样下结论。

一方面，有研究整理了许多在大模型上明显出现的新任务表现，并把它们称为 emergent abilities。

另一方面，也有研究表明，部分看似突然的涌现会在改用连续指标或更细统计后变得平滑。

所以更准确的态度是：

```text
观察到表现跳升
→ 先确认真实现象
→ 再检查指标、采样和训练差异
→ 最后讨论内部机制是否发生质变
```

> [!source]
> 主要来源：[Emergent Abilities of Large Language Models](https://arxiv.org/abs/2206.07682)，Wei 等，2022；[Are Emergent Abilities of Large Language Models a Mirage?](https://arxiv.org/abs/2304.15004)，Schaeffer 等，2023。两篇工作提供了不同解释角度。核对日期：2026-07-29。

## 即使能力真的出现，也不代表已经可靠

模型从“不会”变成“有时会”，与从“有时会”变成“工程上可靠”之间还有很大距离。

```text
0% 成功率
→ 20%
→ 60%
→ 90%
→ 在边界条件、分布变化和攻击下仍可靠
```

前几步可以由模型能力提升推动，最后一步通常还需要：

- 更好的训练和后训练；
- 明确评估；
- 工具获得真实信息；
- 外部验证；
- Agent 工作流和失败恢复。

因此，能力涌现不能替代 Agent 的验收系统。

## 与推理能力的关系

模型规模增加后，一些多步任务可能明显改善，但原因可能混合了：

- 更好的语言和知识表示；
- 更强的上下文利用；
- 更稳定的多步 Token 生成；
- Prompt 或 Chain-of-Thought 提供了更多中间计算空间；
- 后训练专门强化了相应行为。

如果比较的模型还经历了不同后训练，就不能把推理提升全部归因于预训练参数规模。

## 与我们设计 Agent 的关系

对于 Agent 系统，不能采用这种假设：

```text
下一代模型更大
→ 大型项目任务自然完整可靠
```

更合理的是：

```text
模型变强
→ Worker 提案和执行成功率提高

外部目标、事实、工具、证据和验收
→ 继续负责系统级可靠性
```

模型能力提升可以减少循环次数，但不会自动赋予模型对真实世界完成状态的权威判断。

## 常见误解

### 涌现证明模型突然拥有了意识

不能。任务表现变化不能直接证明主观体验或人类式意识。

### 只要参数跨过某个数字，某项能力就一定出现

不能这样预测。数据、训练计算、架构、后训练和评测都可能变化。

### 指标导致跳变，所以规模没有作用

也不对。模型底层表现可能确实随规模改善，只是“突然”的程度需要谨慎解释。

### 某项任务达到高分，就说明能力已经稳定

不一定。还需要测试改写、边界条件、分布变化、污染和真实执行结果。

## 理解检查

1. 为什么底层能力平滑改善，Exact Match 仍可能突然跳升？
2. 判断能力涌现时，为什么要检查模型规模采样和评测指标？
3. 为什么能力出现不等于工程可靠？

## 本小节结论

```text
规模扩大
→ 平均预测能力通常改善
→ 某些任务可能跨过可观察或可用门槛
→ 表现看起来突然出现

但是否发生内部质变
→ 需要更细实验

是否达到可靠完成
→ 仍需要独立验证
```
