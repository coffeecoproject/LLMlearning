# 记忆、泛化与组合怎样区分

> [!summary] 一句话理解
> 记忆偏向复现训练中见过的具体内容，泛化是把学到的规律应用到新例子，组合则把多个已有关系或步骤重新连接；真实模型行为可能同时包含三者。

## 为什么必须区分

当模型给出一个正确答案时，不能只凭结果判断它是：

- 复现了训练中的原句；
- 利用了可迁移规律；
- 组合了多个已学关系；
- 或只是碰巧选中了正确 Token。

这些机制会产生相似表面输出，但可靠性和边界不同。

## 一、记忆

记忆在这里指模型对训练中具体内容或高度相似模式的保留倾向。

例如，某段罕见文字在训练数据中多次出现，模型可能在相似提示下复现其中一部分。

```text
高度相似的训练前缀
→ 高度相似的输出
```

记忆并不一定是逐字保存整个文件，也可能表现为片段、固定表达或强烈关联。

## 二、泛化

泛化是把从许多样本中学到的共同规律，应用到没有原样见过的新例子。

训练中见过：

```text
2 + 3 = 5
4 + 1 = 5
```

测试时回答：

```text
6 + 2 = 8
```

如果训练数据中没有这条完整表达，正确回答可能体现了某种规则迁移。但仅凭一个例子仍不能证明模型掌握了稳定算法，需要换数字、换表达和增加边界测试。

## 三、组合

组合是把多个已经形成的关系或步骤放进同一次处理。

例如模型分别具有这些关系倾向：

```text
法国 → 首都 → 巴黎
巴黎 → 国家 → 法国
```

面对新问法：

```text
“法国首都所在的国家是什么？”
```

模型需要在当前上下文中连接多个关系。更复杂的代码、数学和规划任务需要更多步骤的组合。

组合能力仍可能出错：某一步概率偏差就可能影响后续整段生成。

## 三者不是完全分开的盒子

真实输出经常混合三者：

```text
记住常见事实
+ 泛化语言和任务格式
+ 在当前 Prompt 中重新组合
→ 生成回答
```

例如回答一道历史题，可能同时依赖记住的人名、泛化的问题格式和对多个事实的组合。

因此不要把模型简单归类成“只是记忆”或“完全没有记忆”。更有用的问题是：它在多大程度上能脱离表面形式，并在新条件下保持正确？

## 怎样做简单区分

| 检查方式 | 主要观察 |
|---|---|
| 改写问题但保持含义 | 是否只依赖固定措辞 |
| 更换数字、实体或顺序 | 是否能迁移到新实例 |
| 增加干扰信息 | 是否抓住真正相关关系 |
| 要求连接多个已知条件 | 是否能稳定组合 |
| 检查罕见原文复现 | 是否可能依赖具体记忆 |

这些测试只能增加证据，不能从外部输出完整还原模型内部过程。

## 为什么泛化仍然会失败

- 训练分布与新问题差别太大；
- 学到的是表面相关性，而不是稳定规则；
- 所需关系没有充分形成；
- 当前上下文干扰了正确倾向；
- 生成过程中某一步选择错误，后续继续沿错误前缀生成。

所以“能泛化”不是一个永久的全局标签，而要针对任务、分布和难度判断。

## 与幻觉的关系

模型始终在生成概率较合理的后续，而不是先查询一个保证正确的事实库。即使语言结构和相关概念都很合理，缺失或冲突的事实关系仍可能被模型用流畅内容补齐。

这说明：

```text
语言与组合能力强
≠ 每个事实都可靠
≠ 每次调用都稳定
```

后续会在“能力形成与边界”模块专门讨论幻觉和可靠性。

## 常见误解

### 训练中见过相关资料，就一定只是背诵

不能仅凭资料相关性判断。模型可能同时使用记忆、泛化与组合。

### 输出了训练集中没有的句子，就证明具有强泛化

不是。语言生成本来就能产生新表面组合，还需要系统测试规则是否稳定。

### 能完成一次多步任务，就证明内部一定进行了人类式推理

不能直接证明。输出行为可以提供能力证据，但内部机制仍需要更谨慎研究。
