# 为什么预测下一个 Token 能学到语言规律

> [!summary] 一句话理解
> 下一 Token 目标看起来简单，但要在大量不同文本中持续预测得更准，模型必须利用语法、语义、上下文、知识和文本结构，而不能只记住相邻 Token 的出现次数。

## 所属阶段

**预训练阶段。** 这里解释下一 Token 训练目标为什么可能产生比“词频统计”更丰富的能力。

## 从最简单的规律开始

在下面的上下文中：

```text
今天的天气很
```

“好”“冷”“热”可能比“冰箱”更常成为合理后续。模型可以先从大量文本中学到这种局部搭配。

但只知道两个 Token 经常相邻，很快就不够用了。

## 上下文越复杂，预测需要的信息越多

### 需要语法

```text
这些苹果都很
```

模型要利用词性和句子结构判断后面更可能出现形容词，而不是任意 Token。

### 需要指代关系

```text
小明把书交给小红，因为她明天要考试。她指的是
```

要预测后续，模型需要结合前文角色与语义关系，而不只是看最后一个词。

### 需要事实关系

```text
法国的首都是
```

要让“巴黎”获得较高概率，参数需要从大量训练语境中形成有关“法国—首都—巴黎”的稳定倾向。

### 需要代码结构

```python
def add(a, b):
    return
```

预测后续需要利用编程语法、变量关系和常见实现模式。

因此，训练目标虽然始终是“下一个 Token”，解决这个目标所需的内部信息却可以非常丰富。

## 为什么不能只背下所有句子

现实文本的组合数量极大，同一个规律还会有许多表达方式：

```text
巴黎是法国的首都。
法国首都位于巴黎。
What is the capital of France?
```

如果模型只能记住完整原句，它面对改写、换序或新上下文时就难以继续降低 Loss。

能够复用“实体—关系—实体”、语法结构和上下文模式，往往比为每个句子建立独立记录更有效。这会推动参数形成可在多个样本间共享的表示。

这里的“推动”不是人为指定某个参数必须学习语法，而是：能帮助许多训练样本降低 Loss 的参数变化，会在长期训练中反复得到支持。

## Causal Mask 为什么没有阻止学习上下文

Causal Mask 只禁止当前位置读取未来 Token，并不禁止它读取左侧已经出现的全部可见上下文。

```text
我
我 喜欢
我 喜欢 吃
```

随着前缀增长，每个位置可以使用越来越多的历史信息。Attention 学习从这些历史位置中选择和混合相关内容，FFN 再变换当前位置的表示。

所以 Decoder-only 模型仍然能够学习长距离关系，只是预测时不能偷看目标答案。

## “产生能力”不是目标里显式写好的

训练代码通常不会分别写下：

```text
请学习语法
请学习世界知识
请学习代码
```

它主要提供下一 Token Loss。语法、知识和代码模式之所以出现，是因为它们能帮助模型在相应数据上做出更好的预测。

这类能力因此常被称为训练目标产生的结果，而不是每项能力都有一条独立监督命令。

## 重要边界

### 能预测不等于一定理解正确

模型可能利用浅层相关性得到正确 Token，也可能在熟悉表达中表现好、换个条件就失败。

### 下一 Token 训练不保证事实可靠

训练数据可能冲突、过时或错误；目标要求拟合数据中的分布，并没有内置事实核验器。

### 复杂输出不自动证明意识

从训练中形成抽象模式是可观察的能力现象，但不能仅凭这一点证明模型拥有与人相同的主观理解。

## 常见误解

### 下一 Token 预测只学习前一个词和后一个词

不是。预测可以利用整个可见前缀，参数更新也会经过多层 Transformer。

### 训练目标简单，形成的内部机制也必然简单

不一定。为了在大量复杂上下文中共同降低同一个 Loss，模型可能形成多层次的内部表示。

### 学到关系就等于永远能准确调用

不是。知识可能不完整、相互干扰，并受到 Prompt、上下文和生成概率影响。
