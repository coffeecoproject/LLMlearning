# 切段与文档边界怎样处理

> [!summary]
> 切段把过长 Token 流变成训练长度以内的序列；文档边界则告诉训练系统和模型，哪些内容原本属于不同资料。

## 为什么必须切段

训练使用的序列长度有限。假设训练长度是 8 个 Token：

```text
原始文档：20 个 Token
→ 不能作为一条 20 Token 样本直接进入该训练配置
→ 需要切成若干不超过 8 Token 的序列
```

> [!example] 教学示意

```text
原始 Token：
[A B C D E F G H I J K L]

固定长度 5：
[A B C D E]
[F G H I J]
[K L]
```

最后一段较短，后续可以选择与其他短文 Packing、使用 Padding，或者按配方丢弃。

## 切段为什么不只是“每 N 个切一刀”

机械切段简单高效，但可能切断：

- 一个句子；
- 一段代码或函数；
- 数学推导；
- 问题和对应答案；
- 对话中的一轮消息。

因此真实管线可能结合：

- 固定 Token 长度；
- 段落、章节或代码边界；
- 滑动窗口与重叠片段；
- 保持一条指令样本或对话的完整性；
- 超长样本专用处理策略。

选择取决于预训练、SFT、长上下文训练等不同目标。

## 文档边界为什么重要

假设把两篇无关文档直接接起来：

```text
文档A：苹果是一种水果。
文档B：火星拥有两颗小卫星。
```

如果没有边界，序列可能看起来像：

```text
苹果是一种水果。火星拥有两颗小卫星。
```

模型会把“文档B的第一个 Token”也视为文档A后面的预测目标。加入 EOS 等边界 Token 可以明确表示：一份资料在这里结束，另一份开始。

## 有边界 Token 就一定不能跨文档 Attention 吗

不一定。

```text
EOS：在内容中标记边界
Attention Mask：控制某位置能否读取其他位置
```

一种简单 Packing 实现会插入 EOS，但仍允许后一个文档读取前一个文档；模型通过 EOS 学会文档已结束。

另一种实现会使用 Block-Diagonal Attention、位置重置或其他隔离规则，使不同文档在 Attention 上彼此不可见。

所以必须分别问：

1. 是否插入边界 Token？
2. 是否重置 Position？
3. 是否阻断跨文档 Attention？
4. 跨边界位置是否计算 Loss？

不同训练框架和模型配方答案可能不同。

## 重叠切段解决什么

假设固定切段让关键信息分散在两段：

```text
片段1：……问题条件
片段2：结论和解释……
```

使用一部分重叠可以让相邻片段共享上下文：

```text
片段1：[A B C D E]
片段2：[D E F G H]
```

代价是 D、E 被重复训练，计算量和有效数据权重随之改变。因此重叠不是免费提升。

## 切段与运行时 Truncation 的区别

| 训练阶段切段 | 运行阶段 Truncation |
|---|---|
| 构造长期训练样本 | 处理某次请求超过上下文窗口 |
| 会影响模型反复学习的数据结构 | 只影响本次请求保留哪些输入 |
| 可提前离线处理 | 多发生在请求构建或 Runtime 中 |

二者都受到序列长度限制，但不是同一个阶段。

## 常见误解

- **“文档多长，训练样本就多长。”** 训练样本受到设定序列长度限制。
- **“加了 EOS 就完全隔离两个文档。”** EOS 是 Token，是否阻断 Attention 取决于 Mask 规则。
- **“重叠越多，上下文越完整。”** 重叠也增加重复和计算成本。
- **“训练切段就是运行时截断。”** 两者阶段、对象和影响范围不同。
