# 序列构造概览

> [!summary]
> 序列构造把已经筛选的文档转换为长度受控、边界明确且便于批量计算的 Token ID 序列。

## 主线

```text
干净文档
→ 使用固定 Tokenizer 编码
→ 添加 BOS、EOS 或文档边界标记（按模型配方）
→ 处理过长文档和过短文档
→ 切段与 Packing
→ 必要时 Padding
→ 可供样本字段构造的序列
```

## 三个核心问题

1. [[01-固定Tokenizer怎样编码训练数据|固定 Tokenizer 怎样编码训练数据]]
2. [[02-切段与文档边界怎样处理|切段与文档边界怎样处理]]
3. [[03-Packing与Padding有什么区别|Packing 与 Padding 有什么区别]]

## 先记住的边界

- Tokenizer 决定“怎样编码”，训练配方决定“怎样组织编码结果”。
- `sequence_length` 是训练样本长度或上限，不是原始文档必须具有的固定长度。
- Packing 是尽量利用序列空位；Padding 是补齐形状。二者方向几乎相反。
- 文档被放进同一个训练序列，不代表模型一定被允许跨文档 Attention；这取决于边界标记和 Attention 规则。
