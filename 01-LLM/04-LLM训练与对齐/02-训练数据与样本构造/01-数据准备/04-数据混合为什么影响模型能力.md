# 数据混合为什么影响模型能力

> [!summary]
> 数据混合决定各类内容在有限训练预算中被模型看到的相对频率，因此会改变模型获得哪些能力和偏好的训练机会。

## 什么是数据混合

数据混合（Data Mix）不是把所有文件放进一个目录，而是决定训练时从不同来源或类别抽取多少数据。

> [!example] 教学示意
> 假设一次训练计划只处理 1000 个 Token：

```text
通用网页：700 Token
代码：    200 Token
数学：    100 Token
```

比例就是：

```text
70% 通用网页 + 20% 代码 + 10% 数学
```

这只是直观示例。真实训练会有更多来源，并可能按阶段改变采样权重。

## 为什么不能按“现有文件数量”直接混合

原始数据量不等于期望的重要性：

- 网页文本天然远多于高质量数学证明；
- 英语资源通常多于许多少数语言；
- 重复模板可能制造虚假体量；
- 高质量代码、科学和专业数据可能稀缺但价值较高。

如果完全按自然数量采样，大来源会淹没小而重要的数据域。

## 上采样和下采样

### 上采样

让某类稀缺数据更频繁地进入训练：

```text
数学原本只占 1%
→ 训练时提高到 5%
```

它增加数学数据的训练机会，但重复过多也可能造成过拟合或记忆。

### 下采样

只选取大来源的一部分：

```text
低价值模板网页数量极多
→ 只保留或抽取很小比例
```

它释放计算预算给其他数据，但规则不当会损失覆盖面。

## 混合比例怎样影响能力

```text
某类数据出现得更多
→ 更多训练位置以这类模式作为目标
→ 相关参数获得更多优化信号
→ 可能改善该领域表现
```

这里必须保留三个边界：

1. 数据更多不代表数据更好；
2. 比例增加不保证能力按同样比例上升；
3. 领域之间可能互相促进，也可能产生能力权衡。

## 数据混合不是只做一次

真实训练可能分阶段调整：

```text
早期：覆盖广泛的通用数据
→ 中后期：提高高质量、代码、数学或目标语言比例
→ 上下文扩展阶段：增加更长序列数据
→ 后训练：切换为指令、偏好或可验证任务数据
```

这叫训练课程或阶段化数据策略的一部分，但具体路线因模型而异。

## 怎样判断一个混合更好

团队通常不会只凭直觉确定比例，而会：

- 对候选数据源做质量和覆盖统计；
- 用小模型或较短训练实验比较不同混合；
- 同时检查通用、代码、数学、多语言和安全评测；
- 观察某项提升是否以其他能力下降为代价；
- 根据正式训练中的 Loss 和评测变化继续调整。

Meta 的 Llama 3 官方说明明确提到，用小规模模型训练实验评估数据混合，说明“数据配方”本身也需要实验验证。

## 常见误解

- **“把所有高质量数据都放进去就不需要配比。”** 不同数据体量悬殊，仍会形成隐含比例。
- **“代码占 20%，模型就有 20% 的代码能力。”** 数据比例和能力没有这种线性对应关系。
- **“上采样就是复制文件。”** 实现上可能重复抽取，但核心是改变被看到的概率。
- **“数据混合只影响预训练。”** SFT、偏好训练和强化学习同样需要任务与领域混合。

## 理解检查

1. 为什么数据量最大的来源不应自动获得最高训练比例？
2. 上采样某类数据可能带来什么收益和风险？
3. 为什么不能从“20% 代码数据”直接推导“20% 代码能力”？
