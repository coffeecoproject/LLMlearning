# 数据来源、许可与可追溯性

> [!summary]
> 训练数据首先要回答的不是“内容好不好”，而是“它从哪里来、在什么条件下取得、经过了什么处理，以及能否在需要时追查”。

## 为什么这一步必须在前面

如果一个数据文件只剩下正文，没有来源记录，后面很难判断：

- 是否重复抓取；
- 是否需要删除或更新；
- 是否受特定许可、网站条款或数据协议约束；
- 是否包含不应进入训练的数据；
- 模型出现问题后应回溯哪批数据。

因此，数据可追溯性不是给文档添加一个网址那么简单，而是建立数据的“来历链”。

## 一个具体例子

假设团队得到同一篇文章的三个版本：

```text
A：作者官网原文
B：论坛完整转载
C：聚合网站截取版本
```

如果只比较正文，三份内容可能都很像。但来源记录会帮助团队判断：

- 哪一份是原始来源；
- 转载是否经过授权；
- 哪一份包含更多噪声；
- 去重时应保留哪个版本；
- 将来收到删除请求时应定位哪些派生副本。

## 真实管线通常记录什么

可追溯元数据可能包括：

| 信息 | 作用 |
|---|---|
| 来源标识 | 域名、仓库、数据集或内部系统 |
| 获取时间和版本 | 判断内容新旧并复现实验 |
| 许可或使用依据 | 记录允许和限制条件 |
| 内容类型与语言 | 便于分类、过滤和混合 |
| 原始哈希或文档 ID | 去重、版本对应和删除追踪 |
| 处理流水线版本 | 知道文本经过哪些解析与过滤 |
| 保留或排除原因 | 便于审核规则是否合理 |

不同团队记录的字段会不同，但目标相同：让数据不是一个无法解释的黑箱。

## “公开可访问”不等于什么

网页能被浏览器打开，只说明技术上可以访问；它不自动回答：

- 是否允许批量抓取；
- 是否允许复制和再分发；
- 是否允许用于训练某种模型；
- 是否含有个人信息、机密或第三方权利内容；
- 训练结果将用于研究、内部系统还是商业产品。

这些问题需要结合具体来源、许可、条款、适用规则和项目用途审查。本篇只解释工程边界，不提供法律结论。

## 来源记录怎样影响后续环节

```text
来源与版本记录
→ 支持去重和更新
→ 支持许可与隐私审核
→ 支持按领域和语言混合
→ 支持问题回溯和数据删除
→ 支持模型卡披露与实验复现
```

没有这条链，即使训练已经完成，也可能无法准确说明模型究竟接触过什么。

## 常见误解

- **“只要内容质量高就能训练。”** 内容质量与使用条件是两个独立维度。
- **“保留 URL 就完全可追溯。”** URL 会变化，仍需要时间、版本、哈希和处理记录等信息。
- **“模型只学概率，所以数据权利和隐私不重要。”** 数据是否原样检索与数据能否合规使用是不同问题。
- **“开放权重模型一定公开了完整训练数据。”** 许多模型只披露数据类别或概要，并不发布完整语料和处理记录。

## 理解检查

1. 为什么正文完全相同的两份数据，来源记录仍然有价值？
2. “公开可访问”和“可用于任意训练目的”有什么区别？
3. 如果没有处理流水线版本，后续复现实验会遇到什么问题？
