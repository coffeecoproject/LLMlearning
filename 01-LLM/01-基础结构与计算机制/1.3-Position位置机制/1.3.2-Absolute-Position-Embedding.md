# 1.3.2 Absolute Position Embedding

> [!summary]
> Absolute Position Embedding 为每个绝对位置提供一个位置向量，并通常把它与对应位置的 Token Embedding 相加，使第一层输入同时携带 Token 与位置信息。

## 直观做法

假设一句话有三个 Token：

```text
位置 0：[我]
位置 1：[喜欢]
位置 2：[苹果]
```

模型分别得到：

```text
Token Embedding：这个 Token 是什么
Position Embedding：这个 Token 位于第几个位置
```

然后在每个位置相加：

```text
位置 0 的输入 = “我”的 Token Embedding + 位置 0 的 Position Embedding
位置 1 的输入 = “喜欢”的 Token Embedding + 位置 1 的 Position Embedding
位置 2 的输入 = “苹果”的 Token Embedding + 位置 2 的 Position Embedding
```

两组向量通常拥有相同的 `hidden_size`，才能逐元素相加。

## 为什么相加后不会分不清内容和位置

相加确实把两类信息放进同一个向量，模型不会再收到两个带文字标签的独立字段。但后续参数可以在大量样本中学会利用这种组合表示。

这不保证人类能够逐维指出：

```text
哪些维只表示 Token
哪些维只表示位置
```

信息可能分布在许多维度及其组合中。

## 位置向量从哪里来

Absolute Position 的常见实现包括：

```text
Learned Position Embedding
→ 每个位置拥有可训练向量

固定的 Sinusoidal Position Encoding
→ 根据预定数学函数生成位置表示
```

两者都表达绝对位置，但一个通过训练学习数值，一个使用固定规则。不能把 Absolute Position Embedding 简化为只有一种实现。

## Learned Position Embedding 的形状

如果模型最多预留 `max_position_embeddings` 个位置，每个位置宽度为 `hidden_size`，可学习位置矩阵常可理解为：

```text
[max_position_embeddings, hidden_size]
```

位置编号用于选择其中一行。这和 Token Embedding Lookup 形式相似，但索引对象不同：

```text
Token Embedding Matrix
→ 用 Token ID 选行

Position Embedding Matrix
→ 用 Position ID 选行
```

## 它解决了什么

同一个 Token 出现在不同绝对位置时：

```text
Token Embedding 可以相同
位置向量不同
→ 第一层输入表示不同
```

于是后续 Attention 可以区分“苹果”出现在第 2 个位置还是第 20 个位置。

## 它的边界

绝对位置方案直接标识“第几个位置”，但相对距离通常需要后续网络从这些表示中学习出来。

对于可学习位置表，超出训练和预设位置范围的扩展也不天然容易，因为不存在无限多已经学好的新位置行。具体外推能力还取决于实现、训练范围和扩展方法，不能仅凭“绝对位置”四个字断言模型一定能或不能处理某长度。

## 与“位置编码”术语的关系

资料中常混用：

- Positional Encoding；
- Position Embedding；
- Positional Embedding。

入门阶段可以先看具体机制：它是固定生成、可学习查表、旋转 Q/K，还是修改 Score。名称本身有时不够精确。

## 常见误解

- **“Absolute Position 一定是可学习参数。”** 也可能使用固定的 Sinusoidal Encoding。
- **“位置 ID 就是 Token ID。”** 两者索引不同的对象。
- **“相加后每一维可以明确分成词义维和位置维。”** 真实表示通常是分布式的。
- **“所有现代 Decoder-only LLM 都使用这种输入相加方式。”** 许多模型使用 RoPE 等其他方案。
