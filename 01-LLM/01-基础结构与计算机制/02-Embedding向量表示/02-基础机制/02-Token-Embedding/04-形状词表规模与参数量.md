# 形状、词表规模与参数量

> [!summary]
> 输入 Embedding Matrix 的形状通常是 `[vocab_size, hidden_size]`，因此其参数量通常等于两者相乘；Lookup 输出的形状则由当前输入长度决定。

## 两个形状先分开

### 模型长期保存的 Embedding Matrix

```text
[vocab_size, hidden_size]
```

### 一次输入 Lookup 后的序列表示

不考虑 Batch 时：

```text
[sequence_length, hidden_size]
```

考虑 Batch 时：

```text
[batch_size, sequence_length, hidden_size]
```

Embedding Matrix 的高度由整个词表决定；Lookup 输出的长度由这一次实际输入决定。

## 参数量怎样计算

假设教学模型：

```text
vocab_size = 1000
hidden_size = 64
```

Embedding Matrix 参数量：

```text
1000 × 64 = 64,000
```

这里每个矩阵元素都是一个模型参数。因此词表更大或 hidden size 更宽，都会增加输入 Embedding 的参数量。

## 参数量不等于文件字节数

参数量回答“有多少个数”，存储大小还取决于每个数使用的数据类型：

```text
参数量
× 每个参数占用的字节数
≈ 原始参数存储大小
```

实际模型文件还会受到分片、量化、压缩格式、权重共享和元数据等因素影响，所以不能只用参数量精确推断下载文件大小。

## 开放模型观察：Qwen3-32B

Qwen3-32B 官方 `config.json` 公布：

```json
{
  "vocab_size": 151936,
  "hidden_size": 5120,
  "tie_word_embeddings": false
}
```

由前两个已发布配置可以直接计算其输入 Embedding Matrix 的理论形状：

```text
[151936, 5120]
```

参数量为：

```text
151936 × 5120
= 777,912,320
```

约为 7.78 亿个参数。

### 事实与推导分开

- **官方发布事实**：`vocab_size = 151936`、`hidden_size = 5120`、`tie_word_embeddings = false`。
- **根据配置推导**：输入 Embedding Matrix 的形状是 `[151936, 5120]`，包含 777,912,320 个参数。
- **本节暂不展开**：`tie_word_embeddings = false` 表示输入 Embedding 与输出词表投影不共享同一组权重；输出层将在 LM Head 专题解释。

来源：[Qwen/Qwen3-32B 官方配置](https://huggingface.co/Qwen/Qwen3-32B/blob/main/config.json)，核对日期：2026-07-24。

## Lookup 并不会取出整个矩阵

假设当前只有 3 个 Token：

```text
input_ids = [10, 20, 30]
```

Lookup 只为当前三个位置取得对应行，形成：

```text
[3, 5120]
```

模型仍然保存完整 Embedding Matrix，但一次输入表示不需要把 151936 行全部复制进序列。

## 词表扩大带来的权衡

如果 `hidden_size` 不变，词表每增加一个 Token，输入 Embedding Matrix 就增加一整行：

```text
新增 1 个 Token
→ 新增 hidden_size 个输入 Embedding 参数
```

但这不表示词表越小越好。较大的词表可能让常见文本切得更紧凑，较小的词表则可能带来更长序列。这是 Tokenizer 词表规模与模型参数、序列长度之间的工程权衡。

## 本公式的适用边界

```text
vocab_size × hidden_size
```

计算的是标准输入 Embedding Matrix 的参数量，不代表：

- 整个模型的参数量；
- 当前输入实际使用了多少参数；
- 输出 LM Head 必然额外使用同样数量参数；
- 所有架构都完全没有额外 Embedding 相关参数。

是否共享输入与输出权重、是否还有独立位置 Embedding，取决于具体模型架构。

## 常见误解

- **“输入三个 Token，就只加载三行模型权重。”** 运行系统通常加载完整模型参数，只是该次 Lookup 选择三行参与输入表示。
- **“Embedding 参数量就是模型总参数量。”** Attention、FFN、Norm 和输出层等还有大量参数。
- **“参数量等于文件字节数。”** 还取决于数据类型和保存格式。
- **“词表扩大只影响 Tokenizer 文件。”** 它还会增加模型 Embedding 及可能的输出层参数。
