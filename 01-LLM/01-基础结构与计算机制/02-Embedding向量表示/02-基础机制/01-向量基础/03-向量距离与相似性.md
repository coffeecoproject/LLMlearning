# 向量距离与相似性

> [!summary]
> 向量之间可以用数学方法比较方向或距离，但“更接近”只说明它们在某种表示和指标下关系相似，不自动等于人类定义的同义词。

## 为什么向量可以比较

假设有三个二维示意向量：

```text
猫：  [0.8, 0.7]
狗：  [0.75, 0.72]
汽车：[-0.6, 0.1]
```

在这个人为构造的二维例子中，“猫”和“狗”的坐标较接近，“汽车”较远。于是我们可以对向量提出：

- 两点之间的距离有多远？
- 两个向量的方向有多相似？
- 哪一个向量是某向量的最近邻？

> [!note]
> 这些数值只用于直觉说明，不是真实 LLM 的 Token Embedding。

## 两种常见比较直觉

### 距离

像地图上比较两点距离：差值整体越小，可以说位置越接近。

### 方向

两个箭头即使长度不同，只要指向相近，也可以说方向相似。常见的余弦相似度（cosine similarity）主要比较方向夹角。

这里不要求计算公式。只需知道“距离”和“方向相似度”是不同指标，可能给出不同排序。

## 相似到底代表什么

在训练得到的表示空间中，接近可能来自多种关系：

- 经常出现在相似上下文；
- 具有相似语法作用；
- 同属一个主题或类别；
- 存在替代、对比甚至反义关系；
- 共享拼写、格式或代码模式。

例如“热”和“冷”意义相反，但经常出现在相似句式和话题中，它们的某些表示可能仍表现出较强关联。

因此：

```text
向量接近
≠ 必定同义
≠ 模型已经像人一样理解概念
```

## 初始 Embedding 与 Hidden State 的相似性不同

后面会区分：

- **初始 Token Embedding**：主要由 Token ID 查表得到，尚未吸收当前句子的上下文；
- **Hidden State**：经过模型层后，已经包含当前位置的上下文信息。

同一个 Token “苹果”在“吃苹果”和“苹果发布新设备”中的初始 Embedding 通常相同，但经过上下文处理后的 Hidden State 可以不同。因此谈“词的向量”时，必须先问是哪一层、哪种表示。

## 向量空间为什么能形成关系

这些关系不是开发者逐个写进去的。LLM 训练过程中，为了降低预测误差，大量参数一起被调整。经常在相关计算环境中发挥相似作用的表示，可能逐渐形成可比较的几何结构。

但这只是直觉层解释。不能据此认定每一种语义关系都能通过一个简单距离完整读取。

## 与外部 Embedding 模型的边界

本专题讨论的是 LLM 内部的 Token Embedding 和 Hidden State。RAG 常用的“文本 Embedding 模型”通常把一整段文本编码成适合检索的向量，是另一种产品和训练目标。

```text
LLM Token Embedding：为模型内部每个 Token 位置提供初始表示
检索 Embedding：为句子或文档建立可搜索的整体向量
```

二者有关联，但不能直接当成同一个东西。

## 常见误解

- **“距离最近就一定是同义词。”** 可能反映主题、语法或使用环境等关系。
- **“向量相似度就是模型的理解程度。”** 它只是特定表示下的数学观测。
- **“一个 Token 只有一个永远固定的向量。”** 必须区分初始 Embedding 与各层 Hidden State。
- **“RAG 的文档向量就是 LLM 的 Token Embedding。”** 它们的粒度和训练目标不同。
