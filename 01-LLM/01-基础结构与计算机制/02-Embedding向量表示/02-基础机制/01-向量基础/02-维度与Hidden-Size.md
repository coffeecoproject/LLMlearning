# 维度与 Hidden Size

> [!summary]
> 向量的维度是其中数字的个数；在很多 Transformer 配置中，`hidden_size` 表示模型主干中每个 Token 位置的表示宽度。

## 什么是维度

观察示意向量：

```text
[0.2, -0.7, 0.4, 0.9]
```

它包含 4 个按顺序排列的数，因此是一个 4 维向量。

```text
数字个数 = 向量维度
```

维度不是“有几个 Token”，也不是“词表中有多少 Token”。

## `hidden_size` 是什么

假设某模型配置包含：

```json
{
  "hidden_size": 5120
}
```

对当前学习阶段，可以理解为：

> 模型主干用 5120 个数表示每一个 Token 位置的当前状态。

因此，一个 Token ID 经过 Embedding Lookup 后，会得到长度为 5120 的初始向量；后续经过 Transformer 层，数值会不断变化，但主干表示宽度通常仍保持 5120。

## 三个数量必须分开

假设配置和输入是：

```text
vocab_size = 151936
hidden_size = 5120
当前输入 Token 数 = 3
```

它们分别回答：

| 名称 | 回答的问题 |
|---|---|
| `vocab_size` | 模型配套词表中有多少个可用 Token ID？ |
| `hidden_size` | 每个 Token 位置用多少个数表示？ |
| sequence length | 当前输入一共有多少个 Token 位置？ |

可以先记成：

```text
词表有多高：vocab_size
每行有多宽：hidden_size
这次取出多少行：当前 Token 数
```

这个类比将在 Embedding Matrix 中变成具体矩阵。

## 维度更大意味着什么

更多维度通常意味着模型有更宽的内部表示空间，也会带来更多参数和计算。但不能直接推断：

```text
hidden_size 更大
→ 模型一定更聪明
```

最终能力还取决于层数、Attention 结构、FFN 大小、训练数据、训练方法和参数是否被有效学习等因素。

## 为什么所有 Token 要使用相同维度

模型需要对序列中的各个位置执行同一种矩阵运算，并在位置之间混合信息。如果“苹果”是 5120 维、“汽车”却是 3000 维，许多批量矩阵运算和相加操作就无法直接对齐。

因此同一模型主干中的各 Token 位置通常保持统一的 hidden size：

```text
[我]   → 5120 个数
[喜欢] → 5120 个数
[苹果] → 5120 个数
```

## `hidden_size` 与词义丰富程度

不能把 5120 个维度理解成 5120 个预先命名的词义属性。它规定的是表示宽度；各维组合怎样承载信息，是模型训练出来的结果。

同一个 `hidden_size` 也不会保证两个模型使用相同的表示空间。不同模型参数不同，第 100 维在两个模型中没有跨模型统一含义。

## 常见误解

- **“5120 是模型一次最多接收的 Token 数。”** 那是上下文或序列长度问题，不是 hidden size。
- **“vocab_size 是向量维度。”** vocab size 决定可索引多少行，hidden size 决定每行多宽。
- **“维度越大，模型必然越强。”** 它只是架构容量因素之一。
- **“不同模型相同编号的维度含义相同。”** 向量空间由各自参数训练形成，不能这样对应。

## 理解检查

假设：

```text
vocab_size = 100000
hidden_size = 4096
输入有 20 个 Token
```

请回答：

1. 模型词表提供多少个 ID？
2. 每个 Token 位置的表示包含多少个数？
3. 当前输入有多少个位置？
