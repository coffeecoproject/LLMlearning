# 向量是什么

> [!summary]
> 在本专题中，向量可以先理解为“一组有固定顺序的数”；模型用这组数承载和计算一个 Token 在当前层的表示。

## 从 Token ID 的问题开始

Tokenizer 已经把文本变成整数：

```text
“苹果”
→ Token
→ Token ID：10001（示意）
```

为什么不能直接让模型把 `10001` 当作“苹果”的含义？

因为 Token ID 只是词表中的编号，作用类似座位号：

```text
ID 10001：指向词表中的某个 Token
ID 10002：指向另一个 Token
```

编号相差 1，不表示两个 Token 的意义只相差 1；编号更大，也不表示含义更多或更强。

模型需要一种可以参加加权、组合和变换的数值表示，于是每个 Token ID 会被映射为一组数。

## 标量与向量

一个数可以称为标量（scalar）：

```text
3.5
```

一组按顺序排列的数可以表示一个向量（vector）：

```text
[0.2, -0.7, 0.4, 0.9]
```

顺序很重要：

```text
[0.2, -0.7, 0.4, 0.9]
≠
[-0.7, 0.2, 0.4, 0.9]
```

> [!note]
> 本篇所有向量和 Token ID 都是教学示意，不来自真实模型。

## 为什么一组数比一个编号更有用

单个编号主要回答：

> 它是词表里的哪一项？

向量则提供一个可以被神经网络连续计算的表示：

```text
Token ID
→ 一组数
→ 线性变换、加权组合、非线性变换
→ 逐层形成新的表示
```

这里先不学习这些运算的公式。当前只需要知道：Transformer 的计算对象是向量，而不是文字字符串，也不是把 Token ID 的整数大小当作含义。

## 向量中的每个数表示什么

最容易产生的误解是：

```text
第 1 个数 = 水果程度
第 2 个数 = 红色程度
第 3 个数 = 好吃程度
```

真实 LLM 通常不能这样逐维命名。模型训练后，信息往往分散在许多维度及其组合关系中。一项概念可能需要很多维共同表达，一个维度也可能同时参与多种模式。

因此更准确的说法是：

> 整个向量共同构成当前表示，而不是每个数字都有一个稳定、独立、可由人直接解释的标签。

## 坐标类比及其边界

向量可以类比地图坐标：

```text
[横向位置, 纵向位置]
```

有了坐标，就可以比较方向和距离。这有助于理解为什么模型能对向量进行运算。

但类比到此为止：真实 Token 向量通常有成千上万个维度，各维也不是人工规定的经纬度或语义标签，而是训练中共同形成的参数表示。

## 当前链路

现在只建立了概念：

```text
Token ID：10001（示意）
→ 某个机制找到一组数
→ [0.2, -0.7, 0.4, 0.9]（示意）
```

“某个机制”就是后面要学习的 [[Token-Embedding概览|Token Embedding]]。在进入它之前，还需要知道一组向量包含多少个数，以及多个 Token 的向量如何排列。

## 常见误解

- **“Token ID 本身就是一维向量。”** 可以形式上把一个数装进数组，但 LLM 不把 ID 大小当作 Token 的语义表示。
- **“向量是把文字加密成一串数字。”** 它不是为了保密，而是为了让模型进行数值计算。
- **“每个向量维度都有一个人能说出的含义。”** 真实表示通常是分布式的。
- **“向量一旦产生就永远不变。”** 初始 Embedding 与经过不同模型层后的 Hidden State 要区分。
