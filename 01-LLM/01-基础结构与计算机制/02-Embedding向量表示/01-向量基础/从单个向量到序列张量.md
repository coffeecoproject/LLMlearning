# 从单个向量到序列张量

> [!summary]
> 一句话含有多个 Token，每个 Token 对应一个相同维度的向量；按序列位置排列后，就形成模型可以批量处理的二维表示，加入批次后则常表示为三维张量。

## 从三个 Token 开始

假设 Tokenizer 的示意结果是：

```text
“我喜欢苹果”
→ [我] [喜欢] [苹果]
→ 3 个 Token ID
```

再假设教学模型的 `hidden_size = 4`，每个 Token 得到一个四维向量：

```text
[我]   → [0.1, 0.2, 0.3, 0.4]
[喜欢] → [0.5, 0.6, 0.7, 0.8]
[苹果] → [0.9, 1.0, 1.1, 1.2]
```

> [!note]
> Token 切分、ID、hidden size 和全部向量均为教学示意。

## 排列成二维表

把三个向量按 Token 顺序一行行排列：

```text
[
  [0.1, 0.2, 0.3, 0.4],  ← 第 1 个 Token
  [0.5, 0.6, 0.7, 0.8],  ← 第 2 个 Token
  [0.9, 1.0, 1.1, 1.2]   ← 第 3 个 Token
]
```

它的形状（shape）是：

```text
[sequence_length, hidden_size]
= [3, 4]
```

- 3 行：三个 Token 位置；
- 4 列：每个位置用四个数表示。

## Matrix 与 Tensor

可以先使用下面的入门区别：

```text
Vector：一维排列，例如 [4]
Matrix：二维排列，例如 [3, 4]
Tensor：更一般的多维数值容器
```

严格来说，在深度学习框架里，一维向量和二维矩阵也通常都用 Tensor 对象存储。因此“张量”不是某种神秘的新语义，它首先是一块带有形状信息的多维数字数据。

## 加入批次维度

模型常把多句话一起处理，这组输入称为 Batch（批次）。假设一次处理 2 条序列，每条都整理为 3 个 Token，每个位置为 4 维：

```text
[batch_size, sequence_length, hidden_size]
= [2, 3, 4]
```

可以读成：

```text
2 条序列
× 每条 3 个 Token 位置
× 每个位置 4 个数
```

这里的 Batch 只用于认识张量多出的一层维度。不同长度怎样整理、训练 Batch 怎样参与参数更新、多用户请求怎样调度，分别属于普通运行、训练和 Runtime 专题，不在本篇展开。

## 顺序现在已经表达了吗

把向量排列成第 1、2、3 行，只说明数据结构中存在位置顺序。但 Self-Attention 的核心内容混合本身不会仅凭 Token 含义自动理解“第几个位置”意味着什么。

因此模型还需要专门的位置机制：

```text
Token 表示
+ 位置关系
→ 才能区分不同排列
```

具体怎样加入位置，将在 [[Position位置机制概览|位置机制]] 中学习。

## 一个重要边界：行不是永久绑定某个 Token

矩阵第 1 行表示“当前输入的第 1 个位置”，不是永久表示“我”。换一句话后：

```text
“今天下雨”
```

第 1 行可能对应“今天”的某个 Token。行号表示当前序列位置，Token ID 决定从 Embedding Matrix 取出哪一行参数；这两个“行”不要混淆。

```text
Embedding Matrix 的行号 → Token ID
序列表示矩阵的行号   → 当前 Token 位置
```

## 常见误解

- **“3 个 Token、hidden size 4，所以词表有 12 项。”** `3 × 4` 是当前序列表示的数字数量，与词表规模不同。
- **“Tensor 是 Tokenizer 的输出。”** Tokenizer 主要给出 Token ID；Embedding 之后才得到浮点向量张量。
- **“把向量按顺序放好，模型就天然理解位置。”** 还需要位置机制让后续计算利用顺序或距离。
- **“序列矩阵第 10 行和 Embedding Matrix 第 10 行是同一概念。”** 前者是输入位置，后者由 Token ID 索引。
