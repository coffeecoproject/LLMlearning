# 1.4.2.2.4 Value 是什么

> [!summary]
> Value 是每个来源位置实际参与信息汇总的内容向量；Attention Weight 决定各位置的 Value 有多少进入当前位置的上下文结果。

## Value 在什么时候出现作用

Q 与 K 先负责计算匹配关系：

```text
Q 与 K
→ Attention Score
→ Attention Weight
```

得到权重后，模型才用它们处理各位置的 Value：

```text
位置 0 权重 × V₀
+ 位置 1 权重 × V₁
+ 位置 2 权重 × V₂
→ 当前位置的上下文汇总
```

因此：

```text
K 决定怎样被匹配
V 决定匹配后提供什么
```

## 一个教学示意

假设当前位置得到权重：

```text
[0.2, 0.7, 0.1]
```

对应三个 Value：

```text
V₀ = [1, 0]
V₁ = [0, 2]
V₂ = [1, 1]
```

概念上的汇总是：

```text
0.2 × V₀ + 0.7 × V₁ + 0.1 × V₂
```

这说明一个位置通常可以同时吸收多个来源，而不是只复制最高分位置的 Value。

> [!warning]
> 数字仅为说明加权汇总，并非真实模型内部结果。

## Value 是原始文本吗

不是。Value 通常由当前层输入 Hidden State 通过 Value 投影得到：

```text
Hidden State
→ V 投影
→ Value 向量
```

它已经是模型内部连续表示，不是原始文字、Token ID 或数据库记录。

## 为什么不能直接对 Key 加权求和

Key 被优化用于匹配，不必同时承担最适合传递内容的表示。把 Value 分开后，模型可以分别学习：

```text
什么特征适合判断相关性
什么特征适合传给接收位置
```

这是 Q/K/V 分工带来的表达自由度。

## Value 自己是否知道权重

Value 本身不决定自己最终获得多少权重。权重来自特定 Query 与所有允许 Key 的比较，再经过 Scaling、Mask 和 Softmax。

同一个 Value 面对不同接收位置，可以被赋予不同权重。

## 常见误解

- **“Value 就是 Token 原文。”** 它是投影后的内部向量。
- **“Attention 只取权重最高的一个 Value。”** 标准 Attention 使用多个 Value 的加权和。
- **“Value 自己决定重要性。”** 权重来自 Query–Key 匹配链路。
- **“Key 和 Value 必须是同一个向量。”** 它们通常由不同投影产生并承担不同职责。
