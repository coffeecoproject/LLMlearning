# 1.4.2.3.5 从 Score 到 Weight 的完整流程

> [!summary]
> 一个接收位置先与各候选来源位置比较，得到 Scores；模型调整数值尺度、加入位置影响并排除禁止位置，最后把可见 Scores 转换为用于汇总 Value 的 Weights。

## 非数学主线

仍以“她”这个位置为例：

```text
1. “她”分别与“小明”“书”“小红”等位置比较
2. 每个候选位置得到一个匹配 Score
3. 调整数值尺度，避免差异过度放大
4. 加入当前架构的位置关系影响
5. 排除未来或无效位置
6. 把剩余 Scores 整理成总和为 1 的 Weights
7. 下一步按 Weights 汇总各位置 Value
```

## 一组贯穿到底的教学示例

假设当前正在更新位置 2，它面对四个来源位置。下面的数字全部是为了说明流程而虚构的，不是真实模型输出：

```text
来源位置：   [位置 0, 位置 1, 位置 2, 位置 3]
原始 Score： [  1.2,    0.3,    2.0,    4.5 ]
可见权限：   [  允许,   允许,   允许,   未来 ]
Mask 后：    [  1.2,    0.3,    2.0,    禁止 ]
Softmax 后： [ 0.28,   0.11,   0.61,    0   ]
```

这个例子说明了三件事：

1. 位置 3 即使原始 Score 最高，也会因为没有读取权限而得到 0 Weight；
2. 其余位置不是简单保留原始分数，而是转换成同一组内的相对系数；
3. 得到 Weight 以后还没有完成信息混合，下一步才会把它们分别乘到对应 Value 上。

## Score 与 Weight 对比

| 对象 | 直觉 | 数值特点 | 是否直接加权 Value |
|---|---|---|---:|
| Score | 未整理的匹配强弱 | 可正可负、总和不固定 | 否 |
| Weight | 整理后的相对份额 | 非负、同一行通常和为 1 | 是 |

## 位置机制在哪一步出现

```text
RoPE
→ 通常先改变 Q、K 的位置关系，再产生 Score

ALiBi
→ 通常在 Score 上加入距离偏置
```

因此“位置影响”不是所有模型都在完全相同的一行代码里完成。

## 可选技术总览

掌握直觉后，可以把技术链读成：

```text
QK 点积
→ 除以 √head_dim
→ 加位置偏置（若架构使用）
→ 加 Mask
→ Softmax
→ Attention Weight
```

单头、单条长度为 `S` 的序列中，Score 和 Weight 常都可表示为 `[S,S]`：行是 Query 接收位置，列是 Key/Value 来源位置。形状相同不表示含义相同。

## Weight 能说明与不能说明什么

高 Weight 可以直接说明：

> 在这个层、这个 Head、这个接收位置的本次 Value 汇总中，对应来源位置获得了较大系数。

它不能单独证明：

- 该位置是回答的唯一原因；
- 模型已经形成正确的人类语义解释；
- 其他层、Head、FFN 和残差通道不重要。
