# 1.4.2.1.1 为什么需要位置之间的信息混合

> [!summary]
> 单个 Token 的初始表示无法独自表达它在当前句子中的角色；模型必须让当前位置有选择地吸收其他位置的信息，才能形成上下文相关的 Hidden State。

## 从一个歧义句开始

比较：

```text
我吃了一个苹果。
苹果发布了新设备。
```

如果“苹果”对应同一个 Token ID，它会从同一行 Token Embedding 出发。但要判断本次指水果还是公司，模型必须利用其他位置：

```text
“吃了”“一个”
→ 支持水果语境

“发布”“设备”
→ 支持公司语境
```

这说明一个位置不能永远只处理自己的初始向量。

## 什么叫信息混合

这里的“混合”不是把所有 Token 拼成一个大字符串，也不是把所有向量简单求平均，而是：

```text
当前位置提出自己的信息需求
→ 比较其他可见位置与自己的相关程度
→ 给不同位置分配不同权重
→ 按权重汇总它们提供的内容
```

汇总结果会回到当前位置，成为该位置更新表示的一部分。

## 为什么不能固定只看相邻 Token

语言关系可能跨越很远。例如：

```text
小明把书交给了站在门口的小红，因为她明天要考试。
```

理解“她”可能需要连接前面较远的“小红”。如果模型永远只看左右一个 Token，就必须经过很多步骤才能传递远距离信息，而且容易丢失关键关系。

Self-Attention 允许一个位置在一次 Attention 计算中直接与所有允许看见的位置建立候选关系。

> [!note]
> “可以建立候选关系”不等于一定能正确找到指代对象。模型参数、上下文长度、训练数据和多层计算都会影响结果。

## 为什么不能固定一套关注规则

同一个 Token 在不同句子中需要关注不同对象：

```text
“银行提高了利率。”
→ “银行”与金融语境相关

“他坐在河流的银行旁。”
→ 这个英文歧义示意需要根据上下文判断 bank 的含义
```

Attention 的价值在于权重由当前输入动态计算，而不是提前写死：

```text
第 3 个位置永远关注第 1 个位置
```

## 输出仍然按位置保留

Self-Attention 不会把整句话压成一个单独向量。输入有多少个位置，输出通常仍有多少个位置：

```text
输入：[sequence_length, hidden_size]
输出：[sequence_length, hidden_size]
```

区别是，输出中每个位置的表示已经有机会吸收其他可见位置的信息。

## 它与 FFN 的分工预览

可以暂时这样区分：

```text
Attention
→ 主要解决位置之间怎样交换和汇总信息

FFN / MLP
→ 主要在每个位置内部继续变换表示
```

两者会在 Transformer Block 中配合，不应该把整个模型能力都归因于 Attention。

## 常见误解

- **“信息混合就是把所有 Token 平均起来。”** 权重因当前位置和输入而异。
- **“Attention 会把整句话变成一个向量。”** 通常仍为每个位置输出一个向量。
- **“一次 Attention 就能解决所有上下文关系。”** 模型通常需要多层 Attention、FFN 和残差连接共同处理。
- **“能直接关联远处位置就一定能正确理解长文本。”** 可连接只是结构能力，不保证实际利用质量。
