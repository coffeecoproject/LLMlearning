# Tokenizer 怎样影响模型学习

> [!summary]
> LLM 训练时看到的不是原始字符串，而是 Token ID 序列；Tokenizer 因而会改变模型学习关系时使用的基本单位和序列长度，但不会单独决定最终能力。

## 先标明阶段

- **【Tokenizer 训练阶段】**：从语料中建立词表和切分规则。
- **【LLM 训练阶段】**：固定这套 Tokenizer，把大量文本变成 ID 序列，再更新神经网络参数。
- **【LLM 运行阶段】**：用同一套 Tokenizer 编码用户输入，模型使用已学参数计算结果。

这一篇主要讨论第二步：固定的 Tokenizer 怎样影响 LLM 的训练输入。

## 模型实际看到什么

训练原文：

```text
我喜欢苹果
```

可能被转换为：

```text
[我] [喜欢] [苹果]
→ [ID₁, ID₂, ID₃]
```

LLM 不直接对字符串“苹果”更新参数，而是围绕这些 ID 的 Embedding 和上下文关系学习。Tokenizer 因而定义了模型接触文本的第一层离散接口。

## 切得很碎会发生什么

假设一个术语总被切成四个 Token：

```text
[片段A] [片段B] [片段C] [片段D]
```

模型仍然可能通过训练学会这个整体术语，但需要在多个位置之间建立稳定关系；同一术语也会消耗更多训练位置和上下文位置。

切得较完整时，模型可以更直接地围绕一个常见单位学习统计关系。不过这不意味着“一个词一个 Token”永远最佳，因为新词、拼写变化和开放文本仍需要可组合的更小单位。

## 子结构复用为什么有价值

例如多个词共享后缀：

```text
happiness
kindness
darkness
```

如果 `ness` 是可复用子词，模型可能在不同单词中共享这个输入单位的训练经验。子词表示在“完整常见片段”和“可组合小单位”之间取得平衡。

注意：Token 复用只提供可学习的共同单位，不保证模型一定形成语言学上正确的词缀概念。

## Tokenizer 会不会决定模型懂不懂一种语言

不会单独决定。

```text
合适的 Tokenizer
→ 可能让该语言表示更紧凑、学习更便利

足够且高质量的训练数据
→ 才提供语言规律、知识和用法

模型容量与训练方法
→ 决定能否充分吸收和使用这些规律
```

即使字节级方案能编码一种语言的所有文字，如果训练数据中几乎没有这种语言，模型也不会仅凭“可编码”就掌握它。

## Tokenizer 影响能力，但不是全部原因

比较两个模型时，不能看到某模型 Tokenizer 更高效，就直接断言它一定更强。模型能力还受到：

- 训练数据规模、质量与分布；
- 模型架构和参数规模；
- 优化方法和训练时长；
- 后训练与对齐；
- 运行时给予的上下文。

因此最准确的说法是：

> Tokenizer 塑造了模型的输入表示条件，而模型能力由整个训练与运行系统共同形成。

## 常见误解

- **“词表里有这个词，模型就理解这个词。”** 词表只提供 ID；含义要从 LLM 训练中形成。
- **“切得越完整，学习一定越好。”** 过大的词表会降低组合复用并增加参数负担。
- **“字节回退覆盖所有文字，所以模型掌握所有语言。”** 可编码不等于有训练经验。
- **“模型表现差一定是 Tokenizer 导致的。”** Tokenizer 只是众多影响因素之一。
