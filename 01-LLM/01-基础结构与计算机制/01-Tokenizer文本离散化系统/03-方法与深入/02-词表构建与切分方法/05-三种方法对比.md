# BPE、WordPiece、Unigram 对比

> [!summary]
> 三者都在解决“有限词表怎样表示开放文本”，核心差异是训练时怎样选择词表片段，以及运行时怎样从多个候选中确定切分。

## 一张核心对比表

| 维度 | BPE | WordPiece | Unigram |
|---|---|---|---|
| 典型训练起点 | 小单位词表 | 小单位词表 | 较大的候选词表 |
| 词表变化方向 | 反复添加合并片段 | 反复添加有价值片段 | 反复删除影响较小片段 |
| 入门核心依据 | 相邻对频率 | 候选片段的区分价值 | 删除片段后整体损失变化 |
| 典型运行切分 | 按合并规则或等级处理 | 从左到右最长匹配词表 | 比较完整切分路径得分 |
| 多种切分采样 | 某些变体支持 | 通常确定性 | 天然适合路径采样 |
| 常见关联 | GPT 类 Tokenizer 中常见 BPE 变体 | BERT 系模型 | SentencePiece、T5 等 |

> [!warning]
> 这是教学层面的典型比较。真实 Tokenizer 还会叠加字节路线、预切分、规范化、特殊 Token 和回退机制，不能仅凭算法名字推断全部行为。

## 用同一个示意词看差异

假设需要切分 `playing`，词表和规则都经过各自训练：

```text
BPE：       按已经学到的合并优先级执行
WordPiece：从开头寻找最长可用子词，再处理剩余部分
Unigram：   比较 [play][ing]、[p][lay][ing] 等完整路径的总分
```

三者可能恰好给出相同结果，也可能不同。结果相同不代表内部机制相同。

## 它们不是 Token 的三种类型

如果最终结果都是：

```text
[play] [ing]
```

`play` 和 `ing` 是 Subword Token；BPE、WordPiece、Unigram 是得到或选择这些 Token 的方法。

```text
输出对象：Token
表示粒度：Subword
构建与切分方法：BPE / WordPiece / Unigram
```

## 是否需要判断谁最好

不需要得出统一冠军。实际效果取决于：

- 训练语料的语言和领域；
- 词表规模；
- 字符或字节覆盖方式；
- 规范化与预切分；
- 特殊 Token；
- 与 LLM 训练数据、模型参数是否配套。

对于已经训练好的模型，最重要的不是重新选择算法，而是使用它原本配套的 Tokenizer。

## 适合记住的三句话

```text
BPE：从小片段开始，按合并规则逐渐组成大一些的片段。
WordPiece：建立子词词表，运行时常从当前位置做最长匹配。
Unigram：先准备较多候选再淘汰，运行时选择整体得分更好的切分路径。
```

## 常见误解

- **“BPE 一定只处理字符。”** 一些现代实现以字节为基础单位。
- **“WordPiece 就是 BPE 换名字。”** 它们的词表学习目标和运行切分策略存在差异。
- **“Unigram 每次都会随机切。”** 默认可以选择最佳路径，采样只是可选能力。
- **“算法相同就会得到相同 Token。”** 训练语料、词表和配置不同，结果仍会不同。
