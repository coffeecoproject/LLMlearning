# BPE：怎样通过合并形成 Token

## 一句话理解

> BPE 从较小单位开始，反复合并训练语料中频繁相邻的片段，把有复用价值的组合加入词表；使用时再按照已经学到的合并规则编码新文本。

## 1. 先把两个阶段分开

### 【Tokenizer 训练阶段】

```text
训练语料
→ 统计相邻片段
→ 反复选择并合并
→ 形成 Vocabulary 与 Merge Rules
```

### 【Tokenizer 使用阶段】

```text
新文本
→ 转为基础单位
→ 应用已固定的 Merge Rules
→ 得到 Token
→ 映射为 Token ID
```

BPE 不是在每次用户输入时重新统计当前句子。

## 2. 一个完整的中文示意

下面为了展示机制，从单个汉字开始。真实模型可能从字节等其他基础单位开始，结果也由真实训练语料决定。

假设训练语料是：

```text
苹果
苹果
苹果汁
苹果汁
苹果树
```

初始表示：

```text
苹 | 果
苹 | 果
苹 | 果 | 汁
苹 | 果 | 汁
苹 | 果 | 树
```

## 3. 第一次统计和合并

统计相邻片段出现次数：

```text
苹 + 果：5 次
果 + 汁：2 次
果 + 树：1 次
```

频率最高的是 `苹 + 果`，于是学习一条规则：

```text
苹 + 果 → 苹果
```

把新片段 `苹果` 加入词表，训练语料重新表示为：

```text
苹果
苹果
苹果 | 汁
苹果 | 汁
苹果 | 树
```

## 4. 第二次统计和合并

重新统计当前相邻片段：

```text
苹果 + 汁：2 次
苹果 + 树：1 次
```

于是继续学习：

```text
苹果 + 汁 → 苹果汁
```

此时部分词表和规则可以表示为：

```text
Vocabulary：苹、果、汁、树、苹果、苹果汁……

Merge Rules：
1. 苹 + 果 → 苹果
2. 苹果 + 汁 → 苹果汁
```

## 5. 为什么每次合并后都要重新统计？

因为一次合并会改变后续可见的相邻关系。`苹 | 果 | 汁` 合并成 `苹果 | 汁` 后，新的候选对 `苹果 + 汁` 才出现。

如果只在最初统计一次，就无法正确发现由前一步产生的更长复用片段。

## 6. 什么时候停止？

常见控制方式包括：

- 达到目标词表大小；
- 完成预定数量的合并；
- 候选片段频率低于阈值；
- 受到具体实现的其他约束。

如果无限合并，可能把整句训练文本都存进词表，导致词表巨大且难以复用。BPE 的目标不是记住全部句子，而是在有限容量下选择值得复用的片段。

## 7. 使用阶段怎样编码新文本？

现在输入：

```text
我喝苹果汁
```

先转成相同基础单位：

```text
我 | 喝 | 苹 | 果 | 汁
```

应用已学习规则：

```text
苹 + 果 → 苹果
我 | 喝 | 苹果 | 汁

苹果 + 汁 → 苹果汁
我 | 喝 | 苹果汁
```

最后查词表：

```text
我       → 120
喝       → 846
苹果汁   → 10532
```

这些 ID 是虚构的讲解示意值，不属于任何真实模型。

## 8. 遇到没见过的完整词怎么办？

假设词表没有完整的“苹果味冰淇淋”，仍可以退回已有片段：

```text
苹果 | 味 | 冰 | 淇 | 淋
```

如果底层采用字节或有 byte fallback，那么更少见的字符也能继续退回字节表示。这就是有限词表覆盖开放文本的关键。

## 9. 英文示意

语料反复出现：

```text
play
playing
played
player
```

BPE 可能逐渐形成 `play`，并形成 `ing`、`ed`、`er` 等片段，最终可能切成：

```text
playing → play | ing
played  → play | ed
player  → play | er
```

这是机制示意。真实合并只服从具体语料和实现，不保证与语言学词根词缀完全一致。

## 10. “Byte Pair Encoding”为什么不一定逐字节展示？

BPE 最早来自数据压缩思想，名称保留了 Byte Pair Encoding。用于 NLP 时，基础符号的定义因实现而异。现代 LLM 中常见 Byte-level BPE：

```text
UTF-8 字节提供底层覆盖
        +
BPE 学习频繁片段合并
```

因此必须检查具体 Tokenizer，不能仅凭“BPE”三个字断言它最初按 Unicode 字符还是原始字节处理。

## 11. 合并规则和词表有什么不同？

Vocabulary 告诉系统“有哪些 Token 以及各自 ID”；Merge Rules 告诉 BPE 编码器“哪些相邻片段可以合并，以及优先顺序”。

只有词表而没有正确规则，不一定能复现相同切分；只有规则而没有 Token-ID 映射，也无法形成模型输入。

## 12. 常见误解

- BPE 是方法，不是 Token。
- 高频不代表有真正语义，只代表在训练数据中重复出现。
- BPE 不会在聊天时根据当前对话即时修改词表。
- 最长匹配是有用直觉，但不能替代具体 BPE 实现的合并优先级。
- 不同训练语料、词表大小和预处理会产生不同结果。

## 13. 你应该能复述的完整链路

```text
人选择训练语料、基础单位、BPE 和词表大小
→ 程序统计相邻片段
→ 计算机反复合并
→ 保存 Vocabulary 和 Merge Rules
→ 新文本按这套固定规则编码
→ Token
→ Token ID
```

LLM 训练和普通运行都会使用已经配套好的 Tokenizer，但相应阶段怎样组织数据不在本篇展开。
