# Byte-level：按字节表示

## 一句话理解

> Byte-level 先把文本编码成有限的字节值，使任意 UTF-8 文本都有底层表示；后续仍可把多个字节合并成更长 Token，因此一个字节并不必然等于一个最终 Token。

## 从文字到字节

文本在计算机中需要编码。现代系统常使用 UTF-8，把 Unicode 文本转换成字节序列。一个字节有 256 种可能值，因此底层集合天然有限。

```text
文字
→ Unicode 文本
→ UTF-8 编码
→ 字节序列
```

例如：

```text
字符    UTF-8 字节数
A       1
苹      3
🍎      4
```

这里描述的是 UTF-8 编码，不是 Token 数量。

## 为什么字节能够覆盖任意文本？

只要输入能够编码成 UTF-8，它最终就由 0 到 255 之间的字节组成。因此系统不必为世界上每个汉字、Emoji、新符号分别预留一个最底层词表项。

这带来重要性质：

```text
开放文本
→ 都可以分解为有限的字节集合
→ 不必因为某个字符没收录就直接变成统一 [UNK]
```

## 为什么不直接始终逐字节处理？

如果每个字节都成为一个最终 Token，英文之外的文本往往会变长。例如一个常见汉字在 UTF-8 中通常需要 3 个字节。为了提高效率，实际系统可以学习把频繁出现的相邻字节片段合并。

```text
底层字节：E8 | 8B | B9
后续合并：可能把这个常见片段整体作为一个 Token
```

以上只是机制示意；具体 Token 和 ID 必须用具体 Tokenizer 验证。

## Byte-level BPE 的因果链

```text
原始文本
→ UTF-8 字节
→ 用可处理的符号表示这些字节
→ BPE 学习高频相邻片段的合并
→ 形成包含不同长度字节片段的词表
→ 编码为 Token ID
```

因此 Byte-level 负责底层覆盖，BPE 负责学习合并。二者可以组合，不是互斥选项。

## 中文与 Emoji 的实际含义

假设输入：

```text
苹果🍎
```

UTF-8 会把它编码成若干字节。一个具体 Byte-level Tokenizer 可能：

- 把常见汉字或词对应的字节片段整体合并；
- 把较少见字符拆成多个 Token；
- 对常见 Emoji 有整体 Token；
- 对复杂或少见 Emoji 使用多个片段。

所以“支持 Emoji”与“Emoji 只占一个 Token”是两回事。

## 与 Unicode Code Point 的区别

```text
Unicode Code Point：抽象字符编号
UTF-8 bytes：该文本的一种具体字节编码
Token：具体 Tokenizer 词表中的离散单位
Token ID：Token 在该词表中的整数编号
```

同一个抽象字符可以在 UTF-8、UTF-16 等编码中拥有不同字节表示。讨论 Byte-level Tokenizer 时必须说明所使用的文本编码；主流场景通常是 UTF-8。

## 字节路线的优势

- 最底层集合只有 256 种字节值；
- 能覆盖多语言、代码、网址、控制符和新 Emoji；
- 降低完整未知字符被统一替换的风险；
- 可以与 BPE 等方法结合，提高常见片段效率。

## 字节路线的代价

- 非 ASCII 文本在未充分合并时会占更多 Token；
- Token 对人可能显示成奇怪片段，因为边界未必对应完整字符；
- 单个 Token 的字节序列可能不是独立有效的 UTF-8 文本；
- 解码和调试时必须正确处理字节边界。

## 为什么单 Token 解码可能出现问题？

一个完整汉字的 UTF-8 字节可能被分散在多个 Token 中。单独拿出其中一个 Token 解码，它的字节可能不足以组成合法字符；把完整 Token 序列的字节拼回去后，才可能正确还原文本。

因此：

```text
Token ID → 对应字节片段
多个字节片段连接
→ UTF-8 解码
→ 文本
```

不能假设每个 Token 都能独立显示成一个完整可读字符。

## Byte fallback 是什么？

并非所有 Tokenizer 都完全从字节开始。有些系统主要使用字符或子词词表，但在遇到无法覆盖的字符时退回字节表示。这叫 byte fallback。

```text
Byte-level：底层整体以字节为基础
Byte fallback：通常走其他路线，无法覆盖时退回字节
```

二者目标相近，但实现位置不同。

## 常见误解

- 字节值不是 Token ID；二者可能都是整数，但所属编号系统不同。
- UTF-8 编码不是把 Token ID 再“加密”一次。
- 一个字符占几个字节，不能直接推出它占几个 Token。
- Byte-level 不代表模型直接在神经网络里输入原始字节；最终仍需 Token ID 和 Embedding。
