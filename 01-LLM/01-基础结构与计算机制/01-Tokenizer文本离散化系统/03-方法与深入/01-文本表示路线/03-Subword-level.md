# Subword-level：按子词表示

## 一句话理解

> Subword-level 让高频文本片段成为较大的 Token，让罕见内容退回更小片段，从而在有限词表、较短序列和开放文本覆盖之间取得折中。

## 它在折中什么？

前两条路线各有明显代价：

```text
完整单词：序列短，但新词可能不在词表
单个字符：容易拼出新词，但序列很长
```

子词路线的想法是：不要固定只选大单位或小单位，而是根据语料中的使用情况混合不同粒度。

示意切分，不代表真实模型：

```text
常见词：apple      → ["apple"]
较少见词：apples   → ["apple", "s"]
罕见词：applelike  → ["apple", "like"] 或更小片段
```

## “子词”不一定是真正的语言学词素

`un`、`happy`、`ness` 看起来像有意义的构词成分，但算法学习到的片段主要由训练语料和优化目标决定。它也可能产生不符合人类构词直觉的片段。

更准确的理解是：

> 子词 Token 是可重复利用的文本片段，而不是由语言学家预先标注的词根词缀表。

## 词表如何同时包含不同粒度？

一个简化词表可能同时包含：

```text
小单位：a, p, l, e, s
中等片段：ap, ple, ing
大单位：apple, learning
```

编码时，Tokenizer 根据自己的算法和词表选择一组 Token 覆盖输入。不同算法如何训练词表、如何选切分，将在 [[00-词表构建与切分方法概览|词表构建与切分方法概览]] 中学习。

## 中文中的子词

中文的“子词”不等于“半个汉字”。词表可以包含单个汉字，也可以包含常见多字片段：

```text
示意词表：我、喜、欢、喜欢、苹、果、苹果

“我喜欢苹果”可能切成：
["我", "喜欢", "苹果"]
```

如果某个低频组合不在词表，就可能退回单字或更底层片段。具体切分由模型对应的 Tokenizer 决定。

## 为什么它适合多语言和代码？

子词片段可以复用。例如英文后缀、常见代码符号、重复出现的标识符片段都可能进入词表。它不要求预先列出所有完整单词和变量名。

但训练语料分布会造成差异：某种语言或代码形式在训练语料中更常见，往往更容易获得高效片段；低资源语言可能被切得更碎。

## 子词切分会影响模型吗？

会。Tokenizer 决定模型实际看到多少位置，以及哪些字符被捆绑为同一个输入单位。例如数字可能被整体、按几位或逐位切分，这会影响模型学习数字结构的难度。

但不能简单断言“切分符合人类词义，模型就一定更聪明”。模型还能通过后续 Transformer 层跨 Token 组合信息，最终能力受模型、数据、训练和推理方式共同影响。

## 与 BPE、WordPiece、Unigram 的关系

```text
Subword-level：要达到的表示思路
BPE / WordPiece / Unigram：实现这种思路的不同方法家族
```

所以不能说“Subword 和 BPE 是两种并列 Tokenizer”。更常见的说法是“使用 BPE 方法构建的子词 Tokenizer”。

## 优势与代价

优势：

- 高频片段可用较少 Token 表示；
- 罕见词通常能拆分，而不是全部变成 `[UNK]`；
- 词表规模比枚举完整单词更可控；
- 能适应自然语言、代码和混合文本。

代价：

- 切分结果未必符合人的词义边界；
- 同一句话在不同 Tokenizer 中可能差异很大；
- 低频语言或特殊文本可能被切得更碎；
- 仅有子词基础仍要考虑覆盖最底层未知符号的问题。

## 常见误解

- Subword 不是固定长度片段。
- 一个完整单词可以是一个 Subword Token，因为“子词路线”允许不同粒度。
- 子词边界不是模型最终理解语义的边界。
- BPE、WordPiece、Unigram 不属于 Token 的三种类型。
