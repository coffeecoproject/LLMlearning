# 为什么模型需要 Token

> [!summary]
> Token 把开放、可变的文本拆成有限、可复用、可编号的单位，为字符串世界和神经网络的数值计算建立接口。

## 能保存文字，不等于模型能直接计算文字

计算机可以把“猫”保存为 Unicode 编码，但神经网络进行的是数字运算，例如：

```text
输入数字 × 参数 + 偏置
```

字符串 `"猫"` 不能直接参加这类乘加运算。模型首先需要把文本转换成有限类别的编号，再用编号取得向量。

> [!note] 简单数学边界
> 常见线性计算可写成 `y = Wx + b`。这里只需知道 `x、W、b、y` 都是数字；本节不展开矩阵计算。

## 为什么不把整句话当成一个单位

假设为每句话分配一个 ID：

```text
0 → 我喜欢苹果
1 → 我喜欢香蕉
2 → 小明喜欢苹果
```

这种方法有三个问题：

1. 新句子近乎无限，无法提前列完；
2. 相似句子不能方便地复用“我喜欢”等局部结构；
3. 用户稍微改一个名字或数字，就可能没有对应 ID。

因此需要较小且可以重复组合的单位。

## 为什么不永远按最小单位切

如果始终逐字符或逐字节处理，几乎任何文本都能表示，但序列会变长。若始终把很长片段作为一个 Token，序列会变短，但词表会非常大，而且难以覆盖新文本。

```text
单位较大 → 序列较短，但词表更大、覆盖新文本更难
单位较小 → 词表较小、覆盖更稳，但序列更长
```

Tokenizer 要在这些目标间取得平衡，而不是寻找唯一“正确”的语言学切法。

## 一个完整教学例子

以下切分和 ID 都是虚构的：

```text
文本：我喜欢学习大模型
Token：["我", "喜欢", "学习", "大模型"]
ID：   [105, 832, 2047, 9184]
```

这四个 Token 可以重新组合到其他句子中。模型随后用 ID 查找向量；Tokenizer 本身并没有理解这句话。

## 如果没有 Token 这一层

系统会同时遇到：无法穷举所有输入、无法建立固定大小的输入参数表、无法稳定复用文本片段，以及无法把字符串转换成模型可索引的类别。

所以 Token 的必要性可以压缩为：

```text
无限可能的文本
→ 有限而可组合的符号
→ 稳定编号
→ 数值向量
```

## 常见误解

- **“计算机认识 Unicode，所以模型不需要 Token。”** Unicode 解决字符编码，Tokenization 解决模型输入单位和编号体系。
- **“Token 越大越好。”** 大单位和小单位各有代价。
- **“Tokenizer 在理解句意后才切分。”** 常见 Tokenizer 主要执行已经确定的规则和统计模型。
