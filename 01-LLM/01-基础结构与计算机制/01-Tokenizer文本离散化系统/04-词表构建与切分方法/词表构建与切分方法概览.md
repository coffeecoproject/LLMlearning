# 词表构建与切分方法概览

## 一句话理解

> 表示路线规定从什么基础单位出发；BPE、WordPiece、Unigram 等方法则让程序从训练语料中形成有限词表，并规定新文本怎样被表示成词表中的 Token。

## 本节解决什么问题？

在 [[文本表示路线概览]] 中，我们选择了单词、字符、子词或字节等基础路线。但即使决定从字节出发，仍然不知道：

- 哪些常见字节片段值得成为较大的 Token？
- 最终词表应该保留多少片段？
- 新文本存在多种切法时，应当选择哪一种？
- 训练完成后，切分规则怎样固定下来？

这些问题属于词表构建与切分方法。

## 共同的两阶段结构

### 【Tokenizer 训练阶段】

```text
人选择算法、训练语料和配置
→ 程序读取大量文本
→ 计算机统计频率或估计片段概率
→ 形成 Vocabulary
→ 保存合并规则、片段分数或概率等数据
```

### 【Tokenizer 使用阶段】

```text
输入新文本
→ 加载已经固定的词表和规则
→ 按规则切成 Token
→ 查 Vocabulary
→ 输出 Token ID
```

使用阶段通常不会拿当前一句话重新训练词表。

## 人、程序和数据分别负责什么？

```text
人：定义目标和约束
程序：实现算法并执行大量计算
数据：决定哪些文本片段更常见、更值得保留
```

因此，“程序训练”和“机器训练”并不矛盾。更准确的说法是：人编写和配置程序，计算机在数据上自动执行训练算法。

## 三种方法的总体方向

| 方法 | 起点直觉 | 词表怎样变化 | 编码依据 |
|---|---|---|---|
| BPE | 从小单位开始 | 反复加入高频相邻合并 | 学到的合并规则及优先级 |
| WordPiece | 从小单位开始 | 选择更有价值的候选合并 | 已训练词表上的确定性切分策略 |
| Unigram | 从较大候选集合开始 | 逐步删除贡献较小的片段 | 比较整条切分路径的概率或分数 |

这张表是入门级概括。不同库和论文的实现细节可能不同，后续笔记会分别说明。

## 必须保持的概念边界

```text
Subword-level：表示思路
BPE / WordPiece / Unigram：方法
Vocabulary：训练产物之一
Token：编码结果中的离散单位
Token ID：Token 在词表中的编号
tiktoken / SentencePiece：工具或实现
```
