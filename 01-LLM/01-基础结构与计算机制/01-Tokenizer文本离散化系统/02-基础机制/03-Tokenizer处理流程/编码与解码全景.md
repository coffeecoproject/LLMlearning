# 编码与解码全景

## 一句话理解

> Encode 把文本变成模型约定的 Token ID；Decode 把 Token ID 对应的片段重新组合为文本，二者使用同一套词表与配置。

## 编码示意

以下切分与 ID 均为教学示意：

```text
输入：“我喜欢苹果🍎”
→ 规范化
→ 初步分段
→ [我] [喜欢] [苹果] [🍎]
→ 加入所需特殊 Token
→ [BOS] [我] [喜欢] [苹果] [🍎] [EOS]
→ [1, 105, 8621, 12876, 48102, 2]
```

核心输出通常包括 `input_ids`，工具还可能产生 `attention_mask` 等辅助数据。

## 解码示意

```text
[105, 8621, 12876]
→ [我] [喜欢] [苹果]
→ 拼接片段
→ “我喜欢苹果”
```

Byte-level Tokenizer 可能需要先拼接多个 Token 的字节，再统一做 UTF-8 解码。

## Chat Template 的位置

用户提交的往往是结构化消息：

```text
role: user
content: 我喜欢苹果
```

Chat Template 先把它组织为模型训练时约定的角色与边界格式，然后才进入 Tokenizer。它属于交互协议；这里只说明接口，深入内容留到“模型推理与交互”。

## 哪些阶段是可选的？

Normalization、Pre-tokenization 和自动添加 BOS/EOS 都可能因实现而异。不能仅凭通用流程推断某个具体模型一定执行某一步，必须查看其配置。
