# 同一句文本的真实对比实验

> [!summary]
> 只有实际加载明确版本的 Tokenizer 并记录输出，才能可靠比较 Token；不能根据算法名称凭空猜测 Token 或 ID。

## 实验要回答什么

用同一组文本观察：

```text
相同字符
→ 不同 Tokenizer
→ Token 边界不同
→ Token ID 不同
→ Token 数量可能不同
```

## 阶段定位

- **【训练阶段】**：本实验不重新训练 Tokenizer；被比较的规则早已由各模型制作者确定。
- **【运行阶段】**：加载具体模型的 Tokenizer，对新文本执行 `encode` 与 `decode`。
- **【两阶段共同】**：运行结果反映训练阶段确定的词表、规则和特殊 Token 配置。

## 测试文本

```text
我喜欢苹果🍎
Hello, world!
unhappiness
user_id = 2026
```

四类文本分别暴露中文、Emoji、英文词缀、空格、标点、代码符号和数字的处理差异。

## 必须固定的实验条件

对每个被测对象记录：

1. 工具与版本；
2. 精确模型或 Encoding 名称；
3. 是否自动添加特殊 Token；
4. 是否启用 truncation、padding；
5. 核对日期。

缺少这些信息的“对比结果”很难复现。

## 每条文本记录五项

| 项目 | 要看什么 |
|---|---|
| 原始文本 | 包括真实空格、换行和 Emoji |
| Token ID | 模型真正接收的整数序列 |
| Token / bytes | 人能观察的切分或字节片段 |
| Token 数量 | 上下文占用 |
| Decode 结果 | 是否恢复原输入，以及变化发生在哪里 |

## 可复现实验骨架

### tiktoken

```python
import tiktoken

encoding = tiktoken.encoding_for_model("明确的模型名称")
ids = encoding.encode("我喜欢苹果🍎")
pieces = [encoding.decode_single_token_bytes(i) for i in ids]
print(ids, pieces, encoding.decode(ids))
```

### Hugging Face

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("组织名/精确模型名")
ids = tokenizer.encode("我喜欢苹果🍎", add_special_tokens=False)
tokens = tokenizer.convert_ids_to_tokens(ids)
print(ids, tokens, tokenizer.decode(ids))
```

### SentencePiece

```python
import sentencepiece as spm

sp = spm.SentencePieceProcessor(model_file="明确的 tokenizer.model")
ids = sp.encode("我喜欢苹果🍎", out_type=int)
pieces = sp.encode("我喜欢苹果🍎", out_type=str)
print(ids, pieces, sp.decode(ids))
```

## 怎样读结果，而不是只看结果

看到差异后依次追问：

1. 差异来自表示路线，还是具体词表？
2. 空格是否和相邻文字合并？
3. Emoji 是一个 Token、多个 Token，还是多个字节片段？
4. 数字按整段、数字组还是单字符切分？
5. 是否因为自动加入 BOS/EOS 导致长度增加？

## 理解检查

1. 为什么只写“使用 BPE”不足以让别人复现实验？
2. 为什么比较长度时应统一 `add_special_tokens` 设置？
3. 为什么不能把模型 A 的 ID 含义拿去解释模型 B？
