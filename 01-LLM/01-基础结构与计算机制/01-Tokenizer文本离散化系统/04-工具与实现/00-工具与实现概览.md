# Tokenizer 工具与实现

> [!summary]
> BPE、Unigram 是“怎样构建词表和切分”的方法；tiktoken、SentencePiece、Hugging Face Tokenizers 是把这些方法及完整处理流程做成软件的工具。

> [!note] 阅读定位
> 本节属于可选的工程观察，不是“用户文本 → Tokenizer → Token ID → Embedding”主链中的额外环节。`AutoTokenizer`、模型仓库加载和 Agent 上下文管理只用于说明工具边界，Runtime 机制留到“推理运行与交互”。

## 本节为什么存在

前面已经知道文本会经历规范化、切分、查词表、加入特殊 Token，再变成 Token ID。但真实模型不会每次临时发明规则，而是加载一套已经确定的 Tokenizer 文件，并由软件执行这些规则。

本节连接三层：

```text
原理：BPE、Unigram、词表、特殊 Token
                 ↓
实现：SentencePiece、tiktoken、HF Tokenizers
                 ↓
模型实例：某个具体模型配套的 Tokenizer 文件
```

## 统一的阶段标记

后续每篇都按下面三个标签讲解：

- **【训练阶段】**：从语料中学习词表、合并规则或分词模型，并保存文件。这里训练的是 Tokenizer。
- **【运行阶段】**：加载已经确定的文件，把用户文本编码为 ID，或把 ID 解码为文本。此时通常不再学习规则。
- **【两阶段共同】**：词表、特殊 Token、规范化规则等由训练阶段产生或确定，并在运行阶段被原样使用。

> [!warning] 两种“训练”不要混淆
> “训练 Tokenizer”是在确定文本怎样变成 ID；“训练 LLM”是在更新神经网络参数。通常先固定 Tokenizer，再用它处理 LLM 的训练语料。

## 一张总表

| 名称 | 它是什么 | 可采用的方法 | 训练阶段 | 运行阶段 |
|---|---|---|---|---|
| Hugging Face Tokenizers | 通用 Tokenizer 构建与执行库 | BPE、WordPiece、Unigram 等 | 可以训练 | 可以编码、解码 |
| SentencePiece | Tokenizer 训练器与执行器 | BPE、Unigram | 可以训练 | 可以编码、解码 |
| tiktoken | OpenAI 开源的快速 BPE Tokenizer 工具 | OpenAI 的 BPE Encoding | 普通使用者通常不在这里训练 | 加载 Encoding，编码、解码 |
| `AutoTokenizer` | Transformers 中按模型配置加载正确 Tokenizer 的入口 | 取决于具体模型 | 不是一种新训练算法 | 加载后用于模型输入处理 |

## 读完后的判断标准

你应该能解释：

1. 为什么 BPE 和 tiktoken 不能放在同一分类层级；
2. 为什么“使用 Tokenizer”不等于“训练 Tokenizer”；
3. 为什么同一个工具加载不同模型文件会给出不同结果；
4. 为什么不能只看工具名就推断模型的 Token 划分；
5. 为什么 Agent 必须使用与目标模型匹配的 Tokenizer 估算上下文。
