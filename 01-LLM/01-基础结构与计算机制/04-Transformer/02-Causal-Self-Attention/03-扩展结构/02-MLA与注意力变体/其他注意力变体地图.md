# 其他注意力变体地图

> [!summary]
> “Attention 变体”不是一种单一类别：有的改变 Head 共享，有的改变 K/V 表示，有的改变可见位置，有的稳定 Score，有的近似 Attention 数学，还有的只优化同一计算在硬件上的执行方式。

## 为什么需要这张地图

看到新名称时，如果只问“它是不是另一种 Attention”，很容易把不同层次混在一起。更有效的问题是：

```text
它究竟改了 Attention 的哪一部分？
```

## 第一类：改变 Head 与 K/V 的组织

代表：

```text
MHA、GQA、MQA
```

它们主要回答：

```text
多个 Query Head
分别使用多少组 K/V Head？
```

这部分已经在[[MHA-GQA与MQA概览|MHA、GQA 与 MQA]]专题完整展开。

## 第二类：改变 K/V 的内部表示

代表：

```text
MLA
```

它主要回答：

```text
K/V 内容是否必须以完整多头形式直接产生和保留？
能否先经过较窄的联合潜在表示？
```

这是本专题的主线。

## 第三类：改变哪些 Token 位置可以互相连接

### Full Attention

在遵守 Causal Mask 的前提下，当前位置可以读取全部历史位置：

```text
位置 t → 可看 0 到 t
```

### Sliding Window / Local Attention

当前位置只直接读取最近窗口内的位置：

```text
窗口大小为 4
位置 10 → 直接看位置 7、8、9、10
```

它减少单层直接连接范围与相关运行成本，但不等于模型永远无法获得更早信息；跨层传播、全局层安排和具体模型设计会影响有效感受范围。

Mistral 7B 官方论文是 GQA 与 Sliding Window Attention 同时使用的真实例子。这也说明“Head 共享方式”和“可见位置范围”可以属于两个不同设计维度。

### Sparse Attention

它不让每个位置连接所有允许位置，而是按照局部块、固定间隔、全局 Token 或学习规则选择部分连接。具体 Sparse Attention 方案差异很大，不能只凭名称判断连接图。

## 第四类：改变 Score 的尺度与稳定性

代表：

```text
QK-Norm
```

它在 Q、K 形成 Score 前进行归一化或尺度控制，主要目标是让匹配数值更稳定，减少 Softmax 过早饱和等问题。

它没有自动改变：

- Token 可见范围；
- KV Head 数量；
- 是否使用 KV Latent；
- Decoder-only 的因果方向。

不同模型所说的 QK-Norm 可能采用 L2 Norm、RMSNorm 或其他具体实现，必须查看对应代码，不能把所有版本当成同一个公式。

## 第五类：改变或近似 Attention 的数学计算族

代表：

```text
Linear Attention
```

标准 Attention 显式形成 Token 两两匹配，其计算与存储会随序列长度快速增长。Linear Attention 通常通过核特征映射和矩阵乘法结合顺序等方式，避免显式形成完整的两两 Score 矩阵。

它改变的比 GQA、MLA 更深：不只是 K/V 怎样存，而是 Attention 聚合的计算表达本身。不同 Linear Attention 方案的能力、因果实现和近似性质也不同，后续遇到具体模型时再单独学习。

## 第六类：优化同一 Attention 怎样在硬件上执行

代表：

```text
FlashAttention
```

FlashAttention 的核心是通过 IO-aware 的分块计算减少高带宽显存读写，在不保存完整中间 Score 矩阵的情况下计算**精确 Attention**。

因此它通常属于实现算法，而不是像 GQA、MLA 那样直接定义模型参数的 Q/K/V 表示结构：

```text
模型结构：规定要算什么
FlashAttention：优化怎样算同一个结果
```

一个模型可以使用 MHA、GQA 等结构，同时在 Runtime 选用兼容的 FlashAttention 内核。

## Attention Sink 放在哪一类

Attention Sink 最初描述一种现象：部分模型会把较强 Weight 分配给开头 Token，即使它们并不总有直接语义重要性。StreamingLLM 利用保留初始 Token 加最近窗口的方式改善流式窗口运行。

它更接近：

```text
Attention 行为现象
+ 流式缓存/窗口策略
```

不能简单把它与 MHA、GQA、MLA 并列成同一层架构分类。

## 一张分类表

| 名称 | 主要改变什么 | 不应误认为 |
|---|---|---|
| MHA / GQA / MQA | Query Head 与 KV Head 的对应 | Token 窗口策略 |
| MLA | K/V 内容表示与位置分支 | 只是 KV Head 更少 |
| Sliding Window / Local | 可直接读取的位置范围 | KV 压缩方式 |
| Sparse Attention | Token 之间的连接图 | 单一固定算法 |
| QK-Norm | Q/K 尺度与 Score 稳定性 | 一种长上下文缓存 |
| Linear Attention | Attention 的计算表达 | FlashAttention 的别名 |
| FlashAttention | 精确 Attention 的硬件执行 | 新的模型语义结构 |
| Attention Sink / StreamingLLM | 行为现象与流式窗口策略 | 标准 Head 类型 |

## 阶段边界

> [!info] 模型结构或训练、运行共同
> GQA、MLA、Sliding Window、QK-Norm 等如果写入模型结构，训练与运行通常都会遵循。

> [!info] 运行实现
> FlashAttention、Paged Attention、具体 KV Cache 布局和请求调度主要属于 Runtime；它们可以在不改变模型已学参数含义的前提下优化执行。

> [!warning] 必须查具体版本
> 同一名称可能有不同实现，同一模型也可能组合多种设计。应以对应版本的官方论文、配置和代码为准，而不是只看营销名称。
