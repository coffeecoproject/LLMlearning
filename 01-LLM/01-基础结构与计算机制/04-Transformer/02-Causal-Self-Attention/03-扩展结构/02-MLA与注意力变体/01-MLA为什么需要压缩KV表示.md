# MLA 为什么需要压缩 KV 表示

> [!summary]
> 标准多头 Attention 会为每个历史位置形成多组 K/V；生成序列越长，需要持续保留和读取的 K/V 越多，MLA 因而尝试保存更紧凑但仍足以支持后续注意力计算的表示。

## 从已经学过的标准 MHA 出发

假设标准 MHA 有 4 个 Head。某个 Token 经过 Attention 投影后，会产生：

```text
K0、K1、K2、K3
V0、V1、V2、V3
```

自回归生成下一个 Token 时，新 Query 需要和历史 Token 的 Key 比较，并按 Weight 汇总历史 Value。因此，历史位置的 K/V 不能在生成一步结束后全部丢掉。

序列增长时，可直观看成：

```text
历史位置越多
× 每个位置的 KV Head 越多
× 每个 Head 越宽
× 层数越多
→ 需要保留和反复读取的 K/V 信息越多
```

这就是 MLA 所针对的重要结构动机。

## 为什么不能简单把历史信息都删掉

假设模型已经读过：

```text
小王把蓝色钥匙放进第二个抽屉。……后来他问：钥匙在哪里？
```

生成答案时，当前 Query 需要重新匹配前文中与“钥匙在哪里”有关的位置。如果历史 Key 被全部删除，模型不知道应该重点读取哪些历史位置；如果历史 Value 也不存在，即使找到了位置，也没有对应内容可汇总。

所以目标不是“不要历史信息”，而是：

```text
能否用更紧凑的中间表示
保留后续 Attention 真正需要的信息？
```

## MLA 的核心回答

MLA 对每个位置先形成一个较窄的 KV 潜在表示：

```text
Hidden State
→ 向下投影
→ KV Latent
```

这个 Latent 再通过模型学到的投影，为多个 Head 提供内容 Key 和 Value 所需的信息：

```text
KV Latent
→ 向上投影
→ 多头 K/V 内容表示
```

于是，运行实现有机会围绕较窄的 Latent 保存和计算，而不必把完整多头 K/V 都作为唯一可用形式长期保留。

## 一个只看宽度的示意

> [!example] 教学示意，不是 DeepSeek 的真实维度

```text
原始 Hidden State：8 维
完整多头 K/V：需要更宽的多组表示

MLA：
8 维 Hidden State
→ 3 维 KV Latent
→ 根据需要提供多头 K/V 信息
```

`8 → 3` 表示模型设置了一条较窄的中间通道，不表示任意 8 个数字都能无损还原。模型会在训练中学习“哪些组合信息值得放进这 3 维”。

## 为什么它仍可能支持多个 Head

“潜在表示较窄”不等于“最后只有一个 Head”。同一个 KV Latent 可以经过不同的向上投影路径，形成不同 Head 使用的内容表示：

```text
                  ┌→ Head 0 所需 K/V 内容
KV Latent ────────┼→ Head 1 所需 K/V 内容
                  ├→ Head 2 所需 K/V 内容
                  └→ Head 3 所需 K/V 内容
```

多个 Head 的差异由学习到的投影保留，而共同信息通过 Latent 复用。

## 阶段边界

> [!info] 训练阶段
> 模型学习怎样把 Hidden State 投到较窄空间，以及怎样让该空间支持后续 K/V 与 Attention 任务。这里不是人工指定“第一维放语法、第二维放事实”。

> [!info] 运行阶段
> 参数不再因为普通用户的一次提问而重新训练。模型使用已学好的压缩路径；具体保存完整 K/V 还是保存 Latent，取决于运行实现。

## 来源与证据边界

[DeepSeek-V2 官方论文](https://arxiv.org/abs/2405.04434)把低秩 KV 联合压缩作为 MLA 的核心，并报告其模型实验中的 KV Cache 与生成吞吐改善。论文数值属于 DeepSeek-V2 的整体设计和实验条件，本篇只据此说明 MLA 的结构动机，不把数值外推到所有模型。核对日期：2026-07-27。

## 常见误解

- **“KV Latent 是整段对话的一个总摘要。”** 它按 Token 位置、按层产生，不是整段文本只剩一个向量。
- **“压缩后历史信息就可以全部丢弃。”** 历史位置仍需保留相应的紧凑表示。
- **“MLA 只是一种压缩文件格式。”** 压缩投影是神经网络结构的一部分。
- **“Latent 较窄就能直接证明回答质量更差。”** 表示存在取舍，但实际能力必须由训练结果和评测判断。
- **“MLA 取消了多个 Query Head。”** 它仍可以保留多个 Query Head。

## 理解检查

2. MLA 想减少的是 Token 数量，还是每个历史位置需要保留的表示量？
3. 一个 KV Latent 为什么仍能为多个 Head 提供不同内容表示？
4. `8 维 → 3 维` 为什么只是教学示意，而不是无损压缩保证？
