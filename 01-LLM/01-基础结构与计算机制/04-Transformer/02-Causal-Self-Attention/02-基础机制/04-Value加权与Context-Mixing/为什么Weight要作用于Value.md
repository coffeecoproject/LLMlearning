# 为什么 Weight 要作用于 Value

> [!summary]
> Weight 是“从各来源取多少”的系数，Value 是“各来源实际提供什么”的内容向量；只有让 Weight 作用于对应 Value，相关性判断才能转化为真正的信息传递。

## Weight 已经算出来，为什么还没结束

假设当前位置得到：

```text
来源位置： [小明, 苹果, 小红]
Weight：   [0.15, 0.10, 0.75]
```

这只能告诉我们：在这次汇总中，“小红”对应来源获得了更大的系数。

但 `[0.15, 0.10, 0.75]` 本身没有告诉模型：

- “小红”这个位置能提供哪些内部特征；
- 这些特征应怎样写入当前位置的新表示；
- 最终向量的每个维度应变成什么数值。

因此 Weight 是**路由或分配结果**，不是被传递的内容。

## Key 为什么不能直接代替 Value

在 Q、K、V 分工中：

```text
Query：当前位置正在寻找什么
Key：各来源怎样参与匹配
Value：各来源实际提供什么
```

Key 的任务是帮助计算匹配强弱。Value 的任务是携带被汇总的内容。二者来自同一个输入 Hidden State，但通常经过不同的可学习投影，因此模型可以分别学习：

```text
哪些特征适合用来判断相关性
哪些特征适合被传递给接收位置
```

如果只保留 Key 而没有独立 Value，这两种任务会被迫共用同一种表示，模型的表达空间会受到限制。

## 一个非数学类比，以及类比的边界

可以暂时把它想成查资料：

```text
Key：资料卡片上的检索标签
Weight：这份资料与当前问题的相对相关程度
Value：资料真正提供的内容
```

检索标签帮助你找到资料，但回答问题时需要读取资料内容。

> [!warning] 类比边界
> 模型内部没有真的资料卡、中文标签或完整句子。Q、K、V 都是连续数值向量；“检索”和“内容”只是对它们计算职责的直觉描述。

## Weight 如何与 Value 对齐

每个来源位置的 Weight 必须乘到**同一来源位置**的 Value：

```text
w₀ 对应 V₀
w₁ 对应 V₁
w₂ 对应 V₂
```

不能把位置 0 的权重随意乘给位置 2 的 Value，否则“判断哪个来源相关”与“实际从哪个来源取内容”就会错位。

## 因果链

```text
Q 与 K 比较
→ 决定各来源应占多少 Weight
→ Weight 缩放对应来源的 Value
→ 多个来源的 Value 相加
→ 当前位置得到新的上下文表示
```

缺少 Value 加权这一步，Attention 只能得到“看哪里”的关系图，不能把来源内容汇入当前位置。

## 常见误解

- **“Weight 就是上下文内容。”** Weight 只是标量系数，内容由 Value 向量提供。
- **“最高 Weight 对应的原文会被复制。”** 标准 Attention 通常对多个 Value 求加权和，不复制原文。
- **“Key 和 Value 没有必要分开。”** 分开后可以分别学习匹配特征与传递特征。
- **“Value 决定自己的 Weight。”** Weight 来自特定 Query 与各 Key 的比较链路。
