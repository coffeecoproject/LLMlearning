# 为什么需要 Q、K、V 三种角色

> [!summary]
> Attention 需要分别解决“当前位置与谁相关”和“相关位置实际提供什么内容”；Q、K 负责形成匹配关系，V 负责提供被汇总的信息。

## 一个位置要完成两件不同的事

假设模型正在更新“她”这个位置：

```text
小明把书交给小红，因为她明天要考试。
```

它至少需要处理两个问题：

```text
问题 A：前面哪些位置与“她”相关？
问题 B：确定相关位置后，应从那里取得什么信息？
```

这两个问题并不相同。用于判断“小红”是否匹配“她”的特征，不一定等于最终应该传递给“她”位置的全部内容。

## Q、K 负责匹配，V 负责内容

可以先建立下面的角色分工：

```text
Query（Q）
→ 当前接收位置用于发起匹配的表示

Key（K）
→ 每个候选来源位置用于接受匹配的表示

Value（V）
→ 每个来源位置实际可被汇总的内容表示
```

计算时：

```text
当前位置的 Q
× 各位置的 K
→ 各位置的匹配分数

匹配分数变成权重
× 各位置的 V
→ 当前位置得到的上下文汇总
```

## 为什么 K 与 V 不直接使用同一向量

假设一本书的目录写着：

```text
标签：Transformer、Attention、入门
正文：完整章节内容
```

标签适合判断“是否与问题相关”，正文适合在命中后提供信息。真实 Attention 不是图书馆检索，但这个类比说明：匹配依据与返回内容可以承担不同职责。

如果强制二者完全相同，模型就失去了分别学习“怎样被找到”和“找到后提供什么”的自由度。

## 为什么 Q、K、V 都来自同一个位置表示

在 Self-Attention 中，每个位置既可能作为信息接收者，也可能作为信息来源：

```text
同一个位置的 Hidden State
├→ 产生 Q：它要怎样寻找别处信息
├→ 产生 K：别的位置怎样与它匹配
└→ 产生 V：它能向别的位置提供什么
```

这就是同一位置拥有三种角色表示的原因。

## 类比在哪里失效

不能把 Q、K、V 当作：

```text
Q = 一句自然语言问题
K = 人工填写的关键词
V = 原始 Token 文本
```

真实情况是：

- 三者都是浮点向量；
- 三者由当前 Hidden State 经过不同投影得到；
- 它们的用途由整体训练塑造；
- 某个向量维度通常没有单一、人工命名的含义。

## 常见误解

- **“Q、K、V 是输入文本中三类不同 Token。”** 每个 Token 位置通常都会产生自己的 Q、K、V。
- **“K 是词表里的关键词。”** K 是连续向量，不是人工标签。
- **“V 就是原始 Token Embedding 的复制。”** V 是输入表示经过 Value 投影后的结果。
- **“Q 找到一个 K 后，只能取一个 V。”** Attention 通常会按权重汇总多个允许位置的 V。
