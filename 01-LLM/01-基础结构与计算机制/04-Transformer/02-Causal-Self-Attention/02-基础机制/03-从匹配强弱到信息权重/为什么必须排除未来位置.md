# 为什么必须排除未来位置

> [!summary]
> 在 Causal Self-Attention 中，位置 `i` 的表示只允许依赖位置 `0` 到 `i`；未来位置不属于它的可见上下文，因此必须被排除。

## 先理解这是一条结构规则

`Causal` 表示信息只能沿着序列的因果方向流动：过去可以影响后面，后面的内容不能反过来进入前面位置的表示。

```text
过去位置 ──可以──→ 当前及后续位置
未来位置 ─不可以→ 更早位置
```

如果位置 1 可以读取位置 3，那么位置 1 的表示已经包含了“位于它右侧的信息”，这个网络就不再满足 Causal Attention 的定义。这里的“未来”首先是**相对于某个序列位置而言**，不只是现实时间中的未来。

## 阶段标注：为什么两个阶段都需要这条规则

> [!info] 两阶段共同
> Causal 是 Decoder-only LLM 的结构约束。训练和运行都遵守“位置 `i` 只能依赖位置 `0...i`”，但两个阶段中最容易观察到的作用不同。

### LLM 训练阶段：防止偷看答案

训练时，程序通常会把一段完整 Token 序列一次送入模型，并并行计算多个位置的预测。假设训练片段是：

```text
我 | 喜欢 | 吃 | 苹果
```

当“吃”所在位置用于预测下一个 Token“苹果”时，如果它能直接读取右侧已经放在训练张量中的“苹果”，就相当于提前看到答案：

```text
不加因果限制
→ 前面位置读取后面的目标 Token
→ 训练误差可能虚假降低
→ 模型没有真正学会根据过去预测未来
```

因此训练阶段必须屏蔽未来位置，才能让训练任务与以后左到右生成时的信息条件一致。

### LLM 运行阶段：保持相同的模型结构

运行时即使完整 Prompt 已经存在，标准 Decoder-only 模型也不会临时把 Attention 改成双向结构。Prompt Prefill、逐 Token Decode、最后位置为什么能够利用完整 Prompt，以及这条规则与 KV Cache 的关系，单独进入下一篇：[[为什么运行时仍然保持因果可见性]]。

## 可见规则

长度为 4 的序列：

```text
位置 0 → 只能看 0
位置 1 → 可以看 0、1
位置 2 → 可以看 0、1、2
位置 3 → 可以看 0、1、2、3
```

这就是 Causal Mask 建立的方向：可以看自己和过去，不能看未来。

## 为什么不能只给未来位置较低分

未来信息不是“不太推荐”，而是“不允许使用”。即使某个未来 Token 与当前位置高度匹配，也必须让它最终获得 0 权重。

这与 ALiBi 不同：

```text
ALiBi
→ 对远距离位置施加软偏置，仍可能被关注

Causal Mask
→ 对未来位置施加硬约束，不能被关注
```

因此 Mask 处理的是“有没有读取权限”，Score 处理的是“在有权限的来源中匹配得多强”。这两个问题不能合并。

## 与 Padding Mask 区分

```text
Causal Mask：排除未来位置
Padding Mask：排除为了对齐形状加入的无效位置
```

实现可能合并两种 Mask，但它们解决的问题不同。

## 可选技术补充：极小值

程序通常在 Softmax 前把被禁止位置的 Score 改成负无穷或数据类型可表示的极小值：

```text
[2.0, 1.0, 3.0]
→ [2.0, 1.0, 禁止]
```

经过 Softmax 后，禁止位置的权重为 0。记住“禁止 → 权重为 0”即可，不要求计算指数函数。

## 常见误解

- **“Mask 会从输入中删除未来 Token。”** 它限制 Attention 关系，不必删除张量中的 Token。
- **“未来位置只是受到普通扣分。”** Causal Mask 的目标是让其权重为 0。
- **“ALiBi 可以代替 Causal Mask。”** 软距离偏置不能替代未来硬屏蔽。
- **“Padding 和未来位置都是一回事。”** 一个是无效填充，一个是因果限制。
- **“Causal Mask 只在训练时需要。”** 它是模型的因果结构；逐 Token Decode 中未来尚不存在，可能不必显式构造完整 Mask，但运行仍遵守同一可见性规则。
