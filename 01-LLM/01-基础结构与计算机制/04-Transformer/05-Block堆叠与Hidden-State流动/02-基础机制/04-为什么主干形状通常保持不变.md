# 为什么主干形状通常保持不变

> [!summary]
> 常见 Transformer 主干让每个 Block 的输入和输出保持相同 `hidden_size`，并通常保留相同 Token 位置数，这样 Residual 可以相加，Block 也能直接串联。

## 一个简单形状

假设：

```text
sequence_length = 3
hidden_size = 4
```

整条序列 Hidden States 的形状是：

```text
[3,4]
```

经过一个常见 Block：

```text
Block 输入：[3,4]
Block 输出：[3,4]
```

## 为什么宽度要回到 hidden_size

Residual 需要把子层输出与主干逐元素相加：

```text
[3,4] + [3,4]
```

如果 Attention 或 FFN 最终返回 `[3,7]`，就不能直接与 `[3,4]` 的主干逐元素相加，也不能无缝交给下一层相同结构。

所以子层内部可以临时改变组织方式，但离开子层前通常回到主干宽度。

## Attention 内部的变化

Multi-Head Attention 可以把主干特征组织成多个 Head：

```text
hidden_size
→ 多个 Head 的表示
→ 各 Head 分别计算
→ 拼接或合并
→ Output Projection
→ 回到 hidden_size
```

Head 的拆分不会让 Block 输出永久变成更多 Token。

## FFN 内部的变化

```text
hidden_size
→ intermediate_size
→ 激活或 Gate
→ hidden_size
```

例如：

```text
4096 → 12288 → 4096
```

`12288` 只存在于该 Block 的 FFN 内部。离开 FFN 时已经压回 4096，下一 Block 不会接收 12288 宽的主干。

## Token 位置数为什么通常不变

Self-Attention 会混合不同位置的信息，但通常为每个输入位置都产生一个更新后的输出位置：

```text
3 个输入位置
→ 3 个更新位置
```

它不是文本摘要器，不会默认把整条序列压成一个 Token。

## Batch 形状

如果同时处理两个整理为相同长度的样本：

```text
[batch_size, sequence_length, hidden_size]
= [2,3,4]
```

常见 Block 主干前后仍保持 `[2,3,4]`。Batch 怎样组织请求或训练样本属于训练和运行系统，不在这里展开。

## “通常”为什么重要

某些模型可能使用特殊跨层变换、压缩、扩展或多模态连接，因此不能把形状恒定写成所有 Transformer 的绝对规则。这里描述的是常见 Decoder-only LLM 的 Residual 主干。

## 常见误解

- 形状不变不表示数值没变。
- `intermediate_size` 不会在下一层继续当主干宽度。
- Attention 混合信息不表示减少 Token 数量。
- 层数增加不会让 Hidden State 每层多一个维度。
