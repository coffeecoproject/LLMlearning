# 1.2.4.2 Hidden State 是什么

> [!summary]
> Hidden State 是某个 Token 位置在模型某一层计算后的当前向量表示；它会随输入上下文、所在位置和模型层数而变化。

## 从初始表示到中间状态

假设一条序列有 3 个 Token，`hidden_size = 4`。进入第一层之前，每个位置都有一个四维初始表示：

```text
第 0 层输入：形状 [3, 4]
```

经过第一个 Transformer Block 后，仍然得到每个位置一个四维向量：

```text
第 1 层输出：形状 [3, 4]
```

这些输出就是第 1 层的 Hidden States。继续经过下一层，又得到下一组 Hidden States。

```text
初始表示 h⁽⁰⁾
→ 第 1 层 Hidden State h⁽¹⁾
→ 第 2 层 Hidden State h⁽²⁾
→ ……
→ 最后一层 Hidden State h⁽ᴸ⁾
```

这里的上标只表示第几层，不是数学乘方。

## `State` 为什么叫“状态”

它表示模型计算到当前层时，各 Token 位置暂时携带的数值信息。下一层会读取这些向量并继续变换它们。

因此 Hidden State：

- 不是输入文本本身；
- 不是一个 Token 的永久词义；
- 不是训练后长期保存的模型参数；
- 是本次前向计算产生的中间表示。

## `Hidden` 为什么叫“隐藏”

`Hidden` 主要表示它处在模型内部，不直接等于用户可读的文字，也不直接等于输出概率。它并不意味着这些数字一定被加密或完全不可观察。

在能够访问模型内部张量的研究或开发环境中，可以读取 Hidden State；但即使读取出来，它也只是大量浮点数，通常不能逐维直接翻译成自然语言。

## 一个位置还是整条序列

术语使用中常有两种说法：

```text
某个位置的 Hidden State
→ 形状通常是 [hidden_size]

某一层整条序列的 Hidden States
→ 形状通常是 [sequence_length, hidden_size]
```

加入 Batch 后常见形状是：

```text
[batch_size, sequence_length, hidden_size]
```

所以看到 `hidden_states` 时，要结合上下文判断是在说单个位置的向量，还是整层序列张量。

## Hidden State 与模型参数的区别

| 对象 | 来源 | 是否随输入变化 | 是否保存在权重文件中 |
|---|---|---:|---:|
| Token Embedding 参数行 | 训练形成的权重 | 通常不随当前输入变化 | 是 |
| Hidden State | 本次前向计算 | 是 | 否 |
| 架构配置 `hidden_size` | 模型设计 | 否 | 记录在配置中 |

`hidden_size` 规定向量宽度；Hidden State 是具有这个宽度的实际中间数据。二者名称接近，但不是同一种对象。

## Hidden State 最终有什么用

中间层的 Hidden State 继续传给下一层。最后一层的表示经过最终归一化和 LM Head 后，才会变成词表中各候选 Token 的 Logits。

```text
Final Hidden State
→ LM Head
→ Logits
→ 概率分布
```

完整输出机制放在后续 [[1.5-Output-Layer输出层概览|1.5 Output Layer 输出层]]，这里先记住：Hidden State 仍是模型内部表示，不是最终答案。

## 常见误解

- **“Hidden State 是模型隐藏起来的记忆库。”** 它是一次计算中的临时表示，不是长期数据库。
- **“Hidden State 和 hidden_size 是同一个参数。”** 前者是张量数据，后者是架构规定的维度。
- **“每层形状相同，所以每层没有变化。”** 形状可以不变，里面的数值和携带的信息仍会变化。
- **“最后一层 Hidden State 已经是 Token 概率。”** 还需要输出映射等步骤。
