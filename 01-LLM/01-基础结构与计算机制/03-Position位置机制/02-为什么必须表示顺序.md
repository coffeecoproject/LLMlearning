# 为什么必须表示顺序

> [!summary]
> Token Embedding 说明“当前位置是什么 Token”，但不主动编码“它位于第几个位置”；位置机制让 Attention 能利用顺序和距离关系。

## 顺序为什么会改变含义

比较：

```text
小明帮助小红
小红帮助小明
```

两句话使用了相同的一组词，但人物角色因为顺序不同而交换。再如：

```text
狗咬人
人咬狗
```

如果模型只知道出现了“狗、咬、人”，却不知道排列关系，就无法稳定区分谁执行动作、谁承受动作。

## 不是已经按行排列了吗

Embedding 后的张量确实按顺序存放：

```text
第 1 行 → 第 1 个 Token
第 2 行 → 第 2 个 Token
第 3 行 → 第 3 个 Token
```

但“数据存放在不同的行”与“模型计算能够利用行号”不是同一回事。

基础 Self-Attention 会根据每个位置的内容表示计算关系。如果没有额外位置信息，同一组输入向量整体换一个排列，Attention 本身没有天然的时间轴或第几个位置的概念。它会跟着输入排列产生对应排列的输出，却无法仅凭内容知道哪个位置在前、相距多远。

> [!note]
> 更准确地说，不含位置机制的 Self-Attention 对输入排列具有置换等变性：输入怎样重排，输出也相应重排。这里不要求记住术语，只要理解“Attention 不会自动读取数组下标的语言含义”。

## 模型需要知道哪些位置关系

至少包括两类信息：

```text
绝对位置
→ 当前 Token 是第 1、2、3……个位置

相对位置
→ 两个 Token 谁在前、相隔多远
```

不同位置方案侧重不同。它们不一定把位置保存成一个可独立读取的“位置字段”，而是让后续 Attention 计算对顺序或距离敏感。

## Causal Mask 能不能代替位置机制

不能完全代替。

Causal Mask 规定：

```text
当前位置不能读取未来位置
```

它提供了方向约束，但没有完整表达每个位置的身份和距离。例如，能看见两个过去 Token，不等于已经知道哪个距离当前更近、相隔多少。

因此要区分：

```text
位置机制
→ 提供或注入位置、顺序、距离关系

Causal Mask
→ 限制哪些位置允许互相读取
```

## 三种典型路线预览

```text
Absolute Position Embedding
→ 给不同绝对位置分配位置向量，通常与输入表示相加

RoPE
→ 根据位置旋转 Attention 中的 Q、K，使二者关系包含相对位置信息

ALiBi
→ 根据位置距离直接修改 Attention Score
```

因此不存在适用于所有模型的统一步骤：

```text
Token Embedding + Position Embedding
```

这只准确描述某些方案。

## 阶段边界

位置机制属于模型架构的一部分，训练和普通运行必须使用同一套规则。本专题只认识结构，不讨论位置参数怎样训练、长上下文怎样部署或 KV Cache 怎样管理位置。

## 常见误解

- **“张量已经按顺序排好了，模型自然会理解行号。”** 数组排列存在，不等于 Attention 获得了可利用的位置关系。
- **“Causal Mask 就是位置编码。”** Mask 管可见性，位置机制表达位置或距离。
- **“所有模型都把位置向量加到 Token Embedding。”** RoPE 和 ALiBi 的作用位置不同。
- **“位置机制只需区分第几个位置，不需要相对距离。”** 许多语言关系与相对顺序和距离密切相关。
