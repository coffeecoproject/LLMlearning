# LLM 基础结构与计算机制大纲

## 本部分回答什么

> 一段文本怎样依次变成 Token ID、向量、上下文表示，最后形成下一个 Token 的词表概率？

这里研究模型的五个核心结构和一次前向计算。完整逐 Token 生成属于“普通运行与生成”，参数怎样更新属于“训练与对齐”。

## 阶段标签怎样阅读

为了避免把模型结构、训练和运行混在一起，本部分统一使用四种阶段标签：

| 标签 | 表示什么 | 典型内容 |
|---|---|---|
| `Tokenizer 构建阶段` | 从语料和配置产生 Tokenizer 资产 | Vocabulary、Merge Rules、Unigram 分数 |
| `LLM 训练阶段` | 固定模型结构后，根据训练目标更新模型参数 | Loss、反向传播、Embedding 与投影权重更新 |
| `LLM 运行阶段` | 使用已经训练好的参数处理输入或继续生成 | Prompt Prefill、逐 Token 解码、采样、KV Cache |
| `两阶段共同` | 同一前向计算在 LLM 训练和运行时都会发生 | Embedding Lookup、Attention、FFN、Logits |

“参数由训练形成”不等于“这一步只在训练时执行”。例如 QKV 投影在两个阶段都会计算；差别是训练时投影参数可以被更新，普通运行时只读取固定参数。

Tokenizer 还要额外分清：`Tokenizer 构建阶段`不是`LLM 训练阶段`。一套已经构建好的 Tokenizer，既可以给 LLM 训练语料编码，也可以在模型运行时给用户输入编码。

## 五部分主线

```text
01 Tokenizer
文字 → Token → Token ID
        ↓
02 Embedding
Token ID → 初始向量
        ↓
03 Position
让后续计算利用顺序与距离
        ↓
04 Transformer
多层更新上下文相关 Hidden State
        ↓
05 Output Layer
Final Hidden States → Final Norm → LM Head → Logits
```

这是一条学习主线，不代表所有模型实现都把 Position 作为 Embedding 后面的独立代码步骤。RoPE 作用在 Transformer 内部的 Q/K，ALiBi 作用在 Attention Score；把 Position 单列是为了先讲清职责。

## Tokenizer 文本离散化系统

> [!map]
> [[Tokenizer文本离散化系统概览|进入 Tokenizer 专题]]

核心问题：开放文本怎样转换成有限词表中的稳定整数序列？

```text
Tokenizer
├── Token
├── Vocabulary 与 Token ID
├── Word / Character / Subword / Byte 表示路线
├── BPE / WordPiece / Unigram 方法
├── Encode 与 Decode 流程
├── 工具与实现（可选）
└── 影响与边界
```

必须分清：Token 是离散符号，Token ID 是索引，Embedding 才是向量。

## Embedding 向量表示

> [!map]
> [[Embedding向量表示概览|进入 Embedding 专题]]

核心问题：Token ID 已经是数字，为什么还要查表得到向量？

```text
Embedding
├── 向量、维度与张量的最低必要知识
├── Token Embedding
│   ├── Embedding Matrix
│   ├── Embedding Lookup
│   └── 形状与参数量
├── Embedding 参数与语义边界
└── 初始表示与 Hidden State
```

简单数学只使用类似下面的形状与乘法：

```text
vocab_size=5，hidden_size=3
→ Embedding Matrix：[5,3]
→ 参数数：5×3=15
```

## Position 位置机制

> [!map]
> [[Position位置机制概览|进入 Position 专题]]

核心问题：相同 Token 出现在不同顺序和距离时，模型怎样区分？

```text
Position
├── 为什么必须表示顺序
├── Absolute Position Embedding
├── RoPE
├── ALiBi
└── 三类机制的作用位置对比
```

必须分清：Position 决定怎样利用顺序和距离；Causal Mask 决定哪些位置有读取权限。

## Transformer

> [!map]
> [[Transformer概览|进入 Transformer 专题]]

核心问题：每个 Token 位置怎样吸收上下文并逐层形成新的 Hidden State？

```text
Transformer
├── 01 整体结构
├── 02 Causal Self-Attention
│   ├── Q、K、V
│   ├── Score、Scaling、Mask、Weight
│   ├── Value 加权与 Context Mixing
│   ├── Multi-Head Attention
│   ├── Multi-Head Attention（MHA）/ Grouped Query Attention（GQA）/ Multi-Query Attention（MQA）
│   └── Multi-head Latent Attention（MLA）与其他注意力变体（扩展）
├── 03 Residual 与 Normalization
│   ├── Residual Connection
│   ├── LayerNorm / RMSNorm
│   └── Pre-Norm / Post-Norm
├── 04 FFN / MLP
│   ├── 升维、非线性与降维
│   ├── SwiGLU / GeGLU
│   └── Dense FFN 与 Mixture of Experts（MoE，专家混合）
│       ├── Router
│       ├── Expert
│       └── 总参数与激活参数
└── 05 Block 堆叠与 Hidden State 流动
```

Attention 是 Transformer 的子系统，不等于整个 Transformer。

## Output Layer 输出层

> [!map]
> [[Output-Layer输出层概览|进入 Output Layer 专题]]

核心问题：模型怎样把最后一层各位置的表示转换成整个词表的候选分数，并在训练与运行阶段被不同地使用？

```text
Output Layer
├── Final Hidden States
├── Final Norm
├── LM Head 与 Weight Tying
├── Logits 与形状 [sequence_length, vocab_size]
├── Softmax 与概率分布的计算边界
├── 训练阶段：所有有效位置参与 Loss
└── 运行阶段：最后一个有效位置用于继续生成
```

模型主体最稳定的输出边界是 Logits。Softmax 仍要学习，但必须标明阶段：训练时 Loss 通常直接接收 Logits；运行时 Temperature、Logits Processor 与采样规则会在概率选择前后参与。Top-k、Top-p、停止条件和逐 Token 循环进入普通运行模块。

## 参数放在哪里

不再单独建立“参数体系”作为第六条并列主线。参数属于各组件：

```text
Embedding 参数 → Embedding 专题
Attention 投影参数 → Causal Self-Attention 专题
Norm 参数 → Residual 与 Normalization 专题
FFN / Expert / Router 参数 → FFN 专题
Final Norm 与 LM Head 参数 → Output Layer 专题
```

模型总参数量与配置阅读可以在五部分结束后做汇总；Scaling Law 属于评估优化与模型演进，不塞进基础结构。

## 专题总结：从真实配置还原模型

五个组件学完后增加一次配置阅读练习，但不把它变成第六个模型组件：

```text
vocab_size
→ Tokenizer、Embedding 与 LM Head

hidden_size
→ Embedding 宽度、Hidden State 宽度与多数残差通路

num_hidden_layers
→ Transformer Block 数量

num_attention_heads / num_key_value_heads / head_dim
→ Attention Head 结构与 MHA、GQA、MQA

intermediate_size / hidden_act
→ Dense FFN 的中间宽度与激活方式

rms_norm_eps
→ RMSNorm 数值配置

max_position_embeddings / rope_theta / rope_scaling
→ Position 机制及上下文长度相关配置

tie_word_embeddings
→ 输入 Embedding 与输出 LM Head 是否共享参数

use_cache
→ 运行时是否支持缓存接口，不是新的模型学习参数
```

> [!example] 真实模型校验
> Qwen3-8B 官方配置同时给出 `vocab_size`、`hidden_size`、层数、Attention Head、KV Head、FFN 中间宽度、RMSNorm、RoPE 与 Weight Tying 等字段；DeepSeek-V3 官方权重说明则列出输入 Embedding、61 个 Transformer 隐藏层、Final Norm、LM Head 和额外 Multi-Token Prediction（MTP，多 Token 预测）模块；OpenAI 官方资料说明 `openai/gpt-oss-20b` 是可加载的 Causal LM，并采用 MoE 架构。这说明当前五组件主线成立，但 MLA、MoE、Final Norm 和模型变体必须在对应位置保留入口。

来源：[Qwen3-8B 官方 `config.json`](https://huggingface.co/Qwen/Qwen3-8B/blob/main/config.json)、[DeepSeek-V3 官方权重说明](https://github.com/deepseek-ai/DeepSeek-V3/blob/main/README_WEIGHTS.md)、[OpenAI `gpt-oss` 官方微调说明](https://developers.openai.com/cookbook/articles/gpt-oss/fine-tune-transfomers#prepare-the-model)，核对日期：2026-07-27。

## 每篇笔记的统一讲法

关键名词单独成篇，并尽量包含：

1. 一句话理解；
2. 为什么需要；
3. 输入和输出；
4. 一个具体例子；
5. 真实机制；
6. 与相邻概念的区别；
7. 简单数字或形状示例；
8. 常见误解；
9. 理解检查；
10. 可选技术深入。

数学只服务于机制理解，不让公式成为主线前置条件。所有虚构 Token、ID、向量和概率都必须明确标注为教学示意。
