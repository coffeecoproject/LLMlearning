# 1.1.2.4 词表怎样连接模型输入与输出

> [!summary]
> 在常见 Decoder-only LLM 中，同一套 Token ID 含义既用于选择输入 Embedding 行，也用于标记输出词表中的候选位置。

## 输入侧：ID 负责选行

假设词表大小 `V=4`、向量宽度 `d=3`，输入 Embedding 表有形状：

```text
[V, d] = [4, 3]
```

教学矩阵：

```text
ID 0 → [0.1, 0.2, 0.3]
ID 1 → [0.4, 0.5, 0.6]
ID 2 → [0.7, 0.8, 0.9]
ID 3 → [1.0, 1.1, 1.2]
```

输入 ID `[2, 1]` 会选出第 2 行和第 1 行，得到两个位置的初始向量。ID 参与的是定位，查出的向量才进入后续计算。

## 输出侧：每个位置对应一个 Token 候选

模型最后会为词表中的每个 ID 产生一个候选分数：

```text
ID 0 → 一个输出分数
ID 1 → 一个输出分数
ID 2 → 一个输出分数
ID 3 → 一个输出分数
```

因此词表大小为 `V` 时，输出候选数量通常也是 `V`。

## “同一编号体系”不等于“共享同一矩阵”

输入 Embedding 和输出映射可以共享参数，也可以分别保存参数。`tie_word_embeddings` 常用于描述是否共享，但无论是否共享，两边都必须把同一个 ID 解释为同一个 Token。

```text
编号语义必须一致
≠ 输入输出参数必须共享
```

权重共享的细节属于 [[1.2-Embedding向量表示概览|向量表示专题]]；逐 Token 输出流程属于普通运行模块。

## 常见误解

- **“ID 本身参加了复杂语义计算。”** 它先负责选择参数行。
- **“输入和输出使用同一词表，所以参数一定共享。”** 编号体系一致与参数共享是两件事。
- **“词表只影响输入。”** 它也定义常见 LLM 的输出候选空间。
