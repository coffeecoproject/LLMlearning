# 1.1.2.1 Vocabulary 是什么

> [!summary]
> Vocabulary 是具体 Tokenizer 可以直接识别和编号的有限 Token 集合，不是自然语言单词大全，也不是模型知识库。

## 词表里有什么

它可能包含：完整词、子词、字符、标点、空白片段、数字片段、字节片段和特殊 Token。

所以：

```text
Vocabulary size ≠ 模型认识的单词数量
Vocabulary      ≠ 模型掌握的知识集合
```

## 为什么必须有限

模型需要为每个可用 ID 准备对应参数位置。如果词表可以随着每次输入无限扩张，模型就无法预先确定输入和输出参数的大小，也无法保持已经学习好的 ID 对应关系。

有限词表仍然可以组成大量序列。若一个玩具词表有 `V=4` 个 Token，只看长度为 3 的序列，就已经有：

```text
4 × 4 × 4 = 64
```

种排列。允许不同长度后，可能的文本组合会迅速增加。这个示例只说明“有限单位可以组合出大量序列”，不代表语言组合都同样有效。

## 词表大小的基本权衡

```text
较大词表 → 更容易收录常见长片段 → 序列可能更短
较小词表 → 更多文本需要拆细       → 序列可能更长
```

词表更大还意味着通常需要更多输入和输出参数。因此目标不是单纯追求最大或最小，而是在覆盖范围、序列长度和参数成本间权衡。

## 常见误解

- **“词表是一部词典。”** 它还包含非单词片段和协议符号。
- **“词表有限，所以模型只能说有限句子。”** Token 可以组合成不同长度的序列。
- **“词表越大，模型一定越聪明。”** 模型能力还取决于数据、参数、架构和训练等因素。
