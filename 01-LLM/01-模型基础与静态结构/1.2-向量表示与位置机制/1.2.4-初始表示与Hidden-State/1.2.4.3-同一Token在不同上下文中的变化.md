# 1.2.4.3 同一 Token 在不同上下文中的变化

> [!summary]
> 同一个 Token ID 通常从同一行 Token Embedding 出发，但放进不同上下文后，会通过模型层形成不同的 Hidden State。

## 从“苹果”这个例子开始

比较两句话：

```text
A：我吃了一个苹果。
B：苹果发布了新设备。
```

假设两句中的“苹果”被同一个 Token 表示，那么它们具有相同 Token ID，并从 Embedding Matrix 取出相同的初始 Token Embedding。

```text
同一个 Token ID
→ 同一行初始 Embedding 参数
```

但经过模型层后：

```text
A 中“苹果”的 Hidden State
→ 会受到“吃了”“一个”等上下文影响

B 中“苹果”的 Hidden State
→ 会受到“发布”“设备”等上下文影响
```

最终两者的 Hidden State 可以不同，使后续预测分别倾向于水果语境和公司语境。

## 为什么必须允许表示变化

如果每个 Token 从输入到输出始终只有一个固定向量，模型就很难处理：

- 一词多义；
- 代词指代；
- 否定关系；
- 语法角色；
- 长距离依赖；
- 同一个词在代码、自然语言和专有名词中的不同用途。

例如：

```text
“他没有说苹果很好吃。”
```

模型不仅要识别“苹果”，还要结合“没有”和句子结构理解当前陈述。固定词典式向量不足以表示这种上下文关系。

## 变化是怎样发生的

先建立不依赖公式的因果链：

```text
每个位置从初始表示出发
→ Attention 让当前位置有条件地吸收可见上下文
→ FFN 对每个位置的表示继续变换
→ Residual Connection 保留并累积已有信息
→ 新一层得到更新后的 Hidden State
```

当前只理解各组件的分工。Q、K、V 和具体加权过程将在 `1.3 Causal Self-Attention` 展开。

## Decoder-only 模型中的方向边界

在典型 Causal Decoder-only LLM 中，某个位置通常只能读取它自己及前面的 Token，不能读取未来 Token。

因此更准确地说：

```text
当前位置的 Hidden State
→ 由当前 Token 和当时允许看到的上下文共同决定
```

例如处理“苹果”所在位置时，该位置的表示不能依赖后面尚不可见的 Token；后面的新位置可以读取前面的“苹果”。这描述的是 Causal Attention 的信息方向，运行时如何缓存计算留到普通运行模块。

这一限制来自 Causal Mask，具体机制留到 Attention 专题。

## “上下文含义”不是一个人工标签

模型内部通常不会创建一个人类可读字段：

```text
苹果.type = 水果
```

更准确的说法是：上下文关系分布在高维 Hidden State 的许多数值和方向中，并被后续层继续利用。我们可以观察模型行为或分析表示，但不能默认每一维都有单独、固定的语言标签。

## 不同上下文一定得到完全不同向量吗

不一定。Hidden State 是否不同以及差异多大，取决于：

- 完整输入 Token 序列；
- Token 所在位置；
- 可见上下文；
- 模型参数与架构；
- 比较的是哪一层。

这里的核心不是“两个向量必须距离很远”，而是模型有能力根据上下文计算不同表示。

## 常见误解

- **“同一个 Token 的 Embedding 会在每句话里被临时改写。”** 普通前向计算改变的是 Hidden State，不是权重矩阵中的参数行。
- **“Hidden State 不同，就一定能正确理解歧义。”** 表示能变化不等于模型每次都判断正确。
- **“上下文信息一次 Attention 就能全部解决。”** 表示通常经过多层逐步变换。
- **“Decoder-only 的每个位置可以同时看到整句话。”** Causal Mask 限制它读取未来位置。
