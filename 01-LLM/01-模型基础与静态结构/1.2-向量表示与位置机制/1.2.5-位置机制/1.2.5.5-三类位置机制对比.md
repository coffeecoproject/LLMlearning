# 1.2.5.5 三类位置机制对比

> [!summary]
> Absolute Position Embedding、RoPE 和 ALiBi 都让模型对位置敏感，但它们分别作用于输入表示、Q/K 和 Attention Score，不能被画成同一个处理步骤。

## 一张表先看清区别

| 方案 | 主要作用位置 | 核心做法 | 位置关系侧重 |
|---|---|---|---|
| Absolute Position Embedding | 第一层输入附近 | 将位置向量与 Token 表示结合 | 直接标识绝对位置 |
| RoPE | Attention 的 Q、K | 按位置旋转 Q、K | 让 Q/K 关系体现相对位移 |
| ALiBi | Attention Score | 加入与距离相关的线性偏置 | 直接表达距离倾向 |

最重要的不是背缩写，而是能回答：

```text
位置信息在哪里进入模型计算？
```

## 三条数据路线

### Absolute Position Embedding

```text
Token Embedding
+ Position Embedding
→ 第一层输入表示
→ Attention
```

### RoPE

```text
Hidden State
→ Q、K
→ 根据位置旋转 Q、K
→ Attention Score
```

### ALiBi

```text
Q、K
→ 原始 Attention Score
+ 距离偏置
→ Softmax
```

把三条路线放在一起，就能看到为什么“位置编码就是加法”并不准确。

## 参数形态也不同

```text
Learned Absolute Position Embedding
→ 可能拥有可训练位置矩阵

固定 Sinusoidal Absolute Encoding
→ 位置值由固定公式生成

RoPE
→ 典型旋转规则由位置和频率决定

ALiBi
→ 典型偏置由距离和各 Head 的斜率决定
```

因此不能只问“这个模型有没有 Position Embedding 参数”，就判断它是否具有位置机制。没有可学习位置表的模型，仍可能通过 RoPE 或 ALiBi 利用位置。

## 它们是否互斥

教学时把三者当作不同典型路线最清晰，但具体架构可能组合多种位置思想或使用其他变体。判断某个真实模型时，应查看对应版本的官方配置、代码或技术报告，而不是根据模型家族名称猜测。

## 怎样阅读模型配置

看到配置字段时，可以依次问：

1. 模型使用哪类位置机制？
2. 位置规则作用于输入、Q/K，还是 Score？
3. 是否存在 `max_position_embeddings`、RoPE 频率或缩放相关字段？
4. 官方声明的最大上下文长度是多少？
5. 配置字段描述的是基础架构，还是某种长上下文扩展方法？

字段名称在不同代码库中可能不同，因此不能脱离模型版本和实现解释。

## 长上下文能力不能只看位置机制

位置机制会影响模型处理长距离关系和长度外推，但真实长上下文能力还受到：

- 训练时见过的序列长度；
- 长文本训练数据；
- Attention 架构；
- 推理时的内存与计算限制；
- 模型在长文本中的信息检索和利用能力；
- 具体评测方法。

所以：

```text
支持某个最大输入长度
≠ 能同样有效地利用窗口内每一处信息
```

## 最终心智模型

```text
Token Embedding
→ 提供 Token 的初始内容表示

位置机制
→ 让模型计算对顺序和距离敏感

Causal Mask
→ 限制 Decoder-only 模型不能读取未来位置

Attention
→ 根据内容与位置关系动态混合可见信息
```

四者相互配合，但不是同一个机制。

## 常见误解

- **“没有 Position Embedding Matrix 就没有位置能力。”** RoPE、ALiBi 不需要同样的位置查表结构。
- **“三种机制只是同一算法的不同名字。”** 它们介入计算的位置和方式不同。
- **“最大上下文长度完全由位置机制决定。”** 训练、架构、资源和评测同样重要。
- **“Causal Mask 属于 RoPE 或 ALiBi。”** Mask 是独立的可见性约束。

## 理解检查

1. 请分别指出三种机制作用于输入表示、Q/K 还是 Attention Score。
2. 一个模型没有可学习 Position Embedding Matrix，为什么仍可能理解顺序？
3. 为什么不能根据“支持 128K 上下文”直接断言模型能同样有效利用其中所有信息？
