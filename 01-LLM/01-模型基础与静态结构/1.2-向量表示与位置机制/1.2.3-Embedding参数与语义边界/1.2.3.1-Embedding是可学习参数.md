# 1.2.3.1 Embedding 是可学习参数

> [!summary]
> Embedding Matrix 的结构由模型设计确定，但矩阵里的具体浮点数是可学习参数：训练开始时被初始化，随后与模型其他参数一起通过训练改变。

## “映射表”容易带来的误解

Embedding Matrix 确实可以画成一张表：

```text
Token ID 0 → [一组数]
Token ID 1 → [一组数]
Token ID 2 → [一组数]
```

但它和 Unicode、ASCII 这类人工规定的固定编码表不同。

```text
固定编码表
→ 人为规定符号与数字的对应
→ 使用过程中数值保持不变

Embedding Matrix
→ 架构规定矩阵形状
→ 训练过程学习矩阵数值
```

因此，更准确的叫法是“可训练参数矩阵”。

## 训练开始前，这些数从哪里来

模型还没有学习时，Embedding Matrix 也必须先有数值，计算才能开始。通常会按照某种初始化规则生成较小的随机数。

例如教学示意：

```text
ID 0 → [ 0.01, -0.02,  0.00,  0.03]
ID 1 → [-0.01,  0.01, -0.03,  0.02]
```

> [!note]
> 上述数值仅用于展示“训练前已经存在初始参数”，不代表真实模型的初始化结果。

这些初始数字通常还没有形成有用的语言关系。训练从这个起点出发，不断调整它们。

## 什么叫模型参数

参数可以先理解为：

> 模型内部能够在训练中被调整，并在训练完成后保存到权重文件中的数字。

Embedding Matrix 中的每个元素都是参数。假设矩阵形状为：

```text
[vocab_size, hidden_size]
```

那么标准输入 Embedding 的参数量通常是：

```text
vocab_size × hidden_size
```

这些参数只是整个 LLM 参数的一部分；Attention、FFN、Normalization 和输出层还有其他参数。

## 配置与参数要分开

假设配置写着：

```json
{
  "vocab_size": 151936,
  "hidden_size": 5120
}
```

配置告诉程序矩阵应该有多少行、多少列，却没有列出这 7 亿多个参数的具体数值。

```text
config.json
→ 描述结构和超参数

模型权重文件
→ 保存训练后的大量具体参数
```

Tokenizer 文件又是第三类资产，负责 Token 与 ID 的映射。三者必须配套，但不能混为同一文件。

## 一个 Token 的向量由人定义含义吗

人不会逐行编写：

```text
“苹果”的第 1 维 = 水果
“苹果”的第 2 维 = 红色
```

模型只接收训练目标和大量样本。为了降低预测误差，参数被共同调整，Embedding 行逐渐成为后续网络可以有效使用的起始表示。

因此 Embedding 的意义来自它和整个模型参数系统的协作，而不是一行向量独立附带一本人工词典。

## 可训练不等于运行时一直改变

“可训练参数”的意思是它可以在训练流程中更新，不代表每次使用模型都会改变：

```text
【LLM 训练阶段】参数允许更新
【普通运行阶段】参数通常固定，只读取
```

训练怎样更新这些参数以及普通运行怎样使用它们，分别放在训练模块与运行模块展开。

## 常见误解

- **“Embedding Matrix 是 Tokenizer 生成的固定编码文件。”** 它属于 LLM 权重，并通过 LLM 训练形成。
- **“随机初始化等于随机输出永远不变。”** 初始化只是训练起点。
- **“配置文件保存所有 Embedding 数值。”** 配置主要描述形状，具体参数在权重文件中。
- **“可训练参数会在聊天时自动学习。”** 普通推理通常不会更新参数。
