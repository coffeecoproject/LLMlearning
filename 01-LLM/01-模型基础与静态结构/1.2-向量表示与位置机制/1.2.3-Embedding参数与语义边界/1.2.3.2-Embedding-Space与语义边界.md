# 1.2.3.2 Embedding Space 与语义边界

> [!summary]
> Embedding Space 是所有初始 Token Embedding 所在的高维向量空间；训练可能让其中呈现有用关系，但它不是一张完整、静态、可直接阅读的“人类语义地图”。

## 什么是 Embedding Space

假设模型的 `hidden_size = 4`，每个 Token Embedding 都是四维向量：

```text
Token A → [a₁, a₂, a₃, a₄]
Token B → [b₁, b₂, b₃, b₄]
Token C → [c₁, c₂, c₃, c₄]
```

这些向量共同存在的四维坐标空间，可以称为 Embedding Space。真实模型可能是几千维，无法直接画出来，但仍可以用距离、方向和线性变换等数学方式分析。

## 为什么训练后会出现结构

Embedding 参数不是单独接受“词义标签”训练，而是为了帮助整个模型降低预测误差。

```text
Token 在大量上下文中反复出现
→ 对应 Embedding 反复参与预测
→ 梯度根据整体任务调整参数
→ 向量空间逐渐形成模型可利用的关系
```

所以空间结构是整体训练目标的结果，而不是开发者提前画好分类区域再把词放进去。

## “语义空间”这个说法哪里有用

它帮助我们理解：

- Token 不再只是互不相关的 ID；
- 向量可以承载连续、可组合的关系；
- 相似使用模式可能产生可比较的表示；
- 后续模型层可以对这些表示进行统一计算。

作为入门直觉，这比“每个 Token 只是独立编号”更接近真实机制。

## 这个说法在哪里会误导

### 1. 接近不一定等于同义

两个 Token 可能因为主题、语法角色、搭配关系或反义对照而表现出关联。

### 2. 初始 Embedding 不是完整上下文含义

“苹果”在下面两句中 Lookup 得到的初始 Token Embedding 通常相同：

```text
我吃了一个苹果。
苹果发布了新设备。
```

区分水果公司需要后续 Transformer 根据上下文形成不同 Hidden State。

### 3. 一个 Token 可能不是完整词

Token 可能是子词、字节片段、空格组合或特殊 Token。因此 Embedding 行承载的是模型对该 Token 单位的起始表示，不一定对应一个人类词典词条。

### 4. 每一维通常不能独立命名

不能可靠地说：

```text
第 17 维 = 动物
第 42 维 = 快乐
```

信息往往分布在许多维及其组合中。

## 输入 Embedding 与上下文表示的分工

可以先建立这个分工：

```text
输入 Embedding
→ 为 Token 提供稳定的初始参数表示

Transformer 各层
→ 结合位置和上下文不断改变表示

Hidden State
→ 当前 Token 在某一层、某一上下文中的状态
```

因此 LLM 的“理解能力”不能只归功于 Embedding Matrix，它来自整个模型的多层联合计算与训练。

## 输入空间与输出空间

有些模型让输入 Embedding 与输出词表投影共享权重，有些不共享。共享时两端参数有直接联系；不共享时它们是独立学习的矩阵。

当前讨论的 Embedding Space 特指输入 Token Embedding 所在空间。输出 LM Head 如何给词表 Token 打分，留到输出概率专题。

## 与检索 Embedding 再区分

```text
Token Embedding
→ 每个词表 Token 的初始模型参数表示

文本检索 Embedding
→ 将一段句子或文档编码成适合相似度检索的整体向量
```

RAG 中谈“向量数据库里的 Embedding”，通常指后者，不应直接用输入 Embedding Matrix 的某一行代替整段文本向量。

## 常见误解

- **“Embedding Space 就是模型脑中的完整知识地图。”** 知识和能力分布在整个网络参数及计算中。
- **“两个向量越近，词义就一定越相同。”** 相近可能来自多种统计关系。
- **“同一个 Token 只有一个含义，所以一行 Embedding 足够解释一切。”** 当前含义要靠上下文 Hidden State 区分。
- **“可以逐维翻译成自然语言属性。”** 真实表示通常不是这样组织的。
