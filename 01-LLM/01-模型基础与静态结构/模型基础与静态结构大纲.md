# 模型基础与静态结构大纲

## 本部分定位

这一部分回答：

> 一个训练完成的 LLM 由哪些基本对象与结构组成？

这里只研究模型的静态结构和一次前向计算所需的对象。完整生成循环放在“LLM 普通运行与生成”；参数更新放在“LLM 训练与对齐”；请求调度与多用户 Batch 放在运行模块最后的 Runtime 服务层。

## 总体因果链

```text
原始文本
→ Tokenizer
→ Token
→ Token ID
→ Token Embedding
→ 加入或注入位置信息
→ 多层 Transformer Block
→ Final Hidden State
→ LM Head
→ Logits
→ 下一个 Token 的概率分布
```


### 概念边界

- Tokenizer 是完整的文本离散化系统；Token、Vocabulary 和 Token ID 是理解它时必须区分的核心对象。
- Token ID 只在对应词表中有意义，不是跨模型通用编号。
- Word-level、Character-level、Subword-level 和 Byte-level 是文本表示路线。
- BPE、WordPiece、Unigram 是词表构建与切分方法，不是 Token 的种类。
- tiktoken、SentencePiece 和 Hugging Face Tokenizers 是工具或实现，不与算法完全同层。
- SentencePiece 可以使用 BPE 或 Unigram，因此“工具”和“算法”不能混为一类。

### 示例策略

这一专题以可观察的文本变化为主，不要求先掌握数学：

- 用“苹果”“我喜欢苹果”观察 Token、Token ID 与词表映射；
- 用常见词和生僻词对比子词切分；
- 用中文、英文、数字、代码和 Emoji 对比 Token 数量；
- 用同一句文本在不同 Tokenizer 中的结果说明“Token 不是天然存在的”；
- 数学公式只作为可选补充，不作为理解主线。

### 完成标准

能解释同一文本为什么在不同模型中产生不同 Token 数量，以及为什么模型需要有限词表。

### 概念边界

- Token Embedding 是初始向量，不等于完整、固定的词义。
- Token ID 是词表索引；Embedding Lookup 使用它定位矩阵行，但不会把 ID 的整数大小当成语义大小。
- Embedding Matrix 是 LLM 参数，不是 Tokenizer Vocabulary 本身。
- 同一 Token 的初始 Embedding 可以相同，但不同上下文中的 Hidden State 会不同。
- 语义空间不代表每个维度都有人工可读的固定含义。
- 不能用“Token Vector + Position Vector”统一描述所有位置机制。
- Absolute Position、RoPE 和 ALiBi 注入计算的位置不同。
- 本节只说明 RoPE 与 ALiBi 的目的和作用位置；具体 Attention 计算放在 1.3。
- Embedding 怎样参与普通运行见 [[2.1.1-训练完成后怎样使用Embedding]]；怎样在训练中被更新见 [[3.1.1-训练怎样塑造Embedding]]。

## [[1.3-Causal-Self-Attention概览|1.3 Causal Self-Attention]]

### 核心问题

> 当前位置怎样动态吸收上下文信息，同时又不能偷看未来答案？

### 完整计算链

```text
输入 Hidden State
→ 线性投影得到 Q、K、V
→ 计算 Q 与 K 的点积
→ 除以缩放因子
→ 加入 Causal Mask
→ Softmax
→ 得到 Attention Weight
→ 对 V 加权求和
→ 合并多个 Attention Head
→ Output Projection
→ 返回 Residual Stream
```

```text
1.3 Causal Self-Attention
│
├── 1.3.1 Self-Attention 的目的与边界
├── 1.3.2 Q、K、V 投影系统
│   ├── Query
│   ├── Key
│   └── Value
├── 1.3.3 从 Attention Score 到 Weight
│   ├── Attention Score
│   ├── Scaling
│   ├── Causal Mask
│   ├── Softmax
│   └── Attention Weight
├── 1.3.4 Value 加权与 Context Mixing
├── 1.3.5 Multi-Head Attention
│   ├── 多个 Head 为什么有用
│   ├── Head 拼接
│   └── Output Projection
└── 1.3.6 MHA、GQA 与 MQA
    ├── MHA
    ├── GQA
    └── MQA
```

### 概念边界

- Q、K、V 是 Hidden State 经过不同参数矩阵投影得到的向量。
- Attention Score 是 Softmax 前的分数；Attention Weight 是归一化后的权重。
- Attention Weight 不等于模型思考过程的完整解释。
- Causal Mask 是自回归模型无法读取未来位置的关键约束。
- Multi-Head Attention 后仍需要 Output Projection。

### 完成标准

能按顺序推演一次 Causal Self-Attention，并解释 Scaling、Mask、Softmax 和 Value 加权各自解决什么问题。

## 1.4 Transformer Block 与层级堆叠

### 核心问题

> Attention 完成位置间的信息混合后，模型怎样继续变换表示，并通过多层计算形成复杂表示？

```text
1.4 Transformer Block 与层级堆叠
│
├── Residual Stream
├── Normalization
│   ├── LayerNorm
│   ├── RMSNorm
│   ├── Pre-Norm
│   └── Post-Norm
├── Attention Sublayer
│   ├── Self-Attention
│   └── Output Projection
├── MLP / FFN Sublayer
│   ├── Linear Transformation
│   ├── Activation Function
│   ├── Gated FFN
│   ├── SwiGLU
│   └── GeGLU
├── Residual Connection
├── 单个 Block 的完整数据流
├── Block Stacking
├── 层与层之间的表示变化
└── Final Normalization
```

### 概念边界

- LayerNorm 和 RMSNorm 是两种归一化方法，RMSNorm 不是 LayerNorm 的子类型。
- Pre-Norm 与 Post-Norm 描述归一化相对于子层的位置。
- Attention 主要负责位置间的信息交互；MLP/FFN 主要对各位置表示做非线性变换。
- SwiGLU、GeGLU 是门控 FFN/MLP 设计，不是与 FFN 完全独立的顶层模块。
- Residual Connection 既帮助训练，也形成信息贯穿模型的主要通道。

### 完成标准

能画出一个 Transformer Block，并解释 Attention、MLP、Normalization 与 Residual Connection 的分工。

## 1.5 输出概率的形成

### 核心问题

> 最后一层的 Hidden State 怎样转换成词表中每个候选 Token 的概率？

```text
1.5 输出概率的形成
│
├── Final Hidden State
├── Final Normalization
├── LM Head / Unembedding
├── Logits
├── Softmax
├── Probability Distribution
├── Next-token Prediction
└── Input Embedding 与 Output Weight Tying
```

### 单次前向计算

```text
最后一个位置的 Final Hidden State
→ LM Head 映射到整个词表
→ 每个 Token 得到一个 Logit
→ Softmax 转换成概率分布
```

### 概念边界

- Hidden State 通常需要 LM Head 才能映射到词表空间。
- Logit 是未归一化分数，不是概率。
- Softmax 产生概率分布，但不决定最终选择哪个 Token。
- 单次前向计算只形成下一 Token 的概率；完整文本生成需要选择 Token、追加上下文并重复运行。
- Temperature、Top-k、Top-p、停止条件和完整自回归循环放在第二部分。

### 完成标准

能区分 Hidden State、Logit 和 Probability，并说明模型计算概率与推理系统选择 Token 的区别。

## 1.6 模型参数与架构配置

### 核心问题

> 哪些数字属于模型保存的参数，哪些字段描述人为选择的模型结构？

```text
1.6 模型参数与架构配置
│
├── Learned Parameters
│   ├── Weight
│   ├── Bias
│   ├── Embedding 参数
│   ├── Attention 参数
│   ├── MLP 参数
│   ├── Normalization 参数
│   └── LM Head 参数
├── Architecture Hyperparameters
│   ├── Layer Count
│   ├── Hidden Size
│   ├── Attention Head Count
│   ├── Vocabulary Size
│   └── Context Length
├── Weight Tying
└── Parameter Count
```

### 两类静态对象对比

| 对象 | 是否由训练学习 | 保存在哪里 |
|---|---:|---|
| Weight | 是 | 模型权重文件 |
| Bias | 可以是；部分模型不用 | 模型权重文件 |
| Token Embedding | 是 | 模型权重文件 |
| Layer Count | 否，由架构决定 | 模型配置 |
| Hidden Size | 否，由架构决定 | 模型配置 |

### 概念边界

- Parameter 和 Architecture Hyperparameter 是两类不同的静态对象。
- Bias 可以是可学习参数，但现代模型的部分线性层可能不使用 Bias。
- Hidden State 是一次前向计算的临时表示，已在 1.2.4 单独区分；KV Cache 等 Runtime 状态放到普通运行模块。
- Parameter Count 可以在这里学习；Scaling Law 应放到训练或模型演进部分。

### 完成标准

看到模型配置时，能指出哪些字段描述架构、哪些张量是模型参数，并知道运行时状态属于后续模块。
