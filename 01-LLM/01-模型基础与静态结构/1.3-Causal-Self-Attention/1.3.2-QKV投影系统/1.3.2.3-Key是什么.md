# 1.3.2.3 Key 是什么

> [!summary]
> Key 是每个候选来源位置用于接受 Query 匹配的向量；当前位置的 Query 与各位置 Key 的关系决定原始 Attention Score。

## 每个位置都提供 Key

假设当前层有三个位置：

```text
位置 0 → K₀
位置 1 → K₁
位置 2 → K₂
```

当位置 2 要汇总上下文时，它的 Query 会分别与可见 Key 比较：

```text
Q₂ · K₀ → 位置 0 的原始匹配分数
Q₂ · K₁ → 位置 1 的原始匹配分数
Q₂ · K₂ → 位置 2 的原始匹配分数
```

这里的 `·` 表示点积，具体计算在 `1.3.3` 展开。

## Key 表达“怎样被匹配”

入门时可以把 Key 理解为某个位置对外提供的匹配特征。Query 与它方向越匹配，原始分数可能越高。

但 Key 不是：

- Token ID；
- 词典关键词；
- 数据库的唯一主键；
- 一个布尔值“相关/不相关”。

它是一组连续数值，相关程度由 Query 与 Key 共同计算。

## 同一个 Key 对不同 Query 的结果会不同

一个来源位置的 Key 并不自带固定“重要性”。例如同一个“小红”位置：

```text
代词“她”的 Query 与它比较
→ 可能高度相关

时间词“明天”的 Query 与它比较
→ 可能得到不同关系
```

所以 Attention 不是先给每个 Token 打一个全局重要性分数，而是：

```text
某个 Query
相对于
某个 Key
的匹配程度
```

## 位置机制怎样影响 Key

如果模型使用 RoPE，Key 在用于点积前会根据其位置被旋转；Query 也会根据自己的位置旋转。这样 Q/K 的关系能够体现相对位置。

如果使用 ALiBi，Key 本身不必以同样方式旋转，而是在 Q/K 得到 Score 后加入距离偏置。

这再次说明位置机制与 Q/K 匹配紧密相关，但不同架构的介入点不同。

## Key 与 Value 必须一一对应吗

在概念上，每个来源位置用于匹配的 Key 与用于提供内容的 Value 相对应：某个位置获得多少权重，就用该权重处理相应位置的 Value。

但在 MHA、GQA 和 MQA 中，不同 Query Head 怎样共享 K/V Head 会有所不同。当前先使用单头心智模型，具体共享关系留到 `1.3.6`。

## 常见误解

- **“Key 是 Token 的固定关键词标签。”** 它由当前层 Hidden State 动态投影得到。
- **“一个 Key 自身决定 Token 有多重要。”** 分数由特定 Query 与该 Key 共同决定。
- **“Key 与 Token ID 都是索引，所以是一回事。”** Token ID 用于 Embedding Lookup；Key 用于 Attention 匹配。
- **“RoPE 是修改 Token Embedding。”** 典型 RoPE 作用于用于匹配的 Q、K。
