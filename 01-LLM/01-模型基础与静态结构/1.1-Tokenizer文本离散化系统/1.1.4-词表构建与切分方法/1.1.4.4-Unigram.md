# 1.1.4.4 Unigram

> [!summary]
> Unigram 从一个较大的候选词表开始，逐步删除影响较小的片段；运行时比较整段文本的多种可能切法，选择整体得分更好的路径。

## 最关键的方向差异

```text
BPE / WordPiece：从小词表出发，逐渐添加片段
Unigram：从大候选词表出发，逐渐删除片段
```

可以把 Unigram 理解成“先给出许多候选零件，再不断淘汰最不必要的零件”。

## 【训练阶段】怎样缩小词表

假设初始候选中有：

```text
h, u, g, hu, ug, hug
```

训练程序会考虑：

> 如果删除某个候选片段，整批训练语料的最佳切分会变差多少？

- 删除后几乎不受影响：这个片段比较容易被淘汰；
- 删除后许多文本明显变难表示：这个片段更值得保留。

程序反复计算、删除影响较小的候选，直到词表达到目标规模。基础字符通常会被保留，确保文本仍然可以被切分；具体回退能力取决于实现配置。

## 【运行阶段】为什么要比较整条路径

假设词表允许把 `pug` 切成：

```text
[p] [u] [g]
[p] [ug]
[pu] [g]
```

Unigram 给每个候选 Token 一个从训练语料学到的分数或概率，再计算每条完整切分路径的整体得分，选择更优路径。

```text
列出可行切分
→ 组合各片段分数
→ 比较完整路径
→ 选择整体最佳切分
```

真实实现通常使用动态规划高效寻找最佳路径，不需要把所有组合真的完整列出来。理解主线不需要掌握公式。

## 为什么叫 Unigram

这里的 Unigram 假设每个 Token 自身有一个概率，计算切分路径时把这些 Token 的得分组合起来。它不会像 LLM 那样根据前面整段上下文预测下一个 Token。

所以：

```text
Unigram Tokenizer 中的概率模型
≠ LLM 的下一个 Token 概率模型
```

二者都出现“概率”，但用途和复杂度完全不同。

## 与 SentencePiece 的关系

SentencePiece 是工具，Unigram 是它可以采用的方法之一：

```text
SentencePiece
├── 可以训练 BPE
└── 可以训练 Unigram
```

不能把 SentencePiece 和 Unigram 当作两种并列算法。

## 可选择多种切法的价值

Unigram 为同一文本保留多条有分数的可行路径，因此某些实现可以在训练 LLM 时采样不同切分。这叫 Subword Regularization，可让模型在训练中见到同一文本的不同子词组合。

这是可选训练能力；正常确定性编码通常仍选择最佳路径。

## 常见误解

- **“Unigram 从字符开始不断合并。”** 它的典型方向是从较大候选词表开始删除。
- **“运行时随机挑一个切法。”** 默认通常选整体最佳路径；采样是可选行为。
- **“Unigram 就是 LLM 的概率预测。”** 它只是为 Tokenizer 的切分路径评分。
- **“SentencePiece 等于 Unigram。”** SentencePiece 还可以实现 BPE。
