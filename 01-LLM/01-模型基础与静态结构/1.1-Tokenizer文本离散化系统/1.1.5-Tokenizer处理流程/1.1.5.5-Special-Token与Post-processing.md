# 1.1.5.5 Special Token 与 Post-processing

## 一句话理解

> Post-processing 按模型协议把 BOS、EOS、分隔符或消息边界等特殊 Token 放到普通 Token 序列的正确位置。

## 为什么需要特殊 Token？

普通文本只能表达内容，模型还可能需要知道：

- 序列从哪里开始或结束；
- 两段输入在哪里分隔；
- 哪些位置是填充；
- 一条聊天消息由谁发送；
- 工具调用或结构化输出的边界在哪里。

示意：

```text
[我] [喜欢] [苹果]
→ [BOS] [我] [喜欢] [苹果] [EOS]
```

并非所有模型都会自动添加 BOS/EOS，必须查看配置和调用参数。

## 为什么它们不能被普通算法拆开？

特殊 Token 是协议中的原子控制符号。如果 `<message_end>` 被普通 BPE 切成多个文本片段，模型就无法稳定识别消息边界。因此实现通常为它们保留整体身份和固定 ID。

## Chat Template 与特殊 Token

Chat Template 决定角色和消息怎样排列；特殊 Token 提供协议可使用的边界符号。二者协作，但不是同一个概念：

```text
Chat Template：组装规则
Special Token：规则中使用的特殊符号
```

## 常见特殊 Token

- BOS：Beginning of Sequence；
- EOS：End of Sequence；
- PAD：Padding；
- SEP：Separator；
- MASK：掩码训练使用；
- 模型自定义的角色、消息和工具边界 Token。

字段名称不能单独证明真实用途。例如某个配置的 `eos_token_id` 可能还与生成停止列表共同作用。
