# 1.1.5.6 Token ID 与模型输入整理

## 一句话理解

> 普通与特殊 Token 通过 Vocabulary Lookup 变成 Token ID；Tokenizer 工具还常负责截断、补齐并生成 Attention Mask，使不同长度输入能够组成模型批次。

## Vocabulary Lookup

```text
Token             Token ID（示意）
[BOS]             1
我                105
喜欢              8621
苹果              12876
[EOS]             2
```

最终：

```text
[1, 105, 8621, 12876, 2]
```

这些 ID 是虚构示意值。Token ID 是词表索引，不是 UTF-8 字节值，也不是 Embedding 向量。

## Truncation

如果序列超过调用所允许的长度，工具可能截断：

```text
过长 Token ID 序列
→ 保留指定范围
→ 其余内容丢弃
```

截断可能删除关键开头、结尾或消息边界，因此策略必须与任务匹配。

## Padding

批量输入长度不同时，短序列可能补 PAD：
```text
A：[12, 38, 91, PAD, PAD]
B：[74, 28, 16, 50, 63]
```

左侧补齐还是右侧补齐会影响位置与生成行为，应遵循模型配置。

## Attention Mask

对应上面的序列，可生成：

```text
A：[1, 1, 1, 0, 0]
B：[1, 1, 1, 1, 1]
```

它标明哪些位置是有效输入、哪些是填充。这里的 Attention Mask 是模型输入辅助信息，不是 [[Causal Mask]]；两者作用不同。

## 概念边界

Padding、Truncation 和 Attention Mask 经常由 Tokenizer API 一次返回，但它们不是 BPE 等切分算法。更准确的归类是“Tokenizer 工具提供的模型输入整理”。
