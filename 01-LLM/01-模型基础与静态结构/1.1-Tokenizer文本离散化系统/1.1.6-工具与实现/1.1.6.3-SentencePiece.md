# 1.1.6.3 SentencePiece

> [!summary]
> SentencePiece 是可以直接从原始句子训练并执行子词切分的工具，支持 BPE 和 Unigram；它本身不是第三种与 BPE、Unigram 并列的算法。

## 它解决了什么问题

有些传统流程先依赖语言专用工具切词，再学习子词。SentencePiece 将输入视为 Unicode 字符序列，可以直接从原始句子训练，因此对中文、日文等没有天然空格边界的语言也能使用统一流程。

## 【训练阶段】产生一个 SentencePiece 模型

```text
原始文本语料
→ 选择 BPE 或 Unigram
→ 指定词表大小等设置
→ 统计并学习切分模型
→ 保存 .model 等产物
```

官方示例使用 `SentencePieceTrainer.train(...)` 从文本文件训练，并通过 `model_prefix` 产生模型文件。训练的是 Tokenizer 的切分规则，不是 LLM 参数。

## 【运行阶段】加载并编码、解码

```text
加载 m.model
→ encode(text)
→ 得到 piece 字符串或整数 ID
→ decode(ids)
→ 恢复文本
```

SentencePiece 常用 `▁`（U+2581）显式表示空格。例如 `▁New` 可以理解为“前面带一个空格的 New”。这样空格信息也进入可逆处理过程，而不是在预切分时被悄悄丢掉。

> [!example] 官方示例的意义
> 官方仓库展示了同一模型把英文句子编码为 pieces 或 IDs，再解码回原句。示例中的具体 ID 只属于那个已训练示例模型，不能套用到其他 SentencePiece 模型。

## 【两阶段共同】`.model` 为什么关键

官方仓库说明，`.model` 可以包含规范化规则、词表映射和切分模型。运行端只要加载相同模型文件，就能重现训练端确定的处理规则。

但要注意，“使用 SentencePiece”仍不足以确定输出：

```text
SentencePiece + BPE + 词表 A
与
SentencePiece + Unigram + 词表 B
```

当然可能产生完全不同的 Token。

## 常见误解

- **“SentencePiece 是 BPE 的另一种算法。”** SentencePiece 是工具，可实现 BPE 或 Unigram。
- **“它完全不处理空格。”** 它把空格转成可见元符号 `▁` 来保存边界信息。
- **“任何 `.model` 都能配任何 LLM。”** 不能；模型参数只认识训练时配套的 ID 语义。
- **“运行 `encode` 会继续优化词表。”** 默认运行编码只使用已固定模型。
